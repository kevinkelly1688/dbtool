分区维护

新增：可用分区数量告警
功能说明（请先确认口径，再看下面的交互）

什么叫“可用分区数”

  • 目标表里上界晚于当前时间的分区个数：含正在写入的当前分区，不含已经过去的历史分区，不含 MAXVALUE 兜底分区。
  • 维护正常时它稳定在 预创建数 + 1（预创建 3 → 4 个）；定时维护跑不动（关了、报错、实例连不上）时，它会一天天变少，直到写入报错。

告警条件与数量

  • 可用分区数 < 阈值 就告警，默认阈值 3。
  • 数量可以自己定义：全局默认一个值；每张表可以单独设置（填 0 = 这张表不告警）。小时分区的表 3 个只有 3 小时，可以给它设大一点。
  • 阈值不要超过“预创建数 + 1”，否则续建之后也达不到，会一直告警（列表标“阈值过高”，设置时给提示）。

什么时候检查、什么时候推送

  • 打开 / 刷新页面时，随“状态检查”在列表里标出；不额外连目标库。
  • 定时维护每轮结束后再检查一次：续建成功就不会推，仍然不足才推送。
  • 去重：首次不足推一次，之后按“重复提醒间隔”提醒；回到阈值以上时可选推送“已恢复”。
  • 通道沿用现有“推送设置”里的钉钉 / 飞书 / 企业微信 / Slack。

待你确认

  • 数量是否包含当前分区（原型：包含）。
  • 含 MAXVALUE 的表写入不会失败，是否也告警（原型：告警，并标注）。
  • 不同周期共用一个数量阈值是否合适（原型：列表里额外给出“预计用尽”时间辅助判断）。
