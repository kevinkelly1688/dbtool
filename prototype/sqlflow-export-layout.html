提交数据导出工单：和“提交 SQL 工单”同一套新设计

照“提交 SQL 工单”页的新设计改：①审批流预览挪进页头右侧（“导出工单列表”按钮仍在最右）；②“批量导出”“合并成一个文件”“导出原值（不脱敏）”放进同一个框，横着排在工单名称右边；③“批量导出”始终显示，不是 SQL Server 时置灰，鼠标停上去提示“仅支持 MSSQL”，可用的条件不变。字段位置不变，这一页本来就是 4 列整齐排满。

说明（改了什么、窗口变窄时怎么办）
  • 审批流预览不再占一张卡片，查询语句编辑区整体上移；悬停看可审批人员、某一级无人可审标红，都保留。“导出工单列表”按钮还在页头最右。
  • 选项组：各项放在一个和输入框一样高的框里，项与项之间一条细线，顺序是 批量导出、合并成一个文件、导出原值（不脱敏）。
  • 批量导出始终显示。可用的条件和现在完全一样（有批量权限、资源组里有可批量的实例、当前选的实例是可批量的类型，默认只有 SQL Server；已经打开批量时一直可用）；不可用时置灰、不能勾，鼠标停上去提示原因：不是 SQL Server 提示“仅支持 MSSQL”，是 SQL Server 但没有权限提示“没有批量导出的权限”。
  • 合并成一个文件的出现条件不变：打开批量并且有合并权限。选项 D 选“选项组里”时它出现在“批量导出”右边，说明文字（各实例的数据按勾选顺序写进同一个文件、各实例返回的列必须一致）放在悬停提示里；选“现状”时还在批量实例列表下面。
  • 导出原值（不脱敏）只有超级用户有。勾上要先过高危确认（不变）；勾上后整个选项组变红，必填的理由框紧挨着在选项组下面展开（原来是页面中间的一块卡片，选项和理由框隔得很远）。
  • 窗口变窄时：审批流和“导出工单列表”按钮一起换到标题下面一行；3 列宽度时名称框占第 1 列、选项组占后 2 列；2 列及以下名称框一行、选项组在它下面一行；手机宽度选项组里各项上下排。
  • 只改“提交数据导出工单”页；和“提交 SQL 工单”页共用审批流预览的脚本，所以两页的审批流预览一起变（药丸步骤条只作用在页头里的这一份，别处不变）。
