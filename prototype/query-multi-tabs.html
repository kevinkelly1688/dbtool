设计说明与待确认事项（点开看）

怎么用

  • 运行（Ctrl+Enter）：和现在一样，运行选中的内容，没选中就运行光标所在的一条；选中了多条就一起运行。
  • 运行全部（Ctrl+Shift+Enter）：脚本里的每条语句按顺序运行，一条语句一个结果页签。
  • 只有一个结果时不显示页签条，和今天一样；两个以上才出现页签条。
  • 页签是平铺的“汇总 / 结果 1 / 结果 2…”，序号就是语句在脚本里的第几条。成功的页签什么都不画；转圈 = 执行中，红字 = 失败 / 超时，橙字 = 被拦截（没权限、写操作、防火墙），灰圈 = 排队 / 没执行 / 已取消。编辑器左边的圆点同步显示，点它跳到对应页签；鼠标停在页签上能看到完整 SQL、行数和耗时。
  • 第一个页签是汇总：一张表看完每条的状态、行数、耗时和原因；可“重试失败的”。批量运行时默认停在汇总，随时点开已经完成的页签。
  • 结果表原样不动：悬停单元格出“复制 / 预览”、双击预览、方向键 + Enter 预览 + Ctrl+C 复制、列头复制整列、底部“实际执行的 SQL”——实现时每个页签直接调用现有的 renderResult，一行都不改；新增的只有页签条和汇总页。
  • 页签右键：复制 SQL、定位到语句、只重跑这一条、固定、关闭其他 / 右侧。📌 固定的页签不会被下一次运行替换，方便拿两次结果对比。
  • 执行计划按钮也只是多开一个“计划”页签（不再是结果区里另一层页签）。

执行规则

  • 每条语句单独走现有的查询接口：库表权限、SQL 防火墙、脱敏、行数上限、审计日志都按条处理，不会因为打包运行而放宽。
  • 默认依次执行，遇到错误停后面的（脚本里后面的语句常依赖前面的）；批量选项里可改成“继续执行”或“同时执行（最多 3 条，等于服务端每人并发上限）”。
  • 一次最多 20 条，超过先提示，不执行任何一条。
  • MySQL 脚本开头的 SET 仍作为前置语句随每条一起提交，不单独成页签。
  • 防火墙“要求填写原因”：整批只问一次，原因用于这批里需要原因的语句。
  • 取消：停掉正在执行的那条，后面没跑的标成“未执行”。
  • Redis / MongoDB 一次只能一条命令 / 语句，没有“运行全部”。
  • 结果仍只保存在页面里，刷新即丢（和现在一样）。

  • 页签样式：单行紧凑 or 两行带摘要？（上面可切换）
  • 要不要汇总页签？（上面可切换）
  • 默认遇错是“停止”还是“继续”？
  • “同时执行”要不要做？不做的话批量选项里只剩“遇错”一项。
  • “固定页签”要不要？不要的话每次运行都整批替换。
  • 后端要不要给批量运行记一个批次号（审计里能看出这几条是一起运行的）？前端先逐条调现有接口，后端不用改。
