# 权限申请与查询权限

在线查询、数据导出等功能要求你对具体库表持有**查询权限**。两个页面配合使用：

| 页面 | 菜单 | 用途 | 权限码 |
|---|---|---|---|
| 权限管理（权限申请） | SQL 查询 › 权限管理 | 提交申请、查看审批进度、审批他人申请 | `qpriv.view`、`qpriv.apply`、`qpriv.review` |
| 查询权限 | SQL 查询 › 查询权限 | 查看已授予的权限；有管理权限的人可修改或回收 | `qpriv.list`、`qpriv.manage` |

## 申请查询权限

1. 点「申请权限」（`qpriv.apply`），也可以从在线查询的"无权限"提示里直接进入（实例、库、表会预填）；
2. 选择**实例**（只列出你资源组内的实例，超级用户不限）、**权限范围**：
   - **库权限**：整个库下所有表；
   - **表权限**：指定的若干张表，可多选；
3. 填写**有效期**（可选 7 / 14 / 30 / 90 / 180 天，到期自动失效）、**行数上限**（1 到 100 万，决定在线查询最多返回多少行）和**申请理由**（必填，至少 5 个字，写明用途和数据范围，便于审批人判断）；
4. 提交后系统按所在资源组的"查询权限申请"审批流逐级审批，页面右侧会列出各级的候选审批人，详情页能看到流程图、当前审批人和日志；审批人会收到机器人通知。

已拥有该库表的有效权限时无需重复申请，系统会直接提示；与待审批申请重叠的申请也会被拦下。

### 申请列表

- 页签「我的申请 / 待我审批 / 全部」带数量（后两个需要审批 / 审计权限），可按状态筛选，搜索框匹配编号、申请人、实例、库和表；
- 「审批进度」列显示当前在第几级、哪个审批组审批；申请人可在行内**撤回**待审批的申请；
- 被驳回的申请在详情页可点「重新申请」预填原内容；
- 演示数据里订单中心、支付中心的审批流是组长 → DBA，用户中心、数据平台只有 DBA。

校验规则：

- 库名、表名不能含逗号、不超过 64 字符；
- 已有该库的库权限时，不能重复申请其下的表权限；
- 同一个人对同一实例的**相同内容**不能重复提交待审批申请；
- 资源组没有配置审批流时无法提交，请联系管理员；
- 你选的资源组必须是你自己所在的资源组。
- **Redis 实例没有表**：选到 Redis 实例时库就是 db 编号（`db0`…），只能申请**库权限**，“表权限”选项置灰；管理员在「查询权限」里“直接授予”时同样不能给 Redis 授表权限。Redis 的在线查询结果不做脱敏。
- **PostgreSQL / MongoDB / ClickHouse 库级与表级都可申请**：库 = database；表候选来自库表元数据——PostgreSQL 为 `schema.表名`（如 `public.orders`，含视图 / 物化视图），MongoDB 为集合名（字段是采样推断），ClickHouse 为表 / 视图 / 字典名；库名、表名区分大小写。这三类实例的在线查询结果不做脱敏。带 `read_view` 标签的这三类实例仍会出现在候选里，但在线查询会提示“该类型不支持只读视图模式”。
- **带 `read_view` 标签的其他实例**：即使授权，也只能查询 `v_` 开头的视图。

## 审批

审批人（持有 `qpriv.review`，同时属于当前这一级的权限组和该资源组）在详情页点「通过」或「驳回」：

- 点「通过」前会弹确认框，说明当前是不是末级、通过后进入哪一级审批，备注可不填；撤回申请同样先确认；
- **驳回必须写原因**；任何一级驳回即终止，最后一级通过后**自动授予权限**（审批与授权在同一个事务里完成）；
- **不能审批自己的申请**；
- 申请人可以在审批完成前**撤回**（只有申请人本人能撤回，超级用户也不能替别人撤回）；
- 审批人会收到机器人通知（钉钉 / 飞书 / Lark / Slack），点链接直接进入详情；通知失败不影响审批本身；
- 详情页只有申请人、超级用户、同资源组且有审批权限的人能看，其他人看到的是"不存在"。

## 查看与管理已授予的权限

「查询权限」页面列出库表权限：用户、实例、库、表、类型、行数上限、有效期（带剩余天数）、授予来源（申请单号或「管理员直接授予」）和状态（有效 / 即将到期 / 已过期）。顶部统计卡显示有效权限、7 天内到期、已过期（保留记录，在线查询不再生效）和涉及用户（能看到全部权限的人）/ 涉及实例（其他人）；也可按用户、实例、库和关键词筛选。7 天内到期的权限整行高亮，已过期的变灰。

没有 `qpriv.manage` 也没有审计权限的人只能看到**自己**的权限；需要更多库表请到权限管理提交申请，修改 / 回收他人权限需要 `qpriv.manage`。

有 `qpriv.manage`（高危）的人还可以：

- **修改**有效期和行数上限，保存后立即生效（在线查询最长约 15 秒内感知）；
- **回收**权限（立即生效，对方正在写的查询下一次执行起就会被拒绝）；
- **直接授予**（「＋ 直接授予」）：不走审批，来源记为「管理员直接授予」，并写入审计日志；

管理范围限定在**自己资源组关联的实例**内，且所有修改写入系统审计。

## 权限如何参与查询判断

在线查询时，系统对语句涉及的**每一张表**检查：存在有效的库权限（库名相同或 `*`）或表权限、未过期、未被回收；生效行数取各表限制的**最小值**，再与你选择的行数取小。超级用户、持有 `query.admin_run` 的人，以及 `query.group_run` 对资源组内实例，可以绕过库表授权。详见[在线查询](#help/query)。

> 原型体验：用 rd_zhao 提交一个表权限申请，切到 tl_wang 通过，再回到 rd_zhao 在"查询权限"里看到新授予的权限；也可以试试 tl_wang 审批自己的申请——会被拒绝。

## 常见问题

- **申请一直待审批**：看详情页"当前审批人"。若该级没人有审批权限，找管理员在[审批流程配置](#help/sysadmin)里补人；
- **权限过期了怎么办**：重新提交申请即可，不需要先删除旧权限；
- **看不到别人的申请**：没有 `qpriv.review` 的人只能看到自己提交的。
