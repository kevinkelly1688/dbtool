# SQL 上线（工单）

菜单：SQL 审核 › SQL 上线。所有对生产库的变更（DDL / DML）都通过工单完成：**提交 → 检查 → 逐级审批 → 执行 → 回滚 / 追溯**。在线查询只允许读，变更一律走这里。

## 角色与权限速览

| 动作 | 需要的权限码 | 典型角色 |
|---|---|---|
| 查看自己的工单 | `sqlworkflow.view_own` | 研发 / 测试 |
| 查看资源组内全部工单 | `sqlworkflow.view_group` | 组长 / DBA / 审计 |
| 提交工单 / 批量上线 | `sqlworkflow.submit` / `sqlworkflow.submit_batch` | 研发 / 测试 / 组长 |
| 审批通过 / 驳回 | `sqlworkflow.approve` / `sqlworkflow.reject` | 组长 / DBA |
| 立即执行 | `sqlworkflow.execute_group`（资源组内）或 `sqlworkflow.execute_own`（仅自己的单） | DBA / 研发 |
| 定时执行、确认手工执行结束 | `sqlworkflow.schedule`、`sqlworkflow.manual_finish` | DBA |
| 修改可执行时间 | `sqlworkflow.alter_window` | 当前审批人 |
| 终止自己的工单 | `sqlworkflow.cancel_own` | 提交人 |
| 查看 / 下载回滚语句 | `sqlworkflow.rollback` | 提交人 / DBA |
| 在线改表控制 | `sqlworkflow.osc` | DBA |
| 批量实例重试 / 关闭 | `sqlworkflow.batch_op` | DBA |
| 跳过语法检查 | `sqlworkflow.skip_check`（锁定，仅超级用户） | 管理员 |

没有 `view_group` 的人只能看到自己提交的工单；**看不到的工单一律提示不存在**，不会暴露它是否存在。

## 提交工单

1. 点「提交工单」，填写**工单名称**（≤ 50 字），选择**资源组、实例、数据库**。**资源组决定走哪条审批流**；实例下拉只列出带"可写"标签、属于该资源组、你能访问的实例，从库和只读视图实例不能提交变更；
2. 在编辑器里写变更 SQL（≤ 200 万字符，多条语句用分号分隔，DDL 与 DML 不能混提），可选填需求链接、**可执行时间窗口**（开始、结束都可不填，结束必须晚于开始；只有在窗口内才能执行或设定时）；
3. 选择是否**备份**（生成回滚语句，仅 goInception 检查 / 执行时有效）；SQL Server、批量上线和勾选了"跳过语法检查"的工单不备份，该选项置灰；
4. 点 **检查**：逐条返回"通过 / 警告 / 错误"、影响行数估算和改进建议，结果上方标出检查来源（goInception、SQL Server 语法解析与上线规则）。有错误不能提交；SQL、实例或库任何一项变化后，之前的检查结果作废，需要重新检查；
5. 点提交，工单进入资源组配置的审批流。

页面中部的**审批流程**按所选资源组读取审批流，逐级显示审批组和当前可审批的成员；某一级没有人能审批会标红"无人可审"，此时只有超级用户能审批，请联系管理员补充成员。

持有锁定码 `sqlworkflow.skip_check` 的超级用户还能勾选**跳过语法检查**（Redis 与批量上线不提供）：先弹高危确认，说明风险——不检查、只能原生执行、不备份、无回滚语句、无在线改表；工单上带"跳过检查"标签。

> 提交时服务端会**重新检查一次**，不信任页面上的预览结果；同一用户并发提交也会串行处理。

### 检查规则

- **goInception 已配置**：由 goInception 做语法、规范、索引、表结构层面的审核，并给出影响行数；
- **未配置（降级）**：只做词法级判断——语句必须是 DDL / DML，不连目标库、不校验表结构、拿不到影响行数、不能备份，页面会明确提示"降级检查"；
- **站点规则叠加**：禁止 `SELECT`（请用在线查询）、命中高危语句正则、DDL 与 DML 不能混在同一个工单里；资源组名带 `DDL` / `DML` 字样时要求语句类型与之一致。批次里只要有一条 DDL 就按 DDL 工单处理，**`DELETE` 也归为 DDL**；
- 检查有错误且管理员配置了自动驳回策略时，工单直接变为"自动审批不通过"。

```sql
-- 示例：给订单表加一列并建索引（DDL，建议在低峰执行）
ALTER TABLE order_db.orders
  ADD COLUMN pay_channel VARCHAR(16) NOT NULL DEFAULT '' COMMENT '支付渠道',
  ADD INDEX idx_pay_channel (pay_channel);
```

## 审批流与通知链路

审批流按**资源组 × 工单类型**配置（见[系统管理](#help/sysadmin)里的"审批流程配置"），由若干"级"组成，每一级对应一个权限组，例如：

1. 第 1 级：组长（本资源组内的组长）；
2. 第 2 级：DBA。

规则：

- 审批人必须**同时**属于"当前这一级的权限组"和"工单所属资源组"，并持有 `sqlworkflow.approve`；超级用户可以审批所有工单；
- **不能自己审批自己的工单**（超级用户不受限）；这也是"你是唯一审批人时工单会卡住"的原因；
- 任何一级驳回（必须写原因）即终止；最后一级通过后工单变为"审核通过"；
- **空审批流**：系统直接通过；**没有配置审批流**：提交失败，请联系管理员；
- 自动审核：管理员可开启"自动通过"规则（仅 goInception 检查的低风险、影响行数很小的 DML 才会自动通过，原生降级检查一律走人工）；
- 审批流变更只影响之后提交的工单，已在审批中的不受影响；
- 详情页顶部的步骤条和右侧的**审批进度**按"提交 → 各级审批 → 执行 → 结束"着色，已审批的级别显示审批人、时间和意见；等待审批时显示当前级别和可审批人，本级没人能审批时提示仅超级用户可审批。

通知链路（机器人通知，钉钉 / 飞书 / Lark / Slack，**尽力而为，失败只记日志，不影响业务**）：

| 事件 | 谁会被 @ |
|---|---|
| 提交 / 流转到下一级（待处理） | 当前这一级的审批人 |
| 审批通过 | 提交人 |
| 驳回（含自动驳回，附原因） | 提交人 |
| 提交人终止 | 渠道配置的 @ 规则 |
| 已设置定时执行 / 开始执行 | 提交人 |
| 执行完成 / 执行有异常 | 提交人，DDL 完成时还可额外 @ 指定权限组 |

每条消息包含工单号、发起人、资源组、实例、库、审批流程与当前审批人、SQL 预览（前 500 字符）和详情链接。具体渠道、订阅事件与 @ 规则由管理员在"通知渠道"配置。

## 操作前的确认框

详情页的关键操作都会先弹出确认框，取消不会产生任何变更：

- **审批通过**：说明这一级是不是末级、通过后进入哪一级审批，并汇总检查结果的警告 / 错误条数，可填审批意见；
- **驳回 / 终止**：必须填原因；驳回后工单进入"人工终止流程"；审批通过但尚未执行的工单终止后不可恢复，已设置的定时计划会被取消；提交人**撤回**同样不可恢复，原因可不填；
- **立即执行**：先选执行方式，再进入高危确认，列出实例、库、语句条数和类型；失败即停，已成功的语句**不会自动回滚**；目标实例是生产环境时还要求键入工单号；
- **定时执行**：填写执行时间（须晚于当前且在可执行时间窗内）并选择执行方式，确认后由调度器到点执行；
- **确认手工执行结束**：确认你已在线下执行完该工单的 SQL，工单置为"已正常结束"，系统不执行任何语句；
- **终止在线改表、批量实例重试 / 关闭**：高危确认，说明后果（终止后原表不变、该语句记为失败、其后语句不再执行；重试会在该实例上重新执行整段 SQL；关闭后不再计入成败，也不能再重试）。

> 原型体验：用 rd_zhao 提交一张订单库工单 → 切到 tl_wang 通过 → 切到 dba_li 通过并执行；切换身份时侧栏"SQL 上线"的角标会随之变化。立即执行时可在「原型 · 模拟结果」里选择让第 N 条语句失败，演示"失败即停、其后语句标为未执行"；定时执行的工单详情页有「⏱ 原型：模拟到点触发」按钮，模拟调度器到点触发。

## 工单列表

菜单进入后看到的是你可见范围内的工单（可见范围见上文）：

- 顶部的**状态卡片**显示各状态的数量，点击即按该状态筛选，再点一次取消；
- 页签「全部 / 我提交的 / 待我审批 / 待我执行」带数量，有待办时数量高亮；
- 可按状态、实例、资源组、单实例或批量筛选；搜索框匹配工单号（可带 `#`）、名称、提交人、库和实例；点列标题排序；
- 名称下显示语句类型（DDL / DML），并带标签：`批量 N` 是批量上线工单；`OSC` 含在线改表语句；`跳过检查` 提交时跳过了语法检查、原生执行；`⏱ 时间` 是定时执行时间；
- 「当前审批级」列显示审批进行到第几级和该级可审批的人，已结束的工单显示"N 级审批完成"、在第几级终止或"系统自动驳回"；
- 操作列：「详情」；轮到你审批的带「审批」，你能执行的审核通过 / 定时执行工单带「执行」。

## 工单状态

状态流转：

```
等待审批 →（逐级通过）→ 审核通过 →（立即执行）→ 执行中 → 已正常结束 / 执行有异常
审核通过 →（设定时间）→ 定时执行 →（到点，调度器每 15 秒扫描）→ 执行中
审核通过 / 定时执行 →（确认手工执行结束）→ 已正常结束
等待审批 / 审核通过 / 定时执行 →（撤回 / 驳回 / 终止）→ 人工终止流程
提交时检查有错误 →（自动审批不通过）
```

整体链路是：提交 → 检查 → 审批流（例如组长 → DBA）→ 执行（立即 / 定时 / 手工）→ 结束 / 异常，每个节点都会发机器人通知。

| 状态 | 含义 | 下一步 |
|---|---|---|
| 等待审批 | 已提交，正在某一级审批 | 审批人通过 / 驳回；提交人可撤回 |
| 审核通过 | 全部审批通过，等待执行 | 有执行权限的人立即 / 定时 / 手工 |
| 定时执行 | 已设置执行时间，等调度器到点触发 | 到点自动执行；到点前可终止 |
| 排队中 / 执行中 | SQL 已发往目标库 | **不能终止**；页面自动刷新 |
| 已正常结束 | 全部语句执行成功（含手工确认结束） | 可查看 / 下载回滚语句 |
| 执行有异常 | 有语句失败，失败即停，后面的标"未执行" | 到目标库确认现状，必要时新开工单修复 |
| 人工终止流程 | 提交人撤回或有权限的人驳回 | 终态 |
| 自动审批不通过 | 检查阶段被自动驳回 | 修改 SQL 后重新提交 |

## 执行

有执行权限的人（资源组内 DBA，或提交人本人且持有 `execute_own`）在详情页操作：

- **立即执行**：先校验"可执行时间窗口"，同一实例同一库上已有 DDL 在执行时会被拒绝并指出冲突工单（**同库 DDL 串行**）；
- **定时执行**：选择一个晚于现在、且在时间窗口内的时间，由调度器（每 15 秒扫描）到点触发；每张工单只能有一条定时计划，重设会覆盖，到点前终止工单会取消计划；
- **手工执行**：你在别处已经执行完，点"确认手工执行结束"，工单置为已正常结束，系统不执行任何语句；
- **执行方式**：配置了 goInception 默认走 goInception（逐条结果、支持备份与回滚、在线改表）；否则默认原生执行（同一会话逐条执行，失败即停，不备份，执行前检查 `read_only`）。页面会标出"推荐"；跳过检查、SQL Server、批量上线和 Redis 工单只能原生执行。

当前不在"可执行时间窗口"内时，立即执行会被拒绝，可以设定时到窗口内执行。

执行结果逐条显示：序号、SQL、阶段状态、影响行数、耗时、错误信息。

**复制为新工单**：已结束或已终止的工单详情页有此按钮（批量工单执行有异常时除外），带出名称、实例、库和 SQL，到提交页修改后重新提交。

## 回滚语句

只对**开启了备份且已结束**的 goInception 工单可见：详情页"回滚语句"页签按执行顺序倒序展示，可复制或下载为 `.sql`。回滚语句是反向 SQL，**执行回滚前请先评估数据是否已被后续业务写入**。工单没有开启备份（SQL Server 不支持备份、原生执行、未勾选备份）时没有回滚语句；每次查看和下载都会写入审计。

## 在线改表（OSC）

大表 DDL 可使用 gh-ost / pt-osc。执行中详情页显示进度，并提供 **暂停 / 恢复 / 终止**（需要 `sqlworkflow.osc`，且工单在执行中；命令只接受 get / pause / resume / kill，服务端校验操作的任务确实属于这张工单）。终止后原表不变，该语句记为失败，其后语句不再执行，工单进入"执行有异常"。

## 批量上线

适用于同一段 SQL 在多个实例上执行（管理员只放开了部分实例类型，演示里是 SQL Server）：

- 提交时勾选"批量上线"并选择多个实例（最多 100 个，类型必须一致，可「全选」「清空」），需要 `sqlworkflow.submit_batch`；
- 数据库列表和语法检查只取第一个勾选的实例，另外**预检每个实例**（能连通、库存在）；任一实例预检失败则不允许提交；
- 执行时每个实例各跑一遍（SQL Server 并行，默认 4 路，其余串行），**单个实例失败不影响其他实例**；
- 有失败时工单为"执行有异常"，汇总里写明"已有 N 个实例已生效，请人工核对"；失败实例可单独 **重试**（在该实例上重新执行整段 SQL，用新结果替换旧结果，重试期间工单为"执行中"）或 **关闭**（不再计入成败，也不能再重试）。全部实例都被关闭时不会被标成成功；
- 列表可按"单实例 / 批量"筛选，批量工单带"批量 N"标记。按实例筛选时，批量工单里**任一**实例都算命中，并按实例 ID 整值匹配（筛选 ID 42 不会命中只含 ID 142 的工单）。

### 提交页

- **提交方式**：分段按钮“单实例 / 批量上线”。缺少 `sqlbatch_submit`，或资源组里没有可批量的 SQL Server 实例（实例要带 `can_write` 标签并属于所选资源组）时“批量上线”置灰并写明原因；批量上线只对 SQL Server 开放，同一段 SQL 在所选的每个实例上各执行一遍（用各实例自己的账号）；
- **选择实例**：左侧清单可按名称 / 地址 / 环境 / 角色筛选（多个词用空格分隔），支持“全选当前结果”“反选”“清空”，并显示“已选 N / 100”；没有 `can_write` 标签或不是 SQL Server 的实例收在“另有 N 个实例不能批量上线”里并写明原因；
- **执行顺序与主实例**：右侧“已选清单”按执行与结果的顺序排列，可拖拽或用 ▲ ▼ 调整，“置顶”设为主实例。**第一个是主实例**：目标库清单、语法与规则检查、工单的“主实例”都取自它；
- **审批流程预览**：按所选资源组读取；某一级没有人能审批会标红。批量工单沿用资源组的“SQL 上线”审批流，不因实例数增加而增加审批级，审批人看到的是同一段 SQL 和全部实例；
- **固定约束**：不支持跳过语法检查；不备份、没有回滚语句；语法与规则检查只在主实例上做；每个实例的预检（能连上、目标库存在，库名不区分大小写）并发 8 路；执行并发默认 4 路（系统配置 `batch_parallel_workers`，最多 16）；
- **SQL 输入**：多条语句用分号分隔，或用独占一行的 `GO` 分批；`Ctrl`+`Enter` 检查；检查与执行用同一种切分，每个单元一个事务，失败即停；
- **检查结果分两块**：① 主实例的语法 / 规则表（行号、级别、规则 ID、信息）；② 每个实例的预检矩阵，失败行高亮写原因，可就地“移出”。任一实例预检失败整张工单不能提交；检查之后改了实例、目标库或 SQL，之前的结果作废，需重新检查。

### 详情页

- **状态横幅**：有失败时写“已有 N 个实例的变更已生效，请人工核对”；全部实例都被关闭时明确“不算成功”，工单保持“执行有异常”，避免“一路关闭”把工单变成已完成；
- **进度与实例表**：成功 / 失败 / 已关闭 / 执行中 / 排队计数、分段进度条和并发度；实例表每行可展开看逐条语句（含 `USE` 行、失败即停后级别为“未执行”的行），可按状态或实例名筛选；
- **重试**：在该实例上重新执行整段 SQL，包括已提交的前序语句（各语句独立事务，不会回滚），请确认语句可重复执行；已不存在的实例只能关闭；工单执行中不能对其它实例重试或关闭，避免并发改写同一份执行结果；
- **关闭**：只是在工单里不再跟踪这个实例，不对实例做任何改动，已提交的语句不会回滚；
- 单实例工单没有“重试 / 关闭”，请到目标库核对后用“复制为新工单”重新提交（带出名称、实例、库和 SQL，在提交页修改后再提交）。

### 新增建议（可选，默认关闭）

原型里标“新增建议”的三项是现有设计之外的提议，每项默认关闭，不改变上面的既有语义，可在顶栏“新增建议开关”里试用：

- **预检增强**：预检同时检查“库只读 / 账号权限”，提前发现只读库、缺 DDL / DML 权限的实例，而不是执行时才一个个失败；只增加检查列，不放宽任何现有检查；
- **灰度先行**：提交页每张工单自己勾选。先只在主实例上执行，成功后再按并发度执行其余实例；主实例失败则其余实例保持“未执行”，没有变更扩散，重试成功后点“继续执行其余实例”；
- **一键重试全部失败实例**：等同于逐个点“重试”，每个实例各自替换结果行、工单置“执行中”、写日志；已不存在的实例仍只能关闭。

> 原型体验：顶栏“演示控制条”可选择模拟结局（全部成功 / 部分失败 / 全部失败 / 含已删除实例）、重试后的结果、并发度、速度和提交人身份（张伟可批量提交并执行，李娜缺 `sqlbatch_submit`，王强无执行权限）。建议路径：提交页“载入示例”→ 检查（2 个实例预检失败）→ 移出失败实例 → 重新检查 → 提交 → 详情页“审批通过”→“立即执行”→ 失败实例重试 / 关闭 → 工单列表。

## 终止与撤回

| 当前状态 | 谁能终止 |
|---|---|
| 等待审批 | 提交人（称为"撤回"）、当前审批人（称为"驳回"，需写原因） |
| 审核通过 / 定时执行 | 有执行权限的人，或提交人 |
| 排队中 / 执行中 | 不能终止 |

> ⚠ 执行中的工单一旦发出就无法回头：SQL 已经到达目标库，终止按钮会置灰。请在"审核通过"阶段再确认一遍语句和执行时间。

## Redis 工单

选到 Redis 实例时，提交页是"命令模式"：库选 `db0…`（就是 db 编号），输入框里**每行一条命令**（写法同 redis-cli，支持引号和 `\xHH`，一次最多 200 条），点"检查命令"逐行得到 通过 / 警告 / 拒绝，表头为 行 / 命令 / 涉及键数 / 结果。备份、批量上线、跳过检查等选项对 Redis 不适用，会自动隐藏；切回 MySQL / SQL Server 实例后原样恢复。

- **规则由管理员定义**：每条命令必须同时命中某条启用规则的 命令名、键匹配、适用范围、键数上限，否则拒绝；**没有规则就全部拒绝**。规则只有超级用户能在"系统管理 → Redis 上线规则"里改，见 [系统管理](#help/sysadmin)；
- **硬禁止**：`FLUSHALL`、`FLUSHDB`、`CONFIG`、`EVAL`、`KEYS`、`SELECT`、`AUTH`、`SORT … STORE` 等任何规则都放行不了；`PUBLISH` 这类无键命令、`GET` 这类读命令也不能通过工单执行（读数据请用在线查询）；
- **拒绝的原因**：命令不在受支持的写命令清单里、命中硬禁止命令、键不匹配任何规则、超出键数上限、适用范围不符、没有启用的规则、语法错误（引号没闭合等）；
- **警告不拦截**：例如 `SET` 没带过期时间、`SETNX` / `MSET` 无法设置过期、`EXPIRE` 的时间 ≤ 0（会立即删除）、`PERSIST`、`RENAME` / `COPY` 会覆盖目标键、一次 `DEL` ≥ 20 个键；
- **只要有一行被拒绝就不能提交**；提交时服务端会再检查一次，有拒绝行直接失败（不产生工单）；
- 审批流、通知、定时、手工执行、终止与其他工单一样；执行方式只有原生执行。执行时按**当时的规则整单复检**（审批期间规则被改，以现在的为准，任一行不再通过则一条命令都不发，工单显示原因），再逐条执行，每条记录 结果摘要 / 耗时 / 错误，**遇错即停**，后面的命令标"未执行"，已执行的不回退；
- **没有自动回滚**，详情页会固定提示。规则勾选了"记录执行前值"的命令，被改键的原值会明文记在执行结果里（详情页"执行前的原值"折叠区）供人工恢复——它不是完整备份；
- 命令原文会完整保存在工单里，**请勿在命令里写入密码等敏感信息**；
- 审计：`Redis上线-检查`、`Redis上线-提交检查`、`Redis上线-执行`（执行摘要里疑似密码的值记为 `***`）。

## 使用建议

- DDL 尽量放在低峰窗口，用"可执行时间窗口"限定；大表变更先在测试实例演练；
- 提交前先在 [SQL 分析与优化](#help/optimize) 里看一眼执行计划与索引建议；
- 工单卡在审批？到 [常见问题](#help/faq) 查"工单提交后没有人审批"。
