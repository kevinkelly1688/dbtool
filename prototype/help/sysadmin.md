# 系统管理

菜单：系统管理（仅管理员）。本组页面的按钮在权限树里全部是**锁定码**（除"系统审计"外）：服务端只认超级用户，**不能授予权限组**；切换到非超级用户身份时，这些页面要么不显示，要么按钮显示"仅超级用户可用"。按钮级权限本身见 [按钮级权限](#help/btnperm)。

> 所有写操作都在同一个事务里先改数据再写审计日志，审计写失败则整体回滚；管理类接口每次请求都会回库确认操作者仍是启用的超级用户。

## 审批流程配置

为**每个资源组 × 每种工单类型**配置一条多级审批流。工单类型有三种：查询权限申请、SQL 上线申请、数据归档申请（数据导出、批量上线沿用"SQL 上线申请"的审批流）。**没有配置审批流的组不能提交该类工单**。页面有三个页签：按资源组配置、总览矩阵、审批与通知链路。

- 每一"级"选一个**权限组**，按顺序逐级流转，**级内任一审批人通过即进入下一级**；可拖动或用 ↑ ↓ 调整顺序，最多 10 级，同一权限组不能在同一条流里出现两次；有改动尚未保存时显示“草稿未保存”，可“恢复为当前流程”；
- 左侧只列出未停用的资源组，`n/3` 是已配置的工单类型数，⚠ 表示有级别无人可审；右侧的工单类型页签带状态标记：✓ 已配置、⚠ 有级别无人可审、○ 未配置；
- 页面会列出每一级的**可审批人**：该资源组内、属于该权限组、未停用，且持有该类工单审核按钮的用户（SQL 上线 `sqlworkflow.approve`、查询权限 `qpriv.review`，含单独授权 / 禁用；归档申请没有单独的审核按钮）。超级用户可审批所有工单，不计入；🔒 表示账号已锁定。**该级无人可审会警告**（权限组已被删除、资源组内没有属于该权限组的用户、审批人都没有审核权限、审批人账号都已锁定）——这是工单"卡住"最常见的原因；
- **总览矩阵**：行 = 资源组，列 = 工单类型，点单元格跳到“按资源组配置”；顶部三张 KPI：资源组 × 工单类型总数、已配置、有“无人可审”警告的数量；红色单元格表示该级无人可审，“未配置”的组不能提交该类工单；
- **审批与通知链路**：流程图展示 提交 → 逐级审批 → 通过 / 驳回 → 机器人通知（虚线为机器人通知）；空审批流或命中自动审核规则时，SQL 上线提交后直接“审核通过”，检查有错误则直接驳回；“实际示例”按所选资源组和工单类型列出时间线；
- 保存前会预览并确认变更前后，预览里有“无人可审”的级别时会再次红字警告（仍可继续变更）；删除某条审批流后该组不能再提交该类工单；保存和删除都写入系统审计；
- 审批流在**提交时**复制进工单，变更只影响**之后提交**的工单，审批中的工单不受影响；
- 保存时不允许为空流；SQL 上线的"空审批流自动通过"请通过自动审核规则实现；
- **审批规则**：审批人必须同时属于当前级的权限组和工单所属资源组，不能审批自己提交的工单；任何一级驳回即终止，提交人可撤回，审核通过后有执行权限的人也可终止；通知发往资源组配置的机器人（钉钉 / 飞书 / Slack），更细的事件订阅与 @ 规则在“通知渠道”里配置。

> ⚠ 某一级无人可审时，工单会卡在该级；保存审批流前请留意黄色警告。

## 资源组管理

资源组 = 团队 / 实例分组，仅超级用户可管理。它决定：

- 用户能看到哪些实例（用户 ↔ 资源组 ↔ 实例；持有“查询全部实例”的用户不受限）；
- 每种工单类型的审批流；
- 工单通知发到哪个钉钉 / 飞书 / Slack 群；
- 性能工单把它当“团队”。

权限组与资源组没有直接关系，**审批人 = 资源组内属于某权限组的用户**。

- 页顶 4 张 KPI：启用中的资源组、没有实例的组（用户进来看不到任何实例）、审批流不完整（不足 3 种工单类型）、未配置机器人（工单通知无处可发）。列表显示负责人、成员数、实例数、`n / 3` 审批流配置情况和各机器人是否已配置，黄色行表示没有实例或审批流不完整；
- 新建 / 编辑：名称 1–100 字且唯一（含已停用的），负责人和备注；改名会同步审批流里的显示名；
- **关联对象**：穿梭框（左边未关联、右边已关联）一次增删多个用户或实例，“添加 / 移除”只是暂存，点“保存关联”后整批在一个事务里生效，并写入系统审计；移除用户后 TA 将看不到该组的实例，同一实例可同时属于多个资源组；移除用户可能让审批流出现新的断点，页面会提示；已停用的资源组不能改关联；
- **通知机器人**（钉钉 / 飞书 / Slack webhook）：属于敏感信息，任何页面都只显示“已配置 / 未配置”，**留空表示不修改**，要清除请勾选“清除”；审计里只记“已设置 / 已更新 / 已清除”，不记地址；更细的渠道、签名与 @ 规则在“通知渠道”里配置；
- **停用 / 恢复**：停用是软删除，成员与实例的关联保持不变；有进行中的工单（待审批的流程、已通过但未结束的 SQL 工单）时拒绝并列出明细，需先结束或终止；已停用且没有任何成员、实例和历史工单引用的组可以“彻底删除”（需键入资源组名称，无法恢复）。

## 用户管理

| 功能 | 说明 |
|---|---|
| 概览 | 页顶 4 张 KPI：用户总数、超级用户、已锁定、未绑定 2FA |
| 筛选 | 按权限组（含“超级用户”）、资源组、状态（正常 / 已锁定 / 已停用 / 未绑定 2FA）、关键字（账号 / 姓名 / 邮箱 / 部门）；可按最近登录 / 账号 / 状态排序；列表显示权限组、资源组、认证方式、2FA 绑定、失败次数（已锁定的账号）、最近登录 |
| 详情 / 有效权限 | 右侧抽屉：账号资料、通知标识、单独授权 / 禁用记录和每个按钮的有效权限与来源（可按“仅允许 / 仅禁止 / 仅单独授权”筛选），并可直接编辑、启停、重置密码、重置 2FA、授予 / 收回超级用户 |
| 新建 / 编辑 | 用户名 1–30 字（字母数字和 `@ . + - _`，创建后不可改），姓名（≤10 字）、邮箱、部门、钉钉 UserID / 飞书 OpenID / Slack ID（通知标识，用于工单通知里 @ 到本人）、权限组（可多选，取并集）、资源组（可多选，决定能看到的实例；用户在已停用资源组里的关联保持不变）；新建时选认证方式（本地 / LDAP，LDAP 用户不设本地密码）；初始密码按"登录与安全设置"里的密码策略校验（表单提示里写的"至少 9 位"是固定文案，实际最小长度以设置为准，不满足时提示"密码太短，至少需要 N 个字符"），**由管理员输入，不回显、不进审计** |
| 启停 / 解锁 | 停用后账号无法登录并从审批人中移除，可随时重新启用；账号因失败次数达到阈值被锁定后，解锁 = 失败计数清零（阈值见下文“登录与安全设置”） |
| 重置密码 / 重置 2FA | 重置密码有两种方式：系统生成临时密码（只显示一次，关闭后无法再查看，也不写入审计；用户首次登录须改密；最小长度大于 32 时生成不出合规密码，会提示改为手输），或管理员手输新密码（按密码策略校验，可要求用户下次登录先改密）；新密码不会记录到日志或审计，请通过安全渠道告知用户；LDAP / SSO 等外部认证的用户不能在这里重置。重置 2FA 会删除该用户全部验证方式，用户下次登录重新绑定 |
| 单独授权 / 禁用 | 见 [按钮级权限](#help/btnperm)；必须写原因，可设到期时间 |
| 授予超级用户 | 只有超级用户能改超级用户标记；超级用户绕过全部权限检查，并可使用系统管理的所有页面 |

保护规则：**不能停用或降级自己；不能停用或降级最后一个启用的超级用户**（并发下也有行锁保护）。所有操作写入系统审计，密码从不回显或记录。

## 权限组管理

权限组是"角色"，同时是审批流里的"级"，仅超级用户可管理。页面左侧是权限组列表（带“内置”标签和成员数，可新建），右侧分三个页签：

| 页签 | 内容 |
|---|---|
| 基本信息与成员 | 组名（≤150 字，不含逗号换行，不区分大小写唯一）和说明；已授予按钮数、成员数、被审批流引用数；成员列表只读，成员关系在“用户管理”里按用户调整；列出引用它的审批流 |
| 按钮权限 | 按钮级权限的授予、预设、预览与迁移，用法见 [按钮级权限](#help/btnperm) |
| 按用户查看有效权限 | 选一个用户，列出每个按钮的有效结果与来源，并可对该用户单独授权 / 禁用，见 [按钮级权限](#help/btnperm) |

页面顶部的“按钮权限生效方式”用于切换兼容 / 严格模式，并设置无权限按钮是置灰还是隐藏。新建权限组时可选初始权限：空白、套用预设，或复制已有权限组。带“内置”标签的权限组不能改名、不能删除，但可以调整它们的权限和说明。删除权限组前会检查是否被审批流引用或有成员：有成员或被引用时拒绝并列出明细。

## 登录方式

在页面里定义外部认证，**可同时启用多种、可添加多个同类型**（如两套 LDAP、飞书和 Lark 各一个），即时生效不用重启。

| 类型 | 说明 |
|---|---|
| LDAP | 直连 / StartTLS / LDAPS；DN 模板或先搜后绑；空密码一律拒绝 |
| OIDC / Slack | 授权码 + PKCE + state + nonce，自行校验 id_token（固定 RS256 / ES256） |
| 钉钉 / 飞书 / Lark / 企业微信 | 各自的 OAuth 流程，可限定企业 / 租户 |
| CAS | CAS 1 / 2 / 3 ticket 校验 |

要点：

- **必须测试通过才能启用**：连接类配置改动后会自动停用、测试结果作废；管理员发起的"测试登录"只显示取得的属性和匹配结果，不创建用户、不写绑定、不建会话；
- 密钥加密存储，接口永不回显，留空表示不改；
- 可设"首次登录策略"（自动创建用户 / 仅限已有用户）、默认入组、匹配依据、属性映射和入组规则（只增不减）；
- 回调地址 = 平台对外地址 + `/login/sso/<id>/callback`，需要在 IdP 里登记；
- 页面从上到下：概览（已定义、启用中、未测试、测试异常）、已定义的登录方式、通用规则、登录页预览；第一行是内置的“本地账号密码”，不可停用或删除；其余可拖动 ⋮⋮ 或用 ↑ ↓ 调整登录页按钮顺序；**本地账号登录永远保留给超级用户**（`/login?local=1`），避免外部登录配错把自己锁在外面；
- 所有变更（添加、配置、测试、启停、删除、排序、通用规则）都写入系统审计；启用 / 停用 / 删除和保存配置前会先弹确认框。

各类型的连接参数、属性映射、入组规则、测试与通用规则的详细说明见 [登录、两步验证与账号安全](#help/login) 的“登录方式管理（管理员）”。

## 登录与安全设置

菜单"系统管理 → 登录与安全设置"，**仅超级用户**（权限码 `sec.view` / `sec.edit`，均为锁定码）。页面把分散的安全项集中在一起：顶部是账号锁定策略、两步验证、密码策略、会话 / JWT 四张概览，中间是账号安全、会话与 API、页面水印、两步验证短信服务四张配置卡片，底部“已定义的登录方式”是只读摘要（外部登录在“登录方式”里配置）。保存前会列出变更差异并二次确认，确认后立即生效。取值范围、单位和默认值如下（以真实实现 `internal/authx/settings.go` 为准）：

| 设置 | 取值范围 | 默认 | 说明 |
|---|---|---|---|
| 登录失败几次锁账号 | 1–100 次 | 5 | 失败次数达到该值、且最近一次失败在"锁定时间"之内，账号被临时锁定；锁定期内即使密码正确也拒绝 |
| 锁定时间 | 10–86400 **秒** | 300（5 分钟） | 单位是秒，不是分钟；锁定期满后下一次登录前失败计数自动清零，也可由管理员在用户管理里"解锁" |
| 强制两步验证 | 开 / 关 | 关 | 开启后未绑定的用户登录时必须先绑定 |
| 开放用户自助注册 | 开 / 关 | 关 | 登录页显示注册入口，同 IP 每小时 10 次 |
| 密码最小长度 | 6–64 位 | 9 | 新建用户、重置密码、修改密码、自助注册都按它校验；已有账号不受影响 |
| 密码复杂度 | 开 / 关 | 关 | 开启后新密码必须同时含**字母、数字和特殊字符**（不要求大小写） |
| 会话有效期 | 5–43200 **分钟**（30 天） | 300（5 小时） | 滑动续期：每次请求自动延长，超过这么久没有任何操作才需要重新登录 |
| 关闭浏览器即退出 | 开 / 关 | 开 | 会话 Cookie 不带 Max-Age |
| JWT access 有效期 | 1–720 **小时**（30 天） | 4 | 只有 access token，没有 refresh token |
| JWT 登录要求 OTP | 开 / 关 | 关（与原系统一致） | 开启后，已绑定两步验证的用户通过 API 登录必须带 `otp` |
| API 用户白名单 | 用户多选 | 空 = **不限制** | 非空时只有名单内用户的 JWT 能调用 API。**与原系统相反**：原系统白名单为空则全部拒绝，本系统为空不限制，要收紧就配置白名单 |
| 默认权限组 / 资源组 | 多选 | 空 | 新用户（自助注册或外部登录首次自动创建）的默认归属；外部登录方式自己设置了默认入组的，以那里为准 |

其他设置：

| 设置 | 说明 |
|---|---|
| 页面水印 | **仅超级用户可定义**（`sec.edit` 是锁定码，不能授予权限组），用于截图溯源。可设置：开关；内容模板（点变量按钮插入到光标处，变量 `{账号}` `{姓名}` `{部门}` `{IP}` `{日期}` `{时间}`，必须含 `{账号}` 或 `{姓名}`，否则截图无法追溯到具体的人，最长 60 字）；第二行附加文字（可空，最长 40 字，如“内部资料 严禁外传”）；透明度 3%–30%（太淡拍屏看不清，太浓影响阅读，建议 10%–18%）、字号 12–28 px、倾斜角度 -60 到 0 度（0 为水平，负数向上倾斜）、疏密（紧凑 / 标准 / 宽松）、颜色（跟随主题 / 灰色 / 红色 / 蓝色；跟随主题在深色主题下用浅字、其他主题用深字）。“效果预览”用的是你自己的账号信息，其他用户看到的是他们自己的；也可以“全页预览 5 秒”（未保存）；保存后立即生效，不用刷新。其他用户只能看到水印，不能关闭或修改；水印层被删除 / 隐藏 / 改样式会自动恢复并记审计 |
| 短信服务 | 服务商：关闭（仅 TOTP，默认）/ 阿里云 / 腾讯云。阿里云填 AccessKey ID / Secret、短信签名、模板编号、模板变量名（默认 `code`）；腾讯云填 SecretId / SecretKey、短信签名、模板 ID、SDK AppID。用于短信验证码（6 位，5 分钟有效，同号码 60 秒内不能重复获取）；两步验证方式只有 TOTP 与短信；密钥加密保存、永不回显，留空表示不修改；"发送测试短信"使用**已保存**的配置，改了参数请先保存再测试 |

校验与保存：

- 数字项必须是整数且在上表范围内，超出范围或不是整数时在输入框下方提示（例如"锁定时间应在 10 到 86400 之间"），并阻止保存；
- 保存前弹出**统一确认框**，把**变更差异**（项目 / 原值 / 新值）和**风险提示**合并展示；有风险时按钮是"我已了解风险，确认保存"，没有任何变更时不弹框，提示"没有变更"；密钥类项只显示"已修改"，审计里也不记录密钥内容；
- 风险提示（不阻止保存，只让管理员看清楚）：降低密码最小长度、关闭强制两步验证、开放自助注册、放宽锁定策略（次数变多或锁定时间变短）、关闭"JWT 登录要求 OTP"、关闭页面水印或透明度低于 6%、清空 API 用户白名单、会话有效期超过 24 小时；
- 确认后**立即生效**（本实例立即，其他实例最多 10 秒），锁定次数 / 时长、密码策略、会话与 JWT 有效期下一次登录、新建用户、改密就按新值。

密码策略的实际校验：长度不少于"最小长度"；不能是常见弱口令、不能全是数字、不能包含（或与之过于相似）用户名 / 邮箱前缀 / 姓名；开启复杂度时还要同时含字母、数字和特殊字符。**登录本身不校验密码策略**，只在新建用户、重置密码、修改密码时校验，所以改了策略不会让现有账号（包括演示账号的 `Dba@2026`）无法登录。

设置有约 10 秒的缓存，修改后其他实例最多 10 秒内生效；数据库短暂抖动不会影响登录。

## goInception 配置

goInception 是 SQL 上线检查与执行、查询脱敏所依赖的审核引擎。本页仅超级用户可用，顶部显示进程状态（运行中 / 重启中）、版本、已运行天数、执行中的任务数和重启方式。连接信息保存即生效；goInception 自己的配置文件（`config.toml`：审核规则、备份、在线改表等）提交后需要**重启 goInception 才生效**。页面把"校验 → 对比 → 保存 → 重启 → 健康检查 → 失败自动恢复"做成一条流程，每次修改保留历史版本，可一键回滚，密码类参数不回显明文。页面有四个页签：

- **连接信息**：“审核 / 执行连接”是 dbtool 连 goInception 的地址 / 账号，“备份库”是 dbtool 读取回滚语句用的备份库连接；goInception 自己写备份的账号在配置文件的 `[inc] backup_*`，两处需要一致。"测试连接"、"测试备份库"；保存即生效，无需重启 goInception；密码加密保存、不回显，留空表示不修改；改了地址 / 端口 / 账号而没有重新输入密码时，“测试连接”不会把已保存的密码发给新地址；
- **配置文件**：左侧"常用参数"表单、右侧 `config.toml` 源文件，**双向同步**（行级编辑，保留注释与排版），表单改动会同步到源文件，也可切换为“只看源文件”。表单里没出现过的参数显示为“未设置”（复选框为不确定态），不会被偷偷写入；其余参数请直接在源文件里改，点号键 / 内联表 / 数组表不参与表单同步但原样保留。保存前校验语法和取值——类型写错是错误，未知参数和风险取值（如关闭 DML 必须有 WHERE、允许 DROP DATABASE）是需要确认的警告；密码类参数显示占位符，保存时未改动则保持原值；
- **历史版本**：保留最近 50 个版本，每个版本记录完整文件（密码加密保存，页面、版本详情和版本对比里一律显示占位符）、操作人与重启结果；可对比、可回滚（回滚不改旧记录，而是以旧版本的内容生成新版本并走重启流程，写入系统审计）；失败或已自动回滚的版本不能作为回滚目标；
- **部署与重启**：配置文件路径（绝对路径，`.toml` 结尾）、重启方式（固定为 Docker）、容器名（字母、数字和 `_ . -`，以字母或数字开头，即 `docker ps` 里的 NAMES）、重启命令只读预览、健康检查最长等待（5–600 秒）、等待任务完成的最长时间（10–3600 秒，超时则不重启、版本记失败），以及“健康检查失败时自动恢复上一个生效版本”“有任务执行时默认等待执行完再重启”两个开关；“检查权限与连通性”可先行验证。右侧进程状态显示状态、版本、启动时间、连接 / 任务数、配置文件版本（磁盘文件与生效版本不一致时会提示）与最近一次重启；
- **保存并重启**：goInception 以 Docker 部署，重启方式只有一种——直接 `docker restart <容器名>`。重启命令只来自“部署与重启”里管理员设定的容器名，保存 / 重启时用户只能选“要不要等任务”，不能改命令；dbtool 运行用户需要对配置文件有读写权限，并只被授权执行这一条 docker 命令（sudoers 白名单），不要加入 docker 组（等同 root）。保存时若有进行中的任务，可选"等待完成"或"强制重启"（会中断任务，被中断的工单停在“执行有异常”，需人工确认目标库状态）；重启后健康检查失败会**自动恢复上一版本**；也可以"仅保存"（不重启，页面提示“有未生效的配置”），之后点"仅重启"让它生效。

> ⚠ goInception 重启期间 SQL 检查会短暂不可用；生产环境建议选"等待完成"，并避开业务高峰。

## 通知渠道

工单提交、审批、执行等事件会发到所属资源组配置的机器人和这里定义的渠道。支持钉钉、飞书、Lark、Slack 机器人和**邮件**（SMTP）。每个渠道关联一个或多个资源组，或为全局渠道（对所有资源组生效，如总监与周报；选了“全局”则忽略资源组勾选）。页顶 4 张 KPI：渠道数（启用 / 停用）、资源组覆盖（列出未覆盖的资源组）、事件覆盖、近期发送（含失败数）；列表可按类型、资源组、名称 / 主机筛选；下方是“消息效果预览”（按渠道类型切换，示例事件为待审批）和“最近发送记录”（含测试发送）。

- **Webhook 与签名密钥**（邮件渠道为 **SMTP 密码**）加密入库、不回显，页面只显示主机名和“已加签 / 已设密码”，编辑时留空 = 不修改；签名密钥只在机器人开启了“加签”时填写（钉钉 / 飞书 / Lark，Slack 无需）；更换渠道类型后需要重新填写 Webhook 地址；
- **订阅事件**：工单提交、待审批（新工单 / 流转到下一级审批）、审批通过、被驳回（含系统自动驳回）、提交人终止、已设置定时执行、开始执行、执行完成（含手工确认结束）、执行异常、性能工单超时（SLA 到期未处理）、巡检告警（健康分低于阈值）；不选表示订阅全部事件；数据归档没有单独的订阅项，沿用上述事件：归档开始 → “开始执行”；归档完成、被窗口 / 上限中断 → “执行完成”；负载中断、失败、校验失败、结构变更暂停、自动暂停 → “执行异常”；归档申请的提交 / 流转 / 通过 / 驳回 → “待审批 / 审批通过 / 被驳回”，详见 [数据归档](#help/archive)；
- **@ 规则**：目标可选提交人、当前审批级的审批人（流转到下一级时自动换人）、DBA 值班（按值班表解析）、某权限组成员、指定用户、渠道原生标识、所有人（会 @ 渠道里的所有人，谨慎使用）；每条规则可按事件过滤（不选 = 渠道订阅的全部事件），并可勾选“仅工作时间 @”（周一至周五 09:00–19:00，其余时间只发消息不 @）；一条消息最多 @ 50 个目标，一个渠道最多 20 条规则；用户的渠道标识来自用户资料（钉钉 UserID / 飞书 OpenID / Slack ID），没有标识的用户退化为文本 "@姓名"；
- **渠道原生标识**：Slack 用户 `U...` / 用户组 `S...`，钉钉填手机号（11 位），飞书 / Lark 填 open_id（`ou_...`）；
- **测试发送**：忽略事件订阅过滤，“提交人”规则解析为样例工单的提交人，真实发送会带上渠道对应的签名；已停用的渠道测试发送仍会发出。可选模拟事件、消息来源（SQL 上线 / 权限 / 性能 / 巡检，或数据归档——只有归档对应的六个事件有归档样例，其余事件仍发原有消息）和发送时间（工作时间 / 非工作时间）；“未 @ 的规则”会列出没有 @ 的原因。预览按各渠道的原生格式展示请求体：Slack 的 `& < >` 按 Slack 规则转义，钉钉用 `at.atMobiles` / `isAtAll`，飞书 / Lark 用 `<at id=…>` 标签；加签时钉钉在 URL 上追加 timestamp 与 sign，飞书在请求体里带 timestamp 与 sign；
- 保存、删除、启用 / 停用都会先弹出确认；停用后配置保留，删除会把 Webhook 与签名密钥一并清除（只是暂时不发请用“停用”）；
- **邮件渠道**：类型选“邮件”，填 SMTP 主机（主机名或 IP，不要带 `smtp://` 和端口）/ 端口 / 加密方式（STARTTLS 587、SSL/TLS 465、不加密 25，切换加密方式时端口自动换成对应默认值）、用户名（留空 = 不认证，需要服务器放行本机 IP 中继）和密码、发件人地址与显示名、固定收件人 To / Cc（逗号分隔）和主题前缀。
  - 固定收件人 To / Cc 合计最多 20 个；@ 规则解析出的用户邮箱另算，一封邮件总计最多 50 个收件人；
  - @ 规则解析成**用户资料里的邮箱**：提交人、当前审批人、权限组成员、指定用户、DBA 值班；“所有人”是工单所属资源组的全部用户；“邮箱地址”填一个固定地址。**没有邮箱的用户会被跳过**，并在“发送记录”的说明里写明；同一个邮箱只发一次。页面右侧“将发送给谁”会列出实际收件人，并标出没有邮箱的用户；没有可用收件人时，真实发送会失败；
  - **证书校验默认开启**；关闭后连接仍加密，但无法确认对方身份，有被中间人窃听邮件内容和 SMTP 密码的风险（页面有红色提示，保存时再确认一次），仅在内网自签名证书且无法改用受信任证书时使用；
  - 加密方式为“不加密”时，**默认不允许填用户名密码**（用户名和密码会明文传输）；确需使用要勾选“允许明文认证”，并尽量只在本机或隔离的内网使用；
  - “测试发送”可以填一个测试收件人（只发给他），并逐阶段显示 连接 / STARTTLS / 认证 / 发送 的结果（不含密码）；原型里可以选择“模拟服务器行为”（证书失败、认证失败、超时……）观察各阶段；
  - 邮件正文里的变量都经过转义，主题用 RFC 2047 编码，地址 / 主题里的换行一律剔除或拒绝；
  - 每个渠道每分钟最多发 60 封，超出的丢弃并记入发送记录；连接超时 10 秒、整次发送最长 30 秒，失败最多重试 1 次；邮件里的工单链接用 PUBLIC_URL 拼接，没配置时只写编号。
- 通知是**尽力而为**：失败只记日志（如钉钉机器人限流 20 条 / 分钟），不影响业务；SQL 上线、权限申请、性能工单、巡检共用同一套渠道。

## 消息模板

菜单：**系统管理 › 通知渠道 › 消息模板**（仅超级用户）。每一类通知消息（新工单提交、审批通过、执行成功、权限被回收……）可以单独定制标题、状态色、字段排版、SQL 的显示方式和按钮；没定制的沿用系统默认。谁被 @、发到哪个渠道仍由“通知渠道”里的订阅与 @ 规则决定，这里只管内容。

页面顶部有“历史版本”“恢复系统默认”“测试发送…”“保存”四个按钮和三个页签：**编辑模板**、**生效矩阵**、**变量一览**。

### 编辑模板

编辑页从左到右三块：

1. **选择消息**：按分组（SQL 上线 / 数据导出、查询权限、数据归档、性能工单 / 巡检）列出所有消息，可搜索；已定制的带“自定义”标记，另有范围专属模板的带“+N”；
2. **编辑内容**：先选**适用范围**——全局（所有渠道）、某个资源组、某个渠道；右上角“当前生效”标出这个范围现在用的是哪一层。这个范围还没有专属模板时显示的是上一层的内容（只读），点“定制这条消息”或“创建专属模板”后复制当前内容再改；
3. **预览**：按渠道页签（Slack、钉钉、飞书 / Lark、邮件、纯文本）实时渲染；“示例数据”可切换样例（SQL 类消息有三套）；“渲染效果”是各渠道里看到的样子，“发出的内容”是实际发出的请求体 / 邮件正文。预览下方显示消息大小与渠道上限，以及校验提示。

**生效顺序**：渠道专属模板 → 资源组模板 → 全局自定义模板 → 系统默认，找到的第一个就是；没有任何定制时按系统默认文案发送，行为不变。

模板的组成：

| 项 | 说明 |
|---|---|
| 模板名称 | 只在管理页显示 |
| 启用 | 关闭后这条消息改用上一层模板 |
| 标题 | 邮件主题 / 卡片标题，可写变量 |
| 状态色 | 蓝（信息）、绿（成功）、橙（待办）、红（异常）；用于飞书卡片头与邮件顶条 |
| 图标 | 可选，显示在标题前 |
| 内容 | 若干内容块，可上移 / 下移 / 删除 |

### 变量与内容块

- `{{变量名}}` 替换成这条消息里的值，`{{#if 变量名}}…{{/if}}` 表示“变量有值才显示”；
- 只能用右侧“变量”面板里列出的变量（点一下插入到光标所在的输入框），灰色的是当前消息没有的；模板里不能写表达式或调用函数；
- 引用了不存在的变量时不能保存；引用了当前消息没有的变量，发出去是空的，预览里会提示；
- 变量里的内容按渠道自动转义（Slack / 钉钉 / 飞书 / 邮件各自的特殊字符），模板里写的 `*粗体*`、换行等按各渠道规则渲染。

| 内容块 | 说明 |
|---|---|
| 字段表 | 一行一个“名称：值”；勾选“占半行”的字段在 Slack / 飞书里排成两列，钉钉 / 邮件 / 纯文本里仍是一行一个 |
| 文本 | 一段自由文字，可以写变量和条件块 |
| SQL / 代码块 | 专门放 SQL，可选：只显示前 N 个字（缺省，N 为 50–3000）、隐藏字符串常量（`'…'` 换成 `'***'`）后再取前 N 字、完整显示（受渠道上限限制）、不显示 SQL |
| 链接 / 按钮 | Slack、飞书显示成按钮，钉钉、邮件、纯文本显示成链接 |
| 分隔线 | 钉钉 / 邮件里显示成分隔线，纯文本里是一排横杠 |

各渠道的限制：

| 渠道 | 格式 | 上限 |
|---|---|---|
| Slack | Block Kit（webhook 不支持时降级为文本） | 单块文本 3000 字、字段 2000 字、最多 50 块 |
| 钉钉 | markdown | 约 20000 字节 |
| 飞书 / Lark | 交互卡片 | 约 30 KB |
| 邮件 | HTML + 纯文本备份 | 主题 200 字；正文不限 |

超出上限时按“代码块优先截断”的顺序裁剪，并在末尾写明“内容过长，已截断，完整内容见工单”。

> ⚠ 工单 SQL 里常有 `PrivateKey`、`password` 这类字段，群消息谁都能看到、还会被搜索和留存，所以 SQL 块默认只给前 500 字，并提供“隐藏字符串常量”。示例 SQL 疑似含密钥而选了“完整显示”时，预览会标红提醒；建议改成“隐藏字符串常量”或“不显示 SQL”。

### 生效矩阵与变量一览

- **生效矩阵**：每一行是一种消息，每一列是一个渠道，格子里是这个渠道发这种消息实际用的模板——系统默认、全局自定义、资源组模板、渠道专属；点格子跳到对应的编辑页；
- **变量一览**：列出全部变量的含义、示例，以及在哪类消息（SQL 上线 / 导出、查询权限、数据归档、性能工单、巡检）里可用。

### 保存、测试与历史

- **保存**：有不存在的变量时不能保存；保存、恢复默认都写系统审计（动作“修改通知模板”，只记事件、范围和改动摘要，不记渠道密钥）；
- **恢复系统默认**：删除当前范围的专属模板，改回沿用上一层，内容保留在历史版本里；
- **历史版本**：按消息 × 范围列出修改记录，可恢复到某个旧版本，恢复后需保存才生效；
- **测试发送**：选一个渠道，用当前编辑中的模板（含未保存的改动）和示例数据真的发一条，测试消息带“[测试]”前缀，不 @ 任何人；弹窗里写明这个渠道发这条消息实际会用哪个模板。

### 各类消息的发送时机

| 分组 | 消息 | 何时发送 |

| SQL 上线 / 数据导出 | 新工单提交 | 提交人提交工单、进入第一级审批时（同时属于“待处理”） |
| SQL 上线 / 数据导出 | 流转到下一级审批 | 上一级审批通过后，工单流转到下一级审批人时 |
| SQL 上线 / 数据导出 | 审批通过 | 最后一级审批通过，工单可以执行时 |
| SQL 上线 / 数据导出 | 被驳回 | 审批人驳回工单时，带驳回原因 |
| SQL 上线 / 数据导出 | 提交人终止 | 提交人主动撤回 / 终止工单时 |
| SQL 上线 / 数据导出 | 已设置定时执行 | 给工单设置了定时执行时 |
| SQL 上线 / 数据导出 | 开始执行 | 工单开始执行时 |

| 数据归档 | 归档任务待审批 | 提交归档任务、需要审批时 |
| 数据归档 | 归档完成 | 归档任务一次运行成功结束时 |
| 数据归档 | 归档失败 | 归档任务运行出错、已暂停时 |
| 性能工单 / 巡检 | 新发现慢 SQL | 性能采集发现需要受理的慢 SQL 时 |
| 性能工单 / 巡检 | SLA 超时升级 | 性能工单超过 SLA 未处理、升级给上一级时 |
| 性能工单 / 巡检 | 巡检告警 | 定时巡检发现问题时 |

## Redis 上线规则

菜单"系统管理 → Redis 上线规则"，**仅超级用户**（权限码 `redisrule.view` / `redisrule.edit`，均为锁定码，不能授予权限组）。定义 Redis 工单（见 [SQL 上线](#help/sqlworkflow)）允许哪些命令；预置 0 条规则，**没有规则 = 全部拒绝**：

- 规则字段：名称（唯一，≤50 字）、启用（停用的规则不放行任何命令）、命令（逗号分隔，如 `DEL,UNLINK`，大小写不敏感；可从“支持的写命令”里点选）、键匹配（glob，每行一个，如 `cache:*`；`*` 任意长度、`?` 一个字符、`[ab]` 集合，**至少含一个固定字符**，只含通配符如 `*` 会被拒绝）、适用范围（限定实例，不选 = 全部实例，按住 Ctrl 多选；限定 db 编号，逗号分隔，0–1023，留空 = 全部库）、单条命令键数上限（1 ~ 10000，默认 100，主要约束 `DEL` / `UNLINK` / `MSET` 这类多键命令）、是否"记录执行前值"（执行前记录被改键的原值供人工恢复；**原值会明文显示在工单详情里**，含令牌 / 会话等敏感数据的键不要开，它不是备份）、说明和备注（≤500 字）；
- **白名单语义**：命令必须**同时**命中某条启用规则的命令名、键、范围，并且涉及的键数不超过上限才允许提交和执行，没有命中一律拒绝；没有任何启用的规则时，所有 Redis 工单的检查都会被拒绝，审批中的工单执行时也会复检失败。规则只管“键”：多键命令检查每个键（`MSET` 检查键不检查值，`DEL` 检查全部键，`RENAME` 的两个键都要匹配），无键命令（如 `PUBLISH`）不能被放行；键里的 `*`、`?` 只是普通字符，不会被展开；
- **硬禁止命令**（任何规则都无法放行）和所有无键命令、读命令不能写进规则，选了即时报错；页面下方"命令清单"列出硬禁止与支持的写命令；
- 新增 / 修改 / 启停 / 删除都要**二次确认**（弹窗里列出差异），并写入系统审计（修改只记变化的字段"旧 → 新"，删除前的内容也留在审计里）；规则变更立即对所有 Redis 工单生效，执行时按当时的规则复检；
- "从模板添加"填入常见规则（见下表），只是把字段填进编辑器，仍需核对后二次确认保存；
- "规则测试"选实例、db 编号，输入若干行命令（每行一条），用当前规则试检查并返回命中哪条规则或拒绝原因（不执行、不连接 Redis、不写审计）；
- 🧪 原型演示：页面提供"载入演示规则"，一键加入 5 条规则，方便演示"提交通过"的流程（真实系统没有该按钮）。

| 模板 | 填入的规则 |
|---|---|
| 清理缓存键 | 允许 `DEL` / `UNLINK` 删除 `cache:` 开头的键，一次最多 100 个 |
| 设置过期 | 允许对 `session:` 开头的键设置 / 修改过期时间（`EXPIRE` / `PEXPIRE` / `EXPIREAT` / `PEXPIREAT`） |
| 读后写入（写缓存键） | 允许 `SET` / `SETEX` / `PSETEX` 写 `cache:` 开头的键（建议带过期时间，`SET` 不带过期会给警告） |
| 修复哈希字段 | 允许对 `user:` 开头的哈希 `HSET` / `HDEL` 字段，并记录执行前的字段值供恢复 |

## 数据脱敏

菜单：**系统管理 › 数据脱敏**（仅超级用户）。管理员在这里指定“哪些库表的哪些字段、用什么方式”脱敏；保存即生效，在线查询按同一份配置处理（脱敏结果的呈现见[在线查询](#help/query)，导出结果的脱敏见[数据导出](#help/export)）。

> Redis / Memcached 没有“表 / 字段 / 结果列”的结构，Elasticsearch / OpenSearch 是索引文档而不是 SQL 结果集，Oracle / Cassandra / TDengine 目前只有实例类型、没有在线查询入口，都不在脱敏范围内：实例下拉里灰显，不能选。

页面顶部选**实例**；实例名下的标签显示数据库类型和“结果列定位”精度（精确定位 / 保守匹配 / 字段路径匹配），各数据库的差异见下面“各数据库怎么脱敏”。右上角“粘贴清单选字段”用于批量选字段。

### 配置向导：选字段 → 选规则

1. **选择字段**（左侧）：可以跨库、跨表多选。
   - **库**下拉可选单个库或“全部库”；筛选框按表名 / 字段名 / 注释过滤，多个词用空格分隔；
   - **按表 / 按字段名**两种视图：“按字段名”把所有表里的同名字段聚合成一行（如 `mobile` 出现在 3 张表），勾一下就选中全部，是批量最快的方式；
   - **状态筛选**：全部 / 疑似敏感 / 未脱敏 / 已脱敏。“疑似敏感”只是按字段名猜（手机号、身份证、银行卡、邮箱、姓名、地址、微信），仅作提示，不会自动脱敏；“选中疑似敏感”一键勾选当前范围内所有还没脱敏的疑似敏感字段；
   - **粘贴清单**：从 Excel / 文档直接粘贴，每行一个 `库.表.字段`、`表.字段` 或只写字段名（匹配当前实例所有同名字段），按行从右往左匹配，并告诉你哪几行没匹配到。PostgreSQL / SQL Server 的表带架构，如 `public.account.phone`；MongoDB 写 `集合.字段路径`；
   - **字段目录不全**：MongoDB 的字段来自对最近 1000 个文档的采样，可能不全，缺的路径在“补充字段路径”里手动添加（`集合.字段路径`，如 `users.profile.wechat`）。
2. **选择脱敏方式**（右侧）：一次只应用一种规则到所选字段，方式见下表；常用预设有手机号 3+4、身份证 3+4、银行卡 6+4、姓名 1+0、邮箱 2+0、地址 6+0，**试算**里可以直接改“原值”看结果；
3. **生效范围**：只对所选的“库.表.字段”（精确匹配，同名字段在别的表里不受影响）；或“该实例所有表里的同名字段”（写成 `*.*.字段名`，新建的表里同名字段也自动脱敏）；
4. **应用**只是暂存，保存后才生效。底栏显示“已选 N 个字段”和“待保存 N 项（新增 / 覆盖 / 移除）”，可“放弃变更”；点“保存并生效…”会弹出变更差异表，确认后立即生效并写入系统审计。

| 方式 | 效果 | 说明 |
| --- | --- | --- |
| 保留首尾 | 前 N 位 + `***` + 后 M 位，如 `138***5678` | 中间固定三个星号，不泄露长度；值太短时自动少保留，保证至少隐藏 1 个字符 |
| 三段式 | 按长度三等分，隐藏前 / 中 / 后一段，如 `138****5678` | 沿用原规则 100，星号个数与被隐藏的字符数一致（会泄露长度）；需要不泄露长度请用“保留首尾” |
| 整列隐藏 | 一律显示 `***` | MongoDB 显示为“整字段隐藏” |
| 自定义正则 | 正则 + 要隐藏的第几组 | 高级用法，沿用原系统的“正则 + 隐藏分组”；正则不匹配时原值原样返回，请谨慎使用 |

选字段后右侧会给出影响面板：将对几张表的几个字段设置脱敏；哪些字段已有别的规则会被覆盖；数值类型（脱敏后以文本返回，金额 / 数字列通常不需要脱敏）、类型不统一（如部分文档里是数字：先转成文本再脱敏，结果按文本返回）、JSON / Map 类型（对其中所有文本值逐个按规则处理，不区分键名）等提示；所选字段含多类疑似敏感数据时，可以点“每类用各自的推荐规则”。

### 各数据库怎么脱敏

| 数据库 | 字段层级与来源 | 结果列怎么定位 | 精度 |
| --- | --- | --- | --- |
| MySQL / PolarDB / ADB | 库 › 表 › 字段（目标库 `information_schema.COLUMNS`） | goInception 语法树逐列溯源（含别名、子查询、JOIN、UNION）；实例没有配置 goInception 时降级为按结果列名保守匹配 | 精确 |
| SelectDB / Doris | 库 › 表 › 字段（同 MySQL） | 没有语法树：按结果列名、别名和表达式引用匹配；引用了敏感字段的函数 / 运算结果列会整列脱敏，宁多勿漏 | 保守 |
| SQL Server | 库 › 架构.表 › 列（`sys.schemas` / `sys.tables` / `sys.columns`） | 执行前用 `sp_describe_first_result_set` 取每个结果列的来源库 / 架构 / 表 / 列（视图追溯到基表）；临时表、动态 SQL 等无法静态推断时降级为保守匹配 | 精确 |
| PostgreSQL | 库 › 架构.表 › 列（`pg_catalog`） | 结果集描述里自带每列的表 OID 与列号，反查即得（含别名、JOIN）；表达式列没有来源；json / jsonb 列对其中所有文本值逐个处理 | 精确 |
| ClickHouse | 库 › 表 › 列（`system.columns`） | 协议不返回列来源：按结果列名、别名和表达式引用匹配；Map / Array / Tuple 列对其中的文本值逐个处理 | 保守 |
| MongoDB | 库 › 集合 › 字段路径（采样最近 1000 个文档推断，可手动补充） | 按字段路径匹配返回的文档：嵌套（`profile.phone`）、数组元素（`contacts[].mobile`）逐层处理；管道里改名输出的字段一并脱敏；同一路径下类型不统一时数字先转成文本再脱敏 | 路径 |

**保守匹配**的意思：没有语法树 / 来源信息的引擎，结果列满足任一条件就整列脱敏——列名（或别名）与已配置的字段名相同；列的表达式里引用了已配置的字段名（如 `concat(phone, '')`、`substr(phone,1,3) AS p`）。会有少量误伤，但不会因为改了别名或套了函数就漏掉。

规则与生效位置（所有引擎一致）：在线查询保存即生效，脱敏失败时按系统配置 `query_check` 决定阻断还是放行；数据字典里敏感列打标，按各引擎自己的层级匹配；SQL 导出工单目前导出的是原值（经过审批）。

> 原型体验：页面里有 8 个演示实例（MySQL、PolarDB、SQL Server、PostgreSQL、ClickHouse、MongoDB、SelectDB），所有改动只在页面内存里，刷新即还原。

## SQL 防火墙

菜单：**系统管理 › SQL 防火墙**（仅超级用户）。管理员在这里配置“规则”：语句进入**在线查询、SQL 工单、数据导出**之前先过一遍规则，得到放行 / 拒绝 / 升级审批 / 要求填写原因 / 限制返回行数 / 强制脱敏 / 仅告警的决定，并留下命中记录。三个场景的规则共用同一套，新规则先观察、再生效。

### 它在哪一步生效

用户语句 → 静态检查 → **防火墙规则** → 库表权限 → 执行 → 脱敏 / 审计。

规则在权限校验**之前**评估：被拒绝的语句不会连到目标库，也会进查询事件表。防火墙是增强而不是唯一防线：库表权限、只读会话、数据脱敏都还在。

### 页面

页面顶部是“全局模式”（观察 / 拦截）、“语句测试台”和“新建规则”；下方的概览卡片给出今日评估语句数、命中规则数、已拦截数、观察 / 告警数（“若全部生效，会多拦 N 条”）和启用中的规则数。五个页签：

- **规则**：列表显示优先级、规则与命中条件、适用范围、动作、状态（已生效 / 观察中）、近 7 天命中次数（含每天的小柱图）。可直接启停、编辑、“回放”、删除，并按名称、动作、场景、状态筛选；
- **语句测试台**：粘贴一条语句（也可选内置的示例语句），选场景、实例环境、用户权限组、时间，并填预估扫描 / 影响行数（预估值正式环境里来自 EXPLAIN，这里手填用来试条件），点“评估这条语句”，得到最终决定、每条规则为什么命中，以及命中位置高亮。可一键把语句指纹加入黑名单或为它添加例外；
- **命中记录**：列出时间、用户、实例 / 库、场景、规则、结果和语句；“详情”里可为该用户添加例外。观察模式命中的语句已经正常执行，只留下记录，并写明规则生效后会怎样处理；
- **例外名单**：例外只豁免所选规则对某个用户 / 权限组 / 实例 / 语句指纹的约束，不影响其他规则。必须写原因，有效期可选 7 天 / 30 天 / 90 天或长期，到期自动失效；创建与撤销都写审计；
- **规则模板**：一组常见规则（防误操作、防大查询、防拖库、防探测、合规）。点“添加（观察模式）”后默认是观察模式，不会拦截任何语句；先用“回放”和命中记录确认没有误伤，再切换为生效。

### 规则由什么组成

| 部分 | 说明 |
| --- | --- |
| 基本信息 | 名称、说明、优先级（数字小的先求值；指纹黑名单建议放最前）、模式 |
| 模式 | **观察**：只记录命中，不执行动作；**生效**：执行动作 |
| 适用范围 | 场景（在线查询 / SQL 工单 / 数据导出，可多选）、实例（全部 / 仅生产 / 仅测试，按实例标签推断）、用户（全部 / 仅这些权限组 / 排除这些权限组） |
| 命中条件 | 一条或多条，可选“全部满足”或“任一满足”，取值见下表 |
| 动作 | 命中后执行，见下表 |
| 提示文案 | 被拦截或要求填写原因时用户看到的说明 |
| 通知 | 命中时通知的渠道（钉钉安全群、邮件给 DBA） |

命中条件的取值：

| 条件 | 取值与说明 |
| --- | --- |
| 语句类型 | SELECT / INSERT / UPDATE / DELETE / CREATE / ALTER / DROP / TRUNCATE，可多选 |
| 结构特征 | 没有 WHERE、没有 LIMIT、笛卡尔积（JOIN 缺条件，或逗号多表无条件）、一次提交多条语句、`SELECT *`、LIKE 以 % 开头、IN 列表过长（超过 1000 项） |
| 关键字 / 函数 | 逗号分隔，如 `SLEEP, BENCHMARK`；不区分大小写，按词匹配，忽略注释 |
| 正则（SQL 文本） | 对去掉注释后的 SQL 文本匹配，不区分大小写 |
| 涉及库表（列） | `库.表`、`*.表`、`*.表.列`，逗号分隔；`*` 代表任意；来自语法树，不受别名、反引号、注释影响 |
| 预估扫描行数 ≥ N | EXPLAIN 预估的扫描行数 |
| 预估影响行数 ≥ N | EXPLAIN 预估的影响行数 |
| 时间 | 非工作时间 = 19 点后、9 点前以及周末；工作时间 = 其余时间 |
| SQL 指纹 = | 8 位指纹，常从“命中记录”或语句测试台一键带入 |

动作（由严到宽）：

| 动作 | 效果 |
| --- | --- |
| 拒绝 | 语句不执行，记为“被拦截”，给用户一段说明 |
| 升级为工单审批 | 在线查询 / 导出转成 SQL 工单走审批；工单要求加签 DBA |
| 要求填写原因 | 弹窗让用户写原因，原因随语句进审计 |
| 限制返回行数 | 本次最多返回 N 行（在已有上限上再收紧） |
| 强制脱敏 | 命中的对象无论有没有配置脱敏，都按整体隐藏返回 |
| 仅告警 | 放行，写命中记录并通知；不影响用户 |

多条规则命中时：规则按优先级从小到大求值，取最严的动作（拒绝 > 升级审批 > 要求原因 > 限行 / 强制脱敏 > 仅告警）。**观察模式的规则（或全局观察）永不执行动作**，只记录“若规则生效会怎样”。

### 怎么安全地上线一条规则

1. 在编辑器里写规则，保持“观察”模式保存（新建的缺省就是观察）；
2. 点**回放**：用最近 7 天真实执行过的语句把当前草稿跑一遍，看命中多少条、涉及哪些用户、其中多少来自 DBA 组；命中较多时页面会建议先用观察模式跑一周；
3. 观察一周，到“命中记录”里确认没有误伤；误伤的用户加例外，或调整条件；
4. 把规则切到生效。

全局模式「观察」是总闸门：打开后所有规则只记录命中、不拦截任何语句（包括已经“生效”的规则），适合新规则上线前评估或批量调整前使用，评估完记得切回「拦截」；切到「拦截」后，“生效”的规则才开始执行动作，观察状态的规则仍只记录。

> 原型体验：页面预置了 11 条规则和 12 条命中记录；“语句测试台”的示例语句可以直接评估；所有改动只在页面内存里，刷新即还原。

## 系统审计

菜单权限 `audit.view`，导出需要 `audit.export`（高危）。三个页签：

- **系统审计**：登入 / 登入失败 / 账号锁定由登录认证模块写入，管理动作（改审批流、解锁、重置 2FA、改按钮权限、下载导出文件……）都落在同一份审计。顶部是近 7 天 KPI（审计事件、登录失败 / 拒绝及其中的账号锁定次数、高危操作（使用了需二次确认的高危按钮）、被拒绝（无权限的越权尝试））、近 14 天按天的柱图和近 7 天最活跃用户。可按用户、动作类别、结果、时间范围（今天 / 近 7 天 / 近 30 天 / 全部时间 / 自定义，默认近 30 天）、关键字、仅高危筛选；点一行在抽屉里看详情和该用户的其他近期操作。可导出 CSV（≤ 50000 行，防公式注入；导出前会确认筛选条件和条数，**导出本身也会被审计**）；
- **SQL 上线审计**：全部资源组的 SQL 上线工单的审计视角，数据来自“SQL 上线”页；顶部是工单状态分布，可按状态、资源组、关键字筛选；
- **查询审计**：在线查询的执行记录，被拒绝的语句同样入审；顶部是近 12 天查询数、被拒绝数（无权限 / 非只读语句）、平均耗时（不含被拒绝的语句）和最慢一条；可按用户、实例、关键字和“仅被拒绝”筛选，点一行看详情，SQL 超过 1000 字符在详情里展开；自动追加的 LIMIT、敏感列脱敏会在“结果”里标注。

登录失败连续达到阈值会锁定账号（阈值与锁定时长见“登录与安全设置”），被锁定账号由超级用户在“用户管理”解锁；登录提示语不区分“用户不存在 / 密码错 / 被锁定”，防止枚举账号。

> 原型体验：auditor_chen 只有审计相关权限，可以看日志并导出，但看不到其他系统管理页面。
