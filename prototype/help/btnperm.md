# 按钮级权限

"权限管理细化到页面的按钮"。在原有的菜单权限之上，每个页面里的每个按钮都有一个独立的**权限码**，可以按权限组、按用户精确授予或禁用。完整的码清单见附录 [权限码清单](#help/permcodes)，那一页由脚本根据 `js/perm.js` 自动生成。

## 三层结构

| 层 | 内容 |
|---|---|
| 页面 | 菜单是否显示、能否打开：持有该页面任一"查看类"按钮码即可 |
| 按钮 | 页面里的每个按钮一个码，如 `sqlworkflow.execute_group`（立即执行（资源组内）） |
| 数据范围 | 资源组 / 实例 / 库表授权，沿用原机制，不变 |

按钮码分三类：

- **查看（v）**：显示菜单、打开页面、看数据；
- **操作（o）**：会产生副作用的日常操作；
- **高危（d）**：风险高的操作，点击后必须二次确认（部分还要键入确认文本），授予它们时也会二次确认并写入系统审计，带 ⚠ 标记；
- 另外有一类**锁定码**：服务端只认超级用户，不能授予权限组（系统管理里的大部分按钮、`sqlworkflow.skip_check`，以及数据归档的 `archive.store_edit`、`archive.policy_edit`）。

权限树按"模块 → 页面 → 按钮"组织：SQL 审核、SQL 查询、SQL 优化、性能工单、实例管理、系统管理六个模块。

## 权限组

权限组 = 按钮码的集合，同时是审批流里的"级"。用户可以属于多个权限组，**权限取并集**。内置预设：

| 权限组 | 定位 |
|---|---|
| DBA | 全部可授予按钮；不含"仅自己的立即执行"，不含锁定码；可查看全部实例 |
| 组长 TL | 审批本组工单与查询权限、查看慢日志与数据字典、受理性能工单；**不能执行上线** |
| 研发 RD | 提交工单、立即执行自己的工单、在线查询、申请权限、导出提交、处理自己负责的性能工单；数据归档可查看、新建、试运行 |
| 测试 QA | 提交工单、在线查询、提交与下载导出；不能自行执行上线；数据归档只读 |
| 审计 | 只读审计日志与全部工单、导出审计日志；数据归档只读 |
| Default | 新用户默认：只能在线查询（需另外申请库表权限） |

在「权限组管理」里（三个页签：基本信息与成员、按钮权限、按用户查看有效权限）：

- **基本信息与成员页签**：组名和说明、已授予按钮数（共 N 个可授予）、成员数和被审批流引用数；成员只读，在“用户管理”里调整；
- **按钮权限页签**：按"模块 → 页面 → 按钮"勾选，可搜索页面 / 按钮 / 权限码，模块和页面都有“全选”复选框，点模块名可折叠；高危按钮带 ⚠高危 标记，授予时会二次确认并写审计；标“仅超级用户”的锁定码置灰，服务端只认超级用户，不能授予权限组；
- 工具栏：**套用预设**（DBA / TL / RD / QA / Default，套用后仍可逐项调整，保存才生效）、“仅查看类 / 全选可授予 / 清空 / 撤销修改”批量勾选、“按原权限码生成…”、“保存修改…”；
- **预览页面效果**：选一个页面，按当前勾选（含未保存）显示该页面上的按钮对这个权限组是什么样子——亮的是可用，灰的是无权限；没有任何“查看类”按钮的页面菜单不可见、打不开；
- **保存前确认**：列出新增 / 移除的数量、对多少名成员立即生效（含自己时会注明）、变更前后的差异（只列出发生变化的页面）；只勾选了操作按钮、没勾选“查看类”按钮的页面，用户将打不开（允许保存）；变更会让审批流出现“无人可审”时一并提示；新增高危按钮时必须勾选确认；可填变更原因（选填，写入系统审计）；
- **按原权限码生成**（迁移助手）：左侧勾选该组的原权限码（默认按该组原有权限预选）和原系统“登录即可”的按钮，右侧预览将新增 / 已有 / 无对应按钮；只增不减，点“合并到当前勾选”后仍需在“保存修改”里确认；严格模式下权限组只靠按钮授权，所以切换前建议对每个组都做一次；
- 新建权限组可选初始权限：空白、套用预设或复制已有权限组；删除权限组前会检查是否被审批流引用或有成员。

## 兼容模式与严格模式

页面顶部“按钮权限生效方式”切换（`ag.btnperm`，锁定；切回兼容模式只需确认，原 Django 权限立即重新生效）：

| 模式 | 用户权限 = | 适用 |
|---|---|---|
| 兼容（默认） | 原 Django 权限 ∪ 按钮授予，再扣除对该用户的"单独禁用" | 迁移期；不做任何配置时行为与原系统一致 |
| 严格 | 只认按钮授权和对用户的单独授权 / 禁用，原 Django 权限不再生效 | 迁移完成后的最终形态 |

切到严格模式的建议步骤：

1. 对每个权限组先点"按原权限码生成"，核对预览（"原系统登录即可"的按钮会默认一并勾选）；
2. 点切换时系统会**预检**，列出会因此失去访问的用户（含将失去的按钮数和涉及页面）和有原权限但按钮尚未授予的权限组，并要求键入“严格模式”确认；没有启用的超级用户时禁止切换；
3. 切换后，直接授给用户的 Django 权限不再生效，需改用"单独授权"。

> 超级用户在任何模式下都不受限，所以不会把管理员锁在外面。

## 单独授权与单独禁用

在用户管理里对个别用户微调，而不必新建权限组：

- **单独授权**：在权限组之外额外给某个用户加某个码（如 rd_zhou 单独被授予 `export.download`）；
- **单独禁用**：从该用户的有效权限里扣掉某个码，**禁用优先于一切授权**；
- 两者都**必须写原因**，可设**到期时间**（到期当天结束后自动失效，留空为长期有效），变更写入系统审计；
- 弹窗里可搜索并多选按钮；授予高危按钮（⚠）时必须勾选确认；系统管理类的锁定码仅超级用户，不在可选列表里，也不能给非超级用户单独授权；超级用户不受按钮权限限制，不能被单独授权 / 禁用；
- 入口：用户管理的“详情 / 有效权限”抽屉，以及权限组管理的“按用户查看有效权限”页签；记录列表里可“撤销”。

## 有效权限

「按用户查看有效权限」把一个用户的全部码列出来，并标明**来源**：来自哪个权限组、单独授权，还是被单独禁用。排查"为什么看不到某个按钮"的第一步就是它。可按“全部按钮 / 仅允许 / 仅禁止 · 未授予 / 仅单独授权 · 禁用”筛选，并看到来源汇总（权限组、单独授权、被单独禁用各多少个）；用户管理里的“详情 / 有效权限”抽屉也有同样的视图。原型里点头像菜单的"个人信息与权限"也能看到当前账号的概况。

有效权限 = 所在权限组的并集 ＋ 单独授权 － 单独禁用（**禁用优先于授权**）；超级用户拥有全部；系统管理类按钮仅超级用户。判定顺序（简化）：

1. 已停用用户 → 无权限；
2. 超级用户 → 全部通过；
3. 锁定码 → 只有超级用户；
4. 其余：所有权限组的并集 ∪ 单独授权，再减去单独禁用。

## 按钮的呈现

无权限的按钮默认置灰并带 🔒，悬停显示需要的权限名和码；管理员可在“权限组管理”页顶部的“无权限按钮呈现”里改为**隐藏**（全站立即生效）。无论界面如何呈现，**服务端对每个接口再校验一次**，绕过前端并不能越权；高危按钮的使用还会写入审计。

> 原型体验：在顶栏切换 dba_li / tl_wang / rd_zhao / qa_sun，对照 SQL 上线详情页里"审批 / 执行 / 定时 / 手工结束 / OSC"几个按钮的可用性变化。
