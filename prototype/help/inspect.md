# 性能巡检

菜单：实例管理 › 性能巡检。对实例做一次**只读**的健康体检，输出总分、各检查项结果和改进建议；支持手动立即巡检和定时计划。MySQL / MariaDB、SQL Server 与 Redis 实例在同一个列表里，按开始时间倒序；有进行中的报告时列表和详情页自动刷新。

## 巡检报告

| 功能 | 说明 | 权限码 |
|---|---|---|
| 查看报告 | 列表可按实例、状态、时间筛选；详情页看总分、告警 / 关注数量和各分区 | `inspect.view` |
| 立即巡检 | 选择一个或多个实例，**异步**在后台执行，页面轮询出“进行中 → 完成”；同一实例同一时刻只允许一份进行中的报告，已有进行中巡检的实例会被跳过。SQL Server 单实例约 1–5 分钟，MySQL 与 Redis 为实时指标采集，通常几秒到几十秒 | `inspect.run` |
| 取消巡检 | 取消进行中的巡检，已采集的检查项保留，报告状态变为“已取消” | `inspect.cancel` |
| 删除报告（高危） | 进行中的报告不能删除，需先取消（批量删除时自动排除）；报告过期会按保留天数自动清理 | `inspect.delete` |

### 报告怎么看

详情页顶部是**总分**（100 分起，按检查项扣分，最低 0）和三个提示块（问题 / 警告 / 建议），下面是分区列表，每个检查项按阈值标为"正常 / 关注 / 告警"，单步采集失败只会在该分区标"未采集"，不影响其他分区。MySQL 系报告每个告警扣 6 分、每个关注扣 2 分，并画出该实例的健康分趋势；SQL Server 报告不打分，只统计告警 / 关注 / 正常 / 未采集四类数量。进行中的报告显示进度和最近采集的检查项；巡检失败（目标实例不可达）的报告只有失败原因，没有检查项；已取消的报告只含已完成的部分。

MySQL 系的主要检查项与阈值：

| 分区 | 关注 / 告警条件 |
|---|---|
| 连接 | 使用率 > 80% 关注，> 95% 告警 |
| 缓冲池命中率 | < 99% 关注，< 90% 告警 |
| 慢查询 | > 10 关注，> 100 告警；慢日志未启用关注 |
| 行锁等待 | > 100 关注，> 1000 告警 |
| 长事务 / MDL | 事务 > 60 秒关注，> 300 秒告警；有会话在等 MDL 告警 |
| 自增 ID | ≥ 70% 关注，≥ 85% 告警 |
| 无主键表 | 有则关注；含 100 万行以上的告警 |
| 死锁（近 7 天） | > 0 关注，≥ 10 告警 |
| 大表 / 碎片 | 表 > 50 GB 或 > 5000 万行关注，> 200 GB 告警 |
| 复制与 Binlog | 从库线程异常告警；延迟 > 60 秒关注，> 300 秒告警 |
| 参数基线 | `innodb_flush_log_at_trx_commit`、`sync_binlog` 不安全告警；其余偏离关注 |
| 高危账号 | 匿名 / 远程空密码告警；任意主机高权限、FILE 权限关注 |
| 其他 | 索引冗余、字符集不一致、慢 SQL Top10、容量 |

SQL Server 实例按等待、阻塞、索引碎片、备份、作业等分区检查。巡检**全程只读**，只执行元数据与统计查询；查询复制状态需要账号具备 `REPLICATION CLIENT`，缺少权限时标"未采集"。

Redis 实例按基本信息、主从复制、内存、持久化、客户端连接、性能与命中率、安全、键空间 8 个分区检查（共 26 项），同样有评分和逐项「建议」。巡检只发 `INFO`、`CONFIG GET`、`SLOWLOG GET`、`COMMAND INFO` 等只读命令，不读业务数据，慢日志明细只显示命令**指纹**（`HGETALL ?`），不含 key 名和值：

| 分区 | 关注 / 告警条件 |
|---|---|
| 内存 | 使用率（对 `maxmemory`，没设置则对主机内存）≥ 80% 关注、≥ 90% 告警；碎片率 ≥ 1.5 关注、≥ 2 或 < 1（发生交换）告警；没设置 `maxmemory` 关注；设了 `maxmemory` 却用 `noeviction` 关注 |
| 主从复制 | 从库状态不是 online 告警；延迟 ≥ 10 秒关注、≥ 30 秒告警；从库侧链路断开告警 |
| 持久化 | RDB / AOF 都没开关注；最近一次 RDB 或 AOF 写入 / 重写失败告警；RDB 有变更未保存超过 24 小时关注、72 小时告警 |
| 客户端连接 | 连接数占 `maxclients` ≥ 80% 关注、≥ 90% 告警；阻塞客户端 ≥ 10 关注、≥ 50 告警；有被拒绝的连接关注、≥ 100 告警 |
| 性能与命中率 | 命中率（请求 ≥ 1 万次时）< 90% 关注、< 70% 告警；有被淘汰的 key 关注；慢日志条数 ≥ 10 关注、≥ 100 告警；fork 耗时 ≥ 0.5 秒关注、≥ 2 秒告警 |
| 安全 | 没设置密码告警；监听所有网卡且 `protected-mode no` 关注（同时没密码告警）；`FLUSHALL` / `KEYS` / `CONFIG` / `DEBUG` 等危险命令没有改名关注 |
| 键空间 | 用 `volatile-*` 淘汰策略但没有 / 很少带过期时间的 key 告警 / 关注；**大 key 抽样**默认关闭，「立即巡检」里勾选后限量 `SCAN` 抽样（最多 1000 个 key，逐个 `TYPE` / `MEMORY USAGE`，有速率和时间上限；对线上有轻微压力，建议低峰期使用），最大 key ≥ 1 MB 关注、≥ 10 MB 告警 |

Redis 的评分同样 100 分起扣、最低 0，但**每个检查项有自己的扣分值**（关注 / 告警各一档，例如内存使用率关注 −10、告警 −25，访问密码未设置 −20），未采集不扣分；告警且单项扣分 ≥ 20 的，报告状态记为 critical。云托管的 Redis 经常禁用 `CONFIG`，此时相关检查项标「未采集」；账号缺少某个命令的权限（如 `SLOWLOG`）时，对应检查项同样标「未采集」。Redis 巡检是实时指标采集，通常几秒到几十秒完成，进行中的报告显示已完成的步骤；读取 `INFO` 失败时整份报告失败（其余步骤失败只让对应检查项标「未采集」），请先在实例列表测试连接再重新巡检。Redis 报告详情除总分和各分区外，还有「报告概况」（版本、角色、运行时长、内存、key 数 / 连接数、每秒命令数、大 key 抽样是否开启）和该实例的健康分趋势。

> 评分只是一个相对指标：重点看"告警"项和趋势，而不是追求 100 分。分数突然下降通常比绝对值更说明问题。

## 定时巡检

「定时计划」页签可建多个计划（`inspect.plan_edit`），每个计划自己选一批实例（可跨 MySQL 系、SQL Server 和 Redis）、周期、错峰与并发、通知和报告保留天数；到点自动为每个实例生成一份报告，和手动巡检的报告在同一个列表里，计划按北京时间（Asia/Shanghai）执行。每个计划配置：

- **实例范围**：显式勾选，或按标签 / 资源组动态匹配（也可一键选"全部 MySQL 系 / 全部 SQL Server"）；只能选你资源组内的实例，同一实例可以被多个计划选中，但同一时刻只跑一份；按标签选是运行时实时匹配，新打标签的实例自动加入；
- **周期**：每天 / 每周（多选星期）/ 每月（1–28 日）/ 自定义 cron；**两次运行间隔不得小于 5 分钟**，避免把巡检配成对生产的压测；保存时会预览"下次运行时间"；
- **执行方式**：同时巡检几个实例（1–10）、实例之间的**错峰间隔**、实例上已有进行中巡检时跳过、失败后 5 分钟重试一次、单实例超时；
- **完成后**：通知方式（不通知 / 仅告警或失败或低分时 / 每次汇总）、通知渠道、报告保留天数、是否启用。

行内操作：暂停 / 启用 / 删除（`inspect.plan_toggle`，高危）、立即运行（`inspect.plan_run`，高危）、查看运行记录。暂停后不再按周期触发，手动“立即运行”仍可用；删除计划要输入计划名称确认，运行记录一并删除，已产生的报告保留；立即运行会先确认，并按计划的通知设置发送通知。原系统的"全局定时"显示为"兼容"行（来自原系统「系统配置」里的巡检时刻与实例标签，仅超级用户可操作）：转成正式计划之前仍由原系统调度，点「转为正式计划」会建一个可编辑的计划，并关闭原系统的全局定时，不会重复巡检。

调度保证：多个服务进程同时运行也只会触发一次；错过计划时间超过 15 分钟不补跑，记一条"已跳过"（在业务高峰补跑一轮比漏掉一次更糟）；同一计划不会重叠运行；进程被杀留下的"运行中"记录会被自动收尾为失败。

## 通知

通知复用[系统管理里的通知渠道](#help/sysadmin)及其 @ 规则。"仅告警时发"的触发条件：有告警、有失败实例，或 MySQL / Redis 实例评分低于 70。消息包含计划名、实例成功 / 失败 / 跳过数、告警最多的 5 个实例及报告链接、低分实例和失败原因。通知发送失败只记录在该次运行的"说明"里。

> 原型体验：dba_li 可立即巡检并查看报告；rd_zhao 没有性能巡检菜单。Redis 报告可看 redis-session-prod（无密码、无持久化，多项告警，评分最低）和 redis-order-cache-m / -s；「立即巡检」里选 Redis 实例并勾选「大 key 抽样」，报告的「键空间」分区会多出大 key 明细。
