# 数据归档

菜单：SQL 查询 › 数据归档。把表里"过期"的数据**按计划搬走或清掉**，取代手写的 `pt-archiver` / 定时 `DELETE` 脚本。系统按主键分批、小事务、限速、先做负载自检，**先把数据备份到目标并校验，通过后才删除源表数据**；任何一步失败都不会删。审批流里的"数据归档申请"就是本功能的审批。

> 本功能只执行三类 SQL，任务详情的"将执行的 SQL"里全部可见：**读**（按主键升序取一批）、**写目标**（INSERT 到归档库表，或写文件）、**删源**（`DELETE ... WHERE 主键 IN (...)`，并重复一遍归档条件）。**没有自由 SQL 入口**。

> 原型说明：本页面的规则（参数范围、校验、检查项、审批与状态流转、失败语义）已按真实实现更新；数据全部是模拟的，操作只改内存，刷新页面即还原。"运行"是会走动的模拟（时间被压缩，约 30 秒跑完一次），不连真实库；详见文末「原型里模拟了什么」。

## 页面与角色

| 页签 | 谁能看 | 内容 |
|---|---|---|
| 归档任务 | 持有 `archive.view` | 任务列表、"待我审批"、运行中的实时进度、任务详情（配置、将执行的 SQL、审批进度、最近运行、变更历史） |
| 运行记录 | 持有 `archive.view` | 每次运行一行（定时 / 手动 / 试运行 / 恢复），详情里有吞吐曲线、限流事件、校验结果、备份位置、日志 |
| 备份存储 | 持有 `archive.cfg_view` | 备份存储列表；新建 / 编辑 / 测试连接 / 停用 / 删除仅超级用户 |
| 安全策略 | 持有 `archive.cfg_view` | 全局硬约束；仅超级用户可改 |

任务按**资源组**可见：你只能看到自己所在资源组的任务（有查看全部权限的管理员和超级用户看全部）。

「归档任务」页签顶部的统计卡：任务总数（你可见范围内）、已启用（其中几个正在运行）、待审批（其中几个等你审批）、已暂停（需要处理，原因见任务详情）、累计归档行数（已确认删除 / 备份的行）。列表可按状态、模式、实例、关键字筛选，也可以只看“待我审批”的任务；运行中的任务在状态列里显示实时进度。

## 新建一个归档任务

点"新建归档任务"（`archive.apply`），按六步填写。每一步下一步前都会校验，错误会直接列在表单下方。校验分两层：页面上即时给出的提示（范围、必填、语法）和最终以服务端为准的校验，两者口径一致。

### 第 1 步：来源

- **任务名称**：2–50 字，全局唯一；
- **实例 / 库 / 表**：只能选 MySQL / MariaDB 的**主库**；从库、只读视图（read_view）实例、Redis、SQL Server 不能归档；
- **所属资源组**：决定走哪条审批流。选好之后下面会列出这条审批流的逐级审批人；资源组没有配置"数据归档申请"审批流就不能提交，请联系管理员在「审批流程配置」里配置；某一级没有可审批的人时会提示"本级无人可审，仅超级用户可审"；
- 不允许的表：**没有主键**（含唯一非空键）的表、**受保护库表**（安全策略里配置，默认含 `mysql` `information_schema` `performance_schema` `sys`）、**被外键子表引用**的表、没有 `datetime` / `timestamp` / `date` 列的表。
- **同一张表同时只能有一个进行中的任务**（待审批 / 已启用 / 已暂停都算；草稿、已驳回、已停用不算）；
- 编辑已有任务时，实例 / 库 / 表不可修改，换来源请新建任务。

### 第 2 步：条件

条件是**结构化**的，不是手写 SQL：

- **时间列**：下拉里只列时间类型的列；该列**必须有索引**（是某个索引的最左列），否则试运行会判红（避免全表扫描拖垮线上；表很小时只给黄色）；
- **保留天数**：只归档"时间列早于 N 天前"的数据，1–3650。**不得小于安全策略的最小保留天数**（默认 30，页面上标在字段名后）；想放宽要由管理员改安全策略；
- **附加条件**（可选，≤ 500 字）：不是"过滤危险字符"，而是按一个很小的文法**重新解析**后再生成 SQL。只允许：比较（`= <> != < <= > >= <=>`）、`[NOT] IN (...)`（≤ 200 项）、`[NOT] LIKE`、`BETWEEN ... AND ...`、`IS [NOT] NULL / TRUE / FALSE`、`AND` `OR` `NOT`、括号（≤ 20 层）、字符串和数字字面量、列名（可加反引号，不能带库表名限定）。禁止分号、注释、反斜杠、函数调用、子查询、算术运算、十六进制 / 二进制字面量，以及 `SLEEP` / `BENCHMARK` / `INTO OUTFILE` / `UNION` / DDL / DML 等关键字；引用的列必须是这张表里的列（试运行时核对）。

系统会生成最终的 WHERE，附加条件**永远加括号**、列名加反引号，例如：

```sql
`created_at` < NOW() - INTERVAL 180 DAY AND (`status` IN (3, 4))
```

页面上的预览与校验提示实时给出，最终以服务端结果为准。

### 第 3 步：模式与备份

| 模式 | 做什么 | 什么时候用 |
|---|---|---|
| 归档并删除 | 备份到目标并校验通过后，才删除源表数据 | 最常用 |
| 仅备份 | 只拷贝，不删除源表 | 先观察一段时间，确认条件、速度、备份都没问题 |
| 仅清理 | **不备份**，直接删除 | 日志类临时表；默认不允许，见下 |

**备份去向**可多选，也可以两个都选：

- **归档库表**：同实例或其他实例（也只能是 MySQL / MariaDB 主库），库名 + 表名模板（`{table}` `{yyyy}` `{mm}` `{dd}` `{yyyymm}` `{yyyymmdd}`，如 `{table}_{yyyy}`；只含字母、数字、下划线，展开后不超过 64 位）。目标表不存在时自动按源表结构创建；已存在时要求结构兼容、主键一致。目标表不能就是源表，归档库不能是受保护库；
- **文件存储**：选一个已配置的"备份存储"（存储由管理员在「备份存储」页签维护；连接异常的存储可以选，但试运行判红、运行会被拒绝），格式 CSV 或 SQL，可 gzip 压缩、可 AES-256-GCM 加密（密钥由系统保管，页面不展示，加密后的文件由 DBA 解密），路径模板可用 `{inst}` `{db}` `{table}` `{yyyy}` `{mm}` `{dd}` `{yyyymm}` `{yyyymmdd}` `{run_id}` `{task_id}`，拼在存储前缀之后（不含 `{run_id}` 时试运行给黄色警告，建议带上），单个文件超过上限（1–4096 MB，默认 256）会自动滚动成新文件；运行结束生成清单并回读校验。文件备份有一个**暂存目录**，务必看一下下面「文件备份与暂存目录」。

**仅清理**要同时满足：安全策略里"允许不备份清理"是开启的（默认关闭，仅超级用户能打开）；任务里写明"不备份理由"（5–500 字，审批人审批时会看到）。"不备份"与备份去向互斥。

### 第 4 步：稳定性参数

| 参数 | 默认 | 范围 / 说明 |
|---|---|---|
| 批大小 | 1000 行 | 100–10000；按主键升序取下一批（`主键 > 上一批最大值`，不用 `OFFSET`），每批一个独立的小事务 |
| 批间休眠 | 200 ms | 1–5000；会删除数据的模式（归档并删除 / 仅清理）**不得低于 50 ms**。**不能填 0**：服务端把 0 当作"用策略默认值"，无法表达 0 ms |
| Threads_running 阈值 | 32 | 4–1000；每批开始前检查，超限就暂停等待 |
| 复制延迟阈值 | 5 秒 | 1–3600（同样不能填 0）；**有从库时必检、不提供关闭**；没有从库时自动跳过，并在运行记录里注明"未检测" |
| 磁盘剩余阈值 | 15 % | 5–50；目标是库表时检查目标端；目标是文件时检查存储可用空间；取不到时标"未检测"，不当作通过 |
| 最长等待 | 10 分钟 | 1–60 分钟；负载超限后每 30 秒复查，超过则本次以"负载中断"结束，不算失败 |
| 批耗时目标 | 500 ms | 100–5000；某批超过目标：批量减半（不低于 100）、休眠加倍；连续 5 批正常再逐步恢复（不超过设定值） |
| 连续失败暂停 | 3 批 | 1–10；死锁 / 锁等待超时指数退避重试 3 次，仍失败该批回滚并计 1 次失败；连续失败 N 批自动暂停任务并通知 |
| 单次运行最多处理 | 5,000,000 行 | 不小于 100；实际取它与安全策略"单次运行最大行数"中较小的一个（填得比策略上限大时试运行给黄色警告）；达到上限的运行以"已达上限"结束，下次接着跑 |

页面上"恢复为策略默认值"一键把参数填回安全策略的默认值；表单下方给出吞吐与"单次上限约需多久"的粗略估算（不含限流等待）。

会话 `lock_wait_timeout` 与 `innodb_lock_wait_timeout` 固定 3 秒；binlog 保持开启（从库、备份依赖它），不提供关闭选项。大批量删除会产生大量 binlog，注意从库延迟与磁盘。

### 第 5 步：调度

- **调度方式**：每天 / 每周（选星期）/ 每月（选 1–28 日，避开月末天数差异）+ 开始时间，或高级 cron（5 段：分 时 日 月 周，支持 `*` `,` `-` `/`，**最短间隔 1 小时**，如 `30 1 * * 0` 表示每周日 01:30）；页面会预览**未来 5 次**触发时间，并标出落在窗口外会被跳过的；
- **时区**：调度与窗口按**服务进程所在时区**计算；
- **执行窗口**：开始 – 结束时间，**至少 30 分钟**，可跨零点；**开始 = 结束表示不限制**。只在窗口内运行；窗口结束时当前批做完后**优雅停止**，记录断点（最大主键），下次接着跑；
- 开始时间必须落在窗口内，否则任务永远不会被调度；到点时已错过窗口的那次不运行、也不记录，直接推进到下一次。

### 第 6 步：试运行并提交

见下一节。提交后任务进入**待审批**，通过最后一级后自动变为**已启用**。

**保存草稿**：新建任务和"草稿 / 已驳回"状态的任务可以在这一步点"保存草稿"（已驳回的是"保存修改（不提交）"）。草稿**不要求试运行、不建审批**，但前面各步的基本校验仍要通过（名称、实例、库表、条件、备份去向、参数、调度这些规则；需要连库才能知道的项，如主键 / 外键 / 同表是否已有任务 / 审批流是否存在，要到试运行和提交时才检查）。草稿之后可以随时点"编辑 / 重新提交"补完试运行并提交，不需要了可以删除。**其他状态的任务不能保存草稿**：已生效的任务要改，只能做下面「审批」里说的"更保守"的调整直接保存，或者提交审批。

## 试运行

提交前必须先"试运行"（`archive.dryrun`）。试运行**只读，不写不删**，给出：

- 预估命中行数、占表比例、预计批数、预计耗时（含批间休眠）、预计 binlog 体积（仅备份不删除，没有 binlog；命中行数的统计上限是 1000 万，超过会标注"至少"）；
- 最前 10 行样例（按主键升序）；
- "将执行的 SQL"（试运行报告里是表的真实主键与列；向导预览、任务详情里拿不到表结构，主键写成 `<主键>`）；
- 检查项，每项绿（通过）/ 黄（警告）/ 红（不通过）。每次试运行也会在「运行记录」里留一条"试运行"记录。

| 检查项（key） | 标题 | 红色（不通过） | 黄色（警告） |
|---|---|---|---|
| `protected` | 受保护库表 | 命中受保护库表 | |
| `retention` | 保留天数 | 小于策略下限 | |
| `extra` | 条件语法与安全 | 语法 / 禁止项不通过，或引用了表里不存在的列 | |
| `mode` | 模式与备份去向 | 模式与去向不匹配、策略不允许仅清理 | |
| `dest_table_spec` `dest_file_spec` | 归档库表设置 / 文件备份设置 | 设置不合法 | 路径模板里没有 `{run_id}` |
| `params` | 稳定性参数 | 超出范围 | 单次上限超过策略硬上限（按硬上限截断） |
| `pk` | 主键 | 没有主键 / 唯一非空键 | |
| `time_column` | 时间列 | 不存在或不是 date / datetime / timestamp | |
| `index` | 时间列索引 | 没有索引且表 > 20 万行 | 没有索引但表较小 |
| `fk` | 外键 | 被外键子表引用 | |
| `trigger` | 触发器 | | 表上有触发器（归档删除会触发 DELETE 触发器） |
| `partition` | 分区表 | | 分区表按普通表处理（更推荐用分区维护 `DROP PARTITION`） |
| `engine` | 存储引擎 | | 不是 InnoDB |
| `blob` | 大字段 | | 含 BLOB / TEXT / JSON 且批大小 > 500 |
| `explain` | EXPLAIN | 未走索引且预计扫描 > 20 万行 | 未走索引但表较小；或走索引但预计扫描 > 20 万行 |
| `est_rows` | 命中行数 | 统计失败 | 命中 0 行 |
| `large_batch` | 命中比例 | | **命中超过表总行数 30%**：黄色（标成"需确认"），提交时要额外勾选"已确认大批量"，**不是红色阻断** |
| `max_rows` | 单次总量上限 | | 命中数超过单次上限，需要多次运行才能清完 |
| `purge` | 不备份清理 | | 仅清理不备份，删除后无法恢复 |
| `dest_table` `dest_disk` | 目标 · 归档库表 / 目标 · 磁盘 | 目标库不存在、表缺列 / 类型不一致 / 主键不同、目标磁盘低于阈值 | 目标磁盘取不到 |
| `dest_store` | 目标 · 文件存储 | 存储不可用或已停用、连通性测试失败、可用空间小于预计体积、要求加密但没有密钥 | |
| `replica` | 从库复制延迟 | 关闭延迟检查但有从库（页面上不会出现） | |
| `load` | 当前负载 | | `Threads_running` / 复制延迟 / 磁盘当前已超阈值或未检测 |
| `workflow` | SQL 上线工单 | | 源表有待执行 / 执行中的 SQL 上线工单（工单结束前定时运行会被跳过） |
| `concurrency` | 实例并发 | | 该实例上的归档运行已达并发上限 |
| `flow` | 审批流 | 该资源组没有配置"数据归档申请"审批流 | |

提交规则：

- **红色项不能提交**，回到对应步骤修改后重新试运行；
- **黄色项**需要勾选"我已知晓"（命中比例那一项不算在内，它单独确认）；
- 预估命中**超过表总行数 30%** 属于大批量，需要额外勾选"已确认大批量"；
- 试运行结果 **7 天内有效**（报告里标出有效期至），来源 / 条件 / 备份去向 / 单次上限任一改动后立即失效，需重新试运行；
- 连不上源库或目标时试运行直接报错（没有检查报告，也不记运行记录）。

## 审批

- 新建、修改**关键字段**（来源、条件、模式、备份去向、所属资源组、不备份理由）、**放宽**参数、重新提交被驳回 / 已停用 / 结构变更暂停的任务，都走资源组审批流里的"数据归档申请"；
- 审批人 = 该级权限组中、属于该资源组的用户；**不能审批自己提的申请，超级用户也一样**；该级没有其他可审批人时，只有超级用户能审；
- 审批人在任务详情（或列表行）里点"通过 / 驳回"，审批弹窗里显示当前在哪一级、任务的来源 / 条件 / 备份去向 / 调度；**驳回必须填写原因**（至少 2 个字）并通知申请人，申请人修改后可重新提交；
- 通过最后一级后任务自动**已启用**，按调度运行；侧栏"数据归档"的红色角标是"等我审批"的数量；
- 驳回 / 停用之后重新提交，复用同一条审批记录，页面只展示最近一轮；待审批的任务被修改后重新提交，原审批作废、按新内容重新走；任务被停用时，进行中的审批也随之作废；
- 修改**调度 / 窗口 / 限速参数**不需要重新审批，但**只能更保守**，直接保存、状态不变（已暂停的任务保持暂停）。下面这些算"放宽"，要重新审批：批大小增大、批间休眠减小、单次总量上限提高、Threads_running 阈值提高、复制延迟阈值放宽、磁盘剩余阈值降低、批耗时目标放宽、负载最长等待延长、连续失败暂停阈值提高、执行窗口扩大（总量上限降低不需要审批）；
- 来源 / 条件改了，旧断点不再适用（下次从头）；只改了去向、参数的断点保留。

## 运行与控制

- **立即执行**（`archive.run`，高危）：仅已启用的任务；不等调度，仍遵守负载保护（`Threads_running` / 复制延迟 / 磁盘 / 批耗时自适应），可勾选"忽略执行窗口"；确认框里写明将处理多少行，以及不同模式的后果（仅备份不删除；仅清理不备份，删除后无法恢复；归档并删除先备份并校验，通过后才删源）。前置检查和调度一样：任务已启用、保留天数仍满足策略、策略仍允许仅清理、库表没有变成受保护库表、备份存储存在且可用（未停用、最近一次测试没失败）、在窗口内（除非忽略）、源表没有未结束的 SQL 上线工单、上一次运行已结束、实例并发没满。不通过时给出具体原因（调度命中则记一条"已跳过"运行）；
- **源表结构指纹不一致**（列名 / 类型 / 主键与审批 / 试运行时不一致）不在点击时拦截，而是由引擎在运行开始时判定：运行会正常启动，很快以"结构变更暂停"结束，任务被置为"已暂停（结构变更）"并通知，需要重新试运行并重新提交审批，不能直接恢复；
- **暂停 / 继续**（`archive.pause`）：运行中点暂停，当前批做完后停，保留断点，可继续；空闲的任务点暂停则不再按调度运行，恢复后从断点接着跑；
- **终止**（`archive.stop`，高危）：当前批做完后结束，本次运行标记"已终止"，保留断点；
- 运行中任务在列表里显示进度条、速度、预计剩余、是否正被限流（页面每 2 秒刷新一次）；详情里还有 `Threads_running` / 复制延迟仪表、当前批大小；
- 同一实例同时最多 2 个归档运行（安全策略可调）；任务上一次还没结束就到点，本次**跳过**并记录；源表有待执行 / 执行中的 SQL 上线工单时，本次也会跳过；
- **自动暂停**：连续多批失败、备份校验不一致、收尾上传文件失败、源表结构变更，都会把任务置为已暂停并通知（瞬时的连接错误只算失败、不暂停）；
- **断点**：每次运行记录最后处理的主键，下次接着跑。"归档并删除 / 仅清理"的任务**成功跑完**后断点清空（下次从头，才能捡到后来才过期的小主键行）；"仅备份"成功后保留断点；窗口结束 / 负载中断 / 已达上限 / 失败 / 终止时都保留断点。

## 稳定性保护一览

| 保护 | 说明 |
|---|---|
| 分批与短事务 | 按主键分批，默认 1000 行一批，每批独立小事务，不用 `OFFSET` |
| 负载自检 | 每批前检查 `Threads_running`、从库复制延迟、磁盘剩余；超限暂停并计入"限流事件"，取不到的项标"未检测"（不当作通过，也不阻塞） |
| 自适应降速 | 批耗时超目标则批量减半、休眠加倍，连续 5 批正常再恢复 |
| 锁与重试 | 会话 `lock_wait_timeout` 与 `innodb_lock_wait_timeout` 固定 3 秒；死锁 / 锁等待指数退避重试 3 次；连续失败自动暂停 |
| 总量上限 | 单次运行最多处理 N 行；命中超过表的 30% 需额外确认 |
| 执行窗口与互斥 | 只在窗口内运行；同实例并发有上限；上一次未结束则跳过 |
| 结构指纹 | 源表列名 + 类型 + 主键与审批时不一致，运行立即以"结构变更暂停"结束，任务暂停并通知，需重新试运行并走审批 |
| 随时叫停 | 暂停（保留断点）与终止 |
| binlog | 保持开启（从库、备份依赖它），不提供关闭选项；大批量删除会产生大量 binlog，注意从库延迟与磁盘 |

## 备份去向怎么选

| 场景 | 建议 |
|---|---|
| 以后还可能要查、要回灌 | **归档库表**（同实例的归档库最省事；数据量很大时放到独立的归档实例），库表备份可以直接在页面"恢复数据" |
| 只为合规留档、很少再用 | **文件存储**（CSV + gzip），放对象存储（S3 兼容 / MinIO / OSS 的 S3 兼容端点）或 NFS，成本低；敏感数据勾选加密 |
| 特别重要的表 | 两个都选：库表方便恢复，文件方便离线留档 |
| 日志类临时表、确认没有保留价值 | 模式选**仅清理**，需策略放开并写明理由 |
| 不确定条件对不对 | 先选**仅备份**跑几次，确认后再改成归档并删除（改模式属于关键字段，要重新审批） |

## 文件备份与暂存目录

每次运行写一个或多个文件：`<路径模板展开>/part-0001.csv[.gz][.enc]`（SQL 格式是 `.sql`），运行结束再写 `manifest.json`（行数、每个文件的大小与 sha256、起止主键、列、加密方式…）；同名对象已存在时序号顺延，**不会覆盖早先的备份**。

- **先落本地暂存目录，再上传**：每批的备份先追加写入服务器本地的暂存文件并 `fsync`，行数核对一致后**就删源**；文件滚动 / 运行结束时才上传到备份存储，并回读核对大小与 sha256（上传失败重试 3 次），全部通过才删掉本地暂存文件。所以**删源发生在本地落盘之后、上传之前**；
- 因此**暂存目录必须是持久目录**：由环境变量 `ARCHIVE_SPOOL_DIR` 指定，缺省为 `EXPORT_BASE_DIR`（缺省 `.`）下的 `archive-spool`。请监控它，不要放在会被系统清理的临时目录；
- **进程被强杀 / 机器重启时**，还没上传的备份会留在暂存目录的 `*.tmp` 文件里，**需要人工补传**（引擎不会在下次启动时自动补传）；正常结束、失败、被终止都会先上传再返回；上传失败则运行以"失败"结束并自动暂停，本地文件保留，错误信息里带路径；
- 加密文件（AES-256-GCM）的密钥由系统保管，派生自服务端密钥 `MIRAGE_SECRET_KEY`：**换了这个密钥之后旧的加密备份将无法解密**，请妥善保管；
- 同一批里同时选了库表和文件时，库表先写；文件写失败时库表里多出来的是"已备份未删除"的行，重试是幂等的。

## 备份存储（管理员）

「备份存储」页签列出可用的存储：本地目录、NFS 挂载目录、S3 兼容（含 MinIO）、阿里云 OSS（**通过其 S3 兼容端点**访问）。字段：名称（2–50 字，不重名）、类型、目录（本地 / NFS：绝对路径，不含 `..`；NFS 要求已挂载）或 endpoint（`http(s)://`）/ Region / 桶 / 路径风格、路径前缀、AK / SK、保留天数（0 = 永久，最大 36500）、状态。

- **目录**：本地目录写本机的绝对路径，NFS 写已挂载的目录（系统不负责挂载），都不能含 `..`；**Region** 可不填（OSS 缺省按 endpoint 推断）；**路径风格访问**：MinIO 通常需要勾选（IP / localhost 自动用路径风格）；**路径前缀**拼在路径模板之前，首尾的 `/` 会被去掉，不得含 `..`，最长 200 字；**保留天数**填 0 表示永久，到期由对象存储生命周期或本系统清理；
- **AK / SK 加密保存、永不回显**，编辑时留空表示不修改；有 `archive.store_edit`（超级用户）时列表显示完整 AK，否则脱敏；
- 新建或编辑后状态是**未测试**，点**测试连接**才会变成正常 / 异常；测试会写入、读取、删除一个探测对象，结果分成功 / 失败 / 超时；新建 / 编辑表单里的测试连接不保存，按填写的内容探测；连接异常的存储状态显示"异常"，引用它的任务运行会被拒绝（先备份后删除的前提不成立）；
- **被任务引用的存储不能删除**，也不能改类型；可以先停用（停用会提示受影响的任务数），停用后引用它的任务同样会被拒绝运行，重新启用即可恢复；
- 新建 / 编辑 / 测试 / 停用 / 启用 / 删除都需要 `archive.store_edit`（锁定码，仅超级用户）。

## 安全策略（管理员）

「安全策略」页签是全局硬约束，会直接影响向导里的校验：最小保留天数、默认批量 / 休眠 / 阈值 / 等待上限 / 连续失败暂停、单次最大行数、每实例最大并发、受保护库表、是否允许不备份清理。

- 仅超级用户可改（`archive.policy_edit`，锁定码）；
- 受保护库表是一个"库"或"库.表"的模式列表（每行一个），支持 `*` `?`、不区分大小写（只写"库"只匹配库）；系统库（`mysql` `information_schema` `performance_schema` `sys`）**无论怎么填都一直生效**；
- **固定约束（不可调）**：附加条件 ≤ 500 字且只允许比较 / `IN` / `LIKE` / `AND` / `OR` / `IS NULL`；批大小 100–10000；归档并删除 / 仅清理的批间休眠 ≥ 50 ms（默认批间休眠同样不得低于 50）；执行窗口 ≥ 30 分钟；cron 最短间隔 60 分钟；binlog 保持开启、不提供关闭选项；
- 保存前先看**差异预览**（原值 → 新值）和风险提示，再**二次确认**；每次修改写入系统审计。降低最小保留天数、打开不备份清理、提高单次行数 / 并发、缩小受保护范围会标成"放宽"；
- 已有任务不会被立即改动，但运行前会按新策略再检查（例如保留天数低于新下限的任务运行会被拒绝并提示重新审批）。

## 运行记录与恢复

「运行记录」页签每次运行一行，包含触发方式（定时 / 手动 / 恢复 / 试运行）和结果：

| 结果 | 含义 |
|---|---|
| 运行中 / 已暂停 | 进行中 / 运行被暂停（当前批做完后停，可继续） |
| 成功 | 符合条件的数据全部处理完（读到的行数不足一批），校验通过 |
| 窗口结束中断 | 执行窗口结束，当前批做完后优雅停止，下次接着跑 |
| 负载中断 | 负载超限且累计等待超过最长等待；不算失败，不自动暂停，下次接着跑 |
| 已达上限 | 达到单次运行最大行数，下次接着跑 |
| 失败 | 连续多批失败、源表缺失 / 无主键 / 有外键子表引用、目标表不兼容、收尾上传失败等；失败批已回滚，源数据未被删除。除瞬时的连接错误外会自动暂停任务 |
| 校验失败 | 备份端同主键内容不一致 / 写入数不对 / 回读数不对，已停止，该批源数据**未删除**；自动暂停任务 |
| 已终止 | 人工终止，保留断点 |
| 结构变更暂停 | 源表结构指纹与审批 / 试运行时不一致（运行开始时或运行中），任务置为已暂停并通知 |
| 中断 | 执行进程异常退出或心跳超时（租约过期），运行被标记为中断，下次从最后一批的断点接着跑 |
| 已跳过 | 到点时上一次运行未结束、源表有未结束的 SQL 上线工单、实例并发已满、备份存储不可用 / 已停用、保留天数低于策略、策略不再允许不备份清理、表现在属于受保护库表等，本次没有执行（调度触发才记；立即执行会直接被拒绝并说明原因） |

运行详情包含：批次吞吐曲线（折线为行 / 秒，虚线为当前批大小，红色带是被限流暂停的时段）、限流事件（负载自检：超限则暂停，每 30 秒复查，超过最长等待则以"负载中断"结束，不算失败）、校验结果（目标端 COUNT / 主键集合、写入行数、清单回读 sha256、删除行数）、备份位置与 sha256、错误信息、"已触发自动暂停"提示和日志。

**恢复数据**（`archive.restore`，高危）：仅库表备份、且是已结束的定时 / 手动运行。输入任务名确认后，按该次运行的主键范围用 `INSERT IGNORE` 把数据回灌到源表，**只补缺、不覆盖**；恢复本身也会生成一条运行记录（读到的是备份里该范围的行数，补回的是实际插入的行数）；回灌同样会产生 binlog，注意从库延迟。该运行已恢复过时，再次恢复通常是空操作。文件备份在详情里显示文件清单（行数、大小、sha256）并可"下载清单"，恢复靠 DBA 手工导入（用清单核对 sha256）。

## 任务状态

| 状态 | 说明 |
|---|---|
| 草稿 | 只保存了配置，没有提交审批，也没有试运行；可编辑、提交、删除 |
| 待审批 | 已提交，等待审批流逐级通过；列表里显示当前在哪一级、等谁 |
| 已驳回 | 被某一级驳回，原因在详情里；修改后点"编辑 / 重新提交"（也可以只保存修改，先不提交）；可删除 |
| 已启用 | 按调度运行 |
| 已暂停 | 人工暂停、自动暂停（连续失败、校验失败、上传失败等，原因在详情里）或结构变更暂停；前两种点"恢复任务"从断点接着跑，结构变更暂停需重新试运行并走审批，不能直接恢复 |
| 已停用 | 不再调度；运行记录与已备份的数据保留；可重新提交审批启用，或删除 |

只有草稿、已驳回、已停用的任务可以删除（高危，需输入任务名确认），历史运行记录与已备份的数据保留。

## 说明（已知限制与部署）

1. **文件备份有暂存目录**：删源在本地落盘之后、上传之前，进程被强杀时未上传的备份留在暂存目录需要人工补传，详见「文件备份与暂存目录」；
2. **OSS 只支持 S3 兼容端点**：阿里云 OSS 通过其 S3 兼容端点访问，没有实现 OSS 原生签名，也没有用真实 OSS 验证过；
3. **不支持 `GEOMETRY` 等空间类型列**的表（二进制协议取出的 WKB 不能原样当字符串写回）；BLOB / BIT 以字节原样搬运，在 CSV / SQL 文件里写成 `0x...`；
4. **不处理有外键子表引用的表**（试运行红色、运行失败）；分区表按普通表处理，更推荐用分区维护直接 `DROP PARTITION`；被审批的表结构只比较"列名 + 类型 + 主键"；
5. **多进程部署时的运行级控制**：运行级的"暂停 / 继续 / 终止"只能在启动该运行的进程里操作，其他进程会提示该运行已结束或不在本进程里运行；任务级的暂停 / 恢复 / 停用不受影响。多进程时同一任务只会在一个进程里跑，调度由数据库行锁认领；
6. **断点**运行中每 10 秒写回一次，进程崩溃后最多丢失 10 秒，靠主键幂等重复写目标，不会丢数据；运行靠租约和心跳判活（租约 90 秒），租约过期的运行被标记为"中断"；
7. **部署前**：管理员需先在元数据库执行 `deploy/sql/180_archive.sql`，表没建时页面给出提示而不是报错；`ARCHIVE_SPOOL_DIR`（暂存目录）与 `MIRAGE_SECRET_KEY`（加密密钥）见上；
8. 已有的 `archive_config`（归档配置）**目前不会自动导入**为草稿任务，需要在页面上重新建。

## 原型里模拟了什么

- 所有数据（任务、运行记录、备份存储、策略）是内存里的假数据，操作只改内存，刷新页面还原；不连真实库、不上传真实文件；
- "运行"是会走动的模拟（时间被压缩，约 30 秒跑完一次），离开本页面时模拟暂停推进，回来继续。运行详情里的"演示"按钮可以模拟负载升高、持续高负载（触发"负载中断"）和从库延迟；
- 试运行的命中行数、检查项结果由表行数和条件**确定性地推出**（不是真的查库）；备份存储的"测试连接"结果由地址决定（地址含 `10.255.` 或 `timeout` → 超时，含 `refused` / `invalid` / `bad` / `403` → 失败，其余成功）；
- 通知只在「通知渠道」页的"测试发送"里体现，不会真的发消息；
- 调度到点自动触发运行、多进程部署、租约与心跳不在原型里模拟（用"立即执行"体验运行，历史运行记录里有"已跳过""中断"的示例）。

## 常见问题

**为什么"立即执行"提示源表有未结束的 SQL 上线工单？**
为避免归档删除与 DDL 变更同时进行，源表有待执行 / 执行中的 SQL 上线工单时，本次会被跳过。工单结束后再执行；这类工单可在「SQL 上线」里查看。

**试运行红色项是"时间列没有索引"，怎么办？**
先通过 SQL 上线工单给时间列建索引，再回来重新试运行；否则按时间条件扫描会拖垮线上。

**为什么不能把保留天数设得更短？**
保留天数是硬约束，下限由安全策略决定（默认 30 天），防止误归档近期数据。确需放宽请联系管理员修改安全策略。

**任务被"自动暂停"了怎么办？**
详情里的暂停原因会写明（例如连续多批失败、备份校验不一致）。先排查原因（从库延迟、锁等待、目标端空间等），再点"恢复任务"从断点接着跑；如果是"结构变更暂停"，需要重新试运行并重新提交审批。

**"批间休眠"为什么不能填 0？**
服务端把 0 当作"用策略默认值"（默认 200 ms），所以无法表达 0 ms；仅备份模式想要最快就填 1。复制延迟阈值同理，不能填 0。
