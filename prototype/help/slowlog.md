# 查慢日志与慢查日志

慢日志有两个入口，面向的问题不同：

| 页面 | 菜单 | 回答什么问题 | 权限码 |
|---|---|---|---|
| 查慢日志 | SQL 查询 › 查慢日志 | "这个库今天有哪些慢 SQL？"——按实例 × 库 × SQL 指纹 × 天聚合 | `slowlogs.view` |
| 慢查日志 | SQL 优化 › 慢查日志 | "哪些 SQL 总体最慢、趋势如何、怎么优化？"——统计 + 明细 + 趋势 + 建议 | `slowquery.view`、`slowquery.advise`、`redis.slowlog_reset`（重置 Redis 慢日志） |

## 查慢日志

1. 选择实例、库和**日期范围**（日期框，或点「近 7 天 / 近 31 天 / 近 93 天」快捷项，最长 93 天；超过会提示缩小范围）；搜索框同时匹配 SQL 文本、库名和 `用户@主机`，多个词用空格分隔，需全部包含；
2. 页面顶部是四张统计卡（慢 SQL 总次数、慢 SQL 指纹数（按「实例 × 指纹」计）、累计耗时、最慢单条）和"每日慢 SQL 次数""每日累计耗时"两张折线图，随筛选条件变化；
3. 列表每一行是 **实例 × 库 × SQL 指纹 × 天** 的聚合：执行次数、总耗时、平均 / 最大耗时、扫描行数和返回行数（均值 / 最大值）等，点表头可排序，每页 20 条，单次最大耗时 ≥ 30 秒的标红；
4. 点行展开该指纹当天最近一条的**代表 SQL**（附用户@主机和指纹）；点「详细」打开右侧抽屉：摘要（实例、库、日期、当天次数、平均 / 最大耗时、扫描 / 返回行均值）、SQL 指纹和当天最近 100 条原始记录（执行时间、用户@主机、库名、查询时长、锁定时长、返回行数、扫描行数、SQL）。有优化工具权限时，抽屉里有「去优化工具」链接。

数据来自平台采集器写入的慢日志表（MySQL / PolarDB 读 `mysql.slow_log`，约每 10 秒一轮增量采集）。**只有开启了"慢日志采集"的实例才有数据**（实例列表里可看到开关）；刚开启采集的实例需要等一个采集周期。

页面底部可展开「采集器状态」：采集器是否启用、每多少秒一轮，以及每个实例最近一次采集的状态、最近成功时间、本次 / 累计写入条数和耗时。采集器由管理员通过环境变量 `SLOWLOG_COLLECT_ENABLE` 开启，连续失败的实例按指数退避重试，最长间隔 10 分钟。

## 慢查日志

页面分两个页签：

- **统计**：按 SQL 指纹聚合，顶部是指纹数、总次数、总耗时（含平均）、最慢一次四张卡片；每行列出出现次数、总耗时、平均 / 最大耗时、扫描 / 返回行（总数与平均）、首次 / 最近出现和每天慢查次数的小趋势。点 ▸ 展开代表 SQL 与按天的次数、平均耗时趋势图；点 SQL 指纹文本切到「明细」并按该指纹过滤，点「取消过滤」恢复；
- **明细**：单条慢查询记录（开始时间、实例 / 库、用户@主机、耗时、锁等待、扫描 / 返回行），可按时间、库、关键字过滤；点一行打开抽屉看 SQL 全文，并可「获取优化建议」或「在优化工具中打开」；
- **获取优化建议**：弹窗给出基于规则的静态建议（见下），只读、不连目标库；统计行和明细抽屉里都有入口。

筛选栏有实例（默认"全部有慢日志的实例"）、数据库、时间范围（今天 / 近 3 / 7 / 30 / 93 天或自定义，最长 93 天）、耗时下限和关键字；「耗时 ≥」下限在统计页按**平均耗时**过滤、在明细页按**单次耗时**过滤，「重置」恢复默认条件。

数据源取决于实例类型：

| 实例类型 | 数据源 |
|---|---|
| MySQL（自建，有 pt-query-digest 的 digest 表） | pt-query-digest 库（`dbt_mysql_slow_query_review` / `dbt_mysql_slow_query_review_history` 两张表，由外部脚本推送，平台只读；推送脚本里 `--review` / `--history` 的 `t=` 要写这两个带 `dbt_` 前缀的表名） |
| MySQL（没有 digest 表） | 回退到平台采集的慢日志（`dbt_slow_logs`） |
| PolarDB / PolarDB-X / SelectDB / Doris / ADB | 平台采集的慢日志 |
| MySQL 且手动指定 | 页面上 MySQL 实例会出现"数据源"下拉，可手动选 digest 或平台采集 |

Redis 实例见下面的「Redis 慢查询」；其他类型（Oracle、PgSQL 等）暂不支持。

### Redis 慢查询

在实例下拉里选 **Redis 实例**，页面会换成 Redis 面板（"SQL"改称"命令"）：

- **命令统计**：按**命令指纹**（命令名 + 参数占位，如 `HGETALL ?`、`SET ? ? EX ?`）聚合，列出次数、总耗时、平均 / 最大耗时（毫秒）、首次 / 最近出现和每日小趋势；顶部是指纹数、总次数、总耗时、最慢一次四张卡片和次数 + 平均耗时趋势图；点 ▸ 展开完整命令和该指纹的趋势（柱是次数、线是平均耗时，毫秒），点指纹切到明细并按该指纹过滤，「复制指纹」复制指纹文本，「清除指纹过滤」恢复全部；
- **慢命令明细**：每条慢命令的时间、耗时、命令名、客户端地址和**完整命令**；
- **采集状态**：每个 Redis 实例的采集游标、最近一次采集结果和累计入库条数；
- 可按命令名、耗时下限（1 ms – 1 s，按单次命令的耗时过滤）、时间范围（最长 93 天）和关键字（命令 / 客户端地址）筛选。

数据来自定时 `SLOWLOG GET` 增量采集（实例需在实例管理里勾选「启用」，采集器开关与其它慢日志相同，约每分钟一次）；「立即采集」对当前实例立刻执行一次 `SLOWLOG GET` 并入库（同一实例 10 秒内只能点一次），采集器没开时靠它手动拉取；「采集状态」页签顶部会提示采集器是否启用及采集周期。Redis 的慢日志是内存里的环形缓冲（默认 128 条），采集间隔内产生的慢命令超过缓冲长度会丢，慢命令很多时要调大实例的 `slowlog-max-len`、缩短采集间隔。

「重置慢日志」会对实例执行 `SLOWLOG RESET`（高危，权限码 `redis.slowlog_reset`，默认仅超级用户）：先把现有条目采集入库再清空（采集失败则取消重置），需要输入实例名确认，并写系统审计。平台不会自动重置。完整命令里可能带业务数据（例如 `SET` 的值；`AUTH` 等密码参数已抹成 `***`），请只把查看权限授予需要的人。

### 优化建议的内容

只做词法级静态规则：`SELECT *`、缺 WHERE、LIKE 前导通配符、WHERE 里列上套函数、OR、否定条件、`ORDER BY RAND()`、排序无 LIMIT、深分页（偏移 ≥ 10000）、超长 IN 列表、IN 子查询、UNION 去重等。当记录里带有扫描 / 返回行数时：扫描 ≥ 1 万行且比例 ≥ 100:1 会提示"缺少索引的迹象"，单表语句还会推测候选复合索引（等值列在前、范围列在后，**仅供参考，以 EXPLAIN 为准**）。

弹窗里还有综合评分，规则同[优化工具](#help/optimize)内置建议的 R 系列；需要执行计划、索引推导与 PROFILE 的，点"在优化工具中打开"把 SQL、库和实例带过去并自动运行。

## 与性能工单的关系

平台会把慢查询按"实例 + 库 + SQL 指纹"自动汇总成**性能工单**，按影响程度定 P0–P3 级别并跟踪 SLA，见[性能工单](#help/perf)。DBA 也可以直接从慢日志页面对某条慢 SQL"生成性能工单"。

## 使用提示

- 慢 SQL 的判断阈值（`long_query_time`）在数据库实例上设置，平台只负责采集与展示；
- 看趋势比看单点重要：同一指纹连续几天次数上升，往往比单条最慢记录更值得处理；
- 发现自己的 SQL 在榜上：先用执行计划确认是否缺索引，再按[SQL 上线](#help/sqlworkflow)提交加索引工单。

> 原型体验：切到 mysql-order-prod-m 或 mysql-user-prod-m 查看有数据的慢日志；mysql-dw-prod-s 没有开启采集，页面会提示没有数据。选 redis-order-cache-m 或 redis-session-prod 看 Redis 面板；redis-order-cache-s 的采集账号缺 SLOWLOG 权限，「采集状态」显示失败，「立即采集」会报错；admin 可以试「重置慢日志」（输入实例名确认，写系统审计），其他身份该按钮置灰。
