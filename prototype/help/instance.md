# 实例管理

菜单：实例管理 › 实例列表 / 会话管理 / 数据库管理 / 账号管理 / 参数配置 / Binlog 解析（性能巡检见[单独一章](#help/inspect)）。这组页面面向 DBA，**所有会改变目标库的操作都需要二次确认并写入系统审计**（成功和失败都记，语句里的密码打码）。

## 谁能看到哪些实例

超级用户或持有"查看全部实例"权限的人看全部实例；其余人按资源组关联范围。实例列表里能新增 / 修改 / 删除实例的人也看全部。

添加 / 编辑实例时各类型的差别：Redis 端口默认 6379，连接账号可不填（只用密码认证，Redis 6+ 的 ACL 账号才需要填），不支持 SSH 隧道；PostgreSQL 默认 5432，MongoDB 默认 27017（账号可空，认证库固定为 `admin`），ClickHouse 走 HTTP 接口，默认 8123、使用 TLS 时通常是 8443，这三类第一期只支持在线查询和数据字典。切换类型时，端口只有还是某个默认值才会跟着变。

> 带标签的含义：`can_write` 表示可以提交上线工单，`can_read` 表示可以查询 / 导出，`read_view` 表示只读视图实例（只能访问 `v_` 开头的视图），`批量上线` 表示允许批量上线。

SSH 隧道使用密码或私钥内容（不支持服务器上的私钥路径），隧道不校验跳板机主机公钥，这是已知限制。管理连接仅 MySQL 系实例走隧道。

## 会话管理

选择实例后查看：

- **进程列表**（可筛选用户 / 库 / command 类型 / 耗时 / 关键字）`session.process`：顶部统计连接总数、活跃（非 Sleep）、长时间运行（≥ 300 秒）、受保护；耗时 ≥ 300 秒的行标黄、≥ 1200 秒标红并标“长时间运行”，持有锁让别的事务在等的线程标“阻塞源”；平台自身连接、复制线程、事件调度线程标“受保护”，不能终止；
- **Top 表空间** `session.tablespace`：按总空间降序，只列前 20 张；来自 `information_schema.tables`，MySQL 8.0 默认缓存统计值 24 小时，数字可能略有延迟；碎片率偏高（≥ 8%）的表突出显示，可在低峰期 `OPTIMIZE` 或在线改表；
- **事务**（长事务一眼可见）`session.trx`：来自 `information_schema.innodb_trx`，列出全部 InnoDB 事务，可按“持续空闲 ≥ N 秒”或“仅空闲事务”筛选；空闲 ≥ 300 秒的行标黄（长时间不提交会持锁、撑大 undo），处于 LOCK WAIT 的标红；点线程号跳到进程列表并定位；
- **锁等待**（锁等待链）`session.locks`：MySQL 8.0 读 `performance_schema.data_lock_waits`，5.7 读 `information_schema.innodb_lock_waits`；上方“阻塞链”把互相等待的线程整理成树，根因（只阻塞别人、自己没在等）在最上面，被它阻塞的线程缩进挂在下面；根因线程可到进程列表预览并终止，终止后被它阻塞的线程会自动继续。

**终止会话**（`session.kill`，高危）分两步：先预览将要执行的 `KILL n`；确认后服务端会**再次校验**：线程仍然存在；若带了用户 / 主机必须与现在一致（防止线程号被复用而误杀）；不是平台自己的连接、不是复制线程（`Binlog Dump`、`system user`）、不是事件调度线程。被拒绝的会在结果里给出原因。审计只记线程号、用户、主机、库和状态，**不记录会话正在执行的 SQL**。

> ⚠ 终止一个大事务会触发回滚，回滚期间会话仍占用资源，不要反复重试。先看事务的修改行数再决定。

## 数据库管理

- 库清单（来自实例的 `information_schema` 加平台登记），登记**负责人和备注**（`database.edit`）：“已录入”指平台里登记了负责人 / 备注的库，其余库点“录入”补充，也可在筛选里选“未录入”只看这些库；系统库（`mysql` / `information_schema` / `performance_schema` / `sys`）不显示；录入 / 编辑只修改平台里的登记信息，不改动库本身；没有删除库的功能；
- **创建数据库**（`database.create`，高危）：库名必须字母开头、字母或数字结尾，只含字母、数字、下划线、中划线，≤ 64 字符，不能是系统库名；字符集和排序规则从目标库自己的列表里选，且两者必须匹配、目标库支持；负责人必填；建库后没有任何账号拥有该库的权限，需在「账号管理」授权；
- 创建前会二次确认，执行语句会写入审计。

| 功能 | 说明 | 权限码 |
|---|---|---|
| 查看 | 账号列表与权限；高危账号整行标黄并写明原因：主机为 `%` 且有写 / 结构变更权限、有 ALL PRIVILEGES、含 FILE / SUPER / GRANT OPTION 等高危权限；可按全部 / 已录入 / 未录入 / 高危 / 已锁定筛选，搜索框匹配账号、主机和使用人；列表上方统计账号总数和高危个数 | `account.view` |

| 创建账号（高危） | 账号 1–16 位，字母开头，只含字母、数字、下划线；主机填 IP 或网段，支持 `%`（尽量用网段，避免任意主机），多个主机用竖线分隔，每个主机创建一个账号；密码 8–32 位，含英文、数字和特殊字符，需输入两次；`root`、`mysql.*` 和平台自用账号名不能创建；新账号**没有任何权限**，需用“授权 / 回收”授予 | `account.create` |

| 修改密码 / 锁定 / 解锁 / 删除 | 均为高危。改密会修改库里账号的真实密码，使用该账号的应用需同步更换；锁定后账号无法再登录，已建立的连接不受影响（可在会话管理里终止）；删除不可恢复，要输入“账号@主机”确认 | `account.pwd` / `account.lock` / `account.delete` |

平台自己连接该实例使用的账号（`dbtool_ro` / `dbtool_rw` / `sa_dbtool` 等）和数据库内置账号（如 `mysql.sys`）受保护，不允许改密、锁定、删除、授权或回收权限，避免把平台自己锁在外面，也不判定为高危。库级授权里库名的 `_` `%` 会被转义成只匹配该库。密码在界面、审计和日志里一律打码。

## 参数配置

- **运行值**：当前 `SHOW GLOBAL VARIABLES` 的值（`param.view`），可按参数名 / 描述搜索、按“允许修改”筛选；有推荐值时，运行值与推荐值不一致的行标黄并标“偏离推荐”，可筛选只看偏离推荐值，表头旁统计偏离项数；不在参数模板里的参数标“未在模板中”，不能修改，需先添加参数模板；可改 / 不可改由参数模板决定；
- **参数模板**：由 DBA 维护的"哪些参数允许修改、取值范围、推荐值"（`param.template`）；“可修改值”写成数值范围 `[1-65535]`（上限可写 `…`）或枚举 `[ON|OFF]`，留空表示自由文本；参数名只能是小写字母、数字、下划线；推荐值用于“偏离推荐”标黄，留空则不提示，且必须满足可修改值；黑名单参数和需重启才生效的参数有标识；
- **修改参数**（`param.edit`，高危）：只能改模板里标为"可修改"的参数，值必须在范围内，新值与运行值相同则不执行，记录旧值；修改是动态 `SET GLOBAL`，立即对新连接生效，**不会写入配置文件**，重启后恢复，成功后需自行把值持久化到 `my.cnf`（成功提示里附有 `[mysqld]` 片段）；
- **修改历史**：谁、何时、把哪个参数从什么改成什么、执行的语句，可切换“仅当前实例 / 全部实例”；
- 能执行语句或改文件路径的参数（`init_connect`、`datadir`、`secure_file_priv`、`general_log_file` 等）永远拒绝，即使模板里标了可改；只读参数改动时数据库会返回 `ERROR 1238`，运行值不变，需改配置文件并在维护窗口重启。

> 原型体验：dba_li 具备本章全部操作；rd_zhao 没有实例管理分组；tl_wang 只能在实例列表里查看自己资源组的实例。会话管理里，勾选“平台自身连接”终止会被拒绝；`etl_job` 的短查询会在你确认前自行结束，用来演示“线程已不存在”。

## Binlog 解析

菜单：实例管理 › Binlog 解析。选一个 MySQL 实例，把一段 binlog 还原成 SQL，或生成**回滚 SQL**（用于误删、误更新后的数据恢复）。平台以复制从库的身份读取 binlog，**只读，不会在目标库执行任何语句**，也不影响主从复制。

| 功能 | 说明 | 权限码 |
|---|---|---|
| 打开页面、列出 binlog 文件 | 看实例的 binlog 文件列表（文件名、大小、起止时间）、`binlog_format`、`binlog_row_image` | `binlog.view` |
| 还原 SQL | 把 INSERT / UPDATE / DELETE 行事件还原成语句，可选列出 DDL；也是看任务列表、取消任务的前提 | `binlog.parse` |
| 回滚 SQL | DELETE↔INSERT，UPDATE 的前后镜像互换，按"后发生的先撤销"排序（高危） | `binlog.rollback` |
| 下载 .sql 文件 | 带事务边界（`BEGIN` / `COMMIT`），每次下载都写审计（高危；回滚任务另需 `binlog.rollback`） | `binlog.download` |

用法：

1. 选实例（只列你能看到的 MySQL 系实例；通过 SSH 隧道访问的实例置灰），实例状态里会显示版本、`binlog_format`、`binlog_row_image`、binlog 文件数和服务器时区，以及能否生成回滚 SQL；选起始文件（默认最后一个文件）；需要精确范围时填起始 / 结束位置，或填起止时间（按**服务器时区**解释，时间过滤不会跳到文件中间，仍要从起始文件读起）。起始位置必须落在事务的开头（通常取自 `SHOW BINLOG EVENTS` 或误操作的大致时间），否则会报“起始位置不在事务边界上”；不确定位置时留空，从文件开头读，再用时间、库、表、语句类型缩小范围。结束文件留空表示读到最后一个文件的末尾，结束位置留空表示该文件末尾，指定结束位置时必须同时选结束文件。
2. 点"开始解析"，页面显示进度（已扫描事件、当前位置、已匹配语句、结果体积、事务数），可随时取消；结果分页显示，可逐条复制、复制全部或下载；“我的任务”里可重新查看未过期的任务，超级用户能看到所有人的任务。回滚 SQL 在"生成回滚 SQL"模式下得到，点击后还要二次确认：平台只生成语句、不在目标库执行，是否执行由你决定。
3. 回滚 SQL 执行前先在测试环境验证，并确认范围内没有 DDL（DDL 无法回滚，结果里标"不可回滚"，页面会警告）。

过滤与输出选项：

| 选项 | 说明 |
|---|---|
| 数据库 | 可多选，不选表示全部可见库（系统库和被实例“隐藏库”规则排除的库不会出现） |
| 表 | `表名` 或 `库.表名`，逗号 / 换行分隔，不区分大小写 |
| 语句类型 | 全不选表示 INSERT + UPDATE + DELETE；DDL 只列出，不可回滚 |
| 输出选项 | 不带库名前缀；语句后附位置 / 时间注释；SET / WHERE 带全部列 |

回滚的前提：实例开启了 binlog，`binlog_format=ROW` 且 `binlog_row_image=FULL`，目标表仍存在、列数与 binlog 里一致。不满足时页面会说明原因并禁用回滚，仍可使用"还原 SQL"。**回滚 SQL 必须完整**：结果超过上限、超时或某一行无法生成时，整个任务失败，不会给出只回滚一部分的结果，请缩小范围后重试；"还原 SQL"超限则只截断并提示。列名与主键来自目标库**当前**的表结构：binlog 之后表结构被改过的表，列数对不上时回滚会被拒绝。

限制与注意：

- 每次最多解析 20000 条语句、8MB 结果（默认 500 条、2MB）、最多扫描 500 万个事件、最长 10 分钟（默认 2 分钟）。每人最多同时 2 个任务，结果只在内存里保留 30 分钟，到期自动清理，刷新页面或服务重启即丢失。
- 实例账号需要 `REPLICATION SLAVE` 和 `REPLICATION CLIENT` 权限；目标库的"复制从库列表"里会短暂出现一个随机编号的从库。
- 结果里可能含有业务敏感数据，只有持有对应权限码的人能看，请只在需要时查看，下载的文件妥善保管、用后删除；任务只有创建者和超级用户可见。**回滚、下载默认只给超级用户**，需要在权限组里单独授予；每次解析、回滚、下载、取消都写入系统审计（动作名以"Binlog解析-"开头）。
- 实例的"显示 / 隐藏库"规则同样适用：被隐藏的库、`mysql` / `sys` 等系统库的变更不会解析出来。

> 原型体验：admin 可以做完整流程；dba_li 能解析但"回滚"和"下载"按钮置灰（预设 DBA 组不含这两个码）；rd_zhou 没有 Binlog 解析菜单。`mysql-pay-prod-m`（`binlog_format=MIXED`）和 `mysql-user-prod-m`（`binlog_row_image=MINIMAL`）不能回滚；`mysql-order-view` 没有开启 binlog；`mysql-dw-prod-s` 走 SSH 隧道；`mariadb-log-prod` 连接失败。事务起点位置的示例会显示在"起始位置"的提示里；解析进度是压缩时间后的模拟（几秒跑完），“模拟已运行 N 秒”是按真实读取速度折算的值；原型里 30 分钟的保留时间按真实时间计算。
