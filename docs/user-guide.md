## 1. 功能概述

dbtool 是面向 DBA 的数据库运维管理平台：用一个服务端渲染的 Web 站点，把“查询数据、变更上线、权限申请与审批、慢 SQL 治理、实例与账号管理”放在同一套权限与审批体系里。

| 角色 | 主要做什么 | 对应章节 |
|---|---|---|
| 开发 / 测试 | 在线查询、申请查询权限、提交 SQL 上线工单、数据导出、SQL 分析与优化、查看慢日志、处理性能工单、申请数据归档 | 第 5 章 |
| 组长 / 审批人 | 审批 SQL 上线、查询权限申请、数据归档申请；受理本组性能工单 | 第 6 章 |
| DBA | 执行上线、管理查询权限、实例 / 会话 / 库 / 账号 / 参数管理、Binlog 解析、性能巡检、分区维护、数据归档、性能工单处理 | 第 7 章 |
| 系统管理员 | 审批流程、资源组、用户与权限组、登录方式与安全、数据脱敏、SQL 防火墙、goInception、通知渠道、值班表、系统配置、系统审计 | 第 8 章 |

## 2. 适用范围：数据库类型支持矩阵

“实例类型”是实例列表里登记的类型值。✔ 表示支持，✖ 表示不支持，“部分”的含义见表后说明。表里没有的类型（Oracle、Cassandra、Elasticsearch、OpenSearch、Memcached、TDengine）可以登记为实例，但没有任何业务功能使用它们。

| 实例类型（类型值） | 在线查询 | SQL 上线 | 数据导出 | 数据脱敏 | SQL 防火墙 | 慢日志 | 性能工单 | 性能巡检 |
|---|---|---|---|---|---|---|---|---|
| MySQL（`mysql`） | ✔ | ✔ | ✔ | ✔（精确） | ✔ | ✔ | ✔ | ✔ |
| PolarDB（`polardb`） | ✔ | ✔ | ✔ | ✔（精确） | ✔ | ✔ | ✔ | ✔ |
| PolarDB-X（`polardb-x`） | ✔ | ✔ | ✔ | ✔（保守） | ✔（无预估扫描行数） | ✔ | ✔ | ✔ |
| SelectDB / Doris（`selectdb` / `doris`） | ✔ | ✔ | ✔ | ✔（保守） | ✔（无预估扫描行数） | ✔ | ✔ | ✔ |
| ADB（`adb`） | ✔ | ✔ | ✔ | ✔（精确） | ✔ | 部分 | ✔ | ✔ |
| SQL Server（`mssql`） | ✔ | ✔（含批量） | ✔ | ✔（精确，分析失败时保守） | ✔ | ✖ | ✖ | ✔ |
| Redis（`redis`） | ✔（只读命令） | ✔（命令 + 管理员规则） | ✖ | ✖ | ✖ | ✔（SLOWLOG） | ✖ | ✔ |
| PostgreSQL（`pgsql`） | ✔ | ✖ | ✖ | ✔（精确） | ✔（仅在线查询） | ✖ | ✖ | ✖ |
| MongoDB（`mongo`） | ✔ | ✖ | ✖ | ✔（字段路径） | ✖ | ✖ | ✖ | ✖ |
| ClickHouse（`clickhouse`） | ✔ | ✖ | ✖ | ✔（保守） | ✔（仅在线查询） | ✖ | ✖ | ✖ |

| 实例类型 | 实例管理 | 分区维护 | 数据归档 | Binlog 解析 | SQL 分析 / 优化工具 | 查询权限粒度 |
|---|---|---|---|---|---|---|
| MySQL | 全部页面 | ✔ | ✔（主库） | ✔ | ✔ 全部方式 | 库 + 表 |
| PolarDB | 全部页面（Binlog 清理除外） | ✔ | ✔（主库） | ✖ | ✔ 全部方式 | 库 |
| PolarDB-X | 全部页面（Binlog 清理除外） | ✖ | 部分（主库） | ✖ | ✔ 全部方式 | 库 |
| SelectDB / Doris | 部分 | ✔（Doris 方言） | ✖ | ✖ | 部分（仅执行计划） | 库 |
| ADB | 部分 | ✖ | ✖ | ✖ | 部分（仅执行计划） | 库 |
| SQL Server | 仅实例列表 | ✖ | ✖ | ✖ | ✖ | 库 |
| Redis | 仅实例列表 | ✖ | ✖ | ✖ | ✖ | 库（db 编号） |
| PostgreSQL / MongoDB / ClickHouse | 仅实例列表 | ✖ | ✖ | ✖ | ✖ | 库 + 表（集合） |

“部分”的含义：

- **ADB 慢日志**：实例在慢日志页面可选，但平台采集器的采集清单不含 ADB（`internal/slowlog/service.go` 的 `collectTypes`），没有自动采集的数据来源；ADB 的性能工单只能用自定义采集 SQL；
- **实例管理 · 部分**：SelectDB / Doris / ADB 只有会话（进程 / 表空间）、数据库管理、参数配置；事务与锁等待、账号管理只支持 MySQL / PolarDB / PolarDB-X；Binlog 清理只支持 MySQL；
- **仅实例列表**：只能在实例列表里登记、编辑、测试连接，会话 / 账号 / 参数等页面的实例下拉里不出现它们，页面上标“仅查询”或“暂不支持”；
- **脱敏精确 / 保守**：精确 = 按结果列的来源库表字段匹配（MySQL / PolarDB / ADB 用 goInception 语法树；SQL Server 用结果集来源分析；PostgreSQL 用结果列的表与列号反查）；保守 = 按结果列名、别名和表达式引用匹配，宁多勿漏，不同库表里同名的列也会被脱敏。**PolarDB-X 不调用 goInception 语法树**，视同 SelectDB / Doris 完全按列名保守匹配；调用了存储函数 / 自定义函数的结果列（语句里看不出函数读了哪些字段）整列按该实例最严的一条规则脱敏，ClickHouse 除外；通过视图查询时，平台读取视图定义顺着追到基表字段（MySQL 系、SQL Server、PostgreSQL、ClickHouse、MongoDB），读不到视图定义按脱敏失败处理（受 `query.block_on_mask_error` 控制）；
- **分区维护**：MySQL / PolarDB 与 SelectDB / Doris；初始化未分区表仅 MySQL / PolarDB；
- **数据归档**：来源与库表备份目标只能是 MySQL / MariaDB / PolarDB / PolarDB-X 主库（MariaDB 服务端按 `mysql` 类型登记）；PolarDB-X 标“部分”：引擎对它做兼容降级（会话锁等待参数设不上时忽略、读不到 `sql_log_bin` 时放行、复制延迟 / `Threads_running` 读不到标“未检测”，建表语句去掉拆分子句），没有在真实实例上验证，启用前请先试运行；
- **SQL 防火墙的预估扫描行数**：只对 MySQL、PolarDB、ADB（MySQL 格式的执行计划）有效；PolarDB-X、SelectDB / Doris、SQL Server、PostgreSQL、ClickHouse 上这类条件显示“未评估”、不命中；在线查询里只对 SELECT / WITH 估算。MongoDB、Redis 与线下手工执行的工单不接入防火墙；
- **查询权限粒度**：MySQL 与它的协议系（PolarDB / PolarDB-X / SelectDB / Doris / ADB）都精确到表（库权限或表权限）：MySQL、PolarDB、ADB 用 goInception 解析语句涉及的表，PolarDB-X、SelectDB、Doris 用词法解析（宁多勿漏）；SQL Server 只校验库权限，对它申请表权限不能让查询通过，请申请库权限。

## 3. 前提条件与所需权限

使用业务功能前，需要同时满足：

| 前提 | 说明 | 谁来配置 |
|---|---|---|
| 平台账号 | 本地账号或单点登录账号；没有账号请联系资源组负责人或 DBA（管理员开放自助注册时登录页有“注册用户”） | 管理员 |
| 权限组 | 决定能打开哪些页面、点哪些按钮（按钮级权限，见 8.5）；“个人信息与权限”里能看到自己拥有的全部权限 | 管理员 |
| 资源组 | 只能看到所在资源组关联的实例（有 `query.admin_run` 的人和超级用户不受限）；资源组决定工单走哪条审批流 | 管理员 |
| 实例标签 | `can_read`（支持查询）才能导出和申请查询权限；`can_write`（可以写入）才能提交 SQL 上线工单 | DBA |
| 库表查询权限 | 在线查询要求对涉及的库 / 表有有效的查询权限（第 5.2 节） | 审批人 / 管理员 |
| 审批流 | 每个资源组 × 工单类型要配置审批流，否则不能提交该类工单 | 管理员（8.1） |

内置权限组预设的定位（具体以管理员的配置为准）：

| 预设 | 典型权限 |
|---|---|
| DBA | 全部可授予按钮，含 Binlog 清理、立即巡检；不含“仅自己的立即执行”、Binlog 回滚 / 下载、审计日志、Redis 慢日志重置、值班表管理按钮（`duty.*`，需要时在权限组里显式授予）和全部锁定码；可查看全部实例 |
| TL（组长） | 审批本组工单与查询权限、查看慢日志、受理性能工单、SQL 分析；数据归档可查看 / 新建 / 试运行 / 暂停；不能执行上线 |
| RD（研发） | 提交工单、执行自己的工单、在线查询、申请权限、提交导出、处理自己负责的性能工单 |
| QA（测试） | 提交工单、在线查询、提交与下载导出、查看回滚语句；不能自行执行上线 |
| Default | 在线查询、申请与查看查询权限 |
| 审计 | 审计日志与全部工单只读、导出审计日志（预设，非内置组） |

权限改动后最长约 15 秒生效。完整权限码见帮助章节“权限码清单”（`web/static/help/permcodes.md`）。

## 4. 通用操作（所有角色）

### 4.1 登录与账号安全

目标：登录平台、完成两步验证、处理密码与锁定。

1. 用平台账号登录；登录页可能还有“使用公司账号 / 钉钉 / 飞书……登录”的按钮（管理员配置的单点登录）。超级用户在 SSO 异常时可用 `/login?local=1` 走本地账号；
2. 连续输错密码会被暂时锁定（默认 5 次、300 秒，由管理员设定），登录、登录失败与锁定都会记录审计，提示语不区分原因；
3. 若开启了**两步验证**，密码通过后还要输入验证器（TOTP，6 位、30 秒）或短信验证码（6 位，5 分钟有效，同一号码 60 秒内只能获取一次）；强制开启时第一次登录会引导你绑定；**没有备用码**，验证器丢失请联系管理员“重置 2FA”；
4. 登录页可勾选“记住账号”（只记在本机浏览器里，且只记用户名）、点“显示”看 / 隐藏密码，“忘记密码？”里有找回方式的说明（域账号到公司统一身份平台找回、本地账号联系管理员重置、单点登录账号无需密码）；右上角可切换界面主题（明亮 / 深空 / 护眼，左侧介绍区一起换色）和语言；左上角“元数据库 OK”是登录前的状态提示（读 `/readyz`，连不上或探测失败时显示“异常”）；页面底部的备案号来自配置文件 `[site]` 的 `icp`，没配就不显示；
5. 管理员用“系统生成临时密码”重置过你的密码时，登录后会被带到「修改密码」页，改完才能继续使用；
6. 修改密码页是 `/account/password`（仅本地账号，新密码按密码策略校验，默认至少 9 位）；若管理员开放了“允许用户自行绑定 / 解绑外部账号”，可在 `/account/bindings` 绑定或解绑钉钉 / 飞书 / OIDC 等账号；
7. 管理员可能开启了页面水印（内容与样式由管理员统一定义，默认是你的姓名、账号和时间），用于截图溯源，你不能自行关闭或修改。

更完整的说明见帮助章节“登录、两步验证与账号安全”。

### 4.2 首页与菜单

登录后默认进入**首页**（工作台）：页头有问候、日期和「提交 SQL 工单」；4 张 KPI（待我审批、进行中工单（我的 / 全部）、性能工单待办、我可见的实例——下面一行是这些实例各自最近一次巡检里有告警 / 巡检失败的个数，不是实例当前的连通状态；有告警或失败时点击打开巡检列表，只看每个实例最近一次的报告，否则打开实例列表）和 3 张数量卡（待审核的 SQL 工单 = 可见范围内等待审批、可执行的 SQL 工单 = 审核通过等待执行、待处理的权限申请 = 审批中的查询权限申请）；「我的待办」页签（待我审批（含 SQL 上线、查询权限、数据归档）/ 我提交的 / 性能工单，点一行进详情，“待我审批”最多列 8 行（SQL 上线与查询权限只检查最新 100 张等待审批的单据）；标题旁的数字是待我审批 + 性能工单待办的合计）、最近的工单与申请、近 7 日 SQL 工单柱图（可见范围内全部）、实例健康（最多列 9 个你可见的实例，取最近一次性能巡检的结果，不现场连库，灰点表示没有巡检权限或还没有巡检过；按生产对待的环境带红色环境标记）、最近动态（有审计权限看全平台，否则只看自己）、平台状态（goInception、通知渠道、定时调度器；权限还没迁移时，超级用户还会看到一项“按钮权限迁移”提醒）、快捷入口（按你的权限显示）；没有权限或服务未启用的块不显示。

左侧是导航栏，按你的权限显示，各分组默认全部折叠，只展开当前页所在的分组；点开一组时其余自动折叠（不记忆），窄屏下点左上角 ☰ 打开：

| 分组 | 内容 |
|---|---|
| 变更发布 | 变更工单（SQL 上线）、SQL 体检 |
| 数据服务 | 在线查询、数据导出、数据归档、分区维护、权限申请、授权清单 |
| 性能优化 | 智能调优、慢日志检索、慢 SQL 洞察 |
| 性能治理 | 问题工单、团队榜单，以及管理员用的采集 / 团队 / SLA 配置 |
| 实例运维 | 实例列表、会话诊断、数据库、帐号维护、参数管理、日志解析、性能巡检 |
| 访问控制 | 用户、权限组、资源组、登录认证、安全策略（仅管理员） |
| 安全合规 | 审批流程、数据脱敏、SQL 防火墙、Redis 规则、审计日志（仅管理员；审计日志可授予权限） |
| 平台设置 | 环境设置、通知渠道、值班表、审核引擎（goInception）、系统配置（仅管理员；值班表的管理按钮可以单独授权，见 8.1） |
| 帮助中心 | 使用文档（所有登录用户可见） |

**顶栏的值班信息**：顶栏时钟的左边显示当前值班的 DBA，如“● 值班 张三 08:00–19:00”（所有登录用户可见，不需要权限）。点开能看到当前值班人的联系方式（没填联系方式时显示邮箱）、本班还剩多久、今日排班的 24 小时时间条与明细、下一次交班（如“19:00 交班给 李四”）；有权限的人还有“管理值班表”入口。当前时段没有人值班时显示灰色的“值班 暂无”；窗口较窄时只显示姓名，手机宽度只显示“值班”。没有排好任何班次（值班表页面还没有启用的班次）时顶栏不显示这一块。页面开着不用刷新，到交班时刻、过零点会自己更新（这些自动刷新不算操作，不会延长登录有效期）。时间按服务器所在的时区，浮层里有标注。

**待办角标**：「变更工单」「权限申请」「数据归档」条目右侧的数字是等你审批的单子数（分组折叠时合计显示在分组标题上），「性能治理」分组上的数字是你的待办数（有超时的变橙色）。数字有十几秒缓存，处理完单子后可能稍晚才消失。

**使用文档与个人菜单**：顶栏的「? 使用文档」会打开当前页面对应的文档章节（站内文档，左侧目录、章内全文搜索，章节间链接形如 `/help#help/章节`）；点右上角头像打开个人菜单：个人信息与权限（账号、部门、权限组、资源组、可见实例数，以及你拥有的全部按钮权限，含单独授权 / 单独禁用）、修改密码、两步验证状态、使用手册、界面主题（深空 / 明亮 / 护眼）、退出登录。

**你能看到哪些实例**：只有你所在**资源组**关联的实例（有“查询所有实例”权限的除外）；已被 DBA 停用的实例不再出现；实例可以不绑定资源组，此时普通用户暂时看不到它。**没有权限的按钮默认隐藏**，管理员可改为置灰，悬停会提示需要什么权限。

## 5. 开发与测试人员

### 5.1 在线查询

菜单：数据服务 › 在线查询。需要 `query.view`、`query.run` 和对涉及库表的查询权限。

1. 左上选**实例**和**库**（也可用 `/query?inst=<实例ID或实例名>&db=<库>` 直接预选）；旁边的徽标标出实例的环境（以实例管理里为该实例设置的环境为准，没设置时由实例标签推断生产 / 测试，仅作提示，不参与权限；按生产对待的环境显示红色徽标和页面顶部色条）和主从角色。左侧树显示库里的表和视图（◈ 为视图）及估算行数；名字显示不全时拖动左栏右边缘调整宽度（双击恢复默认，宽度记在浏览器里）；搜索框只按表名过滤（不匹配注释和字段名）。点表名生成展开字段的 SELECT（不用 `*`）；点 ▸ 展开字段（类型、🔑 主键、🛡 敏感字段），点字段名插入编辑器；右键表名打开「对象信息」（5.7）；🔒 表示你没有该表的查询权限（点它直接给出“去申请”），🛡 + 数字表示表里有敏感字段，查询结果中脱敏显示；
2. 在编辑器写 SQL，点“运行”（或 `Ctrl + Enter`）：有选中文本只运行选中部分，否则运行光标所在的语句。结果在下方表格，显示实际返回行数、耗时；超出行数上限时会被截断并提示；
3. 可以开多个标签页分别写 SQL，每个标签各自保存自己的结果和执行计划（SQL 保存在浏览器本地，关闭写有 SQL 的标签会先确认）。工具栏有**格式化**和**示例 SQL**（按当前库的第一张表生成，含正常查询、规则示例和会被拦截的反例，选中后放进编辑器，编辑器非空时放进新标签）；
4. 工具栏下方的提示条只在出了问题、需要你处理时才显示：权限 14 天内到期、其余表无权限（去申请）、在当前库暂无查询权限、脱敏开关没开但库里有敏感字段（Redis 不脱敏）；没有这些就整条隐藏。正常状态的说明（管理员 / 资源组或授权的权限范围与行数上限、到期日、脱敏已开启、是否禁止 `SELECT *`、超时秒数、只读语句范围）都放在鼠标停在“运行”按钮上的提示里；
5. **执行计划**在“结果 / 执行计划”页签里查看，type 按风险着色，并提示全表扫描、函数使索引失效、filesort、前导 `%`、深分页等问题。结果被截断时会估算总行数，并给出“去提交数据导出工单”的链接；敏感列的表头和值用绿色显示（悬停表头可看字段类型）。

**查询规则**（普通用户更严格）：

- 只能执行查询类语句（SELECT、WITH（CTE，主语句必须是 SELECT）、结构类 SHOW、DESC / DESCRIBE、EXPLAIN）；`EXPLAIN ANALYZE` 会真实执行语句，被拦截；不能查 `mysql` 系统库；不能用 `sleep()`、`load_file()` 等函数；不能加锁读与写文件；可能禁止 `SELECT *`（管理员设置）；
- 没带 LIMIT 时系统自动加上；返回行数上限取你在该库表上的**查询权限**里的限制（也受工具栏“返回行数”约束），无表的 SELECT 上限 100 行；
- 有超时时间（默认 60 秒）：查询前设置会话变量 `max_execution_time`（MySQL 5.7.8+，仅对 SELECT 生效），超时或取消时发 `KILL QUERY`；运行中点“取消”同样会终止数据库端的语句；
- MySQL 系查询在服务端只读会话里执行，会写数据的存储函数被数据库拒绝并记为“被拦截”；
- 命中 SQL 防火墙“要求填写原因”规则的语句，运行前弹窗要求写原因（4–200 字），原因随语句进入审计；
- 敏感列（手机号、证件号等）会按脱敏规则显示为脱敏后的值；管理员同样被脱敏。脱敏总开关默认**关闭**，由管理员开启（8.3）。

**运行全部（一条语句一个结果页签）**：脚本里有好几条语句时，点工具栏的“运行全部”（或 `Ctrl + Shift + Enter`），每条语句各占一个结果页签，另有“汇总”页签列出每条的状态、行数、耗时；选中了文本就只运行选区碰到的那几条。一次最多 20 条；每条语句各自做库表权限、SQL 防火墙、脱敏、行数限制并各记一条审计日志。默认依次执行、遇到错误就停（后面标“未执行”），可在“批量选项”里改成继续执行，或同时执行（最多 3 条）。页签上的 📌 固定后下一次运行不会替换它；编辑器行号槽里的状态圆点点一下跳到对应页签。“运行”按钮的行为不变；Redis、MongoDB 没有这个功能。详见帮助页“在线查询”。

**SET 打头的脚本（MySQL 系）**：开头写 `SET @变量 := 值;`（值可以是常量，也可以是只读子查询）或 `SET block_encryption_mode = 'aes-256-cbc';` 这几个会话参数，后面的查询就能引用 `@变量`。**选中整份脚本再运行**，会在同一个会话里按顺序全部执行，显示**最后一条查询**的结果（前面的查询通常是“校验”：子查询返回多行就报错中断）；不选中、把光标放在某条语句上运行时，只运行这条，脚本开头的 `SET` 会自动一起执行。脚本里只要有一条是写语句、其它 `SET`、`INTO` 等，整份都不会执行，错误里会指出是第几条。上限：`SET` 最多 20 条、总长 8000 字符，脚本语句不超过 40 条，其中查询不超过 10 条。没有 `SET` 打头的多条语句仍然只执行第 1 条。变量里存的敏感列同样会脱敏，子查询涉及的表同样要有查询权限。

**SQL Server**：同样可查（只读 SELECT / WITH，可用 `DECLARE @变量` / `SET @变量` 打头、最后 SELECT 输出结果的批处理，批处理里可以用 `DECLARE @t TABLE (…)` 加 `INSERT INTO @t` 把中间结果攒进表变量再统计（只能写这种表变量，写表、`#临时表` 仍然拒绝；表变量带出的敏感字段同样脱敏），行数上限用 `TOP n` 改写，权限按库授予，暂无执行计划），结果有单元格 4 MiB、整个结果 32 MiB 的字节上限（系统配置可调）。

**我的 SQL**：工具栏的“我的 SQL”按钮打开右侧面板，有“收藏”和“执行历史”两个标签。**收藏**是你自己的常用 SQL（点“添加”收藏编辑器里选中的语句，可写注释；双击 SQL 粘贴到编辑器；每人最多 500 条，别人看不到）。**执行历史**列出**你自己**执行过的 SQL，可按语句模糊搜索（空格分隔多个关键词，需全部包含；`%`、`_` 按字面匹配）、按实例、日期和状态过滤，可粘贴、放到新标签、收藏或复制。超级用户在执行历史里能看到**所有人**的记录，并能按用户（用户名或姓名的一部分）和语句模糊过滤，看到“谁、什么时间、在哪个库、执行了什么”。除成功的查询外，也记录**被拦截、失败、超时、已取消**的语句和原因，可按状态过滤（需先执行 `deploy/sql/050_query_reject.sql`，没执行时只有成功记录）；被拦截的语句同时进入系统审计的“被拒绝语句”。收藏需要先执行 `deploy/sql/250_query_favorite.sql`。

**结果表格**：鼠标移到单元格出现工具条可复制；双击单元格预览完整内容（最多前 500,000 个字符）；列名后的复制图标可复制列值、列名和列值、或复制为 IN 列表（去重并跳过 NULL）；结果栏的“复制”复制整个结果（制表符分隔）。

**Redis 实例**：选到 Redis 实例时改为“命令模式”——库是 db 编号（下拉显示 `db0 (键数)`），编辑器是纯文本，没有格式化 / 执行计划；左侧是“key 浏览”（输入匹配模式回车，用 SCAN 分页列出 key 和类型，点 key 自动生成读取命令）；一次只能运行一条命令（选中文本或光标所在行）。只允许固定的只读命令（`GET` / `HGETALL` / `LRANGE` / `SCAN` / `ZRANGE` … 共 60 个），`KEYS`、写命令、阻塞命令、`EVAL`、`CONFIG` / `INFO` / `CLIENT`、`SELECT`、`AUTH` 等一律拒绝并说明原因；`SCAN` 的 COUNT（缺省 100、最多 1000）、`LRANGE` / `ZRANGE` 等区间（单次最多 1000）有上限（超出自动收窄并提示），`MGET` 等多键命令最多 500 个键，`HGETALL` / `SMEMBERS` 遇到超过 5000 个元素的大 key 会被拒绝，请改用 `HSCAN` / `SSCAN`。权限只有**库级**（申请时选库 db 编号，不能选表）。**Redis 查询结果不做脱敏**，请勿查看敏感数据；每人同时最多 3 条 Redis 命令。

**PostgreSQL / MongoDB / ClickHouse 实例**：编辑器模式、示例语句、左侧对象树按类型切换，没有格式化 / 执行计划页签（PG / ClickHouse 的 `EXPLAIN` 当普通语句运行），一次只能运行一条语句。PostgreSQL 的库 = database、表 = `schema.table`（树按 schema 分组，点表名生成带 schema 的 `select … limit 100`）；MongoDB 的库 = database、表 = 集合（点集合名生成 `db.集合.find({}).limit(10)`，字段来自前 100 个文档采样，语句取选中文本或整个编辑器内容）；ClickHouse 的库 = database、表 = 表 / 视图 / 字典。只读规则与拒绝清单见 PostgreSQL / MongoDB / ClickHouse 引擎文档，被拒绝时错误条里直接显示原因；权限**库级与表级都可申请**（PG 表名写 `schema.table`，库名表名区分大小写）；查询结果按“安全合规 › 数据脱敏”的配置脱敏，`warnings` / `notices` 逐条显示；每人同时最多 3 条这类查询（三种类型共用计数）。ClickHouse 如果目标账号的 profile 是 `readonly=1`，服务端会拒绝请求里的设置（错误码 164），需要 DBA 改为 `readonly=2`。

### 5.2 查询权限：申请与查看

- **权限申请**：选择实例、资源组（决定走哪条审批流）、库 / 表、有效期（不早于今天，默认 30 天后）、行数上限（1–1000000），写**申请理由**（必填，5–500 字，说明用途和数据范围，便于审批人判断；标题可不填，系统自动生成）并提交；系统按所在资源组的**审批流**逐级审批，任何一级驳回即终止。Redis 实例只能申请库（db 编号）级权限；PostgreSQL 表权限写 `schema.表`，PostgreSQL / MongoDB / ClickHouse 的库名、表名区分大小写。列表有「我的申请 / 待我审批 / 全部」页签和状态筛选，显示审批进度（第几级、哪一级在审），申请人可在列表行内撤回；审批通过的申请在权限到期后显示为「已过期」。详情页有各级审批人 / 时间 / 意见的时间线、申请人部门、已授予权限的链接；被驳回、已撤回或已过期的申请可一键「重新申请」（预填原内容）。审批通过后自动授予权限。提交、审批通过、驳回、撤销每一步都会写一条系统审计（动作名“查询权限申请-…”）。提交时所选实例必须属于所选资源组；与自己待审批申请的库 / 表有重叠时会提示重复。（申请理由、授予来源需要先执行 `deploy/sql/040_query_apply_ext.sql`、`041_query_priv_ext.sql`；没执行时不要求填理由，其余功能照常。）
- **查询权限**：查看已授予的权限（没有管理权限的人只看到自己的），顶部有「有效 / 7 天内到期 / 已过期（保留记录，不再生效）/ 涉及用户」统计卡，可按用户、实例、库、状态筛选；在线查询的行数上限取涉及各表权限的最小值；状态列区分「有效 / 即将到期 / 已过期」并显示剩余天数，7 天内到期整行高亮，**授予来源**列显示申请单号或「管理员直接授予」。
- 审批人会收到机器人通知（钉钉 / 企业微信 / 飞书 / Lark / Slack / Telegram），点链接直接进入详情。

### 5.3 提交 SQL 上线工单

菜单：变更发布 › 变更工单。需要 `sqlworkflow.submit`，目标实例带 `can_write` 标签。

**提交**：点“提交工单”→ 选资源组（决定走哪条审批流）、实例、库 → 在编辑器写变更 SQL（多条语句用分号分隔，≤ 200 万字符）→ 点**检查**（或按 Ctrl+Enter；SQL、实例、库任一项变化后检查结果作废，需重新检查）。检查由 goInception 完成（未配置时降级为较弱的本地检查），每条语句给出通过 / 警告 / 错误和建议。有错误不能提交；填写工单名称（≤ 50 字）、选择是否备份（生成回滚语句）、可选的“可执行时间窗口”，然后提交。工单进入该资源组的审批流（如 组长 → DBA）。

**工单状态**：等待审批 → 审核通过 → （定时执行 / 排队中 / 执行中）→ 已正常结束 / 执行有异常；也可能是“人工终止流程”“自动审批不通过”。

**检查规则**：禁止 `SELECT`（请用在线查询）；`DELETE` 归为 DDL；批次里只要有一条 DDL 就按 DDL 工单处理；资源组名带 DDL / DML 字样时语句类型必须一致；管理员开启 DDL / DML 分离（`review.ddl_dml_separation`，默认关闭）后同一工单不能混合；命中高危正则（`review.critical_ddl_regex`）的语句被驳回。提交时服务端会重新检查一次。SQL 防火墙规则（8.4）同样参与检查：拒绝类规则让该语句标错误（阶段状态“驳回高危SQL（防火墙）”），仅告警类规则标警告（“SQL 防火墙提示”，不会触发“警告就驳回”）；审批通过后执行前还会再复核一次，只认拒绝，被拒绝的工单进入“执行有异常”并写明规则，一条语句也不会执行。

**Redis 工单（命令 + 管理员规则）**：选到 Redis 实例时，提交页变成“命令模式”——库选 `db0…`，输入框里**每行一条命令**（写法同 redis-cli，一次最多 200 条），点“检查命令”逐行得到 通过 / 警告 / 拒绝；**只要有一行被拒绝就不能提交**。一条命令必须同时命中管理员（超级用户，“安全合规 › Redis 规则”）定义的某条启用规则的 命令名、键模式、适用范围且键数不超上限才允许，没有规则就全部拒绝；`FLUSHALL / CONFIG / EVAL / KEYS …` 等硬禁止命令和所有无键命令任何规则都放行不了。审批流、通知、定时、手工执行与其他工单一样；执行时按当时的规则整单复检（审批期间规则被改，以现在的为准），再逐条执行，**遇错即停，没有自动回滚**（规则勾选“记录执行前值”时，原值会明文记录在执行结果里供人工恢复）。请勿在命令里写入密码等敏感信息，命令原文会保存在工单里。

**建表工单（PolarDB-X / SelectDB / Doris / ADB）**：语句全部是 `CREATE TABLE` 时不走 goInception——检查只做语法检查（括号 / 引号成对、表名、列定义、`LIKE` / `AS SELECT`；不连目标实例，不校验库表是否已存在，认得各家的 `ENGINE=OLAP`、`DISTRIBUTED BY`、`PROPERTIES`、`DBPARTITION BY` 等选项），执行只有原生方式（不备份、无自动回滚，不受“强制使用 goInception”限制），仍走审批、不会自动通过；混有其它语句的工单照旧。

**批量上线**：提交页的“批量提交”开关一直显示在工单名称右边的选项框里，把“目标实例”选成管理员允许批量的类型（默认只有 SQL Server，由 `BATCH_DB_TYPES` 控制）后才能勾选，其它类型置灰，鼠标放上去提示“仅支持 MSSQL”（没有 `sqlworkflow.submit_batch` 时提示“没有批量提交的权限”）；数据导出的提交页仍是选成这类实例后才出现“批量导出”开关。打开批量后页面上其它字段的位置不变，“目标实例”只用来判断能不能批量，提交哪些实例以勾选的为准；把它换成不支持批量的类型，批量会自动关闭并置灰。勾选后在“选择要上线的实例”里选多个实例（标题、搜索框、全选、清空和已选数量排在一行，屏幕够宽时放在日期右边的空位，不够宽时占下面一整行；实例列表在它下面单独占一整行，左右边缘和上面的字段对齐；最多 100 个；搜索框输入即筛选，“全选”只选搜索结果；库列表与语法检查取第一个勾选的实例，另会预检每个实例能否连接、库是否存在），系统逐实例检查并执行；个别实例失败时可对失败实例**重试**（重新执行整段 SQL）或**关闭**（不再计入成败），其余不受影响。需要 `sqlworkflow.submit_batch`。

**列表与详情**：

- 列表顶部是各状态的数量卡片（点击筛选）和页签“全部 / 我提交的 / 待我审批 / 待我执行”（带数量）；可按状态、实例、资源组、种类筛选，搜索工单号（可带 `#`）/ 名称 / 提交人 / 库 / 实例，点列标题排序。列表里能看到资源组、当前审批级（轮到你审批的会标出）和 OSC / 定时 / 跳过检查标签；
- 提交页会按所选资源组在页头标题旁**预览审批流**，逐级只显示审批组（如“第 1 级 · DBA”），鼠标放上去显示这一级可审批的人员，某一级没有人能审批会标红，页头下面同时给出整行提示，提交前就能发现；
- 已结束 / 已终止的工单详情页有**复制为新工单**：带出名称、实例、库和 SQL，到提交页修改后重新提交；
- 详情页有**审批时间线**（已审批的级别显示审批人、时间、意见；某一级没人能审批会标红“无人可审”）；批量实例表显示地址、说明、耗时、数据库版本（页面加载后逐个实例异步取，取不到显示“未知”）；执行中有**进度条**（批量按实例计数，在线改表自动轮询进度）；定时执行的工单可以**取消定时**（回到“审核通过”）；结果表每一列都有定义好的宽度，内容超出列宽的（实例名、阶段、信息、SQL 等）默认折叠成一行，点 ▸ 在同一列宽里展开，列头旁的 ▸ 展开整列，标题旁的“展开全部”管所有列；汇总行的信息整句显示。

**终止**（必须写原因，≤ 500 字）：提交人可在审批阶段撤回，审批人可驳回；工单审核通过后提交人或有执行权限的人可终止，非提交人还需要 `sqlworkflow.reject`。排队中 / 执行中的工单不能终止；执行时间太长时，DBA / 超级用户可在进度卡片里填原因点「取消执行」（见 7.1）。

### 5.4 数据导出

菜单：数据服务 › 数据导出。需要 `export.submit`，目标实例带 `can_read` 标签；下载需要 `export.download`。

1. 选资源组（决定走哪条审批流，页头标题旁的步骤条预览各级审批组，用法同 SQL 上线提交页）、实例、库，写**一条**只读查询（SELECT / WITH；SQL Server 还可以是 `DECLARE @` / `SET @` 打头的只读批处理，批处理里可用 `DECLARE @t TABLE (…)` 加 `INSERT INTO @t` 攒中间结果，最后用 SELECT 输出，批处理无法预先统计行数，检查时只给警告，超过上限在执行时中止；可按 Ctrl+Enter 检查）。系统会先统计行数，超过上限（默认 10000 行，`export.max_rows`）就不允许提交；导出文件按审批通过后执行时的实时数据生成，并按“安全合规 › 数据脱敏”的配置脱敏（需要脱敏总开关 `query.mask_enabled` 已开启，且导出脱敏开关 `export.mask_enabled` 没有关闭，后者默认开启；脱敏失败会中止导出，不产出原值）；PolarDB-X / SelectDB / Doris / ClickHouse 按列名保守匹配；
2. 选格式：CSV / XLSX / JSON / XML / SQL（insert 语句），提交后走审批流；**超级用户**还可以勾选“导出原值（不脱敏）”（提交页上单独的一块卡片，勾选先过高危确认；必须写理由，5–200 字，理由框下方显示字数、够 5 个字变绿，审批人在工单里看得到；只有这次导出本来会脱敏时才出现；SQL 防火墙强制脱敏的列仍会脱敏），普通用户没有这个选项；
3. 审批通过后立即或定时执行，结果打包成 zip；单次查询有超时上限（默认 60 秒，`export.max_seconds`）；检查行数或导出时遇到连接超时、读取超时、连接被拒、连接被中断这类网络错误，信息里先写原因和下一步，最后附“原始错误：…”供 DBA 排查（见 12），其它错误（语法错误、表不存在等）原样显示；
4. 在工单详情点**下载**（需要下载权限；每次下载都会写审计日志）；
5. 支持多实例批量导出（目标实例选成管理员允许批量的类型后才出现“批量导出”开关；默认每个实例一个文件，失败的实例可单独重试，重试成功的文件会合并进同一个压缩包）。实例太多、不想要一堆文件时，提交时勾选**“合并成一个文件”**：各实例导出的数据按勾选顺序依次写进同一个文件（不加实例名称列、表头只有一份），所以各实例返回的列必须一致，检查时就会逐个核对，不一致的实例标红；Excel 格式合并后不能超过 1,048,575 行；重试失败实例时新数据追加到文件末尾。需要区分来源时，在查询里自己加一列（如 MySQL 的 `@@hostname`、SQL Server 的 `@@SERVERNAME`）；
6. **导出工单列表**：状态卡片（待审批、待导出 = 审核通过 + 定时导出、导出中、已完成、导出异常、已终止）、普通 / 批量页签、“只看待我审批”，显示导出行数与资源组；能看到哪些工单取决于 `export.view`（单实例）/ `export.view_batch`（批量）；
7. 提交时可以填**定时导出时间**：审批全部通过后自动转为定时执行，到点由系统导出（到点仍在审批则作废）；定时期间可在详情页取消；
8. 详情页“基本信息”里的**导出文件**一行给出文件名和下载按钮，文件被清理后写明清理时间并隐藏按钮；导出过程中有进度条，导出太久时 DBA / 超级用户可在进度卡片里填取消原因点「取消执行」（见 7.1）。

文件存本地目录（环境变量 `EXPORT_BASE_DIR` + 系统配置 `export.local_path`），sftp / S3 / Azure 暂不支持。

### 5.5 SQL 分析与优化

- **SQL 分析**（变更发布 › SQL 体检，`menu_sqlanalyze`，执行分析另需 `sql_analyze`）：上传 `.sql` 文件、MyBatis3 Mapper XML 或 MySQL 慢日志文本（≤5MB、≤1000 条），选实例（仅 MySQL 系，可不选，不选只做静态规则分析）后逐条分析：SQL 指纹、内置规则建议、执行计划解读、索引建议；配置了 SOAR 时附上 SOAR 报告。上传的内容只在内存里处理，不会保存。后台执行，页面显示进度，可取消，结果只保留约 30 分钟（服务重启即丢失，到期后需重新分析），每人最多同时有 2 个进行中的任务；逐条结果显示评分、指纹 ID、涉及的表，汇总显示平均评分、语句类型分布和各建议级别的语句数；页面底部的「最近报告」列出还在保留期内的任务，可随时切换查看（普通用户只能看自己的，超级用户可看所有人的）。
- **智能调优**（性能优化 › 智能调优，`menu_sqladvisor`）：粘贴一条 SQL（一次只分析一条：有选中文本分析选中部分，否则分析光标所在语句），选实例和库，可用：执行计划（含 JSON 格式）、内置建议、SQLTuning（对 SELECT 采集表结构 / 统计 / 索引、系统参数并做 PROFILE，PROFILE 会真实执行该查询）、SOAR、SQL 美化。MySQL / PolarDB / PolarDB-X 可用全部方式，SelectDB / Doris / ADB 只提供执行计划，Oracle 的 SQL Tuning Advisor 暂不支持。SOAR 是外部程序，程序路径、配置文件与测试环境（`optimizer.soar_*`）由超级用户在“平台设置 › 系统配置 › SQL 优化工具”里设置（保存时会核对程序文件与测试库，见该处说明），没配置时会提示“未配置”（超级用户的提示旁有“去配置”链接），不影响其它功能。内置建议的报告里除了建议和索引 DDL，还会列出相关表的**现有索引**（标出冗余的前缀索引，建议低峰删除）和**建索引前后的执行计划对比**（“后”是按统计信息推导的估算，建好索引后请再 EXPLAIN 确认）。SQLTuning 另需 `optimize_sqltuning`，SOAR 另需 `optimize_soar`。
- 所有分析都是只读的，不会修改目标库的数据或结构。

### 5.6 慢日志

- **慢日志检索**（性能优化 › 慢日志检索，`slowlogs.view`）：按实例 × 库 × SQL 指纹 × 天聚合，选日期范围和搜索；点“详细”看当天最近 100 条，点行展开当天最近一条的代表 SQL。数据来自平台采集器（MySQL / PolarDB 读 `mysql.slow_log`，Doris / SelectDB 读审计日志），页面底部可展开“采集器状态”。页面顶部有总次数、指纹数、累计耗时、最慢单条四张统计卡和每日折线图；可按实例、库筛选，搜索同时匹配 SQL、库名和用户；“详细”抽屉顶部是摘要卡片，并可一键跳到优化工具。
- **慢 SQL 洞察**（性能优化 › 慢 SQL 洞察，`slowquery.view`）：“统计”页签按指纹聚合（次数、总耗时、扫描行数……），行展开看 SQL 和趋势图；“明细”页签看单条记录（先点选一条再“获取优化建议”；汇总模式没有明细）。页签栏右侧的“当前数据源”标明这次实际用的是 digest 库还是平台采集（digest 表为空时自动回退到平台采集）。统计页顶部有指纹数 / 总次数 / 总耗时 / 最慢一次四张卡片；实例下拉第一项“全部实例（汇总）”可把你可见的所有实例放在一起看；“耗时 ≥ N 秒”按平均耗时（统计）或单次耗时（明细）过滤。优化建议弹窗里有综合评分、锁等待与连接列索引提示和推测的候选索引 DDL（仅供参考）。
- 数据来自采集器；**慢日志采集默认开启**（只读，只采实例上“慢日志采集”开关打开的实例；环境变量 `SLOWLOG_COLLECT_ENABLE=0` 可整体关闭）。查询时间范围最长 93 天。两个页面只显示你所在资源组关联的实例；“获取优化建议”另需 `menu_sqladvisor` / `optimize_soar` / `optimize_sqltuning` 中任意一个。
- **Redis 慢查询**：在“慢 SQL 洞察”里选 Redis 实例，页面换成 Redis 面板：命令统计（按命令指纹聚合，含次数 / 总耗时 / 最大 / 平均耗时、首 / 末次时间、每日小趋势）、慢命令明细（客户端地址、时间、耗时、完整命令）、采集状态；可按命令名、耗时下限、时间范围筛选。数据来自定时 `SLOWLOG GET` 采集（“立即采集”对当前实例立刻执行一次并入库；Redis 慢查询的表需先执行 `deploy/sql/130_redis_slowlog.sql`）。“重置慢日志”是高危操作（`SLOWLOG RESET`，需要单独授权 `redis.slowlog_reset`，先采集入库再清空，输入实例名确认并写审计）。完整命令里可能含业务数据，请只授权给需要的人。

### 5.7 库表对象信息

原来独立的“数据字典”页面已经去掉，查看表结构、定义语句改在**在线查询**里：

- 左侧「表」页签里**右键表名**（视图同理）→「对象信息」：基本信息（数据库、表名、估算行数、数据 / 索引大小、引擎、字符集、说明等）、列信息、索引信息和**创建语句**，右上角可复制；
- 左侧「可编程对象」页签（MySQL 系、SQL Server）：按类别列出视图、函数、存储过程、触发器、定时任务，组标题上是数量，**双击**（或选中后按 `Enter`）查看定义，内容只读，右上角可复制；搜索框只按对象名过滤；某一类读取失败时原因显示在该类别下，不影响其它类别；
- 点表名左侧的 ▸ 展开字段（类型、🔑 主键、🛡 敏感字段），点字段名插入编辑器；
- 需要按钮权限 `query.objinfo`（在权限组的“按钮权限”页签里勾选），范围与库表树一致（能访问该实例、库名在允许范围内、不是系统库）；不检查表的查询权限。MySQL 系实例读详情时，`information_schema` 缺列（如 PolarDB-X）会退到基础列，各小节读取失败只在该小节写原因。

### 5.8 性能工单（研发侧）

菜单：性能工单。系统从慢查询等来源**自动建单**，按影响程度定级 P0–P3，并按 SLA 跟踪。

**问题工单**：顶部 6 张统计卡（我的待办、已超时 = SLA 计时中且已过解决截止、待分派 = 还没有负责人、待验证 = 等待 DBA 验证、本周新增 / 本周完成）；页签（我的待办 / 全部未关闭 / 待分派 / 待受理 / 处理中 / 待验证 / 审批中 / 已超时 / 已关闭 / 全部，带数量）；可按级别、团队、处理方、类型、状态、来源筛选；超时高亮；侧栏“性能工单”分组标题上的角标是你的待办数（红色表示有已超时的）。

**状态**：待分派 → 待受理 → 处理中 → 待验证 → 已关闭；还有“豁免审批中”。**SLA 只在待分派 / 待受理 / 处理中计时。**

**研发（负责人 / 团队成员）能做**：

- **受理**：填写承诺完成日（不早于今天、不晚于 SLA 解决截止日）；
- **标记修复**：填方案（可同时填关联的 SQL 上线工单号，详情页会给出跳转链接），进入待验证；详情页的“修复效果”卡片和 DBA 的验证弹窗会对比修复前后的平均耗时与日均浪费；
- **申请延期**：填新日期（晚于当前截止日、不超过一年）和理由，有次数限制；
- **申请豁免**：理由至少 10 字；
- **评论**。

系统会在 SLA 临近 / 超时时升级并通知（L1 / L2 / L3），修复后观察几天自动验证，长期未再出现的自动关闭，已关闭的 SQL 再次出现会自动重开。

### 5.9 数据归档与分区维护（申请侧）

- **数据归档**（数据服务 › 数据归档，需要 `archive.view`，新建 `archive.apply`，试运行 `archive.dryrun`）：把表里“过期”的数据按计划搬走或清掉，系统按主键分批、小事务、限速、先做负载自检，**先把数据备份到目标并校验，通过后才删源**。新建任务是六步向导和试运行，提交后走资源组审批流里的“数据归档申请”。详见 7.7。
- **分区维护**（数据服务 › 分区维护，`partman.view`）：研发默认只读；配置与执行由 DBA 操作，见 7.6。

## 6. 组长与审批人

### 6.1 审批 SQL 上线工单

菜单：变更发布 › 变更工单（侧栏角标显示等你审批的数量）；需要 `sqlworkflow.approve` / `sqlworkflow.reject`，并且同时属于当前这一级的权限组和工单所属资源组。

1. 打开详情页，看检查结果（每条语句的通过 / 警告 / 错误、影响行数、建议）、审批时间线和备份设置；
2. 点“通过”（弹确认框，说明当前是不是末级、通过后进入哪一级）或“驳回”（必须写原因）；最后一级通过后工单进入“审核通过”；
3. 拥有 `sqlworkflow.alter_window` 的审批人可修改可执行时间窗口。

规则：不能审批自己提交的工单（默认；超级用户可以自审非导出的 SQL 上线工单）；任何一级驳回即终止；某一级没人能审批会在时间线上标红“无人可审”，此时只有超级用户能审批。自动审核（`review.auto_approve_enabled`，默认关闭）只对 goInception 检查的、类型与标签在范围内、不命中排除正则、影响行数合计不超过上限（默认 50）的工单生效。

### 6.2 审批查询权限申请与数据归档申请

- **查询权限申请**：菜单 数据服务 › 权限申请，页签“待我审批”；需要 `qpriv.review`。在详情页点“通过”或“驳回”（驳回必须写原因）；最后一级通过后**自动授予权限**；**不能审批自己的申请**（超级用户也不能）。
- **数据归档申请**：菜单 数据服务 › 数据归档，“待我审批”；审批人 = 资源组审批流里该级权限组中、属于该资源组的用户；不能审批自己提的申请；驳回必须写原因。
- 在首页“我的待办 › 待我审批”里可以直接看到全部待办，点一行进入详情。

### 6.3 受理本组性能工单

TL 预设可以受理（`perf.handle`）和评论本组性能工单，操作见 5.8。

## 7. DBA

### 7.1 执行与控制 SQL 上线工单

有执行权限的人（资源组内 DBA，或提交人本人且持有 `execute_own`）在详情页操作：

- **立即执行**（`sqlworkflow.execute_group`）：先校验“可执行时间窗口”，同一实例同一库上已有 DDL 在执行时会被拒绝并指出冲突工单（同库 DDL 串行）；
- **定时执行**（`sqlworkflow.schedule`）：选时间，由系统调度器（每 15 秒扫描）到点执行；每张工单只有一条生效的定时计划，到点前可多次修改（详情页的执行卡片带出当前定时时间，改后点「修改定时时间」覆盖旧计划），也可取消定时；
- **手工执行**（`sqlworkflow.manual_finish`）：你在别处执行完后点“确认已结束”，系统不执行任何语句；
- **执行方式**：配置了 goInception 默认走 goInception（逐条结果、支持备份与回滚、在线改表）；没有 goInception 时执行方式由执行人选择（页面标出推荐默认值），`REQUIRE_GOINCEPTION=true` 时禁用原生。执行失败即停，其后的语句标为未执行；
- **回滚语句**（`sqlworkflow.rollback`）：备份了的 goInception 工单结束后可查看 / 下载回滚语句；回滚语句是反向 SQL，执行前请先评估数据是否已被后续业务写入；每次查看 / 下载写审计；
- **在线改表（OSC）**（`sqlworkflow.osc`）：大表 DDL 可用 gh-ost / pt-osc，详情页提供暂停 / 恢复 / 终止；
- **取消执行**（`sqlworkflow.cancel_run`，高危）：执行时间太长时，在进度卡片里填取消原因（必填，≤ 500 字）后点「取消执行」：正在执行的语句被中断，其后的语句不再执行，已成功的语句不会回滚，工单变为“执行有异常”且不会自动重试（批量工单会中断所有正在执行的实例；用 goInception 执行时只断开与 goInception 的连接，已下发的语句可能仍在执行，请到「会话诊断」核对）；数据导出工单的“导出进度”卡片同样可以取消执行；
- **进程失联**：工单一直停在排队中 / 执行中、且确认没有进程在执行时，可在详情页“执行进程失联了？”里填原因标记为执行异常（需要 `sqlworkflow.cancel_own` 或 `sqlworkflow.reject`）；系统也会在服务启动时和之后每 5 分钟自动处理这类工单，标记后不重试，必须到目标库核对；
- **批量实例**：对失败实例“重试”或“关闭”（`sqlworkflow.batch_op`）。

**生产确认**：工单的目标实例在实例管理里被设置为“按生产对待”的环境（批量工单只要有一个这样的实例）时，详情页的立即执行 / 立即导出、定时执行、确认手工执行结束、取消执行、批量实例重试要在确认框里键入工单号才能提交；审批、驳回 / 终止、取消定时等操作不要求。这是页面上的防误操作确认，服务端不校验；没有给实例设置环境（只靠标签标注“生产”）时不会触发。

提交、审批通过、驳回、撤销、立即 / 手工 / 定时执行、取消定时、修改可执行时间、在线改表的暂停 / 恢复 / 终止、批量实例的重试 / 关闭也会各写一条系统审计（动作名“SQL上线-…”）。

### 7.2 管理查询权限

菜单：数据服务 › 授权清单，需要 `qpriv.manage`（高危）。可以修改有效期 / 行数上限、回收，或点「＋ 直接授予」不经审批直接给同资源组的启用用户授予库 / 表权限（必填原因，至少 5 个字，来源记为「管理员直接授予」，写入系统审计，并通知被授予人）。修改 / 回收也会写审计（含目标用户与新旧值）并通知受影响用户；权限来自申请单时，申请单日志里会追加一条权限变更记录。管理范围限定在自己资源组关联的实例内。

### 7.3 实例管理

- **PostgreSQL / MongoDB / ClickHouse 实例**：新建时端口默认 5432 / 27017 / 8123（ClickHouse 走 HTTP 接口，TLS 通常用 8443，需手填）；只支持在线查询，列表里实例名旁标“仅查询”，详情抽屉里有“支持范围”一行，其它功能的入口隐藏或标“暂不支持”，这些页面的实例下拉里也不出现它们。
- **实例列表**（`instance.*`）：按角色、类型、标签、环境、状态（含已停用）筛选；顶部统计条；每行逐行异步显示健康状态、版本、QPS / 连接数（结果缓存 30 秒，单个实例最多等 8 秒，同时最多探测 6 个；连不上或超时显示“未知”，不会拖慢页面；列表里状态只分“正常 / 异常”，连不上、超时、暂不支持探测或连接使用率达到 80% 都算异常，原因悬停查看；“健康”筛选跨页：选了以后读取符合其他条件的全部实例并逐个探测，命中的行边探测边出现，不再分页），点实例名看详情抽屉。页内新建 / 编辑实例（密码加密保存，编辑时留空表示不改；标签、资源组都可以不选，SSH 隧道、环境（来自环境字典，默认生产 / 测试，超级用户可在“平台设置 › 环境设置”增删）、显示 / 隐藏的库（正则，隐藏优先于显示）；标签在“系统管理”的标签管理里新建、启停，这里只勾选，带 `can_read` 的实例会出现在“申请查询权限”“数据导出”的实例列表里，带 `can_write` 的才能提交 SQL 上线工单；保存前会列出改了哪些字段让你确认）、测试连接、启停慢日志采集、删除（被工单 / 权限 / 性能工单 / 数据归档任务等引用时会拒绝并说明数量）。每行行首有勾选框，上方的操作条提供**批量启用 / 批量停用 / 批量开启采集 / 批量关闭采集 / 批量设置环境（环境字典里的环境或未设置）/ 批量删除**：一次最多 100 个，逐个走与单个操作相同的检查和审计；批量删除先检查引用，要键入“删除N个实例”才能确认，被引用的会跳过；已经是目标状态的会被跳过。**停用实例**后平台不再连接它，它也不再出现在在线查询、SQL 上线、巡检、慢日志采集等页面的实例列表里（已有工单、报告、数据保留，可随时启用）。“Binlog 清理”（仅 MySQL）先预览将清理到哪个文件，并列出连着的从库及其读取位置，清理目标越过从库进度会被拒绝，再输入文件名确认。
- **会话诊断**（`session.*`）：进程列表（可筛选，顶部有连接总数 / 活跃 / 长时间运行 / 阻塞源统计，耗时 ≥300 秒标黄、≥1200 秒标红并标“长时间运行”，持有锁让别的事务在等的线程标“阻塞源”，每行可直接“终止”）、Top 表空间（来自 information_schema.tables，MySQL 8.0 统计值默认缓存 24 小时，碎片率 ≥20% 且碎片 ≥1 GB 的行标黄）、事务（来自 innodb_trx，持续 1 分钟以上标黄，点线程号跳到进程列表并选中该会话）、锁等待（只支持 MySQL / PolarDB / PolarDB-X，带阻塞链）；**终止会话**分两步（先预览 `KILL n`，再确认），服务端会重新校验线程仍存在、不是平台自身连接 / 复制线程。
- **数据库**（`database.*`）：库清单（表数 / 大小来自 information_schema.tables，读不到显示“—”；“已录入”指平台里登记了负责人 / 备注的库；系统库不显示，没有删除库的功能）与负责人 / 备注登记；创建数据库（库名字符校验、字符集 / 排序规则下拉、二次确认）。
- **帐号维护**（`account.*`，仅 MySQL / PolarDB / PolarDB-X）：账号列表（高危账号标黄，可只看未录入 / 高危 / 已锁定）、创建、登记使用人 / 用途 / 到期日（只登记在平台旁路表里，不改库里的账号；到期前 7 天标黄、过期标红）、授权 / 回收（先预览语句再执行，语句由服务端按结构化选项生成；可选 ALL PRIVILEGES，属高危会警告）、改密、锁定 / 解锁、删除；高危口径：任意主机 % 且有写 / 结构变更权限，或有 ALL PRIVILEGES / GRANT OPTION，或全局 SUPER / FILE / PROCESS / RELOAD 等；创建账号的密码为 8–32 位且含英文、数字和特殊字符，新账号没有任何权限；`root@localhost`、`root@127.0.0.1`、`root@::1` 等内置账号和平台自己用的账号受保护，不能锁定、删除、改密、授权或回收。
- **参数管理**（`param.*`）：运行值（有推荐值时，偏离的参数标黄，可只看偏离的）、参数模板总览（含推荐值、黑名单 / 需重启标记）、修改参数（动态 `SET GLOBAL`，不会写入配置文件，成功后需手动持久化到 my.cnf；只允许模板里标为可修改的参数，校验取值范围，记录旧值）、修改历史；黑名单参数（能执行语句或改文件路径，如 `init_connect`、`datadir`）永远不能在平台修改，“需重启”标记的参数动态修改会被数据库拒绝。

停用实例、账号的使用人 / 用途 / 到期日、参数推荐值存在平台自己的旁路表里，需要 DBA 先执行 `deploy/sql/070–072` 三个脚本。以上敏感操作都需要二次确认并写入系统审计，密码不会出现在日志里。

### 7.4 Binlog 解析

实例运维 › 日志解析（仅 MySQL）：选实例和起止范围（位置或时间）、库 / 表 / 语句类型过滤，把 binlog 里的变更还原成 SQL，或生成**回滚 SQL**（DELETE 与 INSERT 互换、UPDATE 前后镜像互换，按后发生的先撤销排序；DDL 只提示不可回滚）。平台以复制从库的身份只读读取 binlog，不在目标库执行任何语句，也不影响主从复制；起始位置必须落在事务的开头，否则会报“找不到表映射事件”，不确定时留空并用时间 / 库表缩小范围；列名与主键取自目标库当前的表结构，binlog 之后被改过结构的表以 `@N` 代替列名（回滚会被拒绝）；回滚要求目标实例 `binlog_format=ROW` 且 `binlog_row_image=FULL`，不满足时会说明原因并拒绝（仍可还原 SQL）。解析在后台进行，可看进度、可取消；结果有条数 / 体积 / 超时上限（“最多条数”“结果体积上限”能填的最大值由超级用户在“平台设置 › 系统配置 › 日志解析”设定）。回滚结果必须完整：超限、超时或目标库中途卡住时，结果在事务边界结束成“一段”，页面给出续接位置和“继续下一段”按钮，生成下一段后**按段号从大到小执行（先执行最后一段，最后执行第 1 段）**；连第一个事务都放不下时没法分段，请调大上限或缩小范围。结果保留 30 分钟（服务重启即丢失；较大的结果存在服务所在机器的临时文件里，过期即删除），可分页查看、复制或下载 `.sql`（带事务边界）；结果里可能含有业务敏感数据，下载的文件请妥善保管、用后删除。需要 `binlog.view`（打开页面）、`binlog.parse`（解析）；`binlog.rollback`（回滚）和 `binlog.download`（下载）是高危权限，默认只给超级用户，需在权限组里单独授予；每次解析 / 回滚 / 下载都写系统审计。

### 7.5 性能巡检

实例运维 › 性能巡检：

- **巡检报告**：列表筛选；“立即巡检”选实例（批量、异步，页面轮询状态；已有进行中巡检的实例会被跳过；SQL Server 单实例约 1–5 分钟，MySQL 与 Redis 通常几秒到几十秒）；立即巡检、取消与删除默认仅超级用户（或被显式授予 `inspect.run` / `inspect.cancel` / `inspect.delete`）；列表按开始时间倒序，有进行中的报告时每 5 秒自动刷新；详情页显示总分、同实例的趋势图（最近 30 次已完成的巡检）、各检查项结果和“建议”列。已在实例管理里停用的实例不会被巡检。巡检全程只读。
- **定时巡检**（`inspect.plan_*`）：可建多个计划，每个计划选实例（或按标签动态匹配，新打标签的实例自动加入；只能选自己资源组内且支持巡检的实例；SQL Server 可限定库范围，最多 200 个）、周期（每天 / 每周 / 每月 / cron，两次间隔不少于 5 分钟，按服务器本地时区）、错峰并发（并发 1–10、实例启动间隔、已有进行中巡检时跳过、失败后 5 分钟重试一次、单实例超时）、通知渠道（可选“仅告警时发”）、报告保留天数（默认 90）；实例与标签不能同时为空；支持启停、立即运行、查看运行记录。定时巡检的表需先执行 `deploy/sql/013_inspect.sql`。
- **Redis 巡检**：Redis 实例和 MySQL / SQL Server 在同一个列表、同一套计划里（Redis 报告表需 `deploy/sql/131_redis_inspect.sql`）。检查项覆盖连通与版本、主从复制、内存、持久化、连接数与阻塞、被拒绝的连接、命中率、淘汰、慢日志条数、fork 耗时、是否设置密码 / `protected-mode` / 绑定地址、危险命令是否被改名、键空间与过期键占比；有评分和逐项建议。“大 key 抽样”默认关闭，可在“立即巡检”里勾选（限量 SCAN 抽样最多 1000 个 key，对线上有轻微压力，低峰期使用）。巡检只发 `INFO` / `CONFIG GET` / `SLOWLOG GET` 等只读命令。

### 7.6 分区维护

数据服务 › 分区维护：为按时间 RANGE 分区的表配置“预创建多少个分区、保留多久”，由系统自动续建 / 清理，支持 **MySQL / PolarDB** 与 **SelectDB / Doris** 实例。

- 新增 / 编辑配置时可**预览**将要执行的 `ALTER TABLE … PARTITION` 语句；系统只接受结构化配置，不接受手写 DDL。库名、表名、分区字段可从目标实例直接选择（分区字段只列 datetime / date / int / bigint 并自动带出字段类型，date 字段只能精确到天，分区周期不能是分钟 / 小时，表需按 `RANGE COLUMNS(字段)` 分区）。
- **时区**：留空（跟随目标库会话时区）、填固定偏移（`+08:00`、`UTC+8`、`GMT+08:00`、`+0800`、`+8`，推荐）或 IANA 名字；超过 20 个字符的名字无法保存，有夏令时的区域会提示“换季日边界漂移”（建议改用固定偏移）。
- **预览并执行**：删除旧分区（DROP PARTITION）必须先预览，并输入 `库.表` 确认；执行前服务端会重新读取表并核对，计划有变化会拒绝并给出新计划。
- **初始化为分区表**（仅 MySQL / PolarDB 的未分区表，状态显示“未分区”）：在“预览 / 执行”里选起点（从当前窗口开始：默认，不读取存量数据；从最早数据开始：对目标表执行一次带 20 秒超时的 `SELECT MIN(分区字段)`；指定起始日期：按配置时区对齐到分区网格，不能晚于当前窗口），查看将创建的分区个数与范围、前置检查，再键入 `库.表` 执行。这是一条整表重建的 ALTER（高危，`partman.run`），表越大耗时越长，期间持有元数据锁、可能阻塞写入，请在业务低峰执行并先确认有备份；**定时维护永远不会初始化**。SelectDB / Doris 的表需要事先建为 RANGE 分区表。
- **推送设置**（有 `change_partmanconfig` 权限的用户）：维护执行了语句或失败之后，向钉钉 / 飞书 / 企业微信 / Slack 推送结果；webhook 地址只显示脱敏形式，加签密钥只显示“已设置”；@ 对象填手机号 / userid / open_id 或 `all`，@ 时机可选仅失败时 / 每次 / 从不；全局推送时机由系统配置项 `partition.notify_on`（`always` 默认 / `on_failure` / `never`）决定，推送失败不影响维护结果。
- “维护日志”显示每次执行（手工、定时、历史外部程序）的语句与结果；每条记录可展开**运行输出**（毫秒时间、INFO / WARN / ERROR 级别的检查与决策过程），可筛选、搜索、复制、下载 .log。
- 列表每行有**状态**（正常 / 待续建 N / 待清理 N / 未分区 / 异常 / 未知），读不到目标库显示“未知”而不是报错（结果缓存约 1 分钟）；列表第一列的开关可一键**启用 / 停用**配置。
- **可用分区告警**（需先执行 `deploy/sql/280_partman_alert.sql`）：列表多出“可用分区”（目标表里上界晚于当前时间的分区个数，含当前分区，不含 MAXVALUE，维护正常时为“预创建数 + 1”）和“告警”两列；可用分区数小于阈值（全局默认 3，系统配置 `partition.alert_min_available`；每张表可在“告警设置”里单独设，填 0 = 不告警）就标“告警中”，页顶统计卡显示数量，并按检查间隔（同自动维护间隔，自动维护没开也检查）推送到“推送设置”里启用的通道：首次不足推一次，之后按 `partition.alert_repeat_hours`（默认 24 小时，0 = 不重复）提醒，回到阈值以上推“已恢复”（`partition.alert_notify_recover`）；可静默 24 小时 / 7 天；页头“告警记录”看推送记录。总开关 `partition.alert_enabled`（默认开）。
- 定时自动维护默认关闭（`partition.auto_run`），由管理员开启；自动执行只续建分区，不删除（除非单独开启 `partition.auto_drop`），永远不初始化未分区的表、不执行 REORGANIZE。同一批目标表同一时间只让一个程序维护与推送，否则会重复改分区、同一事件重复通知。

### 7.7 数据归档

数据服务 › 数据归档：把表里“过期”的数据**按计划搬走或清掉**（取代手写的 `pt-archiver` / 定时 `DELETE`）。系统按主键分批、小事务、限速、先做负载自检，**先把数据备份到目标并校验，通过后才删源**；任何一步失败都不会删。只执行三类 SQL（读一批、写目标、删源并重复一遍归档条件；归档并删除 / 仅清理读取时不排序、没有断点，删掉的行不会再被读到，仅备份才按主键翻页），页面上全部可见，没有自由 SQL 入口。页面有四个页签：

- **归档任务**：列表（模式、备份去向、调度、状态、上次 / 下次运行、累计归档行数）、筛选、“待我审批”；运行中的任务行内每 2 秒刷新进度；点名称看详情（配置、将执行的 SQL、审批进度、最近运行、变更历史）。
- **运行记录**：每次运行一行（定时 / 手动 / 恢复 / 试运行），详情有批次吞吐曲线、限流事件、校验结果、备份位置与 sha256、日志；库表备份的运行可“恢复数据”（高危 `archive.restore`，输入任务名确认，按该次的主键范围 `INSERT IGNORE` 回灌，只补缺不覆盖）。
- **备份存储**（`archive.cfg_view` 可看，`archive.store_edit` 仅超级用户可改）：本地目录 / NFS 目录 / S3 兼容（含 MinIO）/ 阿里云 OSS（走其 S3 兼容端点）；AK / SK 加密保存、永不回显；“测试连接”会写入、读取、删除一个探测对象；被任务引用的存储不能删除、不能改类型。
- **安全策略**（`archive.cfg_view` 可看，`archive.policy_edit` 仅超级用户可改）：最小保留天数、默认批量 / 休眠 / 阈值、单次最大行数、每实例并发上限、受保护库表、是否允许不备份清理；固定约束不可调：附加条件 ≤ 500 字、批大小 100–10000、会删除源数据的模式批间休眠 ≥ 50 ms、执行窗口 ≥ 30 分钟、cron 最短间隔 60 分钟、binlog 保持开启。

**新建任务**（`archive.apply`）是六步向导：来源（只能选 MySQL / MariaDB / PolarDB / PolarDB-X 主库；无主键、受保护库表、被外键子表引用的表不允许；同一张表同时只能有一个进行中的任务）→ 条件（时间列 + 保留天数，不得小于策略里的最小保留天数；时间列可以是 date / datetime / timestamp 列，也可以是存着 10 位秒 / 13 位毫秒 Unix 时间戳的 int / bigint 列，后者要选时间单位，系统会抽样核对并显示最早 / 最晚时间；值为 0 / NULL 的行不会被归档；可加不超过 500 字的附加条件，只允许比较 / IN / LIKE / BETWEEN / AND / OR / IS NULL，禁止分号、注释、子查询、函数调用以及危险关键字；所选时间列必须有索引，否则试运行判红）→ 模式与备份（归档并删除 / 仅备份 / 仅清理；备份去向可选归档库表或文件存储（CSV / SQL、可 gzip 压缩与 AES-256-GCM 加密），可同时选；仅清理默认不允许，放开后必须填“不备份理由”，删除后无法恢复）→ 稳定性参数 → 调度（每天 / 每周 / 每月 1–28 日 / cron，最短间隔 1 小时；时间按服务进程所在时区计算；执行窗口至少 30 分钟，缺省 01:00–05:00）→ 试运行并提交。

**试运行**（`archive.dryrun`）只读，不写不删，给出命中行数、占比、预计批数 / 耗时 / binlog 体积、前 10 行样例、将执行的 SQL 和各项检查。红色项不能提交，黄色项需勾选确认，命中超过表的 30% 要额外勾选“已确认大批量”；结果 7 天内有效，来源 / 条件 / 目标任一改动后失效。

**审批**：新建、修改关键字段或放宽参数，都走资源组审批流里的“数据归档申请”，逐级通过后任务自动**已启用**；不能审批自己提的申请，驳回必须写原因；资源组没有配置该审批流就不能提交。只调整调度 / 窗口 / 限速参数且只更保守无需重新审批。

**运行与控制**：立即执行（`archive.run`，高危，可选“忽略执行窗口”）；暂停 / 继续（`archive.pause`）；终止（`archive.stop`，高危）；停用 / 删除任务（`archive.delete`，高危）。稳定性保护：每批前检查负载，超限则暂停并每 30 秒复查，等待过久以“负载中断”结束（不算失败）；批耗时超目标自动降批量加休眠；连续失败、校验失败或源表结构变化会自动暂停任务并通知。同一实例同时最多 2 个归档运行（策略可调）；上一次未结束或源表有未结束的 SQL 上线工单时，本次调度会被跳过并记录。需要先执行 `deploy/sql/180_archive.sql`。

### 7.8 性能工单（DBA）

DBA 能做：指派 / 改团队、验证通过或不通过（不通过要写原因，工单回到处理中）、同意 / 驳回延期与豁免、调级（调级后不再自动调整）、切换处理方、误报关闭（之后同一 SQL 再出现也不会重开）、重开、重新诊断（可粘贴真实 SQL）、手工建单。

**团队榜单**：各团队健康度、近 12 周新增 / 完成趋势、问题类型分布。健康分 = 100 − 超时×15 − 未受理×5 − 日均浪费 DB 小时×10 − (100−按时率)/5，限制在 0–100，从低到高排序；每周一 09:35 后向管理群和各团队群推送周报（由系统配置 `perf.jobs` 里的 `report` 任务发送）。

**配置**（需要 `perfcfg.*` / `perf_manage`）：采集配置（每个实例一条，采集方式共 8 种：平台慢日志、pt-query-digest、performance_schema、mysql.slow_log、Doris audit_log、PolarDB-X statements_summary / SHOW FULL SLOW、自定义 SQL；平均耗时阈值或窗口总耗时阈值任一超过就建单；“试采集”只预览最近一个窗口）、团队配置（团队、负责人、路由规则，分派顺序为路由规则 → 库负责人 → 团队默认接口人，处理方为 DBA 的问题改派给 DBA 值班）、SLA 策略（各级别的响应 / 解决时限与升级，新策略只对之后建立的工单生效）。**后台任务默认全部关闭**，需要在“平台设置 › 系统配置”设置 `perf.jobs`（collect、sla、verify、report）才会运行。级别评估规则（`perf.severity_rules`）任一条件满足即命中。只有“查看配置”权限的人可以看到配置页面，但修改按钮是灰的。

### 8.2 登录认证与登录安全

应用内章节：「登录、两步验证与账号安全」（含各字段取值范围的对照表）。

- **登录认证**页：新增登录方式选类型、填名称（同一类型可添加多个），进入配置后**测试通过才能启用**；配置与入组规则保存即生效，连接参数变更后已启用的登录方式会被自动停用并要求重新测试。LDAP 测试可填测试账号和密码（密码不保存），其他类型先“测试连接”，再点“测试登录（打开授权页）”在新窗口走完整流程，回到弹窗点“刷新结果”；测试登录不会创建用户或建立会话。回调地址为对外地址加 `/login/sso/<id>/callback`，需要在 IdP 里登记。
- **通用规则**：本地账号密码表单显示方式（始终显示 / 折叠 / 隐藏，隐藏时仅 `/login?local=1` 可用）、匹配依据（顺序固定为 第三方 ID → 用户名 → 邮箱 → 手机号；邮箱、手机号只在唯一匹配时采用）、超级用户只能本地登录、外部登录后仍要求两步验证、回填第三方 ID（用于通知 @）、允许用户自行绑定 / 解绑外部账号。首次登录自动创建用户时，默认入组留空则用“登录与安全设置”里的全局默认。
- **安全策略**页（页面范围）：锁定次数 1–100（默认 5）、锁定时间 10–86400 秒（默认 300）、密码最小长度 6–64（默认 9）、会话有效期 5–43200 分钟（默认 300，滑动续期；页面自己定时发的后台请求，如顶栏值班信息的刷新，不算操作、不延长）、JWT 有效期 1–720 小时（默认 4）；API 用户白名单为空表示不限制；水印内容必须含 `{账号}` 或 `{姓名}`（最长 60 字），透明度 3%–30%（默认 14%，建议 10%–18%）、字号 12–28、倾斜角度 -60 到 0；短信验证码 6 位、5 分钟有效、同号码 60 秒限频。“系统配置”里同名项的允许范围更宽（锁定次数 1–1000、锁定时长 1–2592000 秒），两处是同一份数据。
- “无权限按钮”隐藏 / 置灰的设置不在这一页，在“权限组”页顶部。

### 8.3 数据脱敏

应用内章节：「数据脱敏」。

- 流程：选实例和库 → 在左侧选字段（按表 / 按字段名、筛选、“疑似敏感”、粘贴清单；MongoDB 的字段来自采样，缺的路径可手动补充）→ 在右侧选一种规则（保留首尾 / 三段式 / 整体隐藏 / 自定义正则，可试算）→ 选生效范围（所选字段，或该实例所有同名字段）→ 应用（只是暂存）→ 保存并生效（确认变更差异，写系统审计）。
- 同一字段只保留一条规则，新应用的会覆盖原有规则；数值列脱敏后以文本返回；JSON / Map 列对其中所有文本值逐个处理。
- 页面顶部标出所选实例的结果列定位精度（精确 / 保守 / 字段路径）；导出工单是否脱敏需要总开关 `query.mask_enabled` 开启**且**导出脱敏开关 `export.mask_enabled` 没有关闭（默认开启）；超级用户提交导出申请时可以勾选“导出原值（不脱敏）”（必须写理由，审批人在工单里看得到，SQL 防火墙强制脱敏的列仍会脱敏，执行时会复核提交人仍是超级用户）；总开关（`query.mask_enabled`，**默认关闭**）关闭时有横幅提示，总开关可在页面上直接开启（只提供开启）。**只配了字段、没开总开关，查询返回的仍是原值。**
- 脱敏出错时的处置由 `query.block_on_mask_error` 决定：默认（关闭）放行未脱敏的结果并提示，开启后阻断；导出工单脱敏失败一律中止导出。
- 没有表级“免脱敏名单”，所有人（含管理员）一律脱敏。
- 保守匹配（SelectDB / Doris / PolarDB-X / ClickHouse，以及其它引擎拿不到来源的结果列）宁多勿漏：除列名、别名、表达式引用外，调用存储函数 / 自定义函数的结果列（ClickHouse 除外）整列按该实例已配置字段里最严的一条规则脱敏；SQL Server / MySQL 脚本里的变量和 SQL Server 表变量带出的敏感字段同样脱敏；认不出的写法（用列名列表给 CTE / 派生表改列名、`PIVOT` / `UNPIVOT`、`VALUES` 派生表、`STRING_SPLIT` / `OPENJSON` / `JSON_TABLE` / `unnest` 这类表值函数换个列名输出敏感字段）见下面“已知限制”；详见应用内「数据脱敏」2.2 和第 6 节。

### 8.4 SQL 防火墙

应用内章节：「SQL 防火墙」。

- 规则按优先级从小到大求值，命中多条时取最严的动作（拒绝 > 要求原因 > 限行 / 强制脱敏 > 仅告警）；观察模式的规则和全局观察模式只记录命中、不拦截；总开关关闭后规则不执行、也不记录命中，关闭必须写原因并记高危审计。
- 新建规则默认是观察模式：先用“回放”（最近 7 天、最多 2 万条语句）和命中记录确认没有误伤，再切换为生效；规则模板添加后同样是观察模式。
- 例外只豁免指定规则对某个用户 / 权限组 / 实例 / SQL 指纹的约束，必须写原因和有效期（最长 1 年），到期自动失效，创建与撤销都写审计。
- 规则的动作与场景要搭配：限制返回行数、强制脱敏只用于在线查询与数据导出，要求填写原因只用于在线查询；SQL 工单场景没有这几种能力，跨场景规则在工单里按仅告警处理，只勾工单场景时保存会被拒绝。强制脱敏需要至少一个带列名的对象条件（如 `*.*.id_card`）。
- 语句测试台按已保存的全部规则评估一条语句（可选场景、实例或环境、权限组、时间、用户名），不写命中记录，也不连目标库做 `EXPLAIN`；预估扫描 / 影响行数需手填，留空时这类条件显示“未评估”、不命中。
- 在线查询里 SET 打头的脚本，每条查询（含 `SET` 赋值里的子查询）都各自过一遍规则，任一条被拒绝则整份不执行。
- 命中记录里的语句缺省只存把字符串 / 数字字面量换成 `?` 之后的形态；`firewall.store_sql=raw` 才存原文。需要先执行 `deploy/sql/240_firewall.sql`，没执行 = 没有规则。

### 8.5 从原权限码迁移到按钮权限（升级时一次性）

- 早期版本有“权限码”和“按钮”两套权限；现在只认按钮（1.81 起运行时不再读权限码）。升级时 `dbt-admin perm migrate` 把权限组和用户单独持有的权限码展开成按钮授权，迁移前后每个用户能用的按钮完全相同；没有对应按钮的早期遗留码丢弃（没有任何影响）；执行后在 `dbt_perm_setting` 里记下“已迁移”，服务最多 15 秒内生效，不需要重启。新装的库也走这一步（内置权限组的初始授权以权限码的形式放在基础数据里）。
- `install.sh install / upgrade` 会在健康检查通过之后自动执行一次；也可以手工先预览（`dbt-admin perm migrate`，不加 `--apply` 只演练，列出每个权限组 / 用户新增的按钮和丢弃的权限码），再加 `--apply` 执行。执行前会把“逐条撤销这次迁移”的 SQL 存成文件。只增不减，可重复执行。
- 迁移前权限组页面顶部有黄色提示；迁移失败升级照常完成，但迁移完成前普通用户没有任何按钮权限（超级用户不受影响），请尽快修好后重跑。升级时不想执行迁移可加 `install.sh --skip-perm-migrate`（之后手工执行 `dbt-admin perm migrate`）；迁移最多等 2 分钟，输出实时显示，卡住时 Ctrl+C 是安全的（迁移在一个事务里写入，没写完不会留下半截数据）。
- 超级用户在任何时候都不受限，所以不会把管理员锁在外面。
- 页面顶部“无权限按钮的显示方式”设置无权限按钮的呈现：隐藏（默认）或置灰并提示所需权限。
- 单独授权 / 禁用可以设**到期时间**（到期当天结束后自动失效），且必须写原因（≤ 200 字），变更写入系统审计。

### 8.6 上线前注意

- **后台任务默认关闭**的有：性能工单的采集 / SLA / 验证 / 周报（系统配置 `perf.jobs`）、分区维护自动执行（`partition.auto_run`）、数据保留清理（`retention.enabled`）。慢日志采集默认开启。
- 从早期版本升级：升级脚本会自动执行权限迁移（`dbt-admin perm migrate`），建议升级前先在新包里用不带 `--apply` 的命令预览一次，见 8.5。
- `GOINCEPTION_CONFIG_FILE`（goInception 配置文件路径）、`PUBLIC_URL`（SSO 回调地址与通知里的工单链接）、`REQUIRE_GOINCEPTION`、`BATCH_DB_TYPES`、`EXPORT_BASE_DIR` 见 `configs/env.example` 与 [安装部署指南](ops-manual.md)。
- 生产环境请设置 `REQUIRE_GOINCEPTION=true`，避免漏配 goInception 时库表解析与脱敏悄悄降级。

## 10. 规则、限制与注意事项

> **警告**：执行中的 SQL 上线工单一旦发出就无法回头，页面不再提供终止按钮（只有 DBA / 超级用户能在进度卡片里「取消执行」）；请在“审核通过”阶段再确认一遍语句和执行时间。取消执行不会回滚已成功的语句。

> **警告**：脱敏总开关默认关闭，Redis 查询结果不做脱敏；上线前请确认脱敏规则与开关，不要依赖查询结果“看起来已脱敏”。

> **注意**：`SECRET_KEY` / `MIRAGE_*` 一经设置不要随意更改，加密保存的实例账号密码、登录方式密钥等依赖它们（见 [安装部署指南](ops-manual.md) 2.6）。

- 回滚语句依赖 goInception 备份库保留的备份数据；原生执行、SQL Server、Redis、批量与降级检查没有备份；
- 同库 DDL 串行；执行失败即停，不自动回滚已成功的语句；
- 表级权限校验只对类型为 MySQL 的实例精确到表，其余按库校验；
- 审批流变更只影响之后提交的工单；某一级无人可审时工单会卡住；
- 提交时服务端会重新检查与复核，页面上的预览不被信任；
- 通知是尽力而为，失败不影响业务；
- 同一批目标表同一时间只让一个程序维护分区与推送。

## 12. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 审核引擎页“保存并重启”失败，提示 `permission denied while trying to connect to the Docker daemon socket` | dbtool 的运行用户没有访问 `docker.sock` 的权限（不在 `docker` 组）；配置文件已写入但容器没有被重启 | 请管理员在服务器上执行 `usermod -aG docker dbtool` 并 `systemctl restart dbtool`，然后在页面点“仅重启”；详见帮助“系统管理”的排障表 |
| 看不到某个菜单 / 按钮 | 没有相应权限 | 在“权限组 › 按用户查看有效权限”里查原因 |
| 查询提示没有权限 | 对涉及库表没有有效的查询权限 | 先到“权限管理”申请库表权限；非 MySQL 类型实例申请库权限 |
| 工单提交后没有人审批 / 卡住 | 审批流某一级没有人有审批权限；或你自己是唯一的审批人（不能自审） | 管理员在“审批流程”里能看到警告 |
| SQL 检查报“降级”/只有本地检查 | goInception 没有配置 | 联系管理员 |
| 导出下载不了 | 缺少下载权限，或文件已被清理 | 申请权限，或重新提交 |
| 导出（或检查行数）提示“连接数据库实例超时”“无法连接数据库实例”“与数据库实例的连接被中断” | 实例地址 / 端口不对或实例没在运行，网络 / 防火墙不通，或连接被实例重启 / 网络抖动中断 | 按提示确认实例地址、端口和网络；检查阶段修好后重新检查，批量工单对失败实例点“重试”，单实例导出“复制为新工单”重新提交；仍失败带上整段提示（含“原始错误”）联系 DBA |
| 导出提示“读取数据时与数据库实例的网络连接超时（实例长时间没有返回数据）” | 查询太慢（没走索引、数据量大），或网络 / 防火墙中断了长时间的连接 | 缩小查询范围、加过滤条件，避开业务高峰后重试；仍然超时请 DBA 检查网络 |
| 登录时被要求输入验证码 | 已开启两步验证 | 换手机后联系管理员“重置 2FA”再重新绑定 |
| 账号被锁定 | 连续输错密码 | 等待锁定时间过后重试，或请管理员在用户页里“解锁” |
| 页面时间差 8 小时 | 时区配置不一致 | 反馈给管理员 |
| 系统配置页提示设置表不存在 | 没执行 `deploy/sql/260_setting.sql` | 执行脚本（`install.sh upgrade` 会自动执行） |
| 目标库返回的错误（HTTP 422） | 目标库自己的报错或连接 / 认证失败，原文显示不含密码 | 按提示处理，联系 DBA 检查账号与网络 |

已知限制：

- SSH 隧道经本地转发器连接，**不校验跳板机主机公钥**，无法防御到跳板机的中间人攻击；
- PolarDB-X 没有在真实实例上验证过，脱敏为保守匹配，SQL 防火墙的预估扫描行数不支持；
- 保守匹配的脱敏没有表级精度，表级“免脱敏名单”没有做；保守匹配也认不出用列名列表给 CTE / 派生表改列名（`WITH c(z) AS (SELECT phone …)`、`(SELECT phone …) d(z)`）、`PIVOT` / `UNPIVOT`、`VALUES` 派生表、`STRING_SPLIT` / `OPENJSON` / `JSON_TABLE` / `unnest` 这类表值函数把敏感字段的值换个列名输出的写法（以前就有，不是新版本引入的；MySQL + goInception、SQL Server、PostgreSQL 先按来源精确匹配，能不能追到原字段没有在真实实例上验证）；
- 数据字典功能已去掉，只保留在线查询的“对象信息”与“可编程对象”；
- 数据导出文件只支持本地目录；
- 值班表按服务器本地时区计算，不按用户时区显示；一个时段只有一个值班人（没有主 / 备班），没有法定节假日日历（节假日用临时调班）；值班信息暂时不接入通知的“@ DBA 值班”和性能工单的 DBA 轮询；多实例同时运行时各实例各缓存 30 秒，“班次时间不重叠”的校验只在单个实例内串行，两个实例同一瞬间各保存一个班次时可能产生重叠（重叠时取后开始的班次），建议只从一个实例的页面维护；
- 企业微信通知渠道：用户资料里没有企业微信 ID，按平台用户（提交人 / 审批人 / 权限组成员 / 指定用户 / DBA 值班）@ 时只在正文里写名字、不会真正提醒，要提醒到人用“渠道原生标识”填成员 userid 或手机号，或用“所有人”；每个机器人每分钟最多 20 条；只用本机的假机器人测试过，没有在真实企业微信群里验证过；
- Telegram 通知渠道：用户资料里没有 Telegram 用户名 / ID，按平台用户 @ 时只在正文里写名字、不会真正提醒，要提醒到人用“渠道原生标识”填 Telegram 用户名或数字用户 ID；没有“@所有人”；服务器要能访问 `api.telegram.org`（国内网络通常要配 `HTTPS_PROXY`，通知请求的超时只有 5 秒）；只用本机的假机器人测试过，没有在真实 Telegram 群里验证过；
- 短信验证码、分析任务与 Binlog 解析结果等进程内状态在服务重启后丢失，多实例同时运行时不共享。
