# 管理员指南

菜单：访问控制、安全合规、平台设置三个分组（仅管理员）。这些页面用来配置审批流程、资源组、用户与权限组、登录认证与安全策略、审核引擎（goInception）、通知渠道、Redis 规则、环境字典、值班表、系统配置，并查看审计日志。这些页面的按钮在权限树里全部是**锁定码**（除“审计日志”和“值班表”外）：服务端只认超级用户，**不能授予权限组**；切换到非超级用户身份时，这些页面要么不显示，要么按钮显示“仅超级用户可用”。“审计日志”和“值班表”的按钮可以授予权限组（值班表默认只有超级用户，要在权限组里显式授予）。按钮级权限本身见 [按钮级权限](#help/btnperm)。

> 注意：除“环境设置”“值班表”外，这些页面的写操作都在同一个事务里先改数据再写审计日志，审计写失败则整体回滚（这两个页面的审计在数据修改之后单独写入，写失败只记服务日志、不回滚）；管理类接口每次请求都会回库确认操作者仍是启用的超级用户（值班表的接口按按钮权限校验，没有被授予按钮的非超级用户一律 403）。

## 前提条件与所需权限

- 除“审计日志”和“值班表”外，这些页面需要超级用户身份；
- “审计日志”需要 `audit.view`，导出需要 `audit.export`（高危），这两个可以授予权限组（预设“审计”）；
- 部分页面依赖扩展表，需要 DBA 先执行 `deploy/sql` 下对应脚本，各节会写明；没执行时页面照常，只是缺少对应字段或功能。

## 高危操作的确认框

本组页面的写操作（停用 / 启用 / 解锁用户、重置密码与 2FA、授予超级用户、权限组保存与删除、资源组停用 / 恢复 / 彻底删除、审批流变更与删除、环境新增 / 修改 / 删除、按钮权限单独授权 / 禁用 / 撤销、登录认证启停 / 删除 / 保存配置、安全策略、审计导出）都先弹出统一的确认框：

- 页脚显示**权限码**（和按钮名称），高危操作带红色“高危”标记；高危确认框点遮罩不会关闭，默认焦点在“取消”上，按 Esc 取消（例外：SQL 工单详情页的“立即执行 / 立即导出”，默认焦点就在“确认执行 / 确认导出”上，需要键入工单号确认的生产环境仍先到键入框）；
- 需要写原因的（单独授权、撤销单独授权）原因框必填，不填无法确认，原因写入系统审计；
- 彻底删除资源组要**原样键入资源组名称**、删除环境要**原样键入环境编码**才能确认；
- 保存配置类（审批流、登录认证配置、通用规则、安全策略）会列出**变更前后的差异**，没有任何变更时不弹框、不发请求，提示“没有变更”；密钥类字段只显示“已修改”；
- 确认后接口失败时，错误信息显示在确认框里，不会关闭，可以直接重试；点取消不会发出任何请求。

## 审批流程

目标：为**每个资源组 × 每种工单类型**配置一条审批流。仅超级用户；工单类型有三种：查询权限申请、SQL 上线申请、数据归档申请（数据导出沿用“SQL 上线”的审批流）。**没有配置审批流的组不能提交该类工单**。页面有三个页签：按组配置、总览矩阵、审批与通知链路。

- 每一“级”选一个**权限组**，按选择顺序流转，权限组内任一用户都可审核；可拖动调整顺序（芯片上的 ‹ › 按钮可前移 / 后移，键盘和触屏也能用），最多 10 级，同一个权限组不能在同一条流里选两次；有改动尚未保存时旁边显示“有未保存的修改”，切换资源组 / 工单类型或离开页面前会提示；
- 左侧只列出未停用的资源组，徽标 `n/3` 是已配置的工单类型数，⚠ 表示有级别无人可审；
- 页面会列出每一级的**可审批人**：该资源组内、属于该权限组、启用、且有审批按钮权限的用户（SQL 上线 `sqlworkflow.approve`、查询权限 `qpriv.review`；含单独授权 / 禁用。数据归档申请没有单独的审批按钮：该级权限组 + 资源组内的成员都能审）。因登录失败被锁定的账号（🔒）暂时无法审批，不计入。列表为空、没有人有审批权限或全部被锁定时提示“该级无人可审”，这是工单“卡住”最常见的原因；
- **总览矩阵**：行 = 资源组，列 = 工单类型，点单元格跳到“按组配置”；顶部是已配置 / 未配置 / 无人可审三张 KPI；红色单元格表示该级无人可审，“未配置”的组不能提交该类工单；
- **审批与通知链路**：流程图说明 提交 → 逐级审批 → 通过 / 驳回 → 机器人通知（虚线为机器人通知）；空审批流或命中自动审核规则时，SQL 上线提交后直接“审核通过”，检查有错误则直接驳回；“实际示例”按所选资源组和工单类型列出时间线；
- 保存前会预览并确认变更前后；如果预览里有“无人可审”的级别，确认框里会再次红字警告（仍可选择继续变更）；删除某条审批流后该组不能再提交该类工单；
- 审批流在**提交时**复制进工单，变更只影响**之后提交**的工单，审批中的工单不受影响；
- 保存时不允许为空流；SQL 上线的“空审批流自动通过”请通过自动审核规则实现；
- **审批规则**：审批人必须同时属于当前级的权限组和工单所属资源组；任何一级驳回即终止，提交人可撤回，审核通过后有执行权限的人也可终止；通知发往资源组配置的机器人（钉钉 / 飞书 / Slack），更细的事件订阅与 @ 规则在“通知渠道”里配置；
- **自审规则**：系统配置 `approval.forbid_self_approve` **未设置时默认禁止**审批自己提交的工单（显式设为 `false` 才允许自审）。默认禁止时，超级用户也不能审批自己提交的**查询权限申请、数据导出工单、数据归档**，只有 **SQL 上线**（非导出）工单超级用户可以自审。

> 警告：某一级无人可审时，工单会卡在该级；保存审批流前请留意黄色警告。变更会写入系统审计。

## 资源组

资源组 = 团队 / 实例分组，仅超级用户可管理。它决定：

- 用户能看到哪些实例（用户 ↔ 资源组 ↔ 实例；有“查看 / 查询全部实例，不受库表授权限制”权限的用户不受限）；
- 每种工单类型的审批流；
- 工单通知发到哪些群 / 邮箱（读“通知渠道”里对该组生效的渠道；资源组上的三个旧版 Webhook 只在该组没有同类型的渠道时才用）；
- 性能工单把它当“团队”。

权限组与资源组没有直接关系，审批人 = 资源组内属于某权限组的用户。

- 新建 / 编辑：名称 1–100 字且唯一（含已停用的），负责人（用户名，≤ 30 字，可空）、备注（≤ 100 字，可搜索）。页顶 4 张 KPI：启用中的资源组、没有实例的组（用户进来看不到任何实例）、审批流不完整（不足 3 种工单类型）、未配置机器人（没有旧版 Webhook，“通知渠道”里也没有对它生效的钉钉 / 企业微信 / 飞书 / Lark / Slack / Telegram 渠道，工单通知无处可发）。列表显示用户数、实例数、`n / 3` 审批流配置情况、通知群是否配置，黄色行表示没有实例或审批流不完整；
- **关联用户与实例**：穿梭框（左边已关联、右边未关联）一次增删多个（一次最多 2000 个对象），勾选后点中间的按钮只是暂存，点“保存关联”后整批在一个事务里统一生效，并写入系统审计；移除用户可能让审批流出现新的断点，页面会提示；已停用的资源组不能改关联；
- **通知群**：列表里“通知群”一列把两处合起来看——“通知渠道”里对该组生效的渠道（含全局渠道）显示个数，如“钉钉 ×2”；只有资源组上旧版 Webhook 的显示“（旧版）”；都没有的显示“未配”；Lark、邮件配了才显示。鼠标悬停可看来源。
- **通知请到“通知渠道”配置**：编辑框里没有 Webhook 输入框，只有一句说明、“去‘通知渠道’配置”的链接，以及该组已有的通知渠道（含全局渠道）。资源组上原来的三个旧版 Webhook（钉钉 / 飞书 / Slack）仍然生效，但只在该组没有同类型的通知渠道时才发；这个组还配着旧 Webhook 时，编辑框里会多出一段提示和对应的“清除”勾选（保存后不再回显地址）。改用通知渠道后，建议在这里把旧的清除；
- **停用 / 恢复**：停用是软删除；有进行中的工单（待审批的流程、已通过但未结束的 SQL 工单）时拒绝并列出明细（最多 50 条，可点进详情），需先结束或终止；已停用且没有任何引用（关联用户 / 实例、历史工单、审批记录、权限申请、性能工单、通知渠道）的组可以“彻底删除”（需键入资源组名称，无法恢复）；
- 改名会同步审批流里的显示名；
- 负责人 / 备注保存在扩展表，需先执行 `deploy/sql/080_sysadmin_ext.sql`，没执行时这两项不可用。

## 用户

仅超级用户。常用动作做成行内操作：解锁账号、重置密码、重置两步验证、启停用户，并显示登录失败次数、2FA 绑定和最近登录；所有动作写入系统审计。页顶 4 张 KPI：用户总数、超级用户、已锁定、未绑定 2FA（含已停用的账号）。

| 功能 | 说明 |
|---|---|
| 筛选 | 按权限组、资源组、状态（正常 / 已锁定 / 已停用 / 超级用户 / 未绑定 2FA）、关键字；可按最近登录 / 账号 / 状态（停用、失败多的在前）排序；显示失败次数、剩余锁定时间、认证方式、最近登录 |
| 新建 / 编辑 | 用户名 1–30 字（字母、数字和 `@ . + - _`，创建后不可改），姓名 1–10 字、部门（≤ 50 字）、邮箱、钉钉 UserID（≤ 20）/ 飞书 OpenID（≤ 50）/ Slack ID（≤ 50）（通知标识，用于工单通知里 @ 到本人）、权限组、资源组（可多选）；认证方式为本地或 LDAP，创建后不可改，LDAP 用户不设本地密码；初始密码须满足密码策略（默认至少 9 位，不能全是数字或常见弱口令，不能包含用户名、邮箱或姓名），**由管理员输入，系统不回显** |
| 启停 / 解锁 | 解锁 = 失败计数清零；登录失败达到阈值（默认 5 次）后锁定一段时间（默认 300 秒），可在“安全策略”或系统配置 `security.login_lock_attempts` / `security.login_lock_seconds` 调整 |
| 重置密码 | **系统生成临时密码**（只显示一次，首次登录强制改密），或管理员手输新密码（须满足密码策略，不能包含用户名，可要求下次登录先改密）；新密码不会写入日志或审计，请通过安全渠道告知用户；LDAP 等外部认证的用户密码由外部系统管理，不能在这里重置 |
| 重置 2FA | 会删除该用户全部验证方式，用户下次登录重新绑定 |
| 单独授权 / 禁用 | 见 [按钮级权限](#help/btnperm)；必须写原因，可设到期时间 |
| 授予超级用户 | 只有超级用户能改超级用户标记；授予超级用户和调整权限组都会二次确认并写入审计 |

保护规则：**不能停用或降级自己；不能停用或降级最后一个启用的超级用户**（并发下也有行锁保护）。部门、认证方式、强制改密保存在扩展表，需先执行 `deploy/sql/080_sysadmin_ext.sql`。

## 权限组

权限组是“角色”，同时是审批流里的“级”，仅超级用户可管理。页面分四个页签：

| 页签 | 内容 |
|---|---|
| 基本信息 | 名称和说明（内置权限组不能改名）、引用情况（被哪些审批流引用）；新建时可“复制该组”，连同按钮授权一起复制。权限在“按钮权限”页签里设置 |
| 成员 | 列出成员；成员关系在“用户”页按用户调整（编辑用户 → 权限组） |
| 按用户查看有效权限 | 有效权限 = 所有权限组的并集 ＋ 单独授权 − 单独禁用，超级用户拥有全部权限；每个按钮都显示来源（来自哪个权限组、单独授权 / 禁用、基础按钮、仅超级用户），方便排查“为什么他能 / 不能用”。在这里可以对用户做按钮级的单独授权 / 禁用（必须写原因，可设到期日），用法见 [按钮级权限](#help/btnperm) |
| 按钮权限 | 按钮级权限的授予与预览，用法见 [按钮级权限](#help/btnperm) |

页面顶部的“无权限按钮的显示方式”设置无权限的按钮是隐藏（默认）还是置灰。权限只有按钮这一套；从早期版本升级时，原来的权限码授权由 `dbt-admin perm migrate` 一次性迁移成按钮授权（`install.sh upgrade` 会自动执行，见 [按钮级权限](#help/btnperm)）；迁移之前页面顶部会有黄色提示。按钮权限表需先执行 `deploy/sql/019_btnperm.sql`。

删除权限组前会检查是否被审批流引用或有待审批工单。名称为 DBA / TL / RD / QA / Default 的权限组是**内置**的（带“内置”标签）：不能改名、不能删除，但可以调整它们的权限和说明（需先执行 `deploy/sql/150_builtin_groups.sql`，没执行时按普通组处理）。

## 登录认证

在页面里定义外部认证，**可同时启用多种、可添加多个同类型**（如两套 LDAP、飞书和 Lark 各一个），即时生效不用重启。字段、测试方法与通用规则的完整说明见 [登录、两步验证与账号安全](#help/login)。

| 类型 | 说明 |
|---|---|
| LDAP | 直连 / StartTLS / LDAPS；DN 模板或先搜后绑；空密码一律拒绝 |
| OIDC / Slack | 授权码 + PKCE + state + nonce，自行校验 id_token（固定 RS256 / ES256） |
| 钉钉 / 飞书 / Lark / 企业微信 | 各自的 OAuth 流程，可限定企业 / 租户 |
| CAS | CAS 1 / 2 / 3 ticket 校验 |

要点：

- **必须测试通过才能启用**：连接类配置改动后会自动停用、测试结果作废；管理员发起的“测试登录”只显示取得的属性和匹配结果，不创建用户、不建会话；
- 密钥加密存储，接口永不回显，留空表示不改；
- 可设“首次登录策略”（自动创建用户 / 仅限已有用户）、默认入组、匹配依据、属性映射和入组规则（只增不减）；
- 回调地址 = 平台对外地址 + `/login/sso/<id>/callback`，需要在 IdP 里登记；
- 可拖动或用“上移 / 下移”调整登录页按钮顺序；**本地账号登录永远保留给超级用户**；
- 启用 / 停用 / 删除登录方式、保存配置、保存通用规则都会先弹确认框（权限码 `authp.toggle` / `authp.edit`），配置和通用规则保存前列出变更差异；有用户通过它登录过时，删除会再确认一次；配置弹窗里有未保存的修改时，关闭前会提示。

## 审核引擎（goInception）

goInception 是 SQL 上线检查与执行、查询脱敏所依赖的审核引擎。本页仅超级用户可用，连接信息保存即生效；goInception 自己的配置文件（`config.toml`：审核规则、备份、在线改表等）提交后需要**重启 goInception 才生效**。页面把“校验 → 对比 → 保存 → 重启 → 健康检查 → 失败自动恢复”做成一条流程，每次修改保留历史版本，可一键回滚，密码类参数不回显明文。页面有四个页签：

- **连接信息**：goInception 的地址 / 账号，以及备份库（存回滚语句）；“测试连接”、“测试备份库”；保存即生效。地址留空表示不使用 goInception，此时 SQL 审核回退为内置规则；备份库填的是 dbtool 读取回滚语句用的连接，goInception 自己写备份的账号在配置文件的 `[inc] backup_*`，两处需要一致；
- **配置文件**：左侧“常用参数”表单、右侧 `config.toml` 源文件，**双向同步**（行级编辑，保留注释与排版），表单里没列出的参数直接改源文件，也可切换为“只看源文件”。保存前校验语法、类型与取值范围——类型写错是错误，未知参数和风险取值（如关闭 DML 必须有 WHERE、允许 DROP DATABASE）是需要确认的警告；参数含义见 goInception 官方文档；密码类参数显示占位符；
- **历史版本**：保留最近 50 个版本，每个版本记录完整文件（加密保存，页面和对比里的密码一律脱敏）、操作人与重启结果；可对比、可回滚，回滚会以旧版本的内容生成新版本，同样走重启 → 健康检查流程，并写入系统审计；
- **部署与重启**：配置文件路径（也可用环境变量 `GOINCEPTION_CONFIG_FILE` 指定，优先于页面设置，指定后页面不可改）、Docker 容器名、是否加 `sudo -n`、重启命令超时、健康检查最长等待、等待任务完成的最长时间，以及“健康检查失败时自动恢复上一个生效版本”“有任务执行时默认等待执行完再重启”两个开关；“检查权限与连通性”可先行验证。进程状态卡片显示状态、版本、连接 / 任务数、配置文件与最近一次重启，取不到的项显示“未知”；如果有人绕过页面直接改了磁盘上的文件，会提示“磁盘文件与 #N 不一致”，可一键把磁盘文件导入为新版本。

**保存并重启**：goInception 以 Docker 部署，重启方式只有一种——`docker restart <容器名>`。容器名是 `docker ps` 里的 NAMES，只能由管理员在“部署与重启”里设定，只允许字母、数字和 `_ . -`，以字母或数字开头，最长 128 位，命令不经 shell 执行；未填写时保存并重启、仅重启、回滚都不可用，只能“仅保存”。保存时若有进行中的任务，可选“等待完成”或“强制重启”（会中断任务，被中断的工单需要人工确认目标库状态）；重启后健康检查失败会**自动恢复上一版本**。也可以“仅保存”（不重启，页面提示“有未生效的配置”），之后点“仅重启”让它生效。

> 警告：重启需要 dbtool 所在的机器上有 `docker` 命令，且运行用户能访问 `docker.sock`（在 docker 组里，或勾选 `sudo -n` 并在 sudoers 里只放行这一条命令）；运行用户还需要对配置文件所在目录有写权限（原子替换要在同目录建临时文件）。如果 dbtool 自己跑在没有 docker 命令的容器里（例如 distroless 镜像），页面重启不可用，只能“仅保存”后自行重启 goInception。

> 警告：goInception 重启期间 SQL 检查会短暂不可用；生产环境建议选“等待完成”，并避开业务高峰。

版本历史表需先执行 `deploy/sql/011_gi_config.sql`，没执行时页面提示，只能修改连接信息。

## 通知渠道

菜单“平台设置 › 通知渠道”，仅超级用户。工单提交、审批、执行等事件会发到所属资源组配置的机器人，支持钉钉、企业微信、飞书、Lark、Slack、Telegram 机器人和**邮件**（SMTP）。每个渠道关联一个或多个资源组，或为全局渠道（对所有资源组生效，如总监与周报）；页面顶部显示渠道数、资源组覆盖、事件覆盖和近 7 天发送情况。列表有类型 / 资源组 / 关键字筛选、行内启停、最近发送结果，另有“发送记录”页签。

- **Webhook 与签名密钥**（邮件渠道为 **SMTP 密码**）加密入库、不回显，页面只显示主机名与“已加签 / 已设密码”，编辑时留空 = 不修改；签名密钥只在机器人开启了“加签 / 签名校验”时填写（可“清除已有签名密钥”；企业微信、Telegram 机器人没有加签，页面不显示这一项）；更换渠道类型后原有的密钥 / 密码不沿用；Webhook 主机必须是平台域名，渠道名唯一；
- **订阅事件**（共 11 项）：待处理（新工单、流转到下一级）、新工单提交、审批通过、被驳回、提交人终止、已设置定时执行、开始执行、执行完成、执行异常、性能工单超时（SLA 超期升级）、巡检告警；不勾选表示全部；数据归档没有单独的订阅项，沿用上述事件：归档开始 → “开始执行”；归档完成、被窗口 / 上限中断 → “执行完成”；负载中断、失败、校验失败、结构变更暂停、自动暂停 → “执行异常”；归档申请的提交 / 流转 / 通过 / 驳回 → “待处理 / 审批通过 / 被驳回”，详见 [数据归档](#help/archive)；
- **DBA 值班人员**：平台用户名，逗号分隔，供“DBA 值班”@ 目标使用，留空则该目标不生效；
- **@ 规则**：目标可选提交人、当前审批人、DBA 值班、某权限组成员、指定用户、渠道原生标识、所有人；可按事件过滤（不选 = 渠道订阅的全部事件）；每条规则可勾选“仅工作时间 @”（周一至周五 09:00–19:00，服务器本地时区，其余时间只发消息不 @）；一条消息最多 @ 50 个目标；没有对应渠道 ID 的用户退化为文本“@姓名”，只显示名字、不会提醒（企业微信、Telegram 的用户资料里没有对应的 ID，所有平台用户都是这样，见下面“企业微信渠道”“Telegram 渠道”）；
- **渠道原生标识**：Slack 用户 ID 以 U / W 开头（如 `U012AB3CD`），用户组 ID 以 S 开头（如 `S0ARY4FQATB`，可 @ 整个用户组），也可填 `here` / `channel` / `everyone`，直接粘贴 `<!subteam^S...>` 保存时自动转成 ID；钉钉填手机号（11 位）或 userId；企业微信填成员 userid（账号，如 `zhangsan`）或手机号（11 位）；Telegram 填用户名（如 `dba_wang`，带不带 @ 都行）或数字用户 ID；飞书 / Lark 填 open_id（如 `ou_xxx`）；所有人请用“所有人”目标（Telegram 没有“所有人”）；
- **测试与预览**：编辑面板下方可选择事件（“默认测试消息”忽略规则里的事件过滤，让所有 @ 对象都出现；选具体事件则按真实逻辑处理，“提交人”为你自己）、时间（当前时间 / 工作时间 / 非工作时间）和当前审批级的权限组。“预览”只生成消息内容、各规则的 @ 解析结果和请求体，**不会发送**；“发送测试消息”才真的发到机器人；
- **删除渠道**会先弹出高危确认（Webhook 与签名密钥一并清除；只是暂时不发请用“停用”）；保存和启用 / 停用也会先确认；
- **发送记录**页签：每次向机器人发送（含测试发送）记一条，保留 30 天，可按渠道、事件、仅失败筛选；失败原因不含 webhook 地址；
- 多资源组与值班人员需先执行 `deploy/sql/091_notify_ext.sql`，发送记录需先执行 `deploy/sql/092_notify_log.sql`，渠道表为 `deploy/sql/001_notify_channel.sql`；没执行时其余功能照常；
- 通知是**尽力而为**：失败只记日志，不影响业务；SQL 上线、权限申请、性能工单、巡检共用同一套渠道。

### 邮件渠道

类型选“邮件”，填 SMTP 主机 / 端口 / 加密方式（STARTTLS 常用端口 587、SSL/TLS 465、不加密 25，切换加密方式时端口自动换成对应默认值）、用户名（留空 = 不认证）和密码、发件人地址与显示名、固定收件人 To / Cc 和主题前缀。

- 固定收件人 To / Cc 合计最多 20 个；@ 规则解析出的用户邮箱另算，一封邮件总计最多 50 个收件人；
- @ 规则解析成用户资料里的邮箱：提交人、当前审批人、权限组成员、指定用户、DBA 值班，“所有人”是工单所属资源组的全部启用用户，“邮箱地址”填一个固定地址；**没有邮箱的用户会被跳过**，并在“发送记录”的说明里写明；同一个邮箱只发一次；
- **证书校验默认开启**；关闭后连接仍加密，但无法确认对方就是真正的邮件服务器，有被中间人窃听邮件内容和 SMTP 密码的风险，仅在内网自签名证书且无法改用受信任证书时使用；
- 加密方式为“不加密”时，**默认不允许填用户名密码**（用户名和密码会以明文发送，任何能看到这段网络流量的人都能获取）；确需使用要勾选“允许明文认证”，并尽量只在本机或隔离的内网使用；
- 邮件渠道的测试发送可以填一个测试收件人（只发给他），并逐阶段显示 连接 / STARTTLS / 认证 / 发送 的结果（不含密码）；
- 每个渠道每分钟最多发 60 封，超出的丢弃并记入发送记录；连接超时 10 秒、整次发送最长 30 秒，失败最多重试 1 次；
- 邮件里的工单链接用系统配置的对外地址（`PUBLIC_URL`）拼接；没有配置时邮件里只写编号；
- 需要先在数据库里执行 `deploy/sql/210_notify_email.sql`。

### 企业微信渠道

类型选“企业微信”，Webhook 填企业微信**群机器人**的完整地址（在群里“添加机器人”后复制，形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…`；地址里的 key 等同于往群里发消息的密码，别发给无关的人）。

- 地址的主机必须是 `qyapi.weixin.qq.com`（https）；企业微信机器人**没有加签**，页面不显示“签名密钥”，也不保存（从钉钉 / 飞书 / Slack 改成企业微信时，旧的签名密钥一并清掉）；
- **@ 的写法**：企业微信的 @ 只认成员 userid 或手机号。“渠道原生标识”规则填成员 **userid**（账号）或 **11 位手机号**，“所有人”规则 @ 全员。用户资料里没有企业微信 ID，所以“提交人 / 当前审批人 / 权限组成员 / 指定用户 / DBA 值班”这几类按平台用户 @ 的规则，在企业微信里只在正文写“@姓名”，**不会真正提醒**（预览里这些用户标成“文本，不会提醒”）；要提醒到人，用“渠道原生标识”；
- **消息格式**：没有套用消息模板时发文本消息（标题 + 正文，最长 2048 字节，超出的部分截掉）；套用了消息模板时发 markdown 消息（标题按状态着色，字段 / SQL / 链接用 markdown 排版，最长 4096 字节，太长时先缩短最长的 SQL / 文本块）。markdown 消息只能 @ 成员 userid，要 @ 手机号或所有人时，这条消息改发文本消息（消息的纯文字版），@ 才能真正提醒到；
- 企业微信限制每个机器人**每分钟最多 20 条**，超出的企业微信会返回错误（常见错误码 45009），记在发送记录里，不会重发（通知本来就是尽力而为）；
- 测试发送默认发一条文本消息到群里（选了具体事件、又套用了消息模板时发 markdown 消息）；企业微信返回的 errcode 不是 0 时，页面显示“企业微信返回错误 …”（地址不对时常见错误码 93000），错误里不含 key；
- dbtool 所在服务器要能访问 `qyapi.weixin.qq.com` 的 443 端口；
- 只用假机器人测试过发送格式和错误处理，没有在真实企业微信群里验证过（markdown 的显示、`<@userid>` 的提醒、@ 手机号 / 所有人）：配好后先点“测试发送”到测试群看一眼。

### Telegram 渠道

类型选“Telegram”，Webhook 填机器人的 **sendMessage** 地址：`https://api.telegram.org/bot<Bot Token>/sendMessage?chat_id=<Chat ID>`。

- **Bot Token**：在 Telegram 里找 @BotFather，发 `/newbot` 创建机器人后拿到（形如 `123456789:AAE…`），再把机器人拉进要收通知的群（频道里要把它设为管理员）。Bot Token 等同于机器人的密码，别发给无关的人；它就在 Webhook 地址里，和其它机器人的 Webhook 一样加密入库、页面不回显；
- **Chat ID**：群 / 频道的数字 ID，通常是负数（超级群和频道以 `-100` 开头，如 `-1001234567890`）；公开频道可以直接写 `@频道名`。不知道 ID 时：把机器人拉进群，在群里 @ 一下机器人，再用浏览器打开 `https://api.telegram.org/bot<Bot Token>/getUpdates`，里面 `chat` 下的 `id` 就是；
- 群里开了“话题”想发到某个话题时，地址末尾再加 `&message_thread_id=<话题 ID>`。地址里的其它参数一律忽略（发送的内容和格式由 dbtool 决定）；
- 保存时检查地址：主机必须是 `api.telegram.org`（https），路径必须是 `/bot<Bot Token>/sendMessage`，必须带合法的 `chat_id`，不符合时提示正确的写法。Telegram 机器人**没有加签**，页面不显示“签名密钥”，也不保存（从钉钉 / 飞书 / Slack 改成 Telegram 时，旧的签名密钥一并清掉）；
- **@ 的写法**：“渠道原生标识”规则填 Telegram 用户名（5–32 位字母、数字、下划线，字母开头，如 `dba_wang`，保存时会去掉前面的 @）或数字用户 ID（没有设置用户名的人用它）。Telegram **没有“@所有人”**，选了“所有人”的规则保存时会被拒绝。用户资料里没有 Telegram 的用户名 / ID，所以“提交人 / 当前审批人 / 权限组成员 / 指定用户 / DBA 值班”这几类按平台用户 @ 的规则，在 Telegram 里只在正文写“@姓名”，**不会真正提醒**（预览里这些用户标成“文本，不会提醒”）；要提醒到人，用“渠道原生标识”。@ 的对象都写在消息的第一行；
- **消息格式**：用 Telegram 的 HTML 格式发送，链接预览已关闭。没有套用消息模板时发纯文字（标题 + 正文）；套用了消息模板时，标题加粗，字段一行一个“名称：值”，SQL 放进代码块，链接可以点。Telegram 限制一条消息最长 4096 个字符（按显示出来的文字算），超出时先缩短最长的 SQL / 文本块，缩不动就改发系统默认文案（同样截到 4096 个字符以内，@ 那一行保留）；
- Telegram 建议同一个群每分钟不超过 20 条，发得太快会返回 429 错误，记在发送记录里，不会重发（通知本来就是尽力而为）；
- 发送失败时，页面和发送记录显示“HTTP 状态码（api.telegram.org）：”加 Telegram 返回的原因，里面没有 Bot Token。常见的：`401 Unauthorized`（Bot Token 不对，或已在 @BotFather 里被吊销）、`400 Bad Request: chat not found`（Chat ID 不对，或机器人不在这个群里）、`403 Forbidden`（机器人被移出了群）、`400 Bad Request: message thread not found`（话题 ID 不对）、`429 Too Many Requests`；
- dbtool 所在服务器要能访问 `api.telegram.org` 的 443 端口。网络出不去时（国内网络通常访问不了），给 dbtool 服务配置出站代理环境变量 `HTTPS_PROXY`（配置位置见运维手册）；通知请求的超时只有 5 秒，代理要足够快；
- 只用假机器人测试过发送格式、@ 列表和错误处理，没有在真实 Telegram 群里验证过（消息的显示、`@用户名` 与用户 ID 的提醒效果、话题）：配好后先点“测试发送”到测试群看一眼。

### 消息模板

入口在“通知渠道”页右上角的“消息模板”，仅超级用户。每一类通知消息（新工单提交、审批通过、执行完成、权限被回收……）可以按“消息 × 范围（全局 / 某个渠道）”单独定制标题、状态色、字段排版、SQL 的显示方式和按钮；@ 谁仍在“通知渠道”的 @ 规则里配置，这里只管内容。

- **生效顺序**：渠道专属模板 → 全局模板 → 系统默认文案；没有模板就发原来的文本，行为不变；
- **变量**：模板里用 `{{变量}}` 引用变量，`{{#if 变量}}…{{/if}}` 表示“变量有值才显示”；只能用右侧列出的变量（点一下插入到光标所在的输入框），取不到值的字段行不会发出；
- **内容块**：字段表、文本、SQL / 代码块、链接 / 按钮、分隔线，可上移 / 下移 / 删除；字段值输入框里回车可换行，字段可设“占半行”；
- **SQL 显示方式**：隐藏字符串常量后取前 N 字（`'…'` 换成 `'***'`，新建的代码块默认就是它；先隐藏常量、再按字数截断，不会把一个常量切成两半漏出前半截）、只显示前 N 字、完整显示（最多 3000 字，再受渠道大小限制）、不显示 SQL。`{{sql}}` 出现在代码块以外的位置时同样会自动隐藏常量并截短；
- **预览**：右侧按 Slack / 钉钉 / 企业微信 / 飞书 · Lark / Telegram / 邮件各自的原生版式（Slack Block Kit、钉钉 markdown、企业微信 markdown、飞书卡片、Telegram HTML 消息、邮件 HTML）实时预览，并显示请求体；
- **测试发送**：选一个渠道发一条样例数据（不对应真实工单），按所选渠道的 @ 规则解析；邮件渠道可填测试收件人；
- **保存**：有校验问题（如引用了不存在的变量）时不能保存；保存后最多 20 秒内生效；“历史”可查看修改记录并载入旧版本；“恢复到上一层”会删除当前范围的模板（内容保留在历史里）；
- 需要先执行 `deploy/sql/260_notify_template.sql`；没执行时通知按系统默认文案发送。

各类消息的发送时机：

| 分组 | 消息 | 何时发送 |
|---|---|---|
| SQL 上线 / 数据导出 | 新工单提交 | 提交人提交工单、进入第一级审批时（渠道订阅里同时属于“待处理”和“新工单提交”） |

## Redis 规则

菜单“安全合规 → Redis 规则”，**仅超级用户**（权限码 `redisrule.view` / `redisrule.edit`，不能授予权限组）。定义 Redis 工单（见 [SQL 上线](#help/sqlworkflow)）允许哪些命令。

**白名单语义**：Redis 工单里的每条命令，必须**同时**命中某条**启用**规则的命令、键匹配、适用范围，并且涉及的键数不超过上限，才允许提交和执行；没有命中一律拒绝，**没有规则 = 全部拒绝**。规则只管“键”：多键命令检查每个键（`MSET` 检查键不检查值，`DEL` 检查全部键，`RENAME` 两个键都要匹配），无键命令（如 `PUBLISH`）不能被放行。

| 字段 | 说明 |
|---|---|
| 名称 | 唯一，≤ 50 字 |
| 启用 | 停用的规则不放行任何命令 |
| 命令 | 逗号分隔，大小写不敏感，如 `DEL,UNLINK`；可以从“支持的写命令”里点选 |
| 键匹配 | glob，每行一个：`*` 任意长度、`?` 一个字符、`[ab]` 集合；必须含固定字符，如 `cache:*`；每行 ≤ 200 字节 |
| 适用范围 | 限定实例（不选 = 全部实例）、限定 db 编号（逗号分隔，0–1023，留空 = 全部库） |
| 键数上限 | 单条命令影响键数的上限，1–10000，缺省 100 |
| 记录原值 | 执行前记录被改键的原值，供人工恢复；**原值会明文显示在工单详情里**，含敏感数据的键不要开 |
| 说明 / 备注 | ≤ 500 字 |

- 规则里只能选“支持的写命令”（都带键）；**硬禁止命令**（任何规则都无法放行）和所有无键命令、读命令不能写进规则，选了直接报错；页面下方的“命令清单”列出硬禁止与支持的命令；
- 新增 / 修改 / 启停 / 删除都要**二次确认**，变更立即对所有 Redis 工单生效（执行时按当时的规则复检），并写入系统审计（含变更前后差异，修改只记变化的字段“旧 → 新”）；
- “从模板添加”把常见规则填入编辑器，仍需核对后确认保存；“规则测试”用当前规则试检查一段命令（每行一条，可选实例与 db 编号），不执行、不连接 Redis；
- 需要先执行 `deploy/sql/170_redis_rules.sql`；没执行时页面提示，Redis 工单全部拒绝，MySQL / SQL Server 工单不受影响。

| 模板 | 填入的规则 |
|---|---|
| 清理缓存键 | 允许 `DEL` / `UNLINK` 删除 `cache:` 开头的键，一次最多 100 个 |
| 设置过期 | 允许对 `session:` 开头的键设置 / 修改过期时间（`EXPIRE` / `PEXPIRE` / `EXPIREAT` / `PEXPIREAT`） |
| 读后写入（写缓存键） | 允许 `SET` / `SETEX` / `PSETEX` 写 `cache:` 开头的键（建议带过期时间，`SET` 不带过期会给警告） |
| 修复哈希字段 | 允许对 `user:` 开头的哈希 `HSET` / `HDEL` 字段，并记录执行前的字段值供恢复 |

## 系统配置

菜单“平台设置 → 系统配置”，**仅超级用户**：本系统自己的设置中心，按功能分组管理全部系统参数（存放在元数据库的 `dbt_setting` 表）。

- **设置中心**：左侧是功能分组（登录与安全、短信、在线查询与脱敏、SQL 防火墙、SQL 上线与审核、审批与通知、数据导出、分区维护、数据保留、性能工单、性能巡检、SQL 优化工具），右侧按分区显示每个设置的名称、键、说明、默认值与取值范围；顶部搜索框按名称 / 键 / 说明筛选，“只看已修改”只列与默认值不同的项。goInception 连接信息不在这里，在“审核引擎”页维护；
- **怎么改**：直接在页面上改（开关、数字带单位与范围、下拉、文本各有合适的控件）；修改先积累在页面上，底部出现“有 N 项修改尚未保存”，点“保存修改”会先显示“旧值 → 新值”的确认，确认后**一次写入**：任何一项不合法都不会写入，并在对应项下面说明原因。每项可单独“恢复默认”；
- **高危项**（开启自动审批、自动删除过期分区、数据保留的开关与保留天数、`perf.jobs`、`firewall.store_sql=raw` 等）带“高危”标记，保存时要求**原样键入确认文字**；
- **变更记录**：每项的“变更记录”和页面右上角“变更记录”按时间倒序列出谁、何时、旧值 → 新值；同时写系统审计“修改系统设置”。**敏感项（密钥 / 密码）**只显示“已设置”，可以“修改”（重新填写）或“清除”，变更记录与审计里只记“已更新”，不记内容；
- **专门页面**：有更丰富操作的功能（SQL 防火墙规则、数据脱敏策略、登录方式、性能工单采集 / SLA）在设置项下给出“前往……页”的链接，两边写的是同一份数据；
- **指向服务器程序的项**：SOAR 的程序路径、配置文件与测试环境 DSN（`optimizer.*`）可以在“SQL 优化工具”分组里改，但保存时会核对：程序路径必须是绝对路径、文件名为 `soar`，文件存在、可执行、不能被其他用户改写；测试库不能是已登记的生产实例。三项都标“高危”，要键入确认文字。命令行 `dbt-admin settings` 也能 `list` / `get` / `set` / `reset`（命令行不核对文件与测试库），见 `docs/admin-cli.md`；
- **解不开的敏感项**：密文用当前 `SECRET_KEY` / `MIRAGE_SECRET_KEY` 解不开时按“未设置”处理并在页面顶部列出，分组导航上显示红色数字；多半是当前密钥与加密这些值时用的不一致——在服务器上运行 `dbt-admin check-secrets`（只读，不输出任何密钥或密文）判断是哪把密钥加密的，再按 `docs/admin-cli.md` 里 `check-secrets` / `reencrypt` 的说明处理，或直接在这里重新填写；
- **安全提醒**：`SECRET_KEY` 仍是公开的缺省值时，页面顶部会提示（任何知道它的人都能伪造会话并以超级用户身份登录）。请换成随机值（`dbt-admin gen-secrets` 生成），换后所有人需要重新登录，SSO / LDAP 登录方式需要重新测试。页面只给出“是不是公开值”，不显示任何密钥；
- **设置表不存在**：页面提示 `dbt_setting` 不存在时，先执行 `deploy/sql/260_setting.sql`（`install.sh upgrade` 会自动执行）；在此之前所有设置按默认值运行。各设置项的键、默认值与范围见 `docs/settings-reference.md`。

## 环境设置

菜单“平台设置 → 环境设置”，**仅超级用户**（按钮 `env.view` / `env.edit`，均为锁定码）。维护实例可选的环境字典：实例管理里的环境下拉、筛选与批量设置，SQL 防火墙规则的“实例环境”范围，在线查询与首页的环境徽标，SQL 工单详情的生产确认，都读这份字典。

| 字段 | 说明 |
|---|---|
| 编码 | 小写字母开头，只含小写字母、数字、下划线、中划线，最长 16 位；创建后不可改；`all` 与 `none` 是保留字 |
| 显示名称 | 1–20 个字符，不能与别的环境重名 |

“按生产对待”只影响下面这些位置：

| 位置 | 效果 |
|---|---|
| 实例列表与详情 | 环境徽标显示为红色 |
| 实例列表“批量设置环境” | 目标环境按生产对待时，确认框多一行关于工单键入确认的提示 |
| 在线查询 | 选中实例的环境徽标为红色，页面顶部出现红色色条 |
| 首页“我的实例” | 显示红色环境徽标 |
| SQL 工单详情 | 立即执行 / 立即导出、定时执行、确认手工执行结束、取消执行、批量实例重试这 5 类操作要求键入工单号；其余操作（审批、驳回 / 终止、取消定时等）不要求 |

它不改变防火墙的匹配：规则的“实例环境”按编码精确匹配，“仅生产”只覆盖编码为 `prod` 的实例；新增一个按生产对待的环境，需要为它单独写规则或使用“全部实例”。

> 注意：工单详情的生产确认只在页面上做，服务端不校验是否键入；并且详情只认“实例管理”里为实例设置的环境，没有设置环境、只靠标签标注“生产”的实例不会触发。要让各处一致，请在实例管理里显式设置环境。

- 内置环境 `prod`（生产）、`test`（测试）不可删除、不可改编码，名称与排序可以改；最多 20 个环境。
- 新增、修改、删除都要二次确认，删除还要键入环境编码；写入系统审计，动作名“环境-新增 / 环境-修改 / 环境-删除”，在审计日志里类别显示为“其他”、不带权限码。
- **删除**：仍有实例使用，或仍有防火墙规则把它作为适用范围的环境不能删除，列表里的“使用实例”和“防火墙规则”两列就是这两个数；删除前先把这些实例改成别的环境，或把规则的范围改掉。
- **实例的环境怎么定**：在“实例管理”的实例编辑里设置，或在实例列表里勾选后“批量设置环境”；取值必须在字典里。在线查询、首页与防火墙在实例没有设置环境时才退回按标签推断生产 / 测试（标签编码或名称含 `prod`、生产视为生产，含 `test`、测试视为测试）。
- 本进程内的改动立即生效；多个进程同时运行时，其他进程最多约 30 秒后生效。
- 依赖环境字典表 `dbt_environment`，需先执行 `deploy/sql/270_environment.sql`（同时把实例与防火墙规则里的环境编码列放宽到 16 位）；未执行时只有内置的生产 / 测试，页面提示先执行脚本，新增、修改、删除返回“表不存在”。

## 审计日志

菜单权限 `audit.view`，导出需要 `audit.export`（高危）。三个页签：

- **通用审计**：读 `dbt_audit_log`，包含登入 / 登入失败 / 账号锁定、离线下载，以及各模块的管理动作（改审批流、解锁、重置 2FA、改权限、调整关联、终止会话……）。可按动作、类别、结果、仅高危、用户、关键字、起止日期筛选，默认最近 7 天，审计数据量大时请带上日期范围；点一行看详情和该用户的其他近期操作；顶部有近 7 天 KPI、近 14 天柱图和最活跃用户。可导出 CSV（≤ 50000 行，防公式注入；导出本身也会被审计）；没有 `audit.export` 按钮权限时“导出 CSV”置灰；导出前会确认筛选条件和命中条数，结果超过 50000 行被截断时页面会提示“请缩小筛选范围分批导出”；
- **SQL 上线审计**：列出全部 SQL 上线工单（审计视角），带状态分布条，可按状态、资源组、关键字、日期筛选；
- **查询审计**：读在线查询日志，按用户、实例、关键字、日期筛选，可“仅被拒绝”；包含被拒绝的语句（语句规则、权限等拦截），超过 1000 字符的 SQL 先截断显示，点击 SQL 展开全文。

类别共 8 种：登录认证、SQL 上线、查询与导出、实例管理、性能工单、SQL 优化、系统管理、其他。

结果、来源 IP、类别 / 模块、权限码和高危标记是写入时附带的扩展信息（旁路表 `dbt_audit_ext`），需先执行 `deploy/sql/090_audit_ext.sql`，建表之前写入的历史行显示“—”；没执行时页面照常，只是没有这些列和相应的筛选。被拒绝语句的记录表需先执行 `deploy/sql/050_query_reject.sql`，没执行时查询审计只显示成功执行的查询。

登录失败连续达到阈值会锁定账号（阈值与锁定时长见“安全策略”），被锁定账号由超级用户在“用户”页解锁；登录提示语不区分“用户不存在 / 密码错 / 被锁定”，防止枚举账号。

## 审计与安全说明

| 项 | 说明 |
|---|---|
| 操作审计 | 本组全部写操作写系统审计，与数据变更在同一事务，审计失败则整体回滚；环境设置、值班表例外：审计在数据修改之后单独写入，写失败只记日志、不回滚 |
| 敏感信息 | 密码、Webhook、签名密钥、SMTP 密码、goInception 密码一律不回显、不进日志与审计；变更记录只记“已更新” |
| 超级用户校验 | 管理类接口每次请求都回库确认操作者仍是启用的超级用户 |
| 撤销生效 | 停用用户、取消超级用户的撤销在本进程立即生效，其他实例最迟约 10 秒 |
| 防护 | 不能停用或降级自己、不能停用最后一个超级用户；内置权限组不能改名或删除 |

## 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 工单卡在某一级审批 | 该级无人可审 | 在“审批流程”看红色警告，给权限组补人或调整资源组成员 |
| 资源组停用被拒绝 | 有进行中的工单 | 页面列出明细，先结束或终止 |
| 登录方式启用不了 | 没有测试通过，或配置变更后测试作废 | 重新测试 |
| 保存并重启 / 回滚不可用 | 没有填 Docker 容器名，或运行环境没有 docker 命令 | 在“部署与重启”里填写容器名；否则只能“仅保存”后自行重启 |
| 保存并重启失败，提示 `permission denied while trying to connect to the Docker daemon socket` | dbtool 的运行用户没有访问 `/var/run/docker.sock` 的权限（不在 `docker` 组）。配置文件已写入，goInception 没有被重启，自动恢复后再次重启同样失败 | 在服务器上执行 `usermod -aG docker dbtool`，再执行 `systemctl restart dbtool`（组变更必须重启服务才生效），回到页面点“仅重启”。`docker` 组成员等同于宿主机 root，请评估；也可改用 sudo 白名单，或不在页面重启 |
| 系统配置页顶部提示密钥是公开值 | `SECRET_KEY` 仍是缺省值 | 用 `dbt-admin gen-secrets` 生成并替换，之后所有人重新登录 |
| 系统配置页提示设置表不存在 | 没执行 `260_setting.sql` | 执行脚本（升级脚本会自动执行） |
| 审计页没有结果 / IP / 类别 | 没执行 `090_audit_ext.sql` | 执行脚本，历史行显示“—” |
| 页面缺少负责人 / 部门等字段 | 没执行 `080_sysadmin_ext.sql` | 执行脚本 |
| 环境设置页提示表未创建，新增环境失败 | 没执行 `270_environment.sql` | 执行脚本，约 30 秒内生效，无需重启 |
| 删除环境被拒绝 | 仍有实例使用或防火墙规则引用 | 把实例改成别的环境或“未设置”，把规则的实例环境范围改掉后再删 |
| 顶栏没有值班信息 | 没执行 `300_duty.sql`；或值班表里没有启用的班次（也没有未结束的调班） | 执行脚本（升级脚本会自动执行），到“值班表”页建班次；约 30 秒内生效，无需重启 |
| 顶栏显示“值班 暂无” | 当前时段不在任何班次里，或值班人（班次或调班的人）的账号已停用 / 删除 | 看“值班表”页顶部的提示（空档、账号异常），补班次或换人 |
| 企业微信渠道测试发送提示“企业微信返回错误 93000 …” | Webhook 地址里的 key 不对，或群里的机器人已被删除（错误码以企业微信返回的为准，信息里有原因） | 回到群里重新复制机器人地址，粘贴到渠道的 Webhook 里 |
| 企业微信渠道发送记录里有“企业微信返回错误 45009 …” | 多半是超过了企业微信每个机器人每分钟 20 条的限制 | 减少这个渠道订阅的事件，或把通知分到几个机器人（几个渠道）里 |
| 企业微信里按“提交人 / 审批人”@，群里只看到名字、没有提醒 | 用户资料里没有企业微信 ID，按平台用户 @ 只写名字 | 改用“渠道原生标识”填成员 userid 或手机号，或用“所有人”，见上面“企业微信渠道” |
| Telegram 渠道保存时提示地址应是 `…/bot<Bot Token>/sendMessage?chat_id=…` 的形式，或缺少 chat_id | 地址不是机器人的 sendMessage 地址，或没带 `chat_id` | 按“Telegram 渠道”一节的写法填：`https://api.telegram.org/bot<Bot Token>/sendMessage?chat_id=<Chat ID>` |
| Telegram 渠道测试发送提示 `HTTP 401 … Unauthorized` | Bot Token 不对，或已在 @BotFather 里被吊销 | 向 @BotFather 重新获取 Bot Token，更新渠道的 Webhook |
| Telegram 渠道测试发送提示 `HTTP 400 … chat not found` | Chat ID 不对，或机器人不在这个群里（频道里还要是管理员） | 把机器人拉进群 / 设为频道管理员，按“Telegram 渠道”一节的方法重新查 Chat ID |
| Telegram 渠道提示“请求失败（api.telegram.org）” | 服务器访问不了 `api.telegram.org`（国内网络通常被屏蔽），或代理太慢（通知请求超时只有 5 秒） | 在服务器上用 `curl https://api.telegram.org` 确认网络；需要代理时给 dbtool 服务配置 `HTTPS_PROXY`，重启服务 |
| Telegram 里按“提交人 / 审批人”@，群里只看到名字、没有提醒 | 用户资料里没有 Telegram 用户名 / ID，按平台用户 @ 只写名字 | 改用“渠道原生标识”填 Telegram 用户名或数字用户 ID，见上面“Telegram 渠道” |

## 验证状态与已知限制

| 项 | 状态 |
|---|---|
| 审批流程、资源组、用户、权限组、审计日志的核心流程 | 在真实 MySQL 上冒烟验证过（测试库用户量很小，大数据量耗时未验证） |
| 080 / 090 / 150 号段扩展表相关功能（负责人、部门、审计扩展信息、内置权限组）与前端交互 | 只用假仓库与假驱动验证，没有在真库验证 |
| “只剩一个超级用户”的 409 分支、强制 2FA 下重置 2FA 后重新绑定 | 未验证 |
| 审批流 | 只用“查询权限申请”真实提交验证过，SQL 上线 / 归档申请没有真实提交过 |
| 审核引擎页的 docker 重启 | 收敛为 docker 后没有任何真实执行记录（真实 `docker restart`、`docker.sock` 权限、`sudo -n`）；真实 goInception 的进程状态接口未验证 |
| 邮件渠道 | 没有对任何真实 SMTP 服务器验证过，上线前请对每个邮件渠道做“测试发送” |
| 企业微信渠道 | 只用本机的假机器人验证过（发送格式、@ 列表、错误处理、页面），没有在真实企业微信群里验证过（markdown 的显示、`<@userid>` 与 @ 手机号 / 所有人的提醒效果），上线前请对每个渠道做“测试发送” |
| Telegram 渠道 | 只用本机的假机器人验证过（发送格式、@ 列表、错误处理、页面），没有在真实 Telegram 群里验证过（消息的显示、`@用户名` 与用户 ID 的提醒效果、话题、经代理访问），上线前请对每个渠道做“测试发送” |
| Redis 规则 | 未在真实 Redis 上验证 |
| 审计页性能 | `dbt_audit_log`、`dbt_query_log` 很大且时间列没有索引时会慢，建议 DBA 手工加索引；CSV 导出数据量更大时更慢 |
| 密码策略 | 用户页里的策略与登录模块的自助改密 / 注册策略是两份实现，常见弱口令清单与相似性判定略有差异 |
| 环境设置 | 字典的校验与实例环境批量设置有单元测试（假后端）；页面与接口处理器、真实 MySQL 上执行 `270_environment.sql` 没有验证记录 |
| 值班表 | 时间计算、校验、接口与权限、顶栏与管理页的浏览器测试（内存存储、固定名单）；真实 MySQL 上执行 `300_duty.sql` 与读写没有验证记录 |
