# 变更工单（SQL 上线）

菜单：变更发布 › 变更工单。所有对生产库的变更（DDL / DML）都通过工单完成：**提交 → 检查 → 逐级审批 → 执行 → 回滚 / 追溯**。在线查询只允许读，变更一律走这里。

## 适用范围

| 实例类型 | 检查 | 执行 | 备份 / 回滚 | 在线改表（OSC） | 批量上线 | 数据导出 |
|---|---|---|---|---|---|---|
| MySQL / PolarDB / PolarDB-X / SelectDB / Doris / ADB | goInception；未配置时降级为基础检查（PolarDB-X / SelectDB / Doris / ADB 的建表工单只做语法检查） | goInception 或原生（上述建表工单只有原生） | 仅 goInception | 仅 goInception | 取决于管理员放开的类型 | ✔ |
| SQL Server | T-SQL 解析 + 上线规则 + 服务端 `PARSEONLY` | 原生（逐批次在事务内执行） | ✖ | ✖ | ✔（默认放开的类型） | ✔ |
| Redis | 管理员定义的命令规则 | 原生，遇错即停 | ✖（规则可记录执行前值） | ✖ | ✖ | ✖ |
| PostgreSQL / MongoDB / ClickHouse | 不支持 SQL 工单 | — | — | — | — | — |

“批量上线”能选哪些实例类型由部署环境变量 `BATCH_DB_TYPES` 决定，默认只有 SQL Server。

## 前提条件与所需权限

| 动作 | 需要的权限码 | 典型角色 |
|---|---|---|
| 查看自己的工单 | `sqlworkflow.view_own` | 研发 / 测试 |
| 查看资源组内全部工单 | `sqlworkflow.view_group` | 组长 / DBA / 审计 |
| 提交工单 / 批量上线 | `sqlworkflow.submit` / `sqlworkflow.submit_batch` | 研发 / 测试 / 组长 |
| 审批通过 / 驳回 | `sqlworkflow.approve` / `sqlworkflow.reject` | 组长 / DBA |
| 立即执行 | `sqlworkflow.execute_group`（资源组内）或 `sqlworkflow.execute_own`（仅自己的单） | DBA / 研发 |
| 定时执行、确认手工执行结束 | `sqlworkflow.schedule`、`sqlworkflow.manual_finish` | DBA |
| 修改可执行时间 | `sqlworkflow.alter_window` | 当前审批人 |
| 终止自己的工单 | `sqlworkflow.cancel_own` | 提交人 |
| 查看 / 下载回滚语句 | `sqlworkflow.rollback` | 提交人 / DBA |
| 在线改表控制 | `sqlworkflow.osc` | DBA |
| 取消执行（执行中的工单） | `sqlworkflow.cancel_run` | DBA |
| 批量实例重试 / 关闭 | `sqlworkflow.batch_op` | DBA |
| 跳过语法检查 | `sqlworkflow.skip_check`（锁定，仅超级用户） | 管理员 |

此外：

- 目标实例必须带“可以写入”（`can_write`）标签、属于所选资源组、你能访问；
- 资源组必须配置了“SQL 上线申请”审批流（空审批流表示直接通过，没配置则提交失败）；
- 没有 `view_group` 的人只能看到自己提交的工单；**看不到的工单一律提示不存在**，不会暴露它是否存在。

## 操作指南

### 操作前的确认框

详情页的关键操作都会先弹出统一的确认框，**页脚显示权限码和按钮名称**，高危操作带红色“高危”标记；点“取消”（或 Esc）不会发出任何请求，接口报错时错误会留在确认框里，可以直接重试：

- **审批通过**：说明这一级是不是末级、通过后进入哪一级审批（时间线上能看到的级别和审批组）、检查结果里有几条警告；
- **立即执行 / 立即导出、定时、确认手工执行结束、终止在线改表、批量实例重试 / 关闭、标记为执行异常、驳回 / 终止**：高危确认，列出工单号、实例、库和将执行的 SQL；其中立即执行 / 立即导出、定时执行、确认手工执行结束、取消执行、批量实例重试，在目标实例的环境（只认实例管理里设置的环境）按生产对待时，还要求键入工单号才能确认，批量工单只要有一个这样的实例就要求；这是页面上的确认，服务端不校验；
- **提交页勾选“跳过语法检查”**（仅超级用户）：先弹高危确认说明风险（不检查、只能原生执行、不备份、无回滚、不支持在线改表）；取消则取消勾选。提交时服务端在审计里记录“跳过语法检查”。

- **工单里的敏感值显示为脱敏后的结果**：SQL 里绑定到“数据脱敏”已配置字段的值（如 `password='…'`、`phone='…'`），除超级用户外所有人（含提交人、审批人）在详情、检查 / 执行结果、回滚语句和通知里只看到脱敏后的值；这类工单不能复制，回滚语句不能下载。库里保存的仍是原文，执行不受影响。识别采用词法分析、宁多勿漏，认不出的写法会把该语句里的值全部遮盖。

### 提交工单

目标：把一段变更 SQL 提交给资源组的审批流。入口：变更发布 › 变更工单 › 「提交工单」。

1. 填写**工单名称**（≤ 50 字），选择**资源组、实例、数据库**。**资源组决定走哪条审批流**；实例下拉只列出带“可写”标签、属于该资源组、你能访问的实例；
2. 在编辑器里写变更 SQL（≤ 200 万字符，多条语句用分号分隔），可选填需求链接（≤ 500 字）、**可执行时间窗口**（开始、结束都可不填，结束必须晚于开始）；
3. 在工单名称右边的选项框里选择是否**备份**（生成回滚语句，仅 goInception 检查 / 执行时有效）；框里同一行还有“批量提交”（见“批量上线”）和“跳过语法检查”（仅超级用户看得到）；
4. 点 **检查**（或在编辑器里按 `Ctrl+Enter`）：逐条返回“通过 / 警告 / 错误”、影响行数估算和改进建议。有错误不能提交；SQL、实例、库或“跳过语法检查”任何一项变化后，之前的检查结果作废，需要重新检查；
5. 点提交，工单进入资源组配置的审批流。

预期结果：工单状态为“等待审批”（空审批流直接“审核通过”，检查有错误且配置了自动驳回时为“自动审批不通过”）。

页头里紧跟标题的**审批流程预览**按所选资源组读取审批流，显示成一条步骤“提交 → 第 1 级 · 审批组 → … → 审核通过，可执行”，逐级只显示审批组，鼠标放上去显示这一级可审批的人员，某一级没有人能审批会标红并注明“无人可审”；窄屏时步骤条换到标题下面一行。需要提醒的情况在页头下面用整行提示条显示：某一级没有人能审批时写明是第几级、哪个审批组；审批流为空时提示提交后直接审核通过（此时没有步骤条）；没有配置时提示提交会被拒绝；审批流读不出来时提示失败原因。

> 注意：提交时服务端会**重新检查一次**，不信任页面上的预览结果；同一用户并发提交也会串行处理。

### 检查规则

- **goInception 已配置**：由 goInception 做语法、规范、索引、表结构层面的审核，并给出影响行数；
- **未配置（降级）**：只做词法级判断——语句必须是 DDL / DML，不连目标库、不校验表结构、拿不到影响行数、不能备份，页面会明确提示“降级检查”；
- **站点规则叠加**：禁止 `SELECT`（请用在线查询）、命中高危语句正则（`review.critical_ddl_regex`）；开启 `review.ddl_dml_separation`（默认关闭）后 DDL 与 DML 不能混在同一个工单里；资源组名带 `DDL` / `DML` 字样时要求语句类型与之一致。批次里只要有一条 DDL 就按 DDL 工单处理，**`DELETE` 也归为 DDL**；
- 检查有错误且管理员配置了自动驳回策略（`review.auto_reject_level`，默认“出现错误时驳回”）时，工单直接变为“自动审批不通过”；
- 检查完成后，编辑器下方会显示检查来源：goInception、SQL Server 语法解析与上线规则、Redis 规则、已跳过检查；未配置 goInception 时显示“基础检查”，管理员强制使用 goInception（`REQUIRE_GOINCEPTION`）时 MySQL 实例暂时无法提交；
- **PolarDB-X / SelectDB / Doris / ADB 的建表工单**（语句全部是 `CREATE TABLE`）：不走 goInception——检查只做**语法检查**（括号 / 引号成对、表名、列定义、`LIKE` / `AS SELECT` 写法，不连目标实例、不校验库表是否已存在，认得 `ENGINE=OLAP`、`DISTRIBUTED BY`、`PROPERTIES`、`DBPARTITION BY` 等各家的建表选项），检查来源显示“已做语法检查（原生方式执行）”；执行只有**原生执行**（逐条直连执行，不备份、无自动回滚），不受“强制使用 goInception”限制；仍需走审批，不会自动通过。工单里混有 `ALTER`、`INSERT` 等别的语句时，仍按上面的方式处理。
- 工单检查还会经过 [SQL 防火墙](#help/firewall)：拒绝类规则让该语句标红，仅告警类规则标黄且不触发自动驳回；执行前还会再复核一次。

```sql
-- 示例：给订单表加一列并建索引（DDL，建议在低峰执行）
ALTER TABLE order_db.orders
  ADD COLUMN pay_channel VARCHAR(16) NOT NULL DEFAULT '' COMMENT '支付渠道',
  ADD INDEX idx_pay_channel (pay_channel);
```

### 审批流与通知链路

审批流按**资源组 × 工单类型**配置（见[管理员指南](#help/sysadmin)里的“审批流程”），由若干“级”组成，每一级对应一个权限组，例如：

1. 第 1 级：组长（本资源组内的组长）；
2. 第 2 级：DBA。

规则：

- 审批人必须**同时**属于“当前这一级的权限组”和“工单所属资源组”，并持有 `sqlworkflow.approve`；超级用户可以审批所有工单；
- **不能自己审批自己的工单**（默认；超级用户可以自审非导出的 SQL 上线工单）；这也是“你是唯一审批人时工单会卡住”的原因；
- 任何一级驳回（必须写原因）即终止；最后一级通过后工单变为“审核通过”；
- **空审批流**：系统直接通过；**没有配置审批流**：提交失败，请联系管理员；
- 自动审核：管理员可开启“自动通过”规则（`review.auto_approve_enabled`）。只有 goInception 检查的、实例类型与标签在配置范围内、不命中排除正则（默认排除 alter / create / drop / truncate / rename / delete 等）、影响行数合计不超过上限（默认 50）的工单才会自动通过，原生降级检查一律走人工；
- 审批流变更只影响之后提交的工单，已在审批中的不受影响；
- 详情页的**审批时间线**每一级只显示审批组，鼠标放上去显示这一级可审批的人员；已审批的级别显示审批人、时间和意见；某一级没人能审批会标红“无人可审”，此时只有超级用户能审批，请联系管理员检查审批流和权限。

通知链路（机器人通知，钉钉 / 企业微信 / 飞书 / Lark / Slack / Telegram 与邮件，**尽力而为，失败只记日志，不影响业务**）：

| 事件 | 谁会被 @ |
|---|---|
| 提交 / 流转到下一级（待处理） | 当前这一级的审批人 |
| 最后一级审批通过 | 提交人与有执行权限的人，工单进入“审核通过” |
| 驳回 / 撤回 / 自动审批不通过（附原因） | 提交人 |
| 提交人终止 | 渠道配置的 @ 规则 |
| 已设置定时执行 / 开始执行 | 提交人 |
| 执行完成 / 执行有异常 | 提交人，DDL 完成时还可额外 @ 指定权限组 |

每条消息包含工单号、发起人、资源组、实例、库、审批流程与当前审批人、SQL 预览（前 500 字符）和详情链接。具体渠道、订阅事件与 @ 规则由管理员在“通知渠道”配置。

### 工单列表

菜单进入后看到的是你可见范围内的工单（可见范围见上文）：

- 顶部的**状态卡片**显示各状态的数量，点击即按该状态筛选；
- 页签「全部 / 我提交的 / 待我审批 / 待我执行」带数量，有待办时数量高亮；
- 可按状态、实例、资源组、工单种类（上线 / 导出）、单实例或批量筛选；搜索框匹配工单号（可带 `#`）、名称、提交人、库和实例；点列标题排序；
- 名称下的标签：`导出 CSV` 等是数据导出工单；`OSC` 含在线改表语句；`跳过检查` 提交时跳过了语法检查、原生执行；`⏱ 时间` 是定时执行时间，等待审批时是提交时设定的计划（审批全部通过后自动转入定时，到点仍未批完则作废）；
- 「当前审批级」列显示审批进行到第几级，轮到你审批的会标出「轮到你审批」。

### 工单状态

状态流转：

```
等待审批 →（逐级通过）→ 审核通过 →（立即执行）→ 排队中 → 执行中 → 已正常结束 / 执行有异常
审核通过 →（设定时间）→ 定时执行 →（到点，调度器每 15 秒扫描）→ 排队中
等待审批 →（提交人撤回 / 审批人驳回）→ 人工终止流程
提交时检查有错误 →（自动审批不通过）
```

| 状态 | 含义 | 下一步 |
|---|---|---|
| 等待审批 | 已提交，正在某一级审批 | 审批人通过 / 驳回；提交人可撤回 |
| 审核通过 | 全部审批通过，等待执行 | 有执行权限的人立即 / 定时 / 手工 |
| 定时执行 | 已设置执行时间，等调度器到点触发 | 到点自动执行；到点前可终止 |
| 排队中 / 执行中 | SQL 已发往目标库 | **不能终止**；页面自动刷新。若服务被重启 / 强杀导致一直停在这里，系统会在几分钟内自动置为“执行有异常”（不会重试），也可在详情页“执行进程失联了？”里手工标记 |
| 已正常结束 | 全部语句执行成功（含手工确认结束） | 可查看 / 下载回滚语句 |
| 执行有异常 | 有语句失败，失败即停，后面的标“未执行”；或执行进程失联（工单日志写“进程重启/失联，执行状态未知”，这种情况不知道哪些语句已执行） | 到目标库确认现状，必要时新开工单修复 |
| 人工终止流程 | 提交人撤回或有权限的人驳回 | 终态 |
| 自动审批不通过 | 检查阶段被自动驳回 | 修改 SQL 后重新提交 |

### 执行

有执行权限的人（资源组内 DBA，或提交人本人且持有 `execute_own`）在详情页操作：

- **立即执行**：先校验“可执行时间窗口”，同一实例同一库上已有 DDL 在执行时会被拒绝并指出冲突工单（**同库 DDL 串行**）；
- **定时执行**：选择一个晚于现在、且在时间窗口内的时间，由调度器（每 15 秒扫描）到点触发；每张工单只有一条生效的定时计划，**到点前可以多次修改**：定时期间详情页的执行卡片里会带出当前的定时时间，改成新时间后点「修改定时时间」即可覆盖旧计划（不用先取消）。定时期间可在详情页**取消定时**，工单回到“审核通过”（不是终止工单），之后可重新设置定时或立即执行；
- **手工执行**：你在别处已经执行完，点“确认手工执行结束”，工单置为已正常结束，系统不执行任何语句；
- **执行方式**：配置了 goInception 默认走 goInception（逐条结果、支持备份与回滚、在线改表）；否则默认原生执行（同一会话逐条执行，失败即停，不备份，执行前检查 `read_only`）。页面会标出“推荐”。

执行结果逐条显示：序号、实例（批量工单）、阶段状态、级别、信息、SQL、影响行数、耗时。每一列都有定义好的宽度，内容在这个宽度里放得下就原样显示；放不下（或本身带换行）的折成一行，末尾用“…”省略，行首带 ▸，点 ▸（或这一行）在同一列宽里展开全文，点 ▾ 折叠，展开后这一列不变宽、别的列不挪动。某一列有折叠的内容时，列头旁会出现 ▸，一键展开 / 折叠整列；标题旁的“展开全部 / 折叠全部”管所有列。汇总行的信息（整句汇总）整句显示、不折叠，“在线改表”列的按钮不受影响。窗口变宽 / 变窄后会按新的宽度重新判断；窗口太窄（内容区窄于约 1100 px，批量工单约 1300 px）时表格出现横向滚动条。排队中 / 执行中的详情页会自动刷新并显示进度条（批量工单按实例计数，在线改表自动轮询进度）。

**复制为新工单**：已结束或已终止的工单详情页有此按钮，带出名称、实例、库和 SQL，到提交页修改后重新提交（数据导出工单同理）。

### 回滚语句

只对**开启了备份且已结束**的 goInception 工单可见：详情页“回滚语句”页签按执行顺序倒序展示，可复制或下载为 `.sql`。回滚语句是反向 SQL，**执行回滚前请先评估数据是否已被后续业务写入**。每次查看 / 下载都会写入审计日志。

### 在线改表（OSC）

大表 DDL 可使用 gh-ost / pt-osc。执行中详情页显示进度，并提供 **暂停 / 恢复 / 终止**（需要 `sqlworkflow.osc`，且工单在执行中；服务端校验操作的任务确实属于这张工单）。

### 批量上线

适用于同一段 SQL 在多个实例上执行（管理员只放开了部分实例类型）：

- “批量提交”开关一直显示在工单名称右边的选项框里，把目标实例选成管理员放开批量的类型（默认只有 SQL Server）后才能勾选，其它类型置灰、不能勾选，鼠标放上去提示“仅支持 MSSQL”（放开了其它类型时一并列出）；类型对、但没有 `sqlworkflow.submit_batch` 时提示“没有批量提交的权限”。勾选后在“选择要上线的实例”里选择多个实例（最多 100 个，类型必须一致；标题、搜索框、全选、清空和“已选 n / 100”排在一行，搜索框在全选前，输入即筛选，空格分隔多个关键词，“全选”只选搜索结果）。打开批量后页面上其它字段的位置不变，“目标实例”只用来判断能不能批量，提交哪些实例以勾选的为准；把它换成不支持批量的类型（如 MySQL 系、Redis），批量会自动关闭并置灰；屏幕够宽时，标题和搜索那一行放在日期右边的空位，不够宽时占下面一整行；实例列表在它下面单独占一整行，左右边缘和上面的字段对齐；
- 数据库列表和语法检查只取第一个勾选的实例，另外**预检每个实例**（能连通、库存在）；任一实例预检失败则不允许提交；
- 执行时每个实例各跑一遍（SQL Server 并行，默认 4 路，其余串行），**单个实例失败不影响其他实例**；
- 有失败时工单为“执行有异常”，汇总里写明“已有 N 个实例已生效，请人工核对”；失败实例可单独 **重试**（在该实例上重新执行整段 SQL，用新结果替换旧结果，重试期间工单为“执行中”）或 **关闭**（不再计入成败，也不能再重试）。全部实例都被关闭时不会被标成成功；
- 批量详情里的“各实例状态”表有**数据库版本**列：打开详情页时不连库，页面加载后逐个实例异步取版本，取不到显示“未知”；
- 列表可按“单实例 / 批量”筛选，批量工单带“批量 N”标记。

### 终止与撤回

| 当前状态 | 谁能终止 |
|---|---|
| 等待审批 | 提交人（称为“撤回”）、当前审批人（称为“驳回”，需写原因） |
| 审核通过 / 定时执行 | 提交人，或有执行权限的人（非提交人还需要 `sqlworkflow.reject`） |
| 排队中 / 执行中 | 不能终止（执行时间太长时，DBA / 超级用户可「取消执行」） |

终止、撤回、驳回都必须写原因（≤ 500 字）；非提交人在审批阶段由当前审批人驳回。

**取消执行**（`sqlworkflow.cancel_run`）：在详情页进度卡片（导出工单是“导出进度”卡片）里填写取消原因（必填，最多 500 字）后点「取消执行」，原因和操作人写入工单日志与系统审计；只有正由当前服务进程执行的工单才有这个入口（多个服务实例时，在别的实例上执行的工单在这里点不了，进程已失联的用「标记为执行异常」）。正在执行的语句会被中断（目标库回滚这一条，大事务回滚也要时间），其后的语句不再执行；**已成功的语句不会回滚**，工单变为“执行有异常”，不会自动重试。批量工单会中断所有正在执行的实例；用 goInception 执行时取消只断开与 goInception 的连接，已下发到目标库的语句可能仍在执行，请到[会话诊断](#help/instance)核对并终止。

> 警告：执行中的工单一旦发出就无法撤回：SQL 已经到达目标库，不能终止（DBA 只能「取消执行」，已成功的语句不会回滚）。请在“审核通过”阶段再确认一遍语句和执行时间。

**进程失联怎么办**：工单一直停在排队中 / 执行中、且确认没有进程在执行时，提交人、资源组的执行 / 审批人和超级用户可以在详情页展开“执行进程失联了？”，填原因后点“标记为执行异常”（需要 `sqlworkflow.cancel_own` 或 `sqlworkflow.reject`）。系统会先检查该工单的执行锁，仍在执行的会被拒绝。标记后**不会重试**，请务必到目标库核对哪些语句已经执行。即使不手工标记，系统也会在服务启动时和之后每 5 分钟自动处理这类工单。

### Redis 工单

选到 Redis 实例时，提交页是“命令模式”：库选 `db0…`（就是 db 编号），输入框里**每行一条命令**（写法同 redis-cli，支持引号和 `\xHH`，一次最多 200 条），点“检查命令”逐行得到 通过 / 警告 / 拒绝。

- **规则由管理员定义**：每条命令必须同时命中某条启用规则的 命令名、键匹配、适用范围、键数上限，否则拒绝；没有规则就全部拒绝。规则只有超级用户能在“安全合规 › Redis 规则”里改，见 [管理员指南](#help/sysadmin)；
- **硬禁止**：`FLUSHALL`、`FLUSHDB`、`CONFIG`、`EVAL`、`KEYS`、`SELECT`、`AUTH`、`SORT … STORE` 等任何规则都放行不了；`PUBLISH` 这类无键命令、`GET` 这类读命令也不能通过工单执行；
- **只要有一行被拒绝就不能提交**；提交时服务端会再检查一次。警告不拦截，例如 `SET` 没带过期时间、`EXPIRE` 的时间 ≤ 0（会立即删除）；
- 审批流、通知、定时、手工执行、终止与其他工单一样。执行时按**当时的规则整单复检**（审批期间规则被改，以现在的为准，任一行不再通过则一条都不执行），再逐条执行，**遇错即停**，后面的命令标“未执行”；
- **没有自动回滚**。规则勾选了“记录执行前值”的命令，原值会明文记在执行结果里（详情页“执行前的原值”）供人工恢复，不是完整备份；
- 命令原文会保存在工单里，**请勿在命令里写入密码等敏感信息**。

## 字段与选项说明

| 字段 | 含义 | 取值与默认 | 约束 |
|---|---|---|---|
| 工单名称 | 工单标题 | 文本 | 必填，≤ 50 字 |
| 资源组 | 决定审批流与可选实例 | 下拉 | 必须是你所在的资源组 |
| 实例 / 数据库 | 执行目标 | 下拉 | 实例需带 `can_write` 标签；库名 ≤ 64 字符 |
| 变更 SQL | 要执行的语句 | 文本 | ≤ 2000000 字符；多条用分号分隔 |
| 需求链接 | 关联需求 | 文本，可空 | ≤ 500 字 |
| 可执行时间窗口 | 限定执行的时间范围 | 开始 / 结束，可空 | 结束必须晚于开始；窗口外不能立即执行 |
| 执行前备份 | 生成回滚语句 | 默认勾选 | 仅 goInception 检查有效；SQL Server、Redis、批量与降级检查没有备份 |
| 批量提交 | 同一段 SQL 在多个实例上执行 | 默认不勾选；开关一直显示，目标实例不是管理员放开批量的类型时置灰 | 需要 `sqlworkflow.submit_batch`，见“批量上线” |
| 定时执行时间 | 到点由调度器执行 | 可空 | 必须晚于现在且在窗口内 |

关键系统配置（超级用户在“平台设置 › 系统配置 › SQL 上线与审核”修改）：

| 配置键 | 含义 | 默认 |
|---|---|---|
| `review.critical_ddl_regex` | 命中的语句按高危直接驳回（Go RE2 正则） | 空 |
| `review.ddl_dml_separation` | 同一工单不允许 DDL 与 DML 混合 | 关闭 |
| `review.auto_reject_level` | 检查出问题时自动驳回的级别（warning / error / never） | error |
| `review.auto_approve_enabled` | 满足条件的工单不经人工审批直接通过 | 关闭 |
| `review.auto_approve_max_rows` | 自动通过允许的影响行数合计 | 50 |
| `review.batch_parallel_workers` | 批量工单并发实例数（只有 SQL Server 并发） | 4，范围 1–16 |
| `approval.forbid_self_approve` | 禁止审批自己提交的工单 | 开启 |

> 注意：goInception 检查的工单是否备份，代码里的行为是：`review.backup_enabled` 不为 true（默认）时服务端强制备份，与提交页勾选无关；系统配置页对该项的说明文字与此相反，以实际行为为准，需要管理员核对。

## 规则、限制与注意事项

- DDL 尽量放在低峰窗口，用“可执行时间窗口”限定；大表变更先在测试实例演练；
- 提交前先在 [SQL 体检与智能调优](#help/optimize) 里看一眼执行计划与索引建议；
- 同库 DDL 串行：同一实例同一库上已有 DDL 在执行时，新的立即执行会被拒绝；
- 执行失败即停，不会继续执行后面的语句，也不会自动回滚已成功的语句；
- 原生执行（未配置 goInception 或选择原生）不备份、不支持在线改表；
- 回滚语句依赖 goInception 备份库保留原备份数据，备份库被清理后无法读取。

## 审计与安全说明

| 项 | 说明 |
|---|---|
| 系统审计 | 提交、审批通过、驳回、撤销、立即 / 手工 / 定时执行、取消定时、修改可执行时间、在线改表的暂停 / 恢复 / 终止、批量实例的重试 / 关闭、启动恢复，各写一条系统审计（动作名“SQL上线-…”，归入“SQL 上线”类别并带对应按钮权限码）；写审计失败不影响操作本身 |
| 回滚语句访问 | 查看 / 下载回滚语句的每一次操作都会写入审计日志 |
| 工单日志 | 工单自己的时间线（提交、审批、定时、执行、取消、标记异常）随详情展示 |
| 可见性 | 看不到的工单一律提示“不存在”；服务端对每个接口按权限码再校验 |
| 防火墙 | 提交检查与执行前复核都会经过 SQL 防火墙，复核按**提交人**的身份判断，换人点执行不能绕过 |
| 敏感信息 | Redis 命令原文与记录的原值会明文保存在工单里，请勿写入密码 |

## 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 工单卡在审批 | 某一级无人可审，或你是唯一审批人 | 看时间线上的“无人可审”标红，联系管理员；也可看 [常见问题](#help/faq) |
| 检查只有“基础检查” | goInception 没配置 | 联系管理员配置 goInception |
| 提交时报“未开启上线权限” | 实例缺少 `can_write` 标签 | 联系 DBA 打标签 |
| 立即执行被拒绝 | 不在时间窗口内，或同库已有 DDL 在执行 | 提示里会指出冲突工单，等待或改定时 |
| 执行中想停止 | 不能终止，只能取消执行 | DBA 在进度卡片填原因点「取消执行」，之后到[会话诊断](#help/instance)核对 |
| 看不到回滚语句 | 工单没开备份、未结束，或不是 goInception 执行 | 属正常；需要时手工编写修复语句新开工单 |
| 批量工单部分实例失败 | 个别实例连接或语句失败 | 对失败实例“重试”或“关闭”，其余不受影响 |

## 验证状态与已知限制

| 项 | 状态 |
|---|---|
| 审批引擎、状态机、权限、自动审核 / 驳回、通知、定时、恢复、回滚、OSC、批量、导出 | 单元测试覆盖；原生执行用假 MySQL 验证；脚本化的真库冒烟已移除，当前不再提供 |
| goInception 的检查、执行、备份读取与 OSC | 只用假 goInception 服务验证，真实 goInception 的返回未联调，上线前请在有 goInception 的环境走一遍 |
| SQL Server（T-SQL 解析、`PARSEONLY`、事务内执行、`PRINT` 消息收集、批量并发） | 只用假后端验证，未在真实 SQL Server 上验证 |
| Redis 工单 | 未在真实 Redis 上验证各版本对 `SET … GET`、`GETEX`、`COPY` 等的支持与 ACL 报错文案 |
| 取消执行 | 只能由正在执行该工单的进程处理；goInception 工单取消后目标库上的语句可能仍在执行 |
| 进程被强杀 | 自动置为“执行有异常”，不重试，SQL 可能已部分执行，必须人工核对 |
| 进度条数据 | 在内存里，别的进程执行时只能显示已用时间 |
| 详情页结果表的折叠 | 只用无头 Chrome 的页面测试（折叠 / 展开 / 列头 / 展开全部 / 窗口宽度变化 / 键盘）和一张单实例的测试工单验证过；没有在几十个实例的真实批量工单上看过，各列的宽度按常见内容定的，实例名特别长、结果有几千行时的观感未验证 |
