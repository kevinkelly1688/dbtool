# 快速入门

dbtool 是数据库运维管理平台：围绕 MySQL 协议系实例（MySQL / PolarDB / PolarDB-X / SelectDB / Doris / ADB）、SQL Server、Redis、PostgreSQL、MongoDB、ClickHouse，提供 **SQL 上线审核、在线查询、数据导出、慢日志、SQL 优化、性能工单、实例管理** 和一套细到按钮的权限体系。本手册同时服务于开发、测试、组长（审批人）、DBA 和管理员五类角色，每一章都按“能做什么、前提条件、怎么做、有什么限制”来写。

## 适用范围

下表是各功能对实例类型的支持概览（✔ 支持，部分 = 只支持其中一部分能力，✖ 不支持）。完整矩阵与每个“部分”的含义见各章节；表里没有的类型（如 Oracle、Cassandra）可以登记为实例，但没有任何业务功能使用它们。

| 实例类型 | 在线查询 | SQL 上线 | 数据导出 | 性能巡检 | 实例管理 |
|---|---|---|---|---|---|
| MySQL | ✔ | ✔ | ✔ | ✔ | ✔ |
| PolarDB / PolarDB-X | ✔ | ✔ | ✔ | ✔ | ✔ |
| SelectDB / Doris / ADB | ✔ | ✔ | ✔ | ✔ | 部分 |
| SQL Server | ✔ | ✔（含批量上线） | ✔ | ✔ | 仅实例列表 |
| Redis | ✔（只读命令） | ✔（命令 + 管理员规则） | ✖ | ✔ | 仅实例列表 |
| PostgreSQL / MongoDB / ClickHouse | ✔ | ✖ | ✖ | ✖ | 仅实例列表 |

> 注意：“实例管理”列里，MySQL / PolarDB / PolarDB-X 支持全部页面；SelectDB / Doris / ADB 只有会话、数据库、参数（没有事务与锁、账号管理）；“仅实例列表”表示只能在实例列表里登记、编辑和测试连接。

## 界面介绍

登录后的页面由三部分组成：

- **侧栏（左）**：按分组列出你有权限打开的菜单，默认全部展开，点分组标题可以折叠（会记在本机浏览器）；带数字的角标是你的待办（变更工单 / 权限申请 = 等你审批的单子，数据归档 = 等你审批的归档申请，性能工单 = 你的待办，橙色表示已有超时）。数字有十几秒缓存，处理完单子后可能稍晚才消失。
- **顶栏**：左侧是当前页面标题和所属分组；右侧依次是「? 使用文档」（打开**当前页面对应的文档章节**）和头像菜单（个人信息与权限、修改密码、界面主题、退出登录等）。
- **内容区**：当前页面。表格外层带横向滚动，窗口窄于 900 px 时布局会自动折叠。

页面里只保留操作本身，字段含义、规则、限制和注意事项都写在使用文档里：在任何页面点顶栏的「? 使用文档」，就会打开该页面对应的章节；章节内可以用左侧的搜索框做全文检索。

头像菜单里可以查看“个人信息与权限”（你属于哪些权限组、哪些资源组、能看到几个实例，以及你拥有的全部按钮权限）、修改密码（仅本地账号）、查看两步验证状态、退出登录。

## 前提条件与所需权限

使用任何业务功能之前，需要同时满足下面几项：

| 前提 | 说明 | 谁来配置 |
|---|---|---|
| 平台账号 | 本地账号或公司单点登录账号，见 [登录与账号安全](#help/login) | 管理员（用户） |
| 权限组 | 决定你能打开哪些页面、点哪些按钮，见 [按钮级权限](#help/btnperm) | 管理员（权限组） |
| 资源组 | 决定你能看到哪些实例、工单走哪条审批流 | 管理员（资源组） |
| 实例标签 | 实例带“支持查询”（`can_read`）才能导出和申请查询权限；带“可以写入”（`can_write`）才能提交 SQL 上线工单 | DBA（实例列表） |
| 库表查询权限 | 在线查询要求对涉及的库 / 表有有效的查询权限，见 [权限申请与查询权限](#help/qpriv) | 审批人 / 管理员 |

**界面里没有某个菜单，说明你没有对应权限**（菜单是否显示取决于你是否持有该页面的“查看类”按钮码，见 [按钮级权限](#help/btnperm)）。找管理员或所在资源组的负责人开通。

## 首页

登录后默认进入首页（工作台），汇总你权限范围内需要处理的事项；没有权限或服务未启用的区块不显示。

| 区块 | 内容 |
|---|---|
| 页头 | 问候、日期；右侧「提交 SQL 工单」直达提交页（需要 `sqlworkflow.submit`） |
| 顶部 KPI | **待我审批**（点击跳到下方待办）、**进行中工单（我的 / 全部）**（我提交的、还没结束的 SQL 工单 / 你可见范围内全部进行中的工单）、**性能工单待办**（超时的会标出个数）、**我可见的实例**（下面一行汇总这些实例各自最近一次巡检里有告警、巡检失败的个数——是巡检结果，不是实例当前是否连得上；有告警或失败时点击直接打开巡检列表，只看每个实例最近一次的报告；没有告警时点击打开实例列表） |
| 数量卡 | 待审核的 SQL 工单（可见范围内等待审批）、可执行的 SQL 工单（审核通过、等待执行）、待处理的权限申请（审批中的查询权限申请） |
| 我的待办 | 页签「待我审批」（SQL 上线、查询权限、数据归档）/「我提交的」/「性能工单」，点一行进入详情；标题旁的数字是待我审批与性能工单待办的合计 |
| 最近的工单 / 申请 | 最近的 SQL 工单和权限申请，点「全部」进入列表 |
| 近 7 日 SQL 工单 | 你可见范围内每天提交的工单数，今天的柱高亮 |
| 实例健康 | 你可见的实例及最近一次性能巡检的结果；状态取自巡检结果，不会现场连接数据库，灰点表示没有巡检权限或还没有巡检过 |
| 最近动态 | 有审计权限看全平台，否则只看自己的操作 |
| 平台状态 | goInception 检查服务、通知渠道、定时调度器（权限还没迁移时超级用户另有一项“按钮权限迁移”提醒） |
| 快捷入口 | 按你的权限列出可进入的功能 |

## 按钮的三种状态

页面里所有会产生副作用的按钮都由权限码驱动，你会看到三种形态：

| 形态 | 外观 | 含义 |
|---|---|---|
| 可用 | 正常按钮，悬停提示权限名；高危按钮悬停会注明“（高危）” | 你持有该权限码 |
| 隐藏 | 按钮直接不出现（默认呈现方式） | 你没有该码，且管理员没有改成置灰 |
| 置灰 | 置灰并带 🔒，悬停提示“无权限：需要「xxx」（权限码）” | 你没有该码，且管理员在权限组页把“无权限的按钮”设为置灰；“仅超级用户可用”表示该码是锁定码，权限组也授不出去 |

**高危按钮**（执行上线、终止会话、删除、授权回收等）点击后不会立刻生效：先弹出二次确认，说明将要做什么，部分操作还需要键入指定文本（例如库.表名、Binlog 文件名）才能点确认。所有写操作都会记入[系统审计](#help/sysadmin)。

> 提示：权限刚被管理员修改后，最长约 15 秒生效；刷新页面即可。

## 你能看到哪些实例

实例的可见范围由**资源组**决定：你所在资源组关联的实例才会出现在各页面的实例下拉里。例外是持有“查看 / 查询全部实例”权限（`query.admin_run`）的人以及超级用户，他们看得到所有启用的实例。

例如只属于“订单中心”资源组的研发，只能看到该资源组关联的实例；属于多个资源组的人能看到它们的并集。实例可以不绑定资源组，此时普通用户暂时看不到它。已被 DBA 停用的实例不再出现在在线查询、SQL 上线、巡检等页面。

## 常见角色

平台没有写死的“角色”，角色就是**权限组**（详见 [按钮级权限](#help/btnperm)）。内置的预设权限组如下，具体以管理员的配置为准：

| 角色 | 典型权限 |
|---|---|
| 超级用户 | 全部菜单；访问控制、安全合规、平台设置里的锁定类按钮只有超级用户能点 |
| DBA | 审批 / 执行 SQL 上线、实例管理、性能工单处理、查看全部实例；不含 Binlog 回滚 / 下载、审计日志 |
| 组长（TL） | 审批本组 SQL 工单和查询权限申请，不能执行上线 |
| 研发（RD） | 提交工单、执行自己的工单、在线查询、申请权限、提交导出、受理性能工单 |
| 测试（QA） | 提交工单、在线查询、提交与下载导出、查看回滚语句，不能自行执行上线 |
| 审计 | 只读审计日志与全部工单、导出审计日志（预设，需自行建组套用） |
| Default | 新用户默认：在线查询，以及申请 / 查看查询权限 |

想知道自己是哪一种，点右上角头像 → 「个人信息与权限」，可以看到你所属的权限组以及拥有的全部按钮权限。

## 主题与水印

头像菜单里可在 **明亮 / 深空 / 护眼** 三套主题间切换，选择保存在浏览器本地。页面水印（默认是“姓名（账号）时间”）由超级用户在[安全策略](#help/login)里统一定义，用于截图溯源；你只能看到它，不能自行关闭或修改。

## 一次典型的上线流程

1. 研发在 **权限申请** 申请库表查询权限，在 **在线查询** 里确认数据；
2. 研发在 **SQL 上线** 提交变更 SQL，系统用 goInception 检查；
3. 工单按资源组审批流逐级审批（常见：组长 → DBA）；
4. DBA（或有权限的提交人）选时间执行，必要时下载回滚语句；
5. 上线后慢 SQL 由系统自动转成 **性能工单**，研发按 SLA 处理。

各环节的细节见 [SQL 上线](#help/sqlworkflow)、[权限申请与查询权限](#help/qpriv)、[性能工单](#help/perf)。遇到问题先看 [常见问题](#help/faq)。
