# 实例管理

实例管理是 DBA 登记、查看和维护目标库的入口，包含实例列表、会话诊断、数据库、帐号维护、参数管理和日志解析六个页面（性能巡检见[单独一章](#help/inspect)）。所有会改变目标库的操作都需要二次确认并写入系统审计，成功和失败都记录，语句中的密码会打码。

## 1. 功能概述

| 页面 | 菜单 | 解决的问题 |
|---|---|---|
| 实例列表 | 实例运维 › 实例列表 | 登记、编辑、停用、删除实例；测试连接；查看运行状态；清理 Binlog |
| 会话诊断 | 实例运维 › 会话诊断 | 查看进程、Top 表空间、事务、锁等待链，终止会话 |
| 数据库 | 实例运维 › 数据库 | 查看库清单、登记负责人与备注、创建数据库 |
| 帐号维护 | 实例运维 › 帐号维护 | 查看账号与权限，创建、授权、回收、改密、锁定、删除账号 |
| 参数管理 | 实例运维 › 参数管理 | 查看运行值，按参数模板修改动态参数，查看修改历史 |
| 日志解析 | 实例运维 › 日志解析 | 把一段 binlog 还原成 SQL 或生成回滚 SQL |

## 2. 适用范围

✔ 表示支持，✖ 表示不支持，“部分”的含义写在表后。

| 功能 | MySQL | PolarDB / PolarDB-X | SelectDB / Doris | ADB | SQL Server / Redis | PgSQL / MongoDB / ClickHouse |
|---|---|---|---|---|---|---|
| 实例列表、状态探测 | ✔ | ✔ | 部分 | ✔ | 部分 | 部分 |
| 测试连接 | ✔ | ✔ | ✔ | ✔ | 部分 | 部分 |
| 进程、Top 表空间、终止会话 | ✔ | ✔ | ✔ | ✔ | ✖ | ✖ |
| 事务、锁等待 | ✔ | ✔ | ✖ | ✖ | ✖ | ✖ |
| 数据库 | ✔ | ✔ | 部分 | 部分 | ✖ | ✖ |
| 帐号维护 | ✔ | ✔ | ✖ | ✖ | ✖ | ✖ |
| 参数管理 | ✔ | 部分 | 部分 | 部分 | ✖ | ✖ |
| Binlog 清理、Binlog 解析 | ✔ | ✖ | ✖ | ✖ | ✖ | ✖ |
| 慢日志采集开关生效 | ✔ | ✔ | ✔ | ✖ | 部分 | ✖ |

“部分”的含义：

- 状态探测：SQL Server、Redis、PgSQL、MongoDB、ClickHouse 只测连通性并读取版本，没有 QPS 和连接数；SelectDB / Doris 读不到运行状态时只确认连接与版本，仍判为正常。
- 测试连接：非 MySQL 协议的实例经 SSH 隧道时暂不支持测试，会返回“暂不支持经 SSH 隧道测试”。
- 数据库：创建数据库时指定字符集和排序规则只对 MySQL / PolarDB / PolarDB-X 开放。
- 参数管理：生成 `my.cnf` 片段只对 MySQL 实例提供。
- 慢日志采集：SQL Server 的开关可以置位，但采集器不处理；Redis 走独立的 `SLOWLOG GET` 采集；ADB 的开关可以置位，采集器不处理。
- PgSQL / MongoDB / ClickHouse 在列表里标“仅查询”，只接入[在线查询](#help/query)。
- Oracle、Cassandra、Elasticsearch、OpenSearch、Memcached、TDengine 可以登记，但本章各功能均不适用。
- 实例类型下拉里没有 MariaDB 选项，MariaDB 服务端按 `mysql` 类型登记。

## 3. 前提条件与权限

### 3.1 可见范围

超级用户或持有按钮 `query.admin_run`（查看 / 查询全部实例，不受库表授权限制）的用户看到全部实例。能新增、修改或删除实例的用户也看到全部实例。其余用户按资源组关联范围查看。没有关联资源组的实例，普通用户看不到。

### 3.2 页面与权限码

| 页面 | 按钮码 |
|---|---|
| 实例列表 | `instance.view`、`instance.test`、`instance.add`、`instance.edit`、`instance.delete`、`instance.purge_binlog` |
| 会话诊断 | `session.process`、`session.tablespace`、`session.trx`、`session.locks`、`session.kill` |
| 数据库 | `database.view`、`database.edit`、`database.create` |
| 帐号维护 | `account.view`、`account.create`、`account.edit`、`account.grant`、`account.pwd`、`account.lock`、`account.delete` |
| 参数管理 | `param.view`、`param.edit`、`param.template` |
| 日志解析 | `binlog.view`、`binlog.parse`、`binlog.rollback`、`binlog.download` |

> 注意：`instance.purge_binlog`、`binlog.rollback`、`binlog.download` 默认只给超级用户，需要在权限组里单独授予。按钮权限的分配方法见[按钮级权限](#help/btnperm)。

### 3.3 目标库账号

平台登记的实例账号决定了各功能能否在目标库上成功执行。各类型实例的最小 GRANT 模板见安装部署指南（`docs/ops-manual.md`）附录 E（该权限映射标记为“待验证”）。以下几条来自代码行为：

| 功能 | 账号需要 |
|---|---|
| 进程列表、终止会话 | 能读取进程列表（`PROCESS`）；终止他人线程的权限未在真实服务器上验证 |
| 帐号维护 | 对 `mysql.user` 有 `SELECT`，否则返回 502 |
| Binlog 清理 | 能执行 `SHOW BINARY LOGS`（`REPLICATION CLIENT`） |
| Binlog 解析 | `REPLICATION SLAVE` 和 `REPLICATION CLIENT` |

## 4. 操作指南

> 实例列表的 HOST:PORT 列：地址超过 30 个字符时只显示一半左右（省略号），点一下该地址展开完整内容，再点收起；悬停也能看到完整地址。

### 4.1 添加实例

目标：把一个目标库登记到平台。入口：实例运维 › 实例列表 › 添加实例。

1. 填写名称、类型、角色、主机、端口、管理账号和密码。
2. 按需选择标签、所属资源组、SSH 隧道和显示 / 隐藏库规则。
3. 点保存，在确认框核对将登记的字段（密码只显示“已填写”，不回显）。
4. 确认后实例出现在列表中，可点“测试连接”验证。

预期结果：列表出现新实例；审计记录“新增实例”。新建表单默认角色为 `master`、类型为 `mysql`、端口 3306；切换类型时端口自动填 SQL Server 1433、Redis 6379、PgSQL 5432、MongoDB 27017、ClickHouse 8123（仅当端口为空或仍是某个默认值时才跟着变）。

### 4.2 测试连接

用保存的账号实际连一次目标实例并显示版本。添加和编辑表单里的“测试连接”使用表单当前值，编辑已有实例时密码留空沿用已保存的密码。认证失败和连接失败的提示里不含密码。

### 4.3 编辑、停用与启用

1. 在列表行点“编辑”，修改后保存。密码留空表示不修改。保存前会弹出字段对比确认。
2. 行内“停用 / 启用”是实例级停用：平台不再连接该实例，它也不再出现在在线查询、SQL 上线、巡检、慢日志采集等页面的实例列表里，已有工单、报告和数据保留，随时可以重新启用。
3. “慢日志采集”开关与停用是两回事，只能在编辑表单的复选框或批量“开启 / 关闭采集”里修改。

### 4.4 删除实例

1. 在行内点“删除”，系统先检查引用并列出数量与建议。
2. 没有引用时，在确认框键入实例名确认。

被以下对象引用时会拒绝删除：SQL 工单、批量导出工单、查询权限申请、查询权限、分区维护配置、数据归档任务、脱敏字段配置、巡检报告、性能工单、慢日志采集数据。账号登记、数据库登记、参数修改历史和 Redis 慢查询采集数据会随实例一并删除。归档运行记录只提示、不阻断，并且保留。每类引用统计最多数到 10000，超出显示“N+”。被拒绝的删除会写审计“删除实例（拒绝）”。

### 4.5 批量操作

勾选行首复选框（表头可全选当前页），再点操作条上的按钮。一次最多 100 个，超过会提示“一次最多处理 100 个实例”。

| 操作 | 说明 |
|---|---|
| 批量启用 / 批量停用 | 只处理状态需要变化的实例，已是目标状态的被跳过 |
| 批量开启 / 关闭采集 | 只改慢日志采集开关；不支持采集的类型会被跳过；关闭后已采集的数据保留；已停用的实例要重新启用后才开始采集 |
| 批量设置环境 | 在下拉框选一个环境（环境字典里的项，或“未设置”）后点“批量设置环境”；已是目标环境的被跳过；需先执行 `deploy/sql/070_instance_ext.sql` |
| 批量删除 | 先检查引用，列出能删与不能删的（含原因）；键入 `删除N个实例`（无空格，N 为可删除的个数，如 `删除3个实例`）确认；被引用的跳过 |

除“批量设置环境”只写一条汇总审计外，其余批量操作逐实例留审计并另写一条汇总。

### 4.6 清理 Binlog

目标：释放目标库磁盘上过期的 binlog。仅 `mysql` 类型实例，权限码 `instance.purge_binlog`。

1. 在行内点“Binlog 清理”，选定要保留的起始文件。
2. 点“预览”：页面列出将被删除的文件与大小，以及连着的从库及其读取位置。
3. 如果清理目标越过某个从库的读取进度，预览会标记为不可执行，执行也会被拒绝并写审计“清理Binlog（拒绝）”。
4. 键入所选文件名确认后执行 `PURGE BINARY LOGS TO`，早于该文件的 binlog 被删除。

从库核对只针对平台里登记为从库、类型为 `mysql` 且地址与 `Binlog Dump` 连接来源一致的实例。未登记或读不到进度的从库只给警告，不会阻止清理，请自行确认它们已读过目标文件。

> 警告：清理后的 binlog 不可恢复。从库、增量备份和 Binlog 解析都依赖 binlog，执行前请确认所有消费方已读过目标文件。

### 4.7 查看会话、事务与锁

入口：实例运维 › 会话诊断，先选择实例。各页签按对应权限码分别显示，全部无权限时提示“你没有查看会话、表空间、事务或锁信息的权限”。

| 页签 | 内容 |
|---|---|
| 进程列表 | 可按命令类型、用户、库、时长、关键字筛选。顶部统计连接总数、活跃（非 Sleep）、长时间运行（至少 300 秒，不含 Sleep 和受保护线程）、阻塞源。耗时至少 300 秒标黄、至少 1200 秒标红，两档都带“长时间运行”标记 |
| Top 表空间 | 来自 `information_schema.tables`，按数据、索引与碎片总量降序；碎片率至少 20% 且碎片至少 1024 MB 的行标黄；MySQL 8.0 默认缓存统计值 24 小时（`information_schema_stats_expiry`），数字可能略有延迟 |
| 事务 | 来自 `information_schema.innodb_trx`；事务当前没有语句在跑时，info 取该线程最近执行的语句（需要 `performance_schema`）；持续 60 秒以上标黄；点 thread_id 跳到进程列表并选中该会话 |
| 锁信息 | 5.7 读 `information_schema.innodb_lock_waits`，8.0 读 `performance_schema.data_lock_waits`；“阻塞链”把互相等待的线程整理成树，根因（只阻塞别人、自己没在等）在最上面 |

进程列表最多返回 1000 行，超出时提示“会话太多，只显示了前 1000 个”。事务与锁等待各最多 200 行。

### 4.8 终止会话

目标：终止长时间运行或阻塞他人的会话。权限码 `session.kill`。

1. 勾选多行（一次最多 50 个）或点行内“终止”。
2. 第一步：预览。服务端根据所选线程当前状态生成 `KILL n`，页面不提交任何手写语句。
3. 第二步：确认后服务端再次校验，通过的才执行 `KILL`。
4. 被拒绝的会话在结果里给出原因。

服务端复核的内容：线程仍然存在；带了用户或主机时必须与现在一致（防止线程号被复用而误杀）；不是平台自己的连接；不是复制线程（`Binlog Dump`、`system user`）、事件调度线程和后台线程（`Daemon`）。审计只记线程号、用户、主机、库、状态和已运行秒数，不记录会话正在执行的 SQL。

> 注意：终止一个大事务会触发回滚，回滚期间会话仍占用资源，不要反复重试，先看事务的修改行数再决定。

### 4.9 管理数据库

入口：实例运维 › 数据库，先选择实例。

- 库清单：“已录入”指平台里登记了负责人或备注的库（表 `dbt_instance_database`），其余库来自实例的 `information_schema`。点“录入”补充负责人与备注（`database.edit`），筛选里选“未录入”可只看这些库。系统库不显示，列表以目标库实际存在的库为准。
- 表数与大小来自 `information_schema.tables`（数据加索引），读不到时显示“—”。表数包含视图。没有删除库的功能。
- 创建数据库（`database.create`）：点“创建数据库”，填库名、负责人、备注，按需选择字符集与排序规则，确认后执行并登记。

### 4.10 管理账号

入口：实例运维 › 帐号维护，先选择实例。

| 操作 | 说明 | 按钮码 |
|---|---|---|
| 查看 | 账号列表读取目标库 `mysql.user` 并逐账号读取 `SHOW GRANTS`，账号多时较慢。高危账号整行标黄。可按全部、已录入、未录入、高危、已锁定筛选，筛选旁数字是当前搜索范围内的个数 | `account.view` |
| 登记信息 | 录入使用人、用途、到期日、备注，存在平台旁路表里，不改库里的账号；到期前 7 天标黄，过期标红；需先执行 `deploy/sql/071_account_reg.sql` | `account.edit` |
| 创建账号 | 填账号、主机、密码并确认密码；新账号没有任何权限，需用“授权”授予 | `account.create` |
| 授权 / 回收 | 只提交结构化选项（范围、库、表、列、权限名），语句由服务端生成，先预览再执行，改动任何选项后需重新预览 | `account.grant` |
| 修改密码 / 锁定 / 解锁 / 删除 | 均为高危，需二次确认 | `account.pwd` / `account.lock` / `account.delete` |

高危账号的判定：主机为 `%` 且有写或结构变更权限；有 `ALL PRIVILEGES` 或 `GRANT OPTION`；有全局 `SUPER`、`FILE`、`PROCESS`、`RELOAD`、`SHUTDOWN`、`CREATE USER`、`REPLICATION SLAVE` 等高危权限。授权时 `FILE`、`SUPER`、`PROCESS`、`RELOAD`、`SHUTDOWN`、`CREATE USER`、`REPLICATION CLIENT`、`REPLICATION SLAVE`、`GRANT OPTION`、`ALL PRIVILEGES` 会给出警告。

### 4.11 管理参数

入口：实例运维 › 参数管理，先选择实例。

1. “运行值”页签显示当前 `SHOW GLOBAL VARIABLES`。有推荐值时，运行值与推荐值不一致的参数整行标黄并标“偏离推荐”，可勾选“只看偏离推荐值”。页面一次只显示前 300 项，请用搜索缩小范围。
2. 在参数行点“修改”，填新值，查看预览后确认。成功后弹出提示和可粘贴的 `my.cnf` 片段（`[mysqld]` 段，仅 MySQL）。
3. “参数模板”页签由 DBA 维护哪些参数允许修改、取值范围和推荐值（`param.template`）。不在模板里或没开“允许修改”的参数，可在参数行点“模板”添加或开启。
4. “修改历史”记录谁、何时、把哪个参数从什么改成什么；选“全部实例”可看到有权访问的所有实例的记录（搜索同时匹配参数名和实例名）。

预期结果：修改是动态 `SET GLOBAL`，立即生效但**不会写入配置文件**，重启后恢复，请手动持久化到 `my.cnf`。

### 4.12 解析 Binlog

目标：把一段 binlog 还原成 SQL，或生成回滚 SQL（用于误删、误更新后的数据恢复）。平台以复制从库的身份读取 binlog，只读，不会在目标库执行任何语句，也不影响主从复制。入口：实例运维 › 日志解析（仅 `mysql` 类型、未停用的实例出现在下拉里）。

| 功能 | 说明 | 按钮码 |
|---|---|---|
| 打开页面、列出 binlog 文件 | 看 binlog 文件列表、`binlog_format`、`binlog_row_image` | `binlog.view` |
| 还原 SQL | 把 INSERT / UPDATE / DELETE 行事件还原成语句，可选列出 DDL | `binlog.parse` |
| 回滚 SQL | DELETE 与 INSERT 互换，UPDATE 前后镜像互换，按“后发生的先撤销”排序 | `binlog.rollback`（高危） |
| 下载 `.sql` | 带事务边界（`BEGIN` / `COMMIT`），每次下载写审计 | `binlog.download`（高危） |

步骤：

1. 选实例和起始文件（默认最后一个文件）。需要精确范围时填起止位置，或填起止时间（按服务器时区解释）。
2. 起始位置必须落在事务开头（`BEGIN` 之后第一个事件的起点，通常取自 `SHOW BINLOG EVENTS`），否则会报“找不到表映射事件”。不确定位置时留空，从文件开头读，再用时间、库、表、语句类型缩小范围。结束文件留空表示读到最后一个文件末尾，结束位置留空表示该文件末尾。
3. 点“开始解析”，页面轮询进度，可随时取消。结果分页显示（每页 200 行），可逐条复制、复制全部或下载。
4. “我的任务”里可重新查看未过期的任务，超级用户能看到所有人的任务。
5. 回滚 SQL 在“生成回滚 SQL”模式下得到；执行前先在测试环境验证，并确认范围内没有 DDL（DDL 无法回滚，页面会警告）。

过滤与输出选项：

| 选项 | 说明 |
|---|---|
| 数据库 | 可多选，不选表示全部可见库 |
| 表 | `表名` 或 `库.表名`，逗号、分号或换行分隔 |
| 语句类型 | 全不选表示 INSERT、UPDATE、DELETE；DDL 只列出，不可回滚 |
| 输出选项 | 不带库名前缀；语句后附位置和时间注释；SET / WHERE 带全部列 |

回滚的前提：`binlog_format=ROW` 且 `binlog_row_image=FULL`，目标表仍存在、列数与 binlog 里一致。不满足时页面说明原因并拒绝回滚，仍可使用“还原 SQL”。回滚 SQL 必须完整，不会给出在事务中间截断的结果：某行无法生成回滚语句时整个任务失败；结果超过条数 / 体积上限、扫描事件数达到上限、超时或目标库中途卡住时，结果在**事务边界**结束成“一段”，页面显示“第 N 段”和续接位置，点“继续下一段”会把续接位置填进起始位置，再生成下一段即可。**完整回滚要按段号从大到小执行：先执行最后一段，最后执行第 1 段**（每一段的文件内部也要严格按文件顺序执行）。连第一个事务都放不下时没法分段，请到“平台设置 › 系统配置 › 日志解析”调大上限，或缩小范围。

“最多条数”和“结果体积上限”能填的最大值由超级用户在“平台设置 › 系统配置 › 日志解析”设定。较大的结果会存到服务所在机器的临时文件里（结果保留 30 分钟，过期或任务失败后立即删除），下载时边读边写。

列名与主键来自目标库当前的表结构：binlog 之后表结构被改过的表，列数对不上时会提示并以 `@N` 代替列名，回滚会被拒绝。

## 6. 规则、限制与注意事项

### 6.1 状态与统计

- 状态、版本、QPS、连接数逐行异步探测：结果缓存 30 秒，单个实例最多等 8 秒，同时最多探测 6 个，排队超过 10 秒显示“未知”；连不上或超时显示“未知”，不会拖慢页面。“刷新状态”重新探测当前页。
- 列表状态只分“正常 / 异常”：连不上、超时、暂不支持探测，或连接使用率达到 80% 都算异常，原因悬停查看；详情抽屉区分“告警 / 未知”。已停用实例不探测。
- “健康”筛选跨页：选了以后页面会读取符合其他条件的全部实例并逐个探测（同时最多 6 个，结果缓存 30 秒，页脚显示“已探测 x / y”），命中的行边探测边出现，不再分页；已停用实例不参与。实例很多、且有大量连不上的实例时，需要等一会儿（连不上的实例每个最多等 8 秒）。
- QPS 为两次探测之间的差值；只有一次采样、两次采样相隔超过 10 分钟或计数器回退时，取启动以来的平均值。悬停可看连接上限、延迟和探测时间。
- 顶部统计条：实例（可见范围）、正常 / 异常 / 已停用（默认只统计当前页，选了“健康”筛选后统计符合其他条件的全部实例）、已停用（整个可见范围，紧跟在本页统计之后）、慢 SQL 采集中（开启了采集且未停用的实例）。

### 6.2 受保护对象

- 数据库内置账号（`mysql.sys`、`mysql.session`、`mysql.infoschema`、`mariadb.sys@localhost`、`root@localhost`、`root@127.0.0.1`、`root@::1`）一律拒绝改密、锁定、删除、授权和回收，也不判定为高危。
- 平台自己连接该实例使用的账号：拒绝改密、锁定、删除和回收，授权允许。
- 库级授权里库名的 `_`、`%` 会被转义成只匹配该库。
- 终止会话的受保护线程见 4.8。

### 6.3 SSH 隧道

- 隧道使用密码或私钥内容，不支持服务器上的私钥路径；隧道不校验跳板机主机公钥，这是已知限制。
- 查询、工单、巡检、慢日志、Binlog 解析、Redis 等功能连接配置了隧道的实例时自动走隧道：平台在本机起一个只允许本机访问的转发端口，端口随重启变化，不能手工配置。隧道连不上时，相关功能的报错里带“SSH 隧道…”。
- 目标库开启 SSL 且勾选“校验证书”时，经转发端口访问的功能要求证书包含 `127.0.0.1`，否则请取消勾选。实例管理自己的管理连接（会话、账号、库、参数、测试连接、健康探测、Binlog 清理）直接经 SSH 客户端拨号，校验的是实例真实主机名。

### 6.4 Binlog 解析的限额

| 项目 | 默认 | 上限 |
|---|---|---|
| 单次语句数 | 500 | 20000 |
| 单次结果体积 | 2 MB | 8 MB |
| 扫描事件数 | — | 500 万 |
| 超时 | 120 秒 | 600 秒 |
| 每人同时任务 | — | 2 个，全局 6 个，内存最多保存 40 个任务 |
| 结果保留 | 任务结束后 30 分钟 | 服务重启即丢失 |

超出范围的取值按边界钳位，不拒绝。解析模式超限时只截断并提示，回滚模式超限则整体失败。

### 6.5 其他注意

> 注意：停用的实例会拒绝会话、数据库、账号、参数和 Binlog 清理操作（提示“该实例已停用”），但“测试连接”不检查停用状态。

> 注意：实例的“显示 / 隐藏库”规则在 Binlog 解析里按名称开头匹配（前缀匹配），隐藏优先；被隐藏的库以及 `mysql`、`information_schema`、`performance_schema`、`sys` 的变更不会解析出来。实例管理自己的库清单、Top 表空间和授权库下拉不应用该规则。

> 注意：Binlog 解析结果可能含业务敏感数据，请只在需要时查看，下载的文件妥善保管、用后删除。

## 7. 审计与安全

- 审计动作：新增实例、修改实例、切换慢日志采集、删除实例、停用实例、启用实例、批量启用 / 停用实例、批量开启 / 关闭慢日志采集、批量设置环境、批量删除实例、测试连接、清理Binlog、终止会话、创建数据库、登记数据库信息、创建数据库账号、登记账号信息、账号授权、账号回收权限、修改数据库账号密码、锁定 / 解锁 / 删除数据库账号、修改实例参数、保存参数模板；Binlog 解析写“Binlog解析-解析 / 回滚 / 下载 / 取消”。
- 服务端拒绝的操作（受保护账号、黑名单参数、被引用实例、越过从库进度、受保护会话）写“原动作（拒绝）”。写审计失败只记日志，不回滚已完成的操作。
- 密码在界面、审计和日志里一律打码；Binlog 解析的解析、回滚在任务创建时写审计，校验失败的请求不写。
- 权限校验点：每个接口只校验 3.2 表里对应的按钮码，没有按钮以外的权限判断。
- 任务内容（Binlog 解析结果）只有创建者本人和超级用户能看。

## 8. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 实例状态为“异常”，原因“暂不支持探测” | 实例类型不在可探测范围 | 查看第 2 节矩阵；该类型只能做在线查询或不支持 |
| 状态显示“未知”，原因“探测排队超时” | 同时探测的实例太多 | 稍后点“刷新状态” |
| 添加实例时“环境”不可用 | 旁路表 `dbt_instance_ext` 未建 | 在元数据库执行 `deploy/sql/070_instance_ext.sql`，建表后无需重启，约 30 秒内生效 |
| 帐号维护列表报 502 | 平台账号对 `mysql.user` 没有 `SELECT` | 给平台账号授予读取权限，见安装部署指南（`docs/ops-manual.md`）附录 E |
| “参数 x 不允许在线修改” | 在永久拒绝清单里 | 在数据库侧手工修改并写入 `my.cnf` |
| “参数模板里 x 没有开启允许在平台修改” | 模板未开启 | 在参数行点“模板”开启，或请 DBA 维护模板 |
| 终止会话提示“已经变成另一个连接” | 线程号被复用 | 刷新进程列表后重新选择 |
| Binlog 清理被拒绝 | 目标文件越过从库读取进度 | 选择不晚于从库读取位置的文件 |
| Binlog 解析提示“找不到表映射事件” | 起始位置不在事务开头 | 留空起始位置，或取 `SHOW BINLOG EVENTS` 中事务的起点 |
| 回滚不可用 | `binlog_format` 不是 `ROW`、`binlog_row_image` 不是 `FULL` 或 `log_bin=OFF` | 按页面说明处理，仍可使用“还原 SQL” |
| 账号拉取 binlog 失败 | 缺 `REPLICATION SLAVE` / `REPLICATION CLIENT` | 授予权限后重试；目标库“复制从库列表”里会短暂出现一个随机编号的从库 |

## 9. 验证状态与已知限制

验证状态与已知限制如下：真实 MySQL 8.0 冒烟 215 项通过，所用平台账号只有 `PROCESS` 与测试库权限，没有 `SUPER`、`REPLICATION CLIENT`、`mysql.user` 与 `performance_schema` 的读取权限，因此下列内容没有在真库上执行。

未验证或仅用假后端验证：

- 创建、授权、回收、改密、锁定、删除账号；`SET GLOBAL` 成功路径（含修改历史写入）；`PURGE BINARY LOGS`；终止他人线程（只验证了自建连接，事件调度线程只做了预览）。
- 账号列表与授权预览（真库平台账号没有 `mysql.user` 读取权限）；锁等待（8.0 列名只对文档核对，5.7 与 MariaDB 未验证）；Binlog 列表与预览（缺 `REPLICATION CLIENT`）。
- MySQL 5.7 / 8.4 / MariaDB，SelectDB / Doris / ADB / PolarDB，SSH 跳板机，真实浏览器操作均没有测试环境。
- Binlog 解析只用手工拼装的事件字节和进程内假 MySQL 协议服务验证，没有连接过真实 MySQL。

已知限制：

- 账号权限与各功能的映射（附录 E）标记为“待验证”。
- 参数“是否动态可改”无法提前判断，只能由数据库拒绝；Top 表空间不支持排序切换；高危账号计数需要读取每个账号的 `SHOW GRANTS`，账号多时较慢。
- 不支持 MongoDB、Oracle、TDengine 的会话与账号，不支持 SQL Server 会话，不支持 SelectDB / Doris / ADB 账号管理。
- Binlog 解析：列名和主键取目标库当前结构（改过结构的表不能回滚）；无符号整数在表已不存在时可能显示负数；非 UTF-8 字符集文本可能不一致；不解析 GTID；按时间过滤时仍要从起始文件读起。
- 目标库返回的错误会原样带出平台连接账号名与客户端地址。
- 标签的维护页面与 SSH 隧道的配置页面：在本版本代码里**未核对到**对应的页面或接口（标签与隧道只被实例管理读取，数据在 `dbt_sql_instance_tag` 与 `dbt_ssh_tunnel`），原文档称在“系统管理”的标签管理里维护，此说法未核对。
- 删除实例后，旁路表 `dbt_instance_ext`、`dbt_account_reg` 里该实例的行是否被清理未核对。
- 审计页对“启用实例 / 停用实例 / 批量…”等动作的归类未核对。
