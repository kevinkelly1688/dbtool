# SQL 体检与智能调优

本章涉及两个页面：SQL 体检（变更发布 › SQL 体检，批量文件分析）和智能调优（性能优化 › 智能调优，单条 SQL 即时分析）。两者用于在上线前和排障时给出索引与改写建议。除 SQLTuning 的 PROFILE 会真实执行 SELECT、SOAR 会在其测试库建临时表之外，不会修改目标库的数据或结构。

## 1. 功能概述

| 页面 | 菜单 | 用途 |
|---|---|---|
| SQL 体检 | 变更发布 › SQL 体检 | 对一批 SQL（`.sql` 文本、MyBatis3 Mapper XML、MySQL 慢日志文本）做体检，例如一个迭代里的全部 Mapper 文件 |
| 智能调优 | 性能优化 › 智能调优 | 粘贴一条 SQL，选实例和库，按需使用执行计划、内置建议、SQL 美化、SQLTuning、SOAR |

## 2. 适用范围

| 功能 | MySQL | PolarDB / PolarDB-X | SelectDB / Doris / ADB | 其他类型 |
|---|---|---|---|---|
| SQL 体检（选实例） | ✔ | ✔ | ✖ | ✖ |
| SQL 体检（不选实例，只做静态分析） | ✔ | ✔ | ✔ | ✔ |
| 执行计划（传统格式） | ✔ | ✔ | ✔ | ✖ |
| 执行计划（JSON 格式） | ✔ | ✔ | ✖ | ✖ |
| 内置建议（选实例） | ✔ | ✔ | ✖ | ✖ |
| 内置建议（不选实例）、SQL 美化 | ✔ | ✔ | ✔ | ✔ |
| SQLTuning、SOAR | ✔ | ✔ | ✖ | ✖ |

说明：智能调优的实例下拉只列出 MySQL、PolarDB、PolarDB-X、SelectDB、Doris、ADB；Oracle 的 SQL Tuning Advisor 暂不支持，其他类型的实例不会出现在下拉里。SQL 体检选了不支持的类型会返回“SQL 体检仅支持 MySQL 系的实例”。

## 3. 前提条件与权限

| 页面 / 工具 | 按钮码 |
|---|---|
| SQL 体检：查看报告 | `sqlanalyze.view` |
| SQL 体检：上传并开始分析 | `sqlanalyze.run` |
| 智能调优：执行计划、内置建议、SQL 美化 | `optimize.explain` |
| SQLTuning | `optimize.tuning` |
| SOAR | `optimize.soar` |

- 进入智能调优页面需要按钮 `optimize.explain`，没有返回 403。
- 外部工具 SOAR 是服务器上的外部程序。发布包带有 SOAR 时，安装 / 升级会自动部署到 `<安装目录>/plugins/soar`，并填好程序路径与配置文件（管理员已经填过的不改）；测试库要由超级用户配置。以上设置都在“平台设置 › 系统配置 › SQL 优化工具”里：`optimizer.soar_path`（程序路径）、`optimizer.soar_config`（配置文件，可选）、`optimizer.soar_test_dsn`（测试库）；三项都标“高危”，保存时要键入确认文字，并写入变更记录与系统审计。没配置时只提示“未配置”（超级用户的提示旁有“去配置”链接），不影响其他功能。
- 配置时的安全核对：程序必须是绝对路径、文件名为 `soar`，文件存在、是普通文件（不能是符号链接）、有执行权限，且文件与所在目录都不能被其他用户改写；配置文件同样要求存在且不被其他用户改写（≤ 1MB）；测试库地址不能是已登记的生产实例（含已停用的），实例没有标注环境时也会被拒绝——先到“实例管理”给它设好环境。核对只按地址比对，经代理 / 别名 / SSH 隧道连到生产库的认不出来，请自行确认。
- 任务（SQL 体检与智能调优的后台任务）只有创建者本人和超级用户能查看。

## 4. 操作指南

### 4.1 批量分析 SQL 文件

目标：上线前对一批 SQL 体检。入口：变更发布 › SQL 体检。

1. 选择实例（可选，不选只做静态分析）和库。
2. 上传文件：支持 `.sql`、Mapper XML、MySQL 慢日志文本；先“解析”预览，再点“开始分析”。
3. 后台逐条分析，页面显示进度，可随时取消。
4. 查看汇总（按语句类型、最高建议级别、SQL 指纹、涉及的表统计）和逐条详情；页面底部的“最近报告”列出还在保留期内的任务及剩余时间，可切换查看。

每条 SQL 的分析内容：

- SQL 指纹：常量替换为 `?`，IN 列表与多行 VALUES 折叠，相同结构的语句得到同一个 ID。
- 语句类型与涉及的表、内置规则建议。
- 选了实例时（仅 MySQL 系）：读取表结构与统计信息、解读执行计划、给出索引建议；系统配置了 SOAR 时同时输出 SOAR 报告（没选库时 SOAR 只做离线分析）。
- 所选实例连不上或库不可见时，降级为静态分析并提示；没配置 SOAR 不是错误，只输出内置规则。

输入格式的处理方式：

| 格式 | 处理 |
|---|---|
| `.sql` | 按语句切分 |
| Mapper XML | 展开 `<if>`、`<where>`、`<foreach>`、`<include>` 等动态标签；`#{}` 还原为 `?`，`${x}` 替换为名字 `x`；`<choose>` 只取第一个 `<when>`，没有则取 `<otherwise>`；同名 id 追加 `#n`；根不是 `<mapper>`、解析失败、节点过多或嵌套过深时按普通 SQL 处理 |
| MySQL 慢日志文本 | 保留每条的耗时、扫描行数等统计，汇总里按指纹累加总耗时 |

### 4.2 使用智能调优

目标：对单条 SQL 即时分析。入口：性能优化 › 智能调优。

1. 粘贴 SQL，选择实例和库。有选中文本时分析选中部分，否则分析光标所在的语句，一次只分析一条。
2. 点击需要的工具：

| 工具 | 说明 | 要求 |
|---|---|---|
| 执行计划 | 对目标实例执行 `EXPLAIN`（含 JSON 格式），不执行语句本身，并解读全表扫描、filesort、临时表、join buffer 等 | 选实例 |
| 内置建议 | 词法级规则，不连库也能用；选了实例会再结合真实表结构与执行计划 | 可不选实例 |
| SQL 美化 | 词法级格式化，关键字转大写，不连库 | 无 |
| SQLTuning | 对 SELECT 采集表结构、统计、索引、系统参数并做 PROFILE；可勾选显示的内容：系统参数、执行计划、相关对象（表、索引）统计、PROFILE 跟踪，默认勾选执行计划与对象统计 | 必须选库 |
| SOAR | 小米开源的 SQL 优化与改写工具 | 必须选库，且配置了 `optimizer.soar_test_dsn` |

3. 外部工具与 SQLTuning 作为后台任务运行，页面轮询结果。

### 4.3 从慢日志跳转

在[慢日志检索与慢 SQL 洞察](#help/slowlog)里点“去智能调优”（慢日志检索详情抽屉）或“在智能调优中打开”（慢 SQL 洞察建议弹窗），会把 SQL、库和实例带到智能调优。带 SQL 指纹跳转时，页面取最近 31 天耗时最长的一条样例，取不到只预选实例。带过来后优化方式默认选 **SQLTuning**（需要有该权限，且带过来的库在列表里），否则选“内置规则建议”，并在取到 SQL 时立即运行。选了实例后库下拉是空的时，页面会在上方说明原因：账号看不到任何库，或共有几个库、其中系统库、不符合实例“库名显示规则”、命中“库名屏蔽规则”的各有几个。

## 5. 字段、规则与限额

### 5.1 内置规则

每条建议带级别（高、中、低、提示）、说明和改法。综合评分从 100 起，高扣 20、中扣 10、低扣 3，提示不扣分，最低 0。

| 编号 | 规则 | 级别 |
|---|---|---|
| R001 | `SELECT *` 读取所有列 | 低 |
| R002 | UPDATE / DELETE 没有 WHERE | 高 |
| R003 | WHERE / ON 条件里对列使用函数（如 `date(col)=...` 使索引失效） | 中 |
| R004 | LIKE 以通配符开头 | 中 |
| R005 | 深分页（偏移量至少 1 万为中，至少 10 万为高；建议改用游标或延迟关联） | 中或高 |
| R006 | `ORDER BY RAND()` | 高 |
| R007 | WHERE 中使用 OR | 低 |
| R008 | 否定条件（`NOT IN`、`!=`、`<>`、`NOT LIKE`） | 低 |
| R009 | IN 子查询 | 低 |
| R010 | IN 列表至少 200 项 | 中 |
| R011 | INSERT 没有列清单 | 低 |
| R012 | JOIN 缺少连接条件（笛卡尔积） | 高 |
| R013 | UNION 未指定 ALL | 低 |
| R014 | 与 NULL 用 `=` 或 `!=` 比较 | 中 |
| R015 | SELECT 没有 WHERE 也没有 LIMIT | 中 |
| R016 | LIMIT 没有配合 ORDER BY | 低 |
| S001 | 字符串列与数字比较，发生隐式类型转换（需要实例） | 中 |
| S002 | 查询条件没有可用的索引（需要实例；给出 ADD INDEX 建议；表至少 10 万行为高、不足 1000 行为低，其余为中） | 按表行数 |
| P001–P010 | 执行计划解读：全表扫描（高）、全索引扫描（中）、filesort（中）、临时表（中）、候选索引未使用（中）、join buffer（高）、`DEPENDENT SUBQUERY`（高）、`Range checked for each record`（高）、大量扫描后过滤（低）、WHERE 不可能成立（提示） | 见括号 |

选了实例后基于真实表结构推导索引：按“等值列在前、范围列在后”给出 `ALTER TABLE ... ADD INDEX ...` 草案（仅单表语句；WHERE 含顶层 OR 时不给建议；候选列最多 5 个），已有索引能覆盖时不重复建议。报告里还会列出相关表的现有索引（标出冗余的前缀索引）和建索引前后的执行计划对比：“前”是真实 `EXPLAIN`，“后”是按建议索引的列和表统计信息推导的估算，不是真实执行计划，建好索引后请再次 `EXPLAIN` 确认。

```sql
-- 优化前：列上套函数，无法走 created_at 索引
SELECT id, order_no FROM orders WHERE DATE(created_at) = '2026-10-07';
-- 优化后：改为范围条件
SELECT id, order_no FROM orders
WHERE created_at >= '2026-10-07 00:00:00' AND created_at < '2026-10-08 00:00:00';
```

### 5.2 限额与保留

| 项目 | 值 |
|---|---|
| 上传文件 | 单文件不超过 5 MB，UTF-8 文本，不含 NUL |
| 单次分析语句数 | 最多 1000 条，超过整份拒绝 |
| 单条 SQL | 不超过 60 KB，超过只跳过该条 |
| 每人同时进行中任务 | 2 个（分析任务与智能调优任务合计），全局 16 个 |
| 结果保留 | 任务结束后 30 分钟，服务重启即丢失；“最近报告”最多 30 条 |
| 同步接口 | 全局 3 个名额，等 5 秒不到返回“系统当前分析请求较多” |
| 超时 | 执行计划 30 秒，内置建议 45 秒，SQLTuning 120 秒，SOAR 90 秒 |
| SQLTuning PROFILE | 会话先设只读事务和 `max_execution_time=60000`，任务总超时 120 秒，超时或取消时用另一条连接 `KILL QUERY` |
| 结果集 | 单次最多 500 行，单元格 64 KB，单任务结果 8 MB |

## 6. 规则、限制与注意事项

服务端不信任前端传来的语句，各工具的校验强度不同：

| 工具 | 校验 |
|---|---|
| 执行计划、SQLTuning | 去注释后必须恰好一条语句；只允许 SELECT、UPDATE、DELETE、INSERT…SELECT、REPLACE 和 WITH 开头；用户写的 `EXPLAIN` / `DESC` 前缀会被去掉；拒绝 `EXPLAIN ANALYZE`（会真执行）、`INTO OUTFILE` / `INTO DUMPFILE`、`TABLE` 与 `VALUES` 语句，以及 `sleep`、`benchmark`、`load_file`、`get_lock`、`release_lock`、`master_pos_wait`、`sys_exec`、`sys_eval` 等危险函数 |
| 内置建议 | 只要求单条语句，不限类型 |
| SOAR | 只要求单条语句且以 select、with、insert、replace、update、delete、alter、create、drop、truncate、rename 之一开头，库名走字符白名单 |
| 批量分析 | 不拒绝危险写法，只在 EXPLAIN 步骤记录 `plan_error` |

语句里带库名的表必须落在你可见的库内（执行计划、内置建议、SQLTuning、SOAR、批量分析校验），防止借 EXPLAIN 探测被屏蔽的库。可见库规则：去掉 `information_schema`、`performance_schema`、`mysql`、`test`、`sys`，再按实例的显示 / 隐藏库正则（从开头匹配）过滤。

> 警告：SQLTuning 的 PROFILE 会真实执行该 SELECT，因此只接受 SELECT，只读事务和 60 秒服务端超时是保护措施，不要对生产实例上的大查询勾选 PROFILE。

> 注意：SOAR 需要指向测试环境的 `optimizer.soar_test_dsn`，不能是线上库；工具运行时目标实例的账号密码只出现在命令行参数里，输出里的密码会被替换为 `******`。

## 7. 审计与安全说明

- 审计动作：SQL分析、SQL分析-取消、SQL优化-取消任务、SQL优化-执行计划、SQL优化-内置建议、SQL优化-SOAR、SQL优化-SQLTuning（早期版本的“SQL优化-SQLAdvisor”记录仍可在审计里看到）。SQL 文本只记前 900 个字符。
- 分析与优化的内容只在内存里处理，不落盘。

## 8. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| “文件超过 5MB，请拆分后再上传” | 文件过大 | 拆分后再传 |
| “SQL 超过 1000 条，请拆分后再分析” | 条数超限，整份拒绝 | 拆分文件 |
| “文件不是有效的 UTF-8 文本” | 编码不对或含 NUL | 转为 UTF-8 |
| “一次只能分析一条 SQL，请只保留一条语句” | 智能调优粘贴了多条 | 只保留一条或选中一条 |
| 提示 SOAR “未配置” | 外部程序路径没有配置 | 请超级用户在“系统配置 › SQL 优化工具”里配置 |
| SOAR 提示未配置测试环境 | 缺 `optimizer.soar_test_dsn` | 配置指向测试库的 DSN |
| 保存 SOAR 设置时提示“文件可被其他用户改写” | 程序、配置文件或所在目录对“其他用户”可写 | 在服务器上收紧权限（例如 `chmod o-w`） |
| 保存测试库时提示“已登记的生产实例” | DSN 的主机和端口对应一个生产环境的实例 | 换成独立的测试库；或确认该实例的环境设置是否有误 |
| “请选择数据库” | SOAR、SQLTuning 必须选库 | 选择库 |
| “任务不存在或已过期” | 超过 30 分钟或服务重启 | 重新分析 |
| 返回 429，提示已有任务在运行 | 达到每人 2 个并发任务上限 | 等待或取消现有任务 |
| 403 “数据库 X 不存在，或你没有权限访问它” | 库不可见 | 检查实例的显示 / 隐藏库规则与资源组 |
| “该类型的实例不支持 JSON 格式的执行计划” | 实例是 SelectDB / Doris / ADB | 改用传统格式 |

## 9. 验证状态与已知限制

验证状态与已知限制如下：

- 真库冒烟仅覆盖 MySQL 8.0。
- 未验证：真实 SOAR（参数模板、输出位置、DSN 格式、外部进程超时能否杀掉）；MySQL 5.7、`lower_case_table_names=0`、真实 Percona / 5.7 慢日志格式；页面 JavaScript 接真后端的浏览器操作。
- 外部进程只杀主进程，不处理子进程。

已知限制：

- 建索引前后的计划对比与索引建议只对单表语句有效。
- 原文档称 SQL 美化“保持各引擎方言”，代码里没有方言逻辑，只有词法级格式化，本章已按代码修正。
