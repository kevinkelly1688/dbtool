# 性能巡检

性能巡检对实例做一次只读的健康体检，输出总分、各检查项结果和改进建议，支持手动立即巡检和定时计划。MySQL 系、SQL Server 与 Redis 实例在同一个报告列表里，按开始时间倒序；有进行中的报告时列表和详情页每 5 秒自动刷新。已在实例管理里停用的实例不会被巡检。

## 1. 功能概述

| 页签 | 内容 |
|---|---|
| 巡检报告 | 查看、筛选、立即巡检、取消、删除报告 |
| 定时计划 | 创建多个计划，每个计划选一批实例、周期、错峰与并发、通知和保留天数，到点自动为每个实例生成报告 |

## 2. 适用范围

| 实例类型 | 巡检 | 报告种类 | 健康评分 |
|---|---|---|---|
| MySQL、PolarDB、PolarDB-X、SelectDB、Doris、ADB | ✔（按 MySQL 检查项，部分检查项依类型而异） | MySQL | 有 |
| SQL Server | ✔ | SQL Server | 无，按告警 / 关注 / 正常 / 未采集计数 |
| Redis | ✔，需要表 `dbt_inspect_redis_report`（`deploy/sql/131_redis_inspect.sql`） | Redis | 有 |
| 其他类型（PgSQL、MongoDB、ClickHouse 等） | ✖ | — | — |

SelectDB / Doris 不支持账号风险检查，该项直接标“采集失败”。实例类型下拉里没有 MariaDB，MariaDB 服务端按 `mysql` 类型登记，没有专门的检查逻辑。

## 3. 前提条件与权限

| 功能 | 按钮码 | 说明 |
|---|---|---|
| 打开页面、查看报告与计划 | `inspect.view` | 列表可按实例、级别、触发方式、日期筛选 |
| 立即巡检 | `inspect.run` | 选一个或多个实例异步执行（默认仅超级用户，可单独授予） |
| 取消巡检 | `inspect.cancel` | 取消进行中的巡检，已采集的部分保留（默认仅超级用户，可单独授予） |
| 删除报告（高危） | `inspect.delete` | 进行中的报告不能删，先取消（默认仅超级用户） |
| 新建、编辑计划 | `inspect.plan_edit` |  |
| 暂停、启用、删除计划（高危） | `inspect.plan_toggle` |  |
| 立即运行计划（高危） | `inspect.plan_run` |  |

可巡检的实例范围：超级用户或持有 `query.admin_run` 的用户看全部，其余用户按资源组。目标库账号要求：MySQL 系读取复制状态需要 `REPLICATION CLIENT`，读账号风险需要对 `mysql.user` 有 `SELECT`；SQL Server 缺权限的检查项显示“无权限”；Redis 只发只读命令。缺少权限的检查项标“未采集”，不影响其他分区。

## 4. 操作指南

### 4.1 立即巡检

入口：实例运维 › 性能巡检 › 巡检报告。

1. 点“立即巡检”，选择一个或多个实例。搜索框输入即筛选（空格分隔多个词）；“全选”只选当前搜索结果，已选但被筛掉的实例仍会被巡检。一次最多 100 个实例。
2. Redis 实例可勾选“大 key 抽样”（默认关闭）。
3. 提交后在后台异步执行，页面轮询状态；同一实例同一时刻只允许一份进行中的报告，已有进行中巡检的实例被跳过。
4. 完成后点报告查看详情。

执行时长受预算限制：手动巡检 SQL Server 预算 10 分钟、MySQL 30 分钟，单条 MySQL 语句超时 150 秒，Redis 大 key 抽样不超过 60 秒。SQL Server 超出预算的检查项记“超出 N 分钟时间预算未执行”，MySQL 超时则整份报告失败。

### 4.2 读报告

详情页顶部是总分（100 分起，按检查项扣分，最低 0；至少 90 为良好，70 到 89 需关注，低于 70 较差）和三个提示块（问题、警告、建议），下面是分区列表。每个检查项按阈值标为“正常 / 关注 / 告警”，单步采集失败只在该分区标“未采集”，关注、告警、未采集的检查项在“建议”列给一句处理建议。

同实例趋势：取该实例最近完成的巡检（前端取最近 60 份报告再筛出同种类已完成的后 30 份），点圆点打开对应报告。MySQL 系与 Redis 画健康评分折线，虚线是 90 分和 70 分；SQL Server 报告没有评分，画告警（红）与关注（黄）两条折线。已完成的报告不足 2 份时不画。

> 提示：评分只是一个相对指标，重点看“告警”项和趋势，而不是追求 100 分。分数突然下降通常比绝对值更说明问题。

### 4.3 取消与删除报告

- 取消：选中进行中的报告点“取消”（超级用户或有 `inspect.cancel`），一次最多 200 份。
- 删除：在确认框里输入报告标识（如 `#12`），批量删除输入份数；详情页也可直接删除。确认框页脚显示权限码。

### 4.4 创建定时计划

入口：性能巡检 › 定时计划。

1. 新建计划，填名称。
2. 选实例范围、周期、执行方式和完成后的通知。
3. 保存前页面预览“下次运行时间”。
4. 保存后计划按服务器本地时区执行；到点为每个实例生成一份报告，与手动巡检的报告在同一列表里。

行内操作：暂停 / 启用 / 删除（高危）、立即运行（高危）、查看运行记录。删除计划要在确认框里输入计划名称（运行记录一并删除，已产生的报告保留）；立即运行也会先弹确认框，取消则不发出任何请求。

## 5. 字段与阈值说明

### 5.1 计划字段

| 项 | 说明 | 约束与默认 |
|---|---|---|
| 名称 | 计划名 | 1–60 个字符，不能与已有计划同名 |
| 实例范围 | 显式勾选，或按标签动态匹配，也可一键选“全部 MySQL 系 / 全部 SQL Server / 全部 Redis” | 实例与标签不能同时为空；显式实例最多 500 个；显式勾选的实例只能选你资源组内且支持巡检的；按标签选是运行时动态取实例，新打标签的实例自动加入，不受创建人资源组限制 |
| SQL Server 库范围 | 多个库用逗号分隔，留空为全部用户库 | 最多 50 个；执行时每库检查只跑前 200 个库 |
| 周期 | 每天、每周（多选星期）、每月（1–28 日）、自定义 cron（五段：分 时 日 月 周） | 每天与每周填 `HH:MM`；cron 不接受 `@` 描述符与 `TZ=`；两次运行间隔不得小于 5 分钟（按前两次触发校验） |
| 并发 | 同时巡检几个实例 | 1–10 |
| 错峰间隔 | 每启动一个实例的间隔 | 0–3600 秒 |
| 已有进行中巡检时 | 跳过，或不勾选则等它结束 | 等待最长为“单实例超时”，超时记“等待已有巡检结束超时，已跳过” |
| 失败重试 | 失败后 5 分钟重试一次 | 只在首次状态为失败时触发 |
| 单实例超时 | 分钟 | 1–240，建表默认 15，SQL Server 建议不少于 10 |
| 通知方式 | 不通知、仅告警或失败或低分时、每次汇总 | 选了通知至少选一个渠道，渠道最多 10 个且须已存在 |
| 报告保留天数 | 到期自动清理 | 1–3650，默认 90 |
| 启用 | 是否参与调度 | — |

### 5.2 MySQL 系检查项与阈值

| 分区 | 关注 / 告警条件 |
|---|---|
| 连接 | 使用率超过 80% 关注，超过 95% 告警 |
| 缓冲池命中率 | 低于 99% 关注，低于 90% 告警 |
| 慢查询 | 超过 10 关注，超过 100 告警；慢日志未启用关注；慢 SQL Top10 平均耗时至少 1 秒关注、至少 10 秒告警 |
| 行锁等待 | 超过 100 关注，超过 1000 告警；Undo 版本链超过 10000 关注 |
| 长事务 / MDL | 事务超过 60 秒关注，至少 300 秒告警；有会话在等 MDL 告警 |
| 自增 ID | 至少 70% 关注，至少 85% 告警 |
| 无主键表 | 有则关注；含 100 万行以上的告警 |
| 死锁（近 7 天） | 大于 0 关注，至少 10 告警 |
| 大表 / 碎片 | 表至少 50 GB 或至少 5000 万行关注，至少 200 GB 告警；碎片至少 1 GB 且碎片率至少 30% 给出整理建议 |
| 复制与 Binlog | 从库线程异常告警；延迟超过 60 秒关注，超过 300 秒告警 |
| 参数基线 | `innodb_flush_log_at_trx_commit`、`sync_binlog`（仅 `log_bin` 开启时）不安全告警；其余偏离关注 |
| 高危账号 | 匿名或远程空密码告警；任意主机高权限、`FILE` 权限关注 |
| 其他 | 索引冗余、字符集不一致、慢 SQL Top10、容量 |

总分、提示块（问题、警告）按另一套扣分规则计算，与上表分区阈值不完全一致（例如缓冲池命中率低于 95% 记“问题”、低于 99% 记“警告”，慢查询超过 50 记“问题”）。页面“关注 / 告警”计数按分区阈值，评分按扣分规则。

### 5.3 SQL Server 检查项

共 9 个分区、27 项：实例概况、CPU、内存、IO、阻塞与死锁、索引（缺失索引、无用索引，不做索引碎片检查）、Top SQL、数据库与文件（含备份）、错误日志与作业。需要 SQL Server 2012 及以上（主版本至少 11）。主要阈值：单类型等待占比超过 40% 关注；信号等待超过 25% 告警；阻塞等待超过 30 秒告警；长事务超过 5 分钟告警；死锁大于 0 关注；日志 VLF 超过 1000 告警；完整备份超过 7 天告警；`FULL` 恢复模式日志备份超过 1 小时关注、超过 24 小时告警。累计型指标只在实例未重启时才与上一份报告做差。

### 5.4 Redis 检查项

按基本信息、主从复制、内存、持久化、客户端连接、性能与命中率、安全、键空间 8 个分区检查，同样有评分和逐项建议。巡检只发 `INFO`、`CONFIG GET`、`SLOWLOG LEN/GET`、`COMMAND`、`SCAN`、`TYPE`、`MEMORY USAGE` 等只读命令，不读业务数据。

| 分区 | 关注 / 告警条件 |
|---|---|
| 内存 | 使用率（对 `maxmemory`，没设置则对主机内存）至少 80% 关注、至少 90% 告警；碎片率至少 1.5 关注、至少 2 或低于 1（发生交换）告警；没设置 `maxmemory` 关注；设了 `maxmemory` 却用 `noeviction` 关注 |
| 主从复制 | 主库视角：从库状态为 `wait_bgsave` 等同步中关注，其他非 `online` 告警；延迟至少 10 秒关注、至少 30 秒告警；偏移差至少 100 MB 告警。从库视角：与主库链路断开告警；`master_last_io_seconds_ago` 至少 10 秒关注、至少 60 秒告警；正在全量同步关注 |
| 持久化 | RDB 与 AOF 都没开关注；最近一次 RDB 或 AOF 写入 / 重写失败告警；RDB 有变更未保存超过 24 小时关注、72 小时告警 |
| 客户端连接 | 连接数占 `maxclients` 至少 80% 关注、至少 90% 告警；阻塞客户端至少 10 关注、至少 50 告警；有被拒绝的连接关注、至少 100 告警 |
| 性能与命中率 | 命中率（请求至少 1 万次时）低于 90% 关注、低于 70% 告警；有被淘汰的 key 关注；慢日志条数至少 10 关注、至少 100 告警；fork 耗时至少 0.5 秒关注、至少 2 秒告警 |
| 安全 | 没设置密码告警；监听所有网卡且 `protected-mode no` 关注（同时没密码告警）；`FLUSHALL`、`KEYS`、`CONFIG`、`DEBUG` 等危险命令没改名关注 |
| 键空间 | 用 `volatile-*` 淘汰策略但带过期时间的 key 很少或没有时关注或告警；大 key 抽样见下 |

大 key 抽样默认关闭，在“立即巡检”里勾选后限量 `SCAN` 抽样：抽样数取 1000 与环境变量 `REDIS_INSPECT_BIGKEY_SAMPLE` 中较大者，硬上限 5000；逐个 `TYPE` 与 `MEMORY USAGE`；总时间不超过 60 秒；只扫描连接所在库；保留 Top10。最大 key 至少 1 MB 关注、至少 10 MB 告警；不支持 `MEMORY USAGE` 时按元素数判断（至少 1 万关注、至少 10 万告警）。该环境变量的值也作用于定时计划。对线上有轻微压力，建议低峰期使用。云托管的 Redis 经常禁用 `CONFIG`，相关检查项标“未采集”。

### 5.5 通知

通知复用[平台设置里的通知渠道](#help/sysadmin)及其 @ 规则，@ 规则里的“提交人”指计划创建人。“仅告警时发”的触发条件：有告警、有失败实例，或 MySQL、Redis 实例评分低于 70。消息包含计划名、实例成功 / 失败 / 跳过数、告警最多的 5 个实例及报告链接、低分实例和失败原因（失败实例只列前 5 个）。通知发送失败只记录在该次运行的“说明”里。

## 6. 规则、限制与注意事项

- 巡检全程只读，只执行元数据与统计查询。
- 调度保证：多个服务进程同时运行也只会触发一次；错过计划时间超过 15 分钟不补跑，记一条“已跳过”（在业务高峰补跑一轮比漏掉一次更糟）；同一计划不会重叠运行；进程被杀留下的“运行中”记录（5 分钟无心跳）会被自动收尾为失败。
- 定时巡检的表（`deploy/sql/013_inspect.sql`，可重复执行）还没有创建时，计划页签会提示，请 DBA 在元数据库执行后刷新页面。
- 报告清理：计划产生的报告按计划的保留天数每小时清理一次；不属于任何计划的报告只有在系统配置了 `inspect.mysql_retention_days`、`inspect.mssql_retention_days`、`inspect.redis_retention_days`（1–3650）时才清理，缺省永不清理；运行记录至少保留 30 天。

> 注意：不要把计划间隔配得过密；5 分钟的下限是为了避免把巡检配成对生产的压测。

## 7. 审计与安全说明

- 审计动作：立即巡检、取消巡检、删除报告、新建计划、修改计划、启用计划、停用计划、删除计划、立即运行计划、定时运行计划（操作人为“系统”）。
- 立即巡检、取消、删除、计划操作的权限都在服务端按按钮码校验。
- 报告内容可能包含账号名、慢 SQL 文本等，请按权限控制报告的查看范围。

## 8. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 实例选不了 | 实例已停用、类型不支持或不在你的资源组内 | 见第 2 节 |
| 立即巡检提示实例被跳过 | 已有进行中的报告 | 等其结束或先取消 |
| “复制线程”项显示“采集失败” | 账号没有 `REPLICATION CLIENT` | 授予权限 |
| Redis 巡检报表缺表 | 没有建 `dbt_inspect_redis_report` | 执行 `deploy/sql/131_redis_inspect.sql` |
| 计划页签提示未创建 | 缺定时巡检表 | 执行 `deploy/sql/013_inspect.sql` |
| 计划保存提示“两次运行的间隔不能小于 5 分钟” | cron 太密 | 调整 cron |
| 计划到点没有运行 | 服务未运行超过 15 分钟，或计划已暂停 | 查看运行记录里的“已跳过”原因 |
| Redis 某些检查项“未采集” | 云托管禁用了 `CONFIG` | 属预期 |

## 9. 验证状态与已知限制

验证状态与已知限制如下：

- 真库冒烟仅 MySQL 8.0，且账号只有 `PROCESS` 权限。
- 仅用假后端验证：SQL Server 全部 27 项（没有 SQL Server 测试实例）、Redis 巡检（进程内假 RESP 服务端，未在真实 Redis 上验证）、通知真实发送与 @ 规则。
- 未验证：MySQL 5.7 与 8.4、PolarDB、Doris 的采集语句；失败路径（连不上变为失败报告、`retry_once`）；进程被强杀后的回收（只用伪造的过期心跳验证）；页面未在真实浏览器里点过。

已知限制：

- 清理与到点计划串行：计划很多时，清理期间不会触发到点计划。
- 不规则 cron（如 `0,30,32 * * * *`）可通过“间隔至少 5 分钟”校验，因为只比较前两次触发。
- “SQL Server 单实例约 1–5 分钟”“MySQL 与 Redis 通常几秒到几十秒”等耗时描述只有预算常量作依据，未核对实测耗时。
- SQL Server 巡检不包含索引碎片检查。
