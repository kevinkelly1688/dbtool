# 慢日志检索与慢 SQL 洞察

慢日志有两个入口，面向的问题不同：“慢日志检索”回答“这个库今天有哪些慢 SQL”，“慢 SQL 洞察”回答“哪些 SQL 总体最慢、趋势如何、怎么优化”。数据来自平台采集器写入的慢日志表，或外部推送的 pt-query-digest 库。

## 1. 功能概述

| 页面 | 菜单 | 回答什么问题 | 按钮码 |
|---|---|---|---|
| 慢日志检索 | 性能优化 › 慢日志检索 | 按实例、库、SQL 指纹、天聚合，看当天有哪些慢 SQL | `slowlogs.view` |
| 慢 SQL 洞察 | 性能优化 › 慢 SQL 洞察 | 统计、明细、趋势与优化建议 | `slowquery.view`、`slowquery.advise`、`redis.slowlog_reset` |

页面能不能打开、里面的按钮能不能点，都由上表的按钮码控制。

## 2. 适用范围

| 能力 | MySQL | PolarDB / PolarDB-X | SelectDB / Doris | ADB | Redis | 其他类型 |
|---|---|---|---|---|---|---|
| 平台采集器采集 | ✔（`mysql.slow_log`） | ✔（`mysql.slow_log`） | ✔（审计日志） | ✖ | 部分 | ✖ |
| 慢日志检索页 | ✔ | ✔ | ✔ | ✖ | ✖ | ✖ |
| 慢 SQL 洞察页 | ✔ | ✔ | ✔ | 部分 | ✔ | ✖ |
| pt-query-digest 数据源 | ✔ | ✖ | ✖ | ✖ | ✖ | ✖ |
| 全部实例（汇总） | ✔ | ✔ | ✔ | ✔ | ✖ | ✖ |
| 获取优化建议 | ✔ | ✔ | ✖ | ✖ | ✖ | ✖ |

“部分”的含义：

- Redis 采集：不走 MySQL 采集器，而是定时 `SLOWLOG GET` 增量采集，且需要 Redis 慢查询模块启用（表 `dbt_redis_slowlog` 已建）。
- ADB 慢 SQL 洞察页：页面把 ADB 当作“平台采集”数据源，但平台采集器不采集 ADB，`dbt_slow_logs` 里不会有数据，除非有外部程序写入。
- 实例管理里 PgSQL、MongoDB、ClickHouse 不可开启慢日志采集；SQL Server、Oracle 等类型不出现在本页实例下拉里。
- 实例管理里“停用”的实例不会被采集。

## 3. 前提条件与权限

- 慢日志检索页需要按钮 `slowlogs.view`，慢 SQL 洞察页需要 `slowquery.view`；两页共用的数据接口只要持有其中任一个。
- 获取优化建议：只认按钮 `slowquery.advise`，不要求同时持有 `optimize.*` 或查看按钮。
- 重置 Redis 慢日志：按钮 `redis.slowlog_reset`（高危，默认仅超级用户）。
- 实例可见范围：超级用户或持有 `query.admin_run` 看全部实例，其余用户只看到所在资源组关联的实例。
- 数据前提：实例需在“实例管理”里打开“慢日志采集”开关；目标库上 `slow_query_log = ON` 且 `log_output` 含 `TABLE`（采集的是 `mysql.slow_log` 表，只写文件的不会被采集）；采集账号能读 `mysql.slow_log`。

## 4. 操作指南

### 4.1 慢日志检索：看某个库今天有哪些慢 SQL

入口：性能优化 › 慢日志检索。

1. 选择实例、库和时间范围（今日、最近 7 / 31 / 93 天或自定义，最长 93 天，默认 31 天）。搜索框同时匹配 SQL 文本、库名和 `用户@主机`。
2. 页面顶部是四张统计卡（慢 SQL 总次数、SQL 指纹数（按“实例 × 指纹”计）、累计耗时、最慢单条）和“每日慢 SQL 次数”“每日累计耗时”两张折线图，随筛选条件变化。
3. 列表每行是实例 × 库 × SQL 指纹 × 天的聚合：执行次数、总耗时、AVG / MAX / MIN 耗时、返回与扫描行数的 AVG / MAX / MIN 等，点列头可排序，单次最大耗时至少 30 秒的 MAX 列单元格标红。
4. 点行展开该指纹当天最近一条的代表 SQL（附主表；内容过长标“已截断”）。点“详细”打开右侧抽屉：摘要（实例、库、日期、当天次数、累计耗时、平均 / 最大 / 最小、扫描 / 返回行均值、主表）、SQL 指纹和当天最近 100 条原始记录（时间、用户@主机、库、查询时长、锁定时长、返回 / 扫描行数、SQL）。有智能调优权限时，抽屉里的“去智能调优”带着实例、库和指纹过去。

页面底部可展开“采集器状态”：采集器是否启用（每多少秒一轮、并行几个实例）、各实例最近一次采集时间、最近成功时间、本次与累计写入条数、耗时和错误。非管理员只看到“采集失败（详细原因仅管理员可见）”。采集器被环境变量 `SLOWLOG_COLLECT_ENABLE` 关闭或状态表 `dbt_slowlog_collect_state`（`deploy/sql/015_slowlog.sql`）未创建时，这里会给出一句提示；没有开启采集的实例不出现在这张表里。

### 4.2 慢 SQL 洞察：统计、明细与优化

入口：性能优化 › 慢 SQL 洞察。页面打开时不会自动查询，先选实例（或选“全部实例（汇总）”），再按需改库、时间范围（默认最近 7 天，最长 93 天）和耗时下限，点“查询”。没选实例时只提示“请先选择实例”，这不是出错。

页面分两个页签：

- 统计：按 SQL 指纹聚合。顶部是指纹数、总次数、总耗时（含平均）、最慢一次四张卡片；每行列出出现次数、总耗时、平均 / 最大耗时、扫描 / 返回行（总数与平均）、首次 / 最近出现和范围内每天慢查次数的小趋势。点 ▸ 展开完整 SQL 与历史趋势图（柱为次数，线为 95% 耗时）；点 SQL 文本切到“明细”并按该 SQL 过滤（汇总模式下同时切换到该行所在的实例），点“清除 SQL 过滤”恢复。
- 明细：单条慢查询记录，可按时间、库、SQL 关键字过滤，表里有执行用户和主机。“获取优化建议”要先点选一条记录。

筛选栏里的实例下拉第一项“全部实例（汇总）”把你可见的所有 MySQL 与平台采集类型的实例放在一起看（汇总模式不能按库过滤，也没有明细，不含 Redis）。“耗时下限”（不限、0.5、1、2、5、10、30、60 秒）在统计页按平均耗时过滤，在明细页按单次耗时过滤。

### 4.3 获取优化建议

在慢 SQL 洞察里先点选一条记录，再点“获取优化建议”：弹窗给出基于规则的静态建议、综合评分和建议来源。只读，不连目标库，只支持 MySQL、PolarDB、PolarDB-X 的实例。统计行内也有“优化建议”“智能调优”入口。想进一步分析，点“在智能调优中打开”把 SQL、库和实例带到[智能调优](#help/optimize)。

### 4.4 Redis 慢查询

在慢 SQL 洞察的实例下拉里选 Redis 实例，页面换成 Redis 面板（“SQL”改称“命令”）：

- 命令统计：按命令指纹（命令名加参数占位，如 `HGETALL ?`、`SET ? ? EX ?`）聚合，列出次数、总耗时、平均 / 最大耗时（毫秒）、首次 / 最近出现和每日小趋势；顶部是指纹数、总次数、总耗时、最慢一次四张卡片和次数加平均耗时趋势图。点 ▸ 展开完整命令和该指纹的趋势；点指纹切到明细并按该指纹过滤，“复制指纹”复制指纹文本，“清除指纹过滤”恢复。
- 慢命令明细：每条慢命令的时间、耗时、命令名、客户端地址和完整命令。
- 采集状态：每个 Redis 实例的采集游标、最近一次采集结果和累计入库条数。
- 筛选：命令名、耗时下限（1 ms、5 ms、10 ms、50 ms、100 ms、500 ms、1 s）、时间范围（最长 93 天）和关键字。

采集：定时 `SLOWLOG GET` 增量采集，随慢日志采集器启动（环境变量 `SLOWLOG_COLLECT_ENABLE` 关闭时一并停止），同一实例两次采集的最小间隔默认 60 秒（`REDIS_SLOWLOG_COLLECT_INTERVAL`，10–3600）。“立即采集”对当前实例立刻拉取一次并入库，同一实例间隔至少 10 秒，也不要求实例开启采集开关。Redis 慢日志是内存中的环形缓冲，条目数由实例的 `slowlog-max-len` 决定，慢命令很多时要调大。Redis 慢查询表未创建时，先执行 `deploy/sql/130_redis_slowlog.sql`。

重置慢日志：对实例执行 `SLOWLOG RESET`。先把现有条目采集入库再清空（采集失败则取消重置），页面要求输入实例名确认，并写系统审计。平台不会自动重置。

> 警告：重置慢日志不可撤销。只有拥有 `redis.slowlog_reset` 的用户能执行，默认仅超级用户。

## 5. 字段与选项说明

### 5.1 数据源

| 实例类型 | 数据源 |
|---|---|
| MySQL（自建，digest 历史表里有这个实例 host:port 的数据） | pt-query-digest 库（`dbt_mysql_slow_query_review` 与 `dbt_mysql_slow_query_review_history`，由外部脚本推送，平台只读；推送脚本里 `--review` 与 `--history` 的 `t=` 要写这两个带 `dbt_` 前缀的表名） |
| MySQL（没有 digest 表，或表里没有这个实例的数据） | 回退到平台采集的慢日志。digest 表安装时就会建出（空表），所以要看表里有没有这个实例的数据，不能只看表在不在 |
| PolarDB / PolarDB-X / SelectDB / Doris / ADB | 平台采集的慢日志（ADB 见第 2 节说明） |
| MySQL 且手动指定 | 页面上选中 MySQL 实例后出现“数据源”下拉，可手动选 digest 或平台采集 |

页签栏右侧的“当前数据源”写的就是实际使用的那份。手动选 digest 而表不存在时返回“没有找到 dbt_mysql_slow_query_review 表”。

### 5.2 查询约束

| 项目 | 值 |
|---|---|
| 时间范围 | 最长 93 天 |
| 每页条数 | 默认 30，最多 200 |
| 翻页偏移 | 最大 20000 |
| 搜索关键字 | 至多 200 个字符 |
| 聚合行“详细” | 最多 100 条原始记录 |
| 返回 SQL 文本 | 至多 20000 个字符 |
| 优化建议 SQL | 至多 100000 字节，超时 15 秒 |

### 5.3 采集参数

| 环境变量 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `SLOWLOG_COLLECT_ENABLE` | 开启 | `0`、`false`、`no`、`off` 为关闭 | 整体开关；采哪些实例由实例上的“慢日志采集”开关决定 |
| `SLOW_COLLECT_INTERVAL` | 10 秒 | 5–3600 | 两轮之间的间隔 |
| `SLOW_COLLECT_WORKERS` | 2 | 1–8 | 并行采集的实例数 |
| `SLOWLOG_COLLECT_BACKFILL_DAYS` | 7 天 | 0–365 | 首次采集回溯天数 |
| `REDIS_SLOWLOG_COLLECT_INTERVAL` | 60 秒 | 10–3600 | 同一 Redis 实例两次采集的最小间隔 |

单批 1000 条，每轮最多 10 批，单实例超时 60 秒，失败后指数退避最长 10 分钟。Redis 单次最多读 1000 条，命令文本入库至多 4000 字符，明细保留 93 天。

### 5.4 优化建议规则

只做词法级静态规则，不连目标库。每条建议带级别（严重 / 注意 / 提示），综合评分从 100 起，严重扣 25、注意扣 10、提示扣 3，最低 0。

| 规则 | 级别 | 触发条件 |
|---|---|---|
| UPDATE / DELETE 没有 WHERE | 严重 | 全表修改或删除 |
| `ORDER BY RAND()` | 严重 | 全部命中行排序 |
| 缺少索引的迹象 | 严重 | 扫描至少 1 万行且扫描与返回之比至少 100:1 |
| `SELECT *` | 注意 | 最外层使用 |
| 没有 WHERE 也没有 LIMIT | 注意 | SELECT 全表扫描 |
| LIKE 前导通配符 | 注意 | `%` 或 `_` 开头 |
| WHERE 里列上套函数 | 注意 | 约 30 个常见函数 |
| 深分页 | 注意 | 偏移至少 10000 |
| IN 列表过长 | 注意 | 超过 200 项 |
| 锁等待为主 | 注意 | 锁等待至少 0.05 秒且占耗时至少 50% |
| OR、否定条件、排序无 LIMIT、IN 子查询、UNION 未写 ALL | 提示 | — |
| 单次耗时较长 | 提示 | 至少 10 秒 |

单表语句还会仅由 WHERE 条件推测候选复合索引（等值列在前，取第一个范围列，最多 4 列），没有核对现有索引，仅供参考，以 EXPLAIN 为准。

## 6. 规则、限制与注意事项

- 慢 SQL 的判断阈值 `long_query_time`（默认 10 秒）在 MySQL 系实例上设置，平台只负责采集与展示；SelectDB / Doris 的采集条件固定为审计日志中 `query_time` 大于 1000 毫秒，不受该参数影响。
- 要验证整条链路，可以在测试库上把 `long_query_time` 调小（如 `SET GLOBAL long_query_time = 1`，新连接生效）后执行 `SELECT SLEEP(2)`。

> 注意：不要在生产实例上随意修改 `long_query_time`。

- 完整命令里可能带业务数据（例如 `SET` 的值）；`AUTH`、`HELLO`、`MIGRATE`、`CONFIG SET requirepass` 等密码参数已抹掉。请只把查看权限授予需要的人。
- 优化建议只是线索，请结合 EXPLAIN 与现有索引确认后再变更。
- 看趋势比看单点重要：同一指纹连续几天次数上升，往往比单条最慢记录更值得处理。

## 7. 审计与安全说明

- 获取优化建议写审计“慢日志获取优化建议”，记录实例、库、SQL 指纹 md5、长度和来源，不含 SQL 原文。
- 重置 Redis 慢日志写审计“Redis慢查询-重置慢日志”，含成功或失败结果、重置前条数与保底采集条数。
- 页面与数据接口的权限在服务端校验；重置接口服务端要求 `redis.slowlog_reset`（并持有任一查看按钮），输入实例名确认只在前端校验。

## 8. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 打开页面什么都没有 | 页面打开时不会自动查询 | 先选实例（或“全部实例（汇总）”），再点“查询” |
| 选了实例仍为空 | 范围内没有采集到数据 | 按下面各行逐项检查 |
| 实例下拉里没有我的实例 | 实例没开启慢日志采集（慢日志检索页），或类型不支持，或不在你的资源组内 | 在实例管理里打开“慢日志采集”；SQL Server、PostgreSQL 等不会出现 |
| 慢日志采集开关已开但没数据 | `slow_query_log` 为 `OFF`，或 `log_output` 不含 `TABLE`，或采集账号读不到 `mysql.slow_log` | 在目标库调整并确认账号权限 |
| 开关刚打开没数据 | 需要等一个采集周期（默认约 10 秒），首次默认只回溯 7 天 | 稍后重试 |
| 采集器没运行 | `SLOWLOG_COLLECT_ENABLE` 为 `0` 或 `false` | 去掉该变量并重启 |
| 慢日志检索有数据而慢 SQL 洞察为空 | MySQL 的数据源自动选了 pt-query-digest 但表里没有该实例数据 | 看页签栏右侧“当前数据源”，或手动选“平台采集” |
| 筛选后全空 | 耗时下限、库、关键字把数据筛掉了 | 把耗时下限设为“不限”，范围放到最近 31 天再试 |
| 采集失败原因看不到 | 非管理员只看到概要 | 请管理员在“采集器状态”里查看 |
| Redis 慢命令少 | 内存环形缓冲被覆盖 | 调大实例 `slowlog-max-len`，或缩短采集间隔 |
| 提示 Redis 表未创建 | 缺 `dbt_redis_slowlog` | 执行 `deploy/sql/130_redis_slowlog.sql` |

## 9. 验证状态与已知限制

验证状态与已知限制如下：

- 未验证：真实 `log_output=TABLE` 的采集写入；Doris / SelectDB 审计日志采集 SQL（设计稿称“未经验证”）；pt-query-digest 的 `ts_min` 时区（趋势“天”可能差 8 小时）；SSH 隧道实例经真实跳板机；页面 JavaScript 没有在浏览器里实跑。
- Redis 只用进程内假 RESP 服务端验证过，没有在真实 Redis（Cluster、TLS、ACL、不同版本）上验证；`redis.slowlog_reset` 的“锁定”标记待产品确认。

已知限制：

- `mysql.slow_log` 的采集游标表达式把微秒加了两遍且不单调，相邻慢日志间隔小于 1 秒且小数部分差大于 0.5 秒时可能漏采（设计稿记录为“未改，需要决定”）；耗时小数只保留 4 位。
- `dbt_slow_logs` 默认没有 `(instance_id, start_time)` 索引，大数据量前需手工添加（`deploy/sql/015_slowlog.sql` 注释里有两条可选索引建议）。
- 优化建议只有规则分析，没有 EXPLAIN 或 SOAR 能力；这些在[智能调优](#help/optimize)里。
- 慢日志页面没有“生成性能工单”按钮：接口 `/perf/issues/from-slowlog` 存在（需要 `perf.create`），但页面上没有入口，性能工单由采集器自动建单或 DBA 在性能工单页手工建单，见[性能工单](#help/perf)。
- Redis 慢日志环形缓冲默认 128 条属于 Redis 自身默认值，仓库内没有依据，未核对。
