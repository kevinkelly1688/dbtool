# 权限申请与授权清单

在线查询、数据导出等功能要求你对具体库表持有**查询权限**。查询权限通过“申请 → 逐级审批 → 自动授予”获得，也可以由有管理权限的人直接授予。本章说明如何申请、如何审批、如何查看和管理已授予的权限，以及权限在查询时如何参与判断。

## 适用范围

| 实例类型 | 可申请的粒度 | 说明 |
|---|---|---|
| MySQL | 库、表 | 在线查询按表精确校验（goInception 解析语句涉及的表） |
| PolarDB / PolarDB-X / SelectDB / Doris / ADB | 库、表 | 与 MySQL 一样逐表校验：有库权限或有该表的表权限即可；PolarDB、ADB 用 goInception 语法树精确解析语句涉及的表，PolarDB-X、SelectDB、Doris 用词法解析（宁多勿漏，只会多要权限，不会少要） |
| SQL Server | 库 | 按库授予，没有表级授权 |
| Redis | 库（db 编号） | 没有表，选到 Redis 实例时只能申请库级权限 |
| PostgreSQL / MongoDB / ClickHouse | 库、表（集合） | 库名、表名区分大小写，见下文 |

## 前提条件与所需权限

两个页面配合使用：

| 页面 | 菜单 | 用途 | 权限码 |
|---|---|---|---|
| 权限申请 | 数据服务 › 权限申请 | 提交申请、查看审批进度、审批他人申请 | `qpriv.view`、`qpriv.apply`、`qpriv.review` |
| 授权清单 | 数据服务 › 授权清单 | 查看已授予的权限；有管理权限的人可修改、回收或直接授予 | `qpriv.list`、`qpriv.manage`（高危） |

此外：

- 申请的实例必须属于你的资源组，且带“支持查询”（`can_read`）标签；
- 你选的资源组必须是你自己所在的资源组，所选实例必须属于该资源组（审批流跟着资源组走）；
- 资源组必须配置了“查询权限申请”审批流，否则无法提交，请联系管理员（见 [管理员指南](#help/sysadmin)）。

## 申请查询权限

目标：为自己申请某个实例上某些库 / 表的查询权限。入口：数据服务 › 权限申请 › 「申请权限」，也可以从在线查询的“无权限”提示里直接进入（实例、库、表会预填）。

1. 点「申请权限」（`qpriv.apply`）；
2. 选择**实例**（只列出属于你资源组、且带“可查询”（`can_read`）标签的实例）、**资源组**（决定走哪条审批流）和**权限范围**：
   - **库权限**：整个库下所有表，数据库可多选；
   - **表权限**：指定库里的若干张表，可多选，有过滤框；
3. 填写**有效期**（不能早于今天，默认 30 天后）、**行数上限**（1 到 100 万，决定在线查询最多返回多少行）和**申请理由**（必填，至少 5 个字、最多 500 个字，写明用途和数据范围，便于审批人判断）；标题可不填，系统自动生成；
4. 提交后系统按所在资源组的“查询权限申请”审批流逐级审批，详情页能看到流程图、当前审批人和日志。

预期结果：申请进入“待审批”；最后一级通过后权限自动授予，在线查询即时生效，无需重新登录。

### 申请列表

- 页签「我的申请 / 待我审批 / 全部」带数量（后两个需要审批 / 管理权限），可按状态筛选，搜索框匹配编号、申请人、实例、库和表；
- 「审批进度」列显示当前在第几级、哪个审批组审批；申请人可在行内**撤回**待审批的申请；
- 审批通过的申请在权限有效期过后显示为「已过期」，被驳回、已撤回或已过期的申请可在详情页一键「重新申请」（预填原内容）；
- 详情页有各级审批人 / 时间 / 意见的时间线、申请人部门，以及已授予权限的链接。

### PostgreSQL / MongoDB / ClickHouse 实例

这三类实例的申请页**库权限、表权限都可选**（Redis 只能选库），写法和注意点如下：

| 类型 | “库” | “表” | 要点 |
|---|---|---|---|
| PostgreSQL（`pgsql`） | PostgreSQL database | `schema.table`（如 `public.orders`） | 表权限里写 `schema.表`；库名、表名**区分大小写**；库权限覆盖该库全部表；`pg_catalog` / `information_schema` 免表级权限 |
| MongoDB（`mongo`） | database | 集合（collection） | 库名、集合名**区分大小写**；`db.getCollectionNames()`、`db.stats()` 这类库级语句需要库权限；`$lookup` 等引用的集合也要有权限 |
| ClickHouse（`clickhouse`） | database | 表 / 视图 / 字典 | 库名、表名**区分大小写**；语句涉及的每张表都需要库权限或表权限；`system` 库里放行的摘要表和 `INFORMATION_SCHEMA` 免权限 |

这三类实例的查询结果按“安全合规 › 数据脱敏”的配置脱敏（PostgreSQL 按结果列来源精确匹配，ClickHouse 保守匹配，MongoDB 按字段路径）。

## 审批

目标：审批他人的查询权限申请。审批人（持有 `qpriv.review`，同时属于当前这一级的权限组和该资源组）在详情页点「通过」或「驳回」：

- 点「通过」前会弹确认框，说明当前是不是末级、通过后进入哪一级审批；时间线上每一级只显示审批组，鼠标放上去显示这一级可审批的人员；撤回申请（详情页和列表行内）同样先确认，取消不会发请求；
- **驳回必须写原因**；任何一级驳回即终止，最后一级通过后**自动授予权限**（审批与授权在同一个事务里完成）；
- **不能审批自己的申请**（超级用户也不能自审查询权限申请）；
- 申请人可以在审批完成前**撤回**（只有申请人本人能撤回，超级用户也不能替别人撤回）；
- 审批人会收到机器人通知（钉钉 / 企业微信 / 飞书 / Lark / Slack / Telegram），点链接直接进入详情；通知失败不影响审批本身；
- 详情页只有申请人、超级用户、同资源组且有审批权限的人能看，其他人看到的是“不存在”。

## 查看与管理已授予的权限

「查询权限」页面列出库表权限：用户、实例、类型、库、表、行数上限、有效期（带剩余天数）、授予来源（申请单号或「管理员直接授予」）和状态（有效 / 即将到期 / 已过期）。顶部统计卡显示有效权限、7 天内到期、已过期（保留记录，不再生效）和涉及用户（管理者）/ 涉及实例（普通用户），点击可筛选；也可按用户、实例、库、状态和关键词筛选。7 天内到期的权限整行高亮。

没有 `qpriv.manage` 的人只能看到**自己**的权限；需要更多库表请到权限申请页提交申请，修改 / 回收他人权限需要 `qpriv.manage`。

有 `qpriv.manage`（高危）的人还可以：

- **修改**有效期和行数上限：点“修改”在编辑框里改，保存前会用**差异预览**列出改了哪几项；没有变化时提示“没有变更”，不会发请求；
- **回收**权限（立即生效，对方正在写的查询下一次执行起就会被拒绝）：高危确认框，列出用户、实例、库表和有效期；
- **直接授予**（「＋ 直接授予」）：不走审批，来源记为「管理员直接授予」；授予原因必填（至少 5 个字）并写入系统审计，只能授予与你同一资源组的启用用户；有效期不能早于今天，行数上限 1 到 100 万，用户已拥有同样的权限时拒绝重复授予；提交前同样弹高危确认，汇总用户、实例、库表、有效期和授予原因，授予后会通知被授予人。

管理范围限定在**自己资源组关联的实例**内。修改 / 回收也会写审计（含目标用户与新旧值）并通知受影响用户；权限来自申请单时，申请单日志里会追加一条权限变更记录。

## 权限如何参与查询判断

在线查询时，系统对语句涉及的**每一张表**（MongoDB 为集合）检查：存在有效的库权限（库名相同或 `*`）或表权限、未过期、未被回收；生效行数取各表限制的**最小值**，再与你选择的行数取小。超级用户、持有 `query.admin_run` 的人，以及 `query.group_run` 对资源组内实例，可以绕过库表授权。表级精确校验只对类型为 MySQL 的实例生效，其余 MySQL 协议类型与 SQL Server 只看库权限，Redis 只看 db 编号。详见[在线查询](#help/query)。

## 字段与校验规则

| 字段 | 含义 | 取值与默认 | 约束 |
|---|---|---|---|
| 实例 | 申请权限的目标实例 | 下拉 | 属于所选资源组且带 `can_read` 标签 |
| 资源组 | 决定审批流 | 下拉 | 必须是你所在的资源组 |
| 权限范围 | 库权限或表权限 | 库 / 表 | 库名、表名不能含逗号、不超过 64 字符；已有该库的库权限时，不能重复申请其下的表权限 |
| 有效期 | 权限截止日 | 默认 30 天后 | 不能早于今天 |
| 行数上限 | 在线查询最多返回行数 | 数字 | 1 到 1000000 |
| 申请理由 | 用途与数据范围 | 文本 | 必填，5 到 500 字 |

校验规则：

- 同一个人对同一实例的**相同内容**不能重复提交待审批申请；与自己待审批申请的库 / 表有重叠时会提示重复；
- 资源组没有配置审批流时无法提交，请联系管理员；
- 你选的资源组必须是你自己所在的资源组。

## 审计与安全说明

- 提交、审批通过、驳回、撤销每一步都会写一条系统审计（动作名“查询权限申请-…”，归入“查询与导出”类别）；直接授予、修改、回收同样写审计并带目标用户与新旧值；
- 回收、修改、直接授予要求按钮权限 `qpriv.manage`，服务端逐次校验；
- 申请理由与授予来源保存在扩展表中，需要先执行 `deploy/sql/040_query_apply_ext.sql`、`deploy/sql/041_query_priv_ext.sql`；没执行时不要求填理由，其余功能照常；
- 通知渠道是尽力而为，失败只记日志，不影响审批本身。

## 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 申请一直待审批 | 看详情页“当前审批人”；该级没人有审批权限 | 找管理员在[审批流程](#help/sysadmin)里补人 |
| 权限过期了怎么办 | 有效期已过 | 重新提交申请即可，不需要先删除旧权限 |
| 看不到别人的申请 | 没有 `qpriv.review` 的人只能看到自己提交的 | 需要审批请联系管理员授权 |
| 提交时提示资源组未关联实例 | 所选实例不属于所选资源组 | 换资源组，或联系管理员调整关联 |
| 有表权限，PolarDB 等实例仍提示无权限 | 查询里涉及的表不止授权的那一张（JOIN、子查询、视图背后的表都要有权限）；或权限已过期 / 被回收 | 看错误提示里指出的库表，补申请这张表的权限；已过期的重新申请 |
