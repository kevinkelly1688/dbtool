# 数据导出

在线查询有行数上限且不能下载，需要拿一批数据（对账、报表、迁移）时，通过导出工单：写一条只读查询、审批、执行、下载压缩包。导出工单与 SQL 上线共用同一套审批、定时和通知机制。菜单：数据服务 › 数据导出。

## 1. 功能概述

| 环节 | 说明 |
|---|---|
| 提交 | 选资源组、实例、库、导出格式，写一条只读查询，检查并统计行数后提交 |
| 审批 | 沿用资源组里配置的“SQL 上线”审批流，导出工单不会被自动审核规则自动通过 |
| 执行 | 审批通过后立即导出或定时导出，结果打包为 zip |
| 下载 | 在工单详情里下载，每次下载写审计 |

## 2. 适用范围

| 实例类型 | 单实例导出 | 批量导出 | 说明 |
|---|---|---|---|
| MySQL、PolarDB、PolarDB-X、SelectDB、Doris、ADB | ✔ | 部分 | 按 MySQL 规则校验，原生查询，不经 goInception；批量串行执行 |
| SQL Server | ✔ | ✔（默认开放） | 按 T-SQL 规则校验，支持 `DECLARE` / `SET @` 开头的只读批处理（可用表变量攒中间结果，见 5.1）；全部实例为 SQL Server 时批量并行 |
| Redis | ✖ | ✖ | 提示“请用在线查询” |
| PgSQL、Oracle、MongoDB、ClickHouse 等 | ✖ | ✖ | 提示“暂不支持 X 类型的实例提交 SQL 工单” |

“部分”的含义：批量导出的实例类型由环境变量 `BATCH_DB_TYPES`（逗号分隔，默认 `mssql`）决定，不在列表里的类型不能批量导出。所有类型都要求实例带启用的 `can_read` 标签，批量要求所选实例类型一致。

## 3. 前提条件与权限

| 按钮码 | 作用 |
|---|---|
| `export.view` | 查看、列表单实例导出工单 |
| `export.view_batch` | 查看、列表批量导出工单 |
| `export.submit` | 提交单实例导出 |
| `export.submit_batch` | 提交批量导出 |
| `export.download`（高危） | 下载导出文件 |
| `export.unmasked`（高危，锁定） | 提交时勾选“导出原值（不脱敏）”，见 5.4（仅超级用户） |
| `sqlworkflow.approve` / `sqlworkflow.reject` | 审批通过、驳回 |
| `sqlworkflow.execute_group` / `sqlworkflow.execute_own` | 立即导出（状态须为审核通过或定时执行） |
| `sqlworkflow.schedule` | 设置、取消定时导出 |
| `sqlworkflow.batch_op` | 批量实例的重试与关闭 |

- 查看他人的导出工单：除对应的 `export.view` / `export.view_batch` 外，还需要同资源组且持有 `sqlworkflow.view_group` 或 `sqlworkflow.execute_group`，或持有 `audit.view`、是超级用户；提交人始终能看到自己提交的。
- 只持有 `export.view` 或 `export.view_batch` 其中之一时，列表只显示对应类型（单实例或批量）的工单。
- 实例要求：带 `can_read` 标签、属于所选资源组、你可见（或持有 `query.admin_run`）。
- **库表查询权限**：导出用的是“查询权限”（权限申请里申请的库权限 / 表权限，与在线查询同一份）。提交页的实例和库列表只显示你有权限的实例与库；提交（以及“检查并统计行数”）时还会校验语句涉及的每张表你都有库权限或表权限，没有就报“你无 库.表 表的查询权限，请先申请”，且不会产生工单。超级用户、持有 `query.admin_run` 的用户、持有 `query.group_run` 的资源组管理员（实例须开启查询）不受限。SQL Server 只看库权限。SQL 上线工单不受这条限制。
- 审批人规则同[SQL 上线](#help/sqlworkflow)：不能自审，由系统配置 `approval.forbid_self_approve`（默认 true）决定，导出工单属于“严格类”，超级用户也不能自审；该设置显式设为 `false` 时不限制。

## 4. 操作指南

### 4.1 提交导出

目标：提交一条导出工单。入口：数据服务 › 数据导出 › 提交数据导出。

1. 点“提交数据导出”（`export.submit`），选择资源组、实例、库（只列出你有查询权限的实例与库；没有权限的先到“权限申请”页申请）。资源组决定走哪条审批流，页头标题旁的**审批流程预览**会按资源组显示成一条步骤“提交 → 第 1 级 · 审批组 → … → 审核通过，可执行”，鼠标放上去显示这一级可审批的人员，某一级没有人能审批会标红；需要提醒的情况（无人可审、没配置审批流、读取失败）在页头下面用整行提示条显示。
2. 选择导出格式：CSV、XLSX、JSON、XML、SQL（INSERT 语句）。
3. 写一条只读查询，点“检查并统计行数”（或在编辑器里按 `Ctrl+Enter`）。
4. （仅超级用户）需要导出未脱敏的原值时，在提交页的“导出原值（不脱敏）”卡片里勾选：先过高危确认（取消则不勾选），勾上后卡片变红并出现理由框，理由必填、5–200 字，默认已填好“业务需要查看原值”（可直接改，清空则提交会被拦下），框右下角显示“已写字数 / 200”，够 5 个字变绿，见 5.4；普通用户看不到这个选项。
5. 通过后填写名称（必填，至多 50 字）提交，进入审批流。需求链接（至多 500 字，须 `http(s)` 开头）、可执行时间窗口、定时导出时间都可不填。填了定时导出时间时，审批全部通过后自动转为定时导出，到点仍未批完则作废，定时期间可在详情页取消。

预期结果：工单进入审批流；资源组“SQL 上线”审批流为 0 级时，导出工单“无需审批，系统直接审核通过”（页头里没有步骤条，页头下面的提示条会写明提交后直接审核通过）。检查有错误时提交会被系统自动审核不通过。

### 4.2 审批与执行

1. 审批人在工单详情里通过或驳回。选了“导出原值”的工单，详情里有醒目的“导出原值 · 不脱敏”标记和提交人写的理由，通知标题与列表里也有标识，请核对理由是否合理再审批。
2. 审批通过后，有执行权限的人点“立即导出”或设置定时导出。导出工单不支持跳过检查，也没有“手工执行”。
3. 导出文件按审批通过后、执行时的实时数据生成。查询在目标实例执行，`LIMIT` 为“行数上限加 1”：多出的一行用来发现“执行时数据已经超限”，超限会直接中止，不会把超限的数据写出去；单次查询最长为 `export.max_seconds`（默认 60 秒）。
4. 结果打包为 zip：单实例一个文件，批量时默认每个实例一个文件（提交时勾选“合并成一个文件”则只有一个文件，见 4.4）。
5. 检查行数或导出时遇到连接超时、读取超时、连接被拒、连接被中断这类网络错误，结果里的信息先写原因和下一步，最后附“原始错误：…”（含实例地址和端口，给 DBA 排查），见 8；语法错误、表不存在、没有权限等语句自己的错误原样显示。
6. 导出太久时，DBA / 超级用户可以在详情页“导出进度”卡片里填取消原因（必填，≤ 500 字）点「取消执行」：正在进行的导出被中断，工单变为“执行有异常”，不会自动重试（批量导出会中断所有正在导出的实例），详见 [SQL 上线](#help/sqlworkflow)的“取消执行”。

### 4.3 下载

1. 在工单详情“基本信息”的“导出文件”一行点“下载文件”（`export.download`，高危），状态须为“已正常结束”或“执行有异常”。
2. 先弹确认框（提示文件是业务数据、下载会写审计）。确认后若文件已按保留策略清理、已不在存储里或你没有权限，确认框里会给出可读的说明，页面不会跳走。
3. 文件被清理后，这一行会写明清理时间并隐藏下载按钮；导出过程中详情页有进度条（批量按实例计数）。

下载需要同时满足：持有下载权限、能看到这张工单、文件名取自这张工单自己的记录。超过 256 MB 的文件不经浏览器内存，直接由浏览器下载，服务端会多记一条下载审计。

### 4.4 批量导出

同一条查询在多个实例上各导出一份（需要 `export.submit_batch`，实例类型受管理员限制）。

1. 把目标实例选成管理员放开批量的类型（默认只有 SQL Server）后，提交页才会出现“批量导出”开关。
2. 至少选 2 个实例（只导出一个实例请用单实例导出），最多 100 个；搜索框输入即筛选（空格分隔多个关键词），“全选”只选搜索结果。
3. 第一个勾选的实例用于选择数据库；预检每个实例：能连接、存在所选数据库、待导出行数不超过上限，预检不通过的实例需取消勾选后重新检查；不通过的原因写在“实例预检”表的“说明”列（连不上、超时的会给出处理建议，见 8）。
4. 默认每个实例一个文件，统一打成一个压缩包。实例多、不想要一堆文件时，勾选下面的“合并成一个文件”。

**合并成一个文件**（提交批量导出时勾选，需要已执行 `deploy/sql/290_export_unmasked.sql`；没执行时页面不出现这个选项）：压缩包里只有一个文件 `<工单号>/merged_<工单号>.<格式>`，各实例导出的数据按勾选顺序依次接在一起，**不加实例名称列**，表头（CSV 首行、XML 字段列表、Excel 首行）只有一份。CSV、Excel、JSON、XML、SQL 五种格式都支持。

- 各实例返回的列必须一致（列名和顺序，忽略大小写）。点“检查并统计行数”时会逐个实例探一次列名，不一致的实例直接标红，需要取消勾选该实例后重新检查；`DECLARE` / `SET @` 批处理没法预先探列，执行时再核对；用了 `select *` 而各实例表结构不同时，请改成明确的列名。
- 执行时以第一个导出成功的实例的列为准，列对不上的实例按失败处理（结果行写明两边的列），不写进文件，其它实例不受影响。
- 每个实例的行数上限（`export.max_rows`）不变，合并后的总行数是各实例之和。Excel 格式合并后总行数不能超过 1,048,575（含表头），超了不允许提交，请改用 CSV 或缩小范围。
- 文件里看不出每行来自哪个实例，每个实例的行数在工单的“执行结果”里。需要区分来源时，在查询里自己加一列，例如 MySQL 的 `@@hostname`、SQL Server 的 `@@SERVERNAME`。
- 脱敏、“导出原值”、SQL 防火墙复核仍然对每个实例分别生效；“导出原值”可以和合并同时选。

部分失败：成功实例的文件仍可下载，工单标为“执行有异常”，汇总写明哪些实例没导出；全部失败则不生成文件。重试失败实例：新文件会合并进同一个压缩包，其余实例已导出的文件不会丢（合并成一个文件时，重试实例的数据追加到合并文件末尾，其它实例已写入的数据不变，所以重试过的实例排在最后）；全部成功后变为“已正常结束”。失败实例除“重试”外还可“关闭”；全部关闭不置成功。审批后被删除的实例会写“实例已不存在，跳过导出”，不影响其他实例。

### 4.5 查看导出工单列表

- 顶部统计卡：待审批、待导出（审核通过加定时导出）、导出中（排队中加导出中）、已完成、导出异常、已终止（人工终止加自动审批不通过）；待审批、已完成、导出异常的卡片可点击筛选。
- 页签“全部导出 / 普通导出 / 批量导出”，以及“只看待我审批”“我提交的”“待我执行”三个快捷筛选（带数量）；可按状态、实例、资源组筛选，搜索框匹配工单号、名称、提交人、库和实例。
- 行数列：“已正常结束”和“执行有异常”的是实际导出行数，其余是检查阶段统计的预计行数（前面带 ≈）。

## 5. 规则与字段说明

### 5.1 语句与行数规则

- 只允许一条 SELECT 或 WITH；拒绝 `INTO OUTFILE`、`INTO DUMPFILE`、`FOR UPDATE`、`LOCK IN SHARE MODE`、`load_file` 等危险函数、`;` 夹带第二条语句、查询 `mysql.user`。
- SQL Server：SELECT、WITH，或 `DECLARE @` / `SET @` 开头的只读批处理（`GO` 行会被去掉）；多个语句单元报“检测到 N 个语句”。批处理里可以用 `DECLARE @t TABLE (…)` 声明表变量，再 `INSERT [INTO] @t SELECT … / VALUES (…)` 攒中间结果，最后用 `SELECT` 输出要导出的数据（导出的是第一个结果集）。表变量的数据放在 SQL Server 的 tempdb 里，中间结果攒得太大会占用 tempdb 空间，别拿它搬大批量数据。只放行写这种表变量：写真实表、`#临时表`、没用 `DECLARE … TABLE` 声明的变量被拒绝，提示“INSERT 只能写入 DECLARE @变量 TABLE (…) 声明的表变量，不能写入表或临时表”；`INSERT … EXEC`、`SELECT … INTO`、`OUTPUT`（包括不带 `INTO` 的 `INSERT … OUTPUT`，它会把写入的行当成第一个结果集返回，绕过脱敏）、对表变量的 `UPDATE` / `DELETE`、`EXEC`、事务控制等被拒绝，提示“只读查询里不允许出现 xxx”。检查阶段不会确认批处理里有没有输出结果的 `SELECT`，只有 `INSERT`、没有 `SELECT` 的脚本要到执行时才报“该批处理没有返回结果集（需要一条 SELECT 输出结果）”。
- 系统会先统计行数（`SELECT COUNT(*) FROM (你的查询)`；SQL Server 会去掉最外层 `ORDER BY`），超过上限判错，不允许提交，提示“导出数据行数(N)超过阈值(M)”，请加条件或拆分。
- SQL Server 的 `DECLARE` / `SET @变量` 批处理无法预统计，会给出警告，行数限制留到执行时兜底：批处理不会被改写成 `TOP`，执行时读到“上限加 1”行即中止。
- SQL 全文至多 2,000,000 字符，批量最多 100 个实例，定时时间须晚于当前且落在可执行时间范围内（定时功能需要 `dbt_sql_schedule` 表）。

```sql
-- 导出某天的退款流水
SELECT refund_no, order_no, amount, status, created_at
FROM pay_db.refund_record
WHERE created_at >= '2026-10-01' AND created_at < '2026-10-02';
```

### 5.2 导出格式

| 格式 | 说明 |
|---|---|
| CSV | UTF-8（无 BOM，Excel 直接打开中文可能乱码）；首行为列名，所有字段加引号，换行为 `\r\n`，NULL 写成带引号的 `"null"`，与字符串 `'null'` 不可区分 |
| XLSX | 全部按文本单元格，避免长数字和前导零被 Excel 改写；NULL 写空串；单工作表 `Sheet1`，含表头不超过 1,048,576 行，超出报错 |
| JSON | 数组，每行一个对象，键保持列顺序 |
| XML | `<tabledata><fields><field>列名</field>…</fields><data><row id="N"><column-1>值</column-1>…`，列用 `column-N` 命名而不是列名，NULL 为 `(null)`，非法控制字符被剔除 |
| SQL | 每行一条 `INSERT INTO your_table_name (...) VALUES (...);`，表名由使用者替换；NULL 与空字符串都写成 NULL，列名不加引号，数字与布尔不加引号，字符串与日期用单引号；MySQL 方言把 `\` 转成 `\\` |

### 5.3 系统配置与环境变量

| 配置项 | 默认 | 范围与说明 |
|---|---|---|
| `export.max_rows` | 10000 | 1–10,000,000；导出工单最多导出多少行，结果全部读进内存，别调太大 |
| `export.max_seconds` | 60 | 1–86400；导出查询（及行数统计）的最长时间 |
| `export.storage_type` | `local` | 目前只支持本地目录 |
| `export.local_path` | `downloads/DataExportFile/` | 相对路径时相对环境变量 `EXPORT_BASE_DIR`，不能含 `..`，服务账号需要写权限 |
| `export.mask_enabled` | `true` | 导出工单是否按脱敏规则处理 |
| `query.mask_enabled` | `false` | 数据脱敏总开关，关闭时导出也不脱敏 |
| `review.batch_parallel_workers` | 4 | 至多 16 且不超过实例数，仅在全部实例为 SQL Server 时并行 |
| `BATCH_DB_TYPES`（环境变量） | `mssql` | 允许批量导出（与批量上线共用）的实例类型 |

### 5.4 脱敏

导出结果按“安全合规 › 数据脱敏”的配置脱敏：`export.mask_enabled` 默认开启，但总开关 `query.mask_enabled` 默认关闭，需先在[数据脱敏](#help/masking)页开启总开关，否则导出的是原值。脱敏失败会中止导出，不会产出原值；结果行里写明“已脱敏”的列。SQL Server 批处理里变量、表变量带出的敏感字段，以及调用存储函数 / 自定义函数的结果列，也按同样规则脱敏，见[数据脱敏](#help/masking)的保守匹配。

**导出原值（仅超级用户）**：导出文件默认按上面的规则脱敏，没有“个人例外”。超级用户在提交导出申请时可以勾选“导出原值（不脱敏）”（权限码 `export.unmasked`，锁定，只认超级用户，不能授予权限组）：
- 只有“这次导出本来会脱敏”（总开关 `query.mask_enabled` 开着、`export.mask_enabled` 没关，且已执行 `deploy/sql/290_export_unmasked.sql`）时，页面才出现这个选项；勾选要先过高危确认，**必须写理由**（5–200 字，理由框下方实时显示字数，够 5 个字变绿）。
- 审批人在工单详情里看到“导出原值”标记和理由，列表上有“导出原值”标签，通知标题带“数据导出申请（导出原值，不脱敏）”，系统审计留痕；结果行写明“导出原值，未脱敏”。
- 执行时会复核提交人**仍是启用的超级用户**，否则这张单按脱敏设置导出（详情里会提示选择已不生效）；记录读不出来也按脱敏导出。
- **SQL 防火墙要求强制脱敏的列照样脱敏**，选了导出原值也不放开。
- 只影响这一张导出工单；批量导出、定时导出、失败实例重试都遵守同一个选择。其他用户、在线查询、其它设置都不受影响。

SQL 防火墙对导出场景同样生效：检查与执行前复核都会求值，可拒绝、可把行数上限压低（与 `export.max_rows` 取小）、可强制脱敏（即使脱敏总开关关闭，做不了就中止），见[SQL 防火墙](#help/firewall)。没有配置脱敏的字段仍是原值，请只导出业务确实需要的列，并遵守公司的数据安全规范。

### 5.5 文件命名与保留

- 单实例：`<库名>_<yyyymmddHHMMSS>_<8位随机>.zip`；批量：`<工单号>_<时间戳>_<随机>.zip`，内含 `<工单号>/<实例名>.<ext>`，实例名里的非法字符换成下划线，重名追加 `_<实例ID>`；合并成一个文件时包里只有 `<工单号>/merged_<工单号>.<ext>`。
- 默认不自动清理。管理员开启数据清理（`retention.enabled`）并设置 `retention.export_files_days`（不小于 7，0 或未设置为不清）后，到期的 zip 被删除，工单记录保留；下载时提示“文件已于 … 按保留策略清理，请重新提交导出”。文件被手工删除则返回“文件不存在（可能已被清理）”。请在保留期内下载。

## 6. 限制与注意事项

> 注意：导出文件保存在服务端本地目录，多实例部署需要共享目录；导出进度只存本进程内存，多进程部署时其它进程看不到进度。

> 注意：导出文件是业务数据，每次下载都会写审计，请只导出需要的列。

- 导出工单不能跳过检查、不支持手工执行，也不会被自动审核规则自动通过；资源组审批流为 0 级时除外（见 4.1）。
- 批量工单仅在“无待处理失败实例且至少一个实例成功”时变为已正常结束。

## 7. 审计与安全说明

- 导出工单走 SQL 上线通用动作（“SQL上线-”前缀）：提交、审批通过、立即执行、定时执行、取消定时、批量实例重试 / 关闭、取消工单执行、标记执行异常；额外信息里类型标为“数据导出”或“批量导出”。
- 下载写审计“离线下载”（额外信息含工单 id 与文件名）：只在到达文件层才写，无权限、工单不可见、状态未结束、非导出工单不写；没有文件名、存储错误、文件不存在写带 error 的记录。
- 权限校验点：提交时校验提交与实例权限，以及语句涉及的库表查询权限（没有则拒绝提交，不产生工单）；下载时校验下载权限、工单可见与状态。

## 8. 常见问题与排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| “导出数据行数(N)超过阈值(M)” | 超过 `export.max_rows` | 加条件或拆分 |
| “实例未开启‘查询’权限（缺少 can_read 标签）” | 实例没有 `can_read` 标签 | 请管理员给实例打标签 |
| 实例 / 库下拉里没有想导出的 | 你没有该实例 / 库的查询权限（库权限或表权限） | 到“权限申请”页申请查询权限 |
| “你无 库.表 表的查询权限，请先申请” | 语句里有你没有权限的表 | 申请该表（或整个库）的查询权限，或去掉该表 |
| “数据导出工单不支持跳过检查” | 提交时选了跳过检查 | 去掉跳过检查 |
| “批量导出至少选择 2 个实例” | 只选了一个 | 改用单实例导出 |
| “返回的列与第一个实例「…」不一致” / “返回的列与合并文件不一致” | 合并成一个文件时，某个实例返回的列和别的实例不同（表结构不一致、`select *`） | 查询里写明确的列名；或取消勾选该实例；或不合并（每个实例一个文件） |
| “合并后的行数超过 Excel 的上限” | 合并成一个文件、格式选了 Excel，各实例行数加起来超过 1,048,575 | 改用 CSV，或缩小范围 |
| 提示“合并成一个文件需要先更新 dbt_sql_export_ext 表” / 提交页没有“合并成一个文件” | 没执行（或只执行过旧版的）`deploy/sql/290_export_unmasked.sql`，表里缺 `merge_files` 列（升级时 `install.sh` 会自动执行） | 执行脚本后刷新页面 |
| 某一级审批流标红 | 该级没有人能审批 | 请管理员配置审批组 |
| 检查或导出提示“连接数据库实例超时，实例可能不可达或网络不通……” | 连接实例时超时：地址 / 端口不对、实例不可达，或网络 / 防火墙不通 | 按提示确认实例地址、端口和网络 / 防火墙。提交前：修好后重新点“检查并统计行数”（批量时可先取消勾选该实例）；已提交：批量工单对失败实例点“重试”，单实例工单“复制为新工单”重新提交 |
| 提示“读取数据时与数据库实例的网络连接超时（实例长时间没有返回数据）……” | 查询太慢（没走索引、数据量大），或网络 / 防火墙中断了长时间的连接 | 缩小查询范围、加过滤条件，避开业务高峰后重试（重试方式同上一行）；仍然超时请 DBA 检查网络 |
| 提示“无法连接数据库实例：地址解析失败或端口没有服务在监听……” | 连接被拒绝或域名解析失败：地址写错、端口不对、实例没在运行 | 请 DBA 确认实例地址、端口和实例状态，恢复后按上面的办法重试 |
| 提示“与数据库实例的连接被中断（实例重启、网络抖动，或被防火墙 / 会话终止断开）……” | 导出过程中连接被对端重置或断开 | 稍后重试；反复出现请 DBA 检查实例和网络 |
| 上述提示末尾的“原始错误：…” | 驱动返回的原文，含实例地址和端口 | 给 DBA 排查用，联系时带上整段提示；语法错误、表不存在、没有权限这类语句自己的错误不会被改写，原样显示 |
| 下载提示文件已清理 | 超过保留期 | 重新提交导出工单 |
| 导出的还是原值 | `query.mask_enabled` 关闭，或字段没配置脱敏；也可能是超级用户提交时选了“导出原值” | 见 5.4；选了导出原值的工单在详情里有标记和理由 |
| 提示“导出原值需要先创建 dbt_sql_export_ext 表” | 没执行 `deploy/sql/290_export_unmasked.sql`（升级时 `install.sh` 会自动执行） | 执行脚本后刷新页面 |
| 详情里提示“提交人现在已不是超级用户，执行时不会导出原值” | 提交后提交人被降级或停用 | 按脱敏设置导出；确需原值请由超级用户重新提交 |
| 提交后直接显示“审核通过” | 审批流 0 级 | 属预期 |
| CSV 中文在 Excel 乱码 | 文件为 UTF-8 且无 BOM | 用“数据 › 从文本导入”并选 UTF-8，或改用 XLSX |

## 9. 验证状态与已知限制

验证状态与已知限制如下：

- SQL Server 导出路径未对真实 SQL Server 验证（`datetime2`、`decimal`、`uniqueidentifier`、`varbinary`、`nvarchar` 的各格式内容、带 `ORDER BY` 的行数统计、`DECLARE` 批处理）；大结果集（接近上限、宽表）下 XLSX 的内存与耗时未验证。
- MySQL 系批量导出（放开 `BATCH_DB_TYPES` 后）只有测试覆盖。
- 导出遇到网络错误时的中文提示按错误文字识别（`i/o timeout`、`connection refused`、`no such host`、`connection reset`、`broken pipe`、`bad connection`、`unexpected EOF`），只用构造的错误文字测试过，没有在真实断网 / 超时的 MySQL 或 SQL Server 上验证；认不出的错误（如 `no route to host`、`invalid connection`）原样显示。
- 存储类型仅本地目录。
